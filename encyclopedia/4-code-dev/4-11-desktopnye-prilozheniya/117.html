Microsoft Store и публикация Windows-приложений

ОБЯЗАТЕЛЬНОДЛЯ НОВИЧКОВ
Разработчику Архитектору Инженеру

Практичный порядок чтения​

Для первого релиза пройдите материал в порядке: учетная запись → пакет → submission → обновления.
Так вы быстрее соберете рабочий checklist и снизите риск отказа на этапе сертификации.

Microsoft Store как платформа​

Microsoft Store — официальный канал дистрибуции приложений и игр для Windows, а также связанная витрина для Xbox-экосистемы. Это не только "магазин в Windows", а часть общей инфраструктуры Microsoft для доставки, обновлений, лицензирования и модерации ПО.

Официальная витрина: apps.microsoft.com.
Контекст для индустрии игр: Цифровые магазины и физические дистрибьюторы.

На уровне пользователя Microsoft Store решает четыре задачи:

  • поиск и установка приложений/игр;
  • централизованные обновления;
  • управление покупками и лицензиями через Microsoft Account;
  • доверенная модель распространения с проверкой пакетов и политик.

На уровне разработчика это единый маршрут "билд → пакет → submission → сертификация → обновления".

Что получает пользователь​

Типичный пользовательский сценарий в Microsoft Store включает:

  • карточку приложения или игры с описанием, скриншотами и системными требованиями;
  • рейтинги и отзывы;
  • каталог с подборками и рекомендациями;
  • установку в один поток без отдельного веб-установщика (для Store-пакетов);
  • автоматические обновления через Store.

Для части продуктов работает кросс-экосистемный сценарий: покупка и доступ через Microsoft Account на нескольких устройствах, если это поддержано издателем и моделью лицензии.

Microsoft Store, Xbox Store и Xbox App​

В практической эксплуатации это три связанных слоя:

  • Microsoft Store — общий каталог приложений и части игр в Windows;
  • Xbox Store — консольная витрина и лицензирование в экосистеме Xbox;
  • Xbox App (Windows) — отдельный клиент для Game Pass, библиотеки и социальных игровых функций.

Для разработчика это означает, что в игровых сценариях важны не только требования Store, но и связка с Xbox-сервисами, если проект рассчитывает на PC Game Pass, достижения Xbox или кросс-девайсные сценарии.

Почему это важно разработчику​

Публикация через Store даёт:

  • централизованную доставку и обновления;
  • встроенную инфраструктуру доверия (подпись, проверка пакетов);
  • доступ к аудитории Windows и промо-возможностям витрины;
  • единый Partner Center для релизного цикла.

Trade-off тоже есть: вы принимаете требования сертификации, правила контента и ограничения на упаковку/поведение приложения в зависимости от выбранной модели распространения.

Быстрый чеклист перед отправкой​

  • пакет собирается воспроизводимо и ставится на "чистую" систему;
  • версия, release notes и метаданные согласованы;
  • listing отражает реальное поведение приложения;
  • права доступа и capabilities обоснованы;
  • сценарий обновления и отката проверен;
  • подготовлен план реакции на review feedback и post-release инциденты.

Microsoft Store - распространение под Windows​

Microsoft Store — канал распространения, через который приложение получает установку, обновления и поиск среди пользователей Windows. Microsoft позиционирует Store как способ доставить приложение миллионам пользователей с проверкой подписи, политиками безопасности и единым интерфейсом установки.

Официальное руководство: Начало работы с Microsoft Store.

Контекст платформы и выбора стека (WinUI, WPF, WinForms): Разработка приложений для Windows. Общие практики упаковки десктопа: Особенности разработки десктопных приложений (раздел DevOps, MSIX).

Учётная запись разработчика​

Перед отправкой приложения нужна учётная запись разработчика Windows в Partner Center. Два типа:

ТипКому подходит
ИндивидуальнаяНезависимые разработчики, хобби, учебные и некоммерческие проекты
КорпоративнаяКомпании, для которых публикация в Store — часть бизнеса

Инструкции: открыть индивидуальную учётную запись, корпоративную (разделы на той же ветке документации).

Формат пакета — MSIX и альтернативы​

Microsoft рекомендует упаковывать приложение как MSIX — независимо от того, собрано ли оно на UWP, Win32, WinUI / Windows App SDK, PWA и т.д.

Преимущества MSIX для Store (по документации Microsoft):

  • бесплатное размещение бинарников и подпись кода со стороны Microsoft для публикации в Store;
  • поэтапное развёртывание пакетов, интеграция с Windows (общий доступ к файлам, запуск из Store);
  • резервное копирование и восстановление в Windows 11.

Обзор формата: MSIX overview. Упаковка классического Win32: Package a desktop app.

Альтернативный путь в Store — MSI или EXE (веб-скачивание внутри Store); для новых проектов MSIX остаётся предпочтительным.

Переход с EXE/MSI на MSIX

Если приложение уже распространяется с сайта как EXE/MSI, перед публикацией в Store подготовьте сценарий миграции пользователей, чтобы избежать параллельных конфликтующих установок. Практическое руководство: transition users to Store packaged app.

PWA: веб-сайт можно превратить в Progressive Web App и опубликовать в Store — Turn your website into a PWA.

Коммерция и доход​

Store поддерживает покупки в приложении, подписки, рекламу и чаевые. Разработчик может:

  • использовать собственную коммерческую платформу и оставлять 100% дохода (для приложений, не относящихся к играм, в описанной модели);
  • или платформу Microsoft с комиссией ~12% для игр и ~15% для приложений (актуальные цифры — в документации по монетизации).

Детали меняются — сверяйтесь с get-started Store на момент публикации.

Процесс публикации MSIX / PWA (этапы)​

1. Зарезервировать имя приложения​

Имя в Store должно быть уникальным. Резервирование возможно до трёх месяцев до фактической публикации, даже если разработка ещё не началась.

  1. Откройте Apps and games в Partner Center.
  2. Создать продукт → Приложение MSIX или PWA (для игр — тип "Игра").
  3. Проверьте доступность имени и зарезервируйте его.

Подробнее: Reserve your app's name.

2. Создать отправку (submission)​

После резерва откройте обзор приложения → Начать отправку. Черновик включает вкладки:

ВкладкаСодержание
Цены и доступностьЦена, регионы, пробные версии — price and availability
СвойстваКатегория, системные требования — app properties
Возрастные рейтингиАнкета IARC — age ratings
ПакетыЗагрузка MSIX — upload app packages
Листинг StoreОписание, скриншоты, логотипы — store listing

После заполнения отправка уходит на сертификацию Microsoft (проверка политик, безопасности, работоспособности).

3. Обновления​

После публикации новые версии загружаются как обновлённые пакеты MSIX через Partner Center; пользователи получают обновления через Store (в отличие от ручного скачивания EXE с сайта).

  2. Соберите MSIX из Visual Studio: Publish → Create App Packages.
  3. Staged rollout 5% — проверка на реальных пользователях.

Подготовка пакета до отправки в Store​

Что проверить в release-сборке​

  1. Версия приложения, номер пакета и changelog синхронизированы.
  2. Подпись пакета корректна, сертификат действителен.
  3. Иконки, скриншоты и описание соответствуют фактическому UI.
  4. Разрешения и capabilities минимальны и обоснованы.
  5. Установщик обновляет предыдущую версию без ручного удаления.

Техническая проверка перед submission​

  • Установка на чистую VM без developer-инструментов.
  • Проверка запуска без прав администратора.
  • Проверка сценария обновления с предыдущей стабильной версии.
  • Smoke-тест на медленной сети и без сети.

Частые причины задержек на review​

  • Некорректный возрастной рейтинг и несоответствие контенту.
  • Формальные ошибки в Store listing, метаданных и локализациях.
  • Избыточные разрешения без объяснения в описании продукта.
  • Нестабильная работа при первом запуске или после обновления.

Практика публикации без сюрпризов​

Рекомендуемый ритм релизов​

  1. Подготовка release candidate на отдельной ветке.
  2. Техническая и контентная проверка Store listing.
  3. Публикация с ограниченным rollout и мониторингом.
  4. Расширение rollout после подтверждения стабильности.

Что держать под контролем после релиза​

  • Crash rate и ошибки запуска на разных версиях Windows.
  • Конверсию установки из карточки Store.
  • Долю успешных обновлений с предыдущей версии.
  • Качество пользовательских отзывов по каждой новой версии.
