Вопросы на собеседовании — Core Java

НЕ ОБЯЗАТЕЛЬНОДЛЯ НОВИЧКОВ
Разработчику

Эта страница — карта подготовки к собеседованию по языку Java (без Spring и DevOps). Полные разборы — в указанных главах; здесь — тема, что обычно ждут услышать и ссылка "копнуть глубже".

Материал удобно использовать как "тренажёр устных ответов": открываете строку таблицы, проговариваете определение, короткий пример и ограничение.

Как пользоваться​

  1. Пройдите рекомендуемый порядок по энциклопедиям — хотя бы один раз с примерами кода.
  2. Откройте внешний список (JavaRush / ITVDN) и отмечайте пункты: "могу объяснить вслух" / "нужно перечитать".
  3. Закройте пробелы по чек-листу самопроверки.
  4. На собеседовании отвечайте структурой: определение → пример → ограничение или типичная ошибка.

Источники для сверки формулировок:

  • JavaRush: Top-50 Java Core, часть 1 (ООП, синтаксис)

Советы по подготовке​

Говорите вслух. Определение без примера звучит заученно. Одна строка кода или сценарий ("два ключа с одинаковым hash в HashMap…") повышает доверие.

Признавайте границы. "В проде PostgreSQL, детали G1 смотрю в 23" — нормальный ответ для Junior.

Legacy. Если спрашивают Date — в новом коде java.time (11, 300).

Spring отдельно. Цепочка 271 → 272 → 274 → 303 — типичный REST-стек на собеседовании.

Шаблон ответа, который нравится интервьюеру​

Для большинства вопросов по Core Java отлично работает структура из трёх шагов:

  1. Короткое определение термина.
  2. Мини-пример из практики или 2-3 строки кода.
  3. Ограничение, типичная ошибка или компромисс.

Пример для "чем HashMap отличается от TreeMap":

  • HashMap даёт быстрый доступ по хешу без сортировки ключей;
  • TreeMap хранит ключи в отсортированном виде;
  • если нужен упорядоченный вывод, берут TreeMap, если важнее скорость и порядок не нужен, чаще выбирают HashMap.

Что часто недоговаривают кандидаты​

ВопросЧастая недосказанностьЧто стоит добавить
equals и hashCodeГоворят только про equalsУточнить контракт: равные объекты обязаны иметь одинаковый hash
volatileОписывают как "ускоряет"Пояснить, что это про видимость, не про атомарность
ArrayList vs LinkedListТолько Big-O из учебникаДобавить, что cache locality у ArrayList часто даёт выигрыш в реальном CPU
Checked / uncheckedТолько определенияДобавить, где на практике используют runtime-исключения

Мини-блок "кодом, а не словами"​

Если просят объяснить тему, короткий фрагмент кода обычно сильно усиливает ответ:

Map<String, Integer> map = new HashMap<>();
map.put("A", 1);
map.put("A", 2); // ключ тот же, значение заменилось
System.out.println(map.get("A")); // 2

По этому примеру легко и уверенно объяснить:

  • ключи в Map уникальны;
  • повторный put перезаписывает значение;
  • поведение связано с equals и hashCode.

Как связать Core Java с backend-интервью​

  1. Core Java.
  2. Коллекции и многопоточность.
  3. Spring и REST.
  4. База данных и интеграции.

Поэтому полезно сразу держать мосты к следующим разделам:

  • Spring Boot — первый API
  • Ошибки REST — @Valid и @ControllerAdvice
