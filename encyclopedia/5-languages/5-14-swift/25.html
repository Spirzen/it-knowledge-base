Свойства-обёртки в Swift

ОБЯЗАТЕЛЬНОДЛЯ НОВИЧКОВ
Разработчику Архитектору

property wrapper - перехват доступа к свойству​

В проектах часто повторяется одна и та же логика вокруг свойства: чтение/запись в UserDefaults, валидация, потокобезопасный доступ, синхронизация с UI. Копировать её в каждом поле утомительно и ошибочно.

Свойство-обёртка (property wrapper) — тип, который перехватывает доступ к помеченному свойству: при чтении и записи вызывается код обёртки, а снаружи синтаксис остаётся обычным (settings.isDarkMode = true).

Обёртки появились в Swift 5.1; в экосистеме Apple они стали основой SwiftUI (@State, @Binding, …) и части Combine.

Минимальная своя обёртка​

@propertyWrapper
struct Clamped {
    private var value: Int
    let range: ClosedRange<Int>

    init(wrappedValue: Int, _ range: ClosedRange<Int>) {
        self.range = range
        self.value = min(max(wrappedValue, range.lowerBound), range.upperBound)
    }

    var wrappedValue: Int {
        get { value }
        set { value = min(max(newValue, range.lowerBound), range.upperBound) }
    }
}

struct Player {
    @Clamped(0...100) var health = 100
}

Разбор:

  • @propertyWrapper помечает тип как обёртку, которую можно навесить на свойства через @Clamped.
  • wrappedValue определяет поведение при чтении и записи: значение всегда зажимается в границы range.
  • init(wrappedValue:..., _ range: ...) принимает стартовое значение и допустимый диапазон.
  • min(max(...)) реализует clamp-логику и защищает состояние от выхода за пределы.
  • В Player свойство health получает эту логику автоматически без дублирования кода.

Обязательные элементы типа-обёртки:

ЧленНазначение
wrappedValueТо, что видит код при обращении к свойству
init(wrappedValue:) или кастомный initНачальное значение и параметры обёртки
@propertyWrapper на типеПомечает тип как обёртку

Компилятор разворачивает @Clamped в хранение экземпляра обёртки и прокси-доступ к wrappedValue.

Параметры обёртки​

Аргументы в скобках после @ передаются в инициализатор:

@Clamped(0...100) var stamina = 50

Разбор:

  • Аргумент 0...100 передаётся в инициализатор обёртки как ограничение диапазона.
  • Значение 50 идёт как wrappedValue и проходит ту же валидацию.
  • Для вызывающего кода это выглядит как обычное свойство, но под капотом работает дополнительная логика.

Можно задавать несколько параметров и значения по умолчанию — как у обычного инициализатора структуры.

Своя обёртка с projectedValue (учебный аналог $):

@propertyWrapper
struct Logged<Value> {
    private var value: Value
    init(wrappedValue: Value) { self.value = wrappedValue }

    var wrappedValue: Value {
        get { value }
        set {
            print("было: \(value), стало: \(newValue)")
            value = newValue
        }
    }

    var projectedValue: Logged<Value> { self }
    func reset(to newValue: Value) { value = newValue }
}

struct Form {
    @Logged var email = ""
}

var form = Form()
form.email = "a@b.c"
form.$email.reset(to: "")

Разбор:

  • wrappedValue — обычный доступ к полю; при set печатается аудит изменения.
  • projectedValue возвращает саму обёртку, поэтому $email даёт доступ к reset(to:).
  • Компилятор генерирует $email только если объявлен projectedValue.
  • Паттерн похож на @Binding/@State в SwiftUI, но в упрощённом учебном виде.

projectedValue и $​

Некоторые обёртки предоставляют проецируемое значение — доступ через префикс $ к дополнительному API (часто Binding в SwiftUI):

struct ContentView: View {
    @State private var count = 0
    var body: some View {
        Stepper("Счёт: \(count)", value: $count)
    }
}

Разбор:

  • @State private var count создаёт локальное состояние SwiftUI-представления.
  • Stepper(..., value: $count) получает Binding через $count, чтобы менять состояние двусторонне.
  • При изменении count SwiftUI автоматически пересчитает body и обновит интерфейс.
  • Здесь хорошо видно различие: count — само значение, $count — его проекция (projectedValue).

count — обычное чтение/запись; $count — проекция для двусторонней связи с UI. Это не "магия доллара", а соглашение: если у обёртки есть projectedValue, компилятор генерирует $имя.

Пример без UI — настройки приложения​

Повторяющийся доступ к UserDefaults удобно вынести в обёртку (упрощённый учебный вариант):

@propertyWrapper
struct Storage<T> {
    let key: String
    let defaultValue: T

    var wrappedValue: T {
        get {
            UserDefaults.standard.object(forKey: key) as? T ?? defaultValue
        }
        set {
            UserDefaults.standard.set(newValue, forKey: key)
        }
    }
}

struct AppSettings {
    @Storage(key: "darkMode", defaultValue: false)
    static var isDarkMode: Bool
}

Разбор:

  • Обёртка Storage<T> обобщённая: подходит для разных типов T, поддерживаемых UserDefaults.
  • key задаёт ключ хранения, defaultValue возвращается при отсутствии сохранённого значения.
  • get читает объект из UserDefaults и приводит к типу T; при неуспехе подставляет дефолт.
  • set сохраняет новое значение по тому же ключу.
  • В AppSettings статическое свойство isDarkMode получает единообразный доступ к персистентной настройке.

В продакшене для сложных типов добавляют кодирование (Codable) и потокобезопасность; идея та же — одна реализация, много свойств.

Более развёрнутый пример — в рекомендациях по разработке.

Где встречаются в стандартной экосистеме​

ОбёрткаКонтекст
@State, @Binding, @ObservedObjectSwiftUI — состояние и связь с UI

@MainActorИзоляция на главном акторе (async)
@UIApplicationDelegateAdaptor и др.Мосты в SwiftUI App

Перед SwiftUI достаточно понять модель: обёртка = тип + доступ к wrappedValue. Тогда аннотации Apple читаются как конкретные реализации той же идеи.

Ограничения и правила​

  • Обёртку можно применять к stored property в struct, class, enum; для static и class — отдельные правила версии Swift.
  • Нельзя обернуть вычисляемое свойство без backing storage так же просто, как хранимое — компилятор требует место для экземпляра обёртки.
  • Обёртки на уровне локальных переменных и параметров поддерживаются в новых версиях языка — проверяйте целевую версию в Package.swift / настройках проекта.
  • Тестируйте обёртку отдельно: она должна вести себя предсказуемо при get/set.

Практические советы​

  1. Не оборачивайте всё подряд — обёртка оправдана при трёх и более повторениях одного паттерна.
  2. Документируйте, что делает get/set (потоки, персистентность, побочные эффекты).
  3. Имя обёртки должно читаться в объявлении: @ValidatedEmail var email понятнее @Wrapper1.
  4. Для SwiftUI сначала освойте @State и @Binding, затем @ObservedObject / @EnvironmentObject.

Практика использования property wrapper​

Свойства-обёртки эффективны, когда нужно единообразно внедрить повторяющееся поведение на десятках полей.

Хорошие кандидаты​

  • Доступ к настройкам через UserDefaults/Keychain.
  • Валидация диапазонов и форматов.
  • Унифицированное логирование или аудит изменения значения.

Когда выбрать другой инструмент​

  1. Логика относится к целому объекту, а не к одному полю.
  2. Нужна генерация большого объема кода — лучше макрос или кодогенерация.
  3. Требуется сложная оркестрация сервисов — лучше DI-слой.

Сквозной мини-кейс — настройки приложения​

Несколько полей с единой логикой чтения/записи в UserDefaults:

@propertyWrapper
struct AppStorage<T> {
    let key: String
    let defaultValue: T

    var wrappedValue: T {
        get {
            UserDefaults.standard.object(forKey: key) as? T ?? defaultValue
        }
        set {
            UserDefaults.standard.set(newValue, forKey: key)
        }
    }
}

struct Settings {
    @AppStorage(key: "darkMode", defaultValue: false)
    static var isDarkMode: Bool

    @AppStorage(key: "fontScale", defaultValue: 1.0)
    static var fontScale: Double
}

Разбор:

  • Это практический вариант той же идеи: одна обёртка обслуживает разные настройки приложения.
  • Свойства Settings.isDarkMode и Settings.fontScale объявлены декларативно и читаются как доменные параметры.
  • Логика чтения/записи в UserDefaults централизована в одном месте, что упрощает сопровождение.
  • При изменении политики хранения нужно править только обёртку, а не каждое поле отдельно.

Экран настроек в SwiftUI:

struct SettingsView: View {
    @State private var dark = Settings.isDarkMode

    var body: some View {
        Toggle("Тёмная тема", isOn: $dark)
            .onChange(of: dark) { Settings.isDarkMode = dark }
    }
}

Разбор:

  • @State private var dark хранит локальное UI-состояние переключателя.
  • Toggle(..., isOn: $dark) связывает контрол с состоянием через binding.
  • onChange(of: dark) реагирует на изменение и синхронизирует его в Settings.isDarkMode.
  • Этот слой отделяет UI-стейт от механизма хранения и показывает практичную интеграцию обёртки в экран.

Для production добавьте Codable + JSON в UserDefaults для сложных типов и потокобезопасность при доступе из фона.
