## Когда нужен объектный стиль

Внутри F#-проекта домен чаще описывают **записями** и **размеченными объединениями**. Классы и интерфейсы подключают, когда:

- сборку вызывают из C# / VB;
- нужно наследовать тип из .NET Framework;
- реализуют интерфейс DI-контейнера (`IService`, `IHostedService`);
- оборачивают изменяемый компонент с событиями и `IDisposable`.

Цель статьи — **минимальный** набор ООП, достаточный для interop, без дублирования полного курса по C#.

**Предварительно:** [F# в экосистеме .NET](./18.md) · [Сопоставление с образцом](./186.md).

## Класс с полями и методами

```fsharp
type Counter() =
    let mutable value = 0
    member _.Increment() = value <- value + 1
    member _.Current = value
```

- Конструктор `()` — создание экземпляра;
- `member` — методы и свойства, видимые снаружи;
- `let` в теле класса — приватное состояние экземпляра.

Вызов из F#:

```fsharp
let c = Counter()
c.Increment()
printfn "%d" c.Current
```

Из C# тот же тип выглядит как обычный класс с методами `Increment()` и свойством `Current`.

## Свойства и автосвойства

```fsharp
type Person(name: string, age: int) =
    member val Name = name with get, set
    member val Age = age with get, set
```

Параметры конструктора можно использовать в выражениях инициализации. Для DTO, которые сериализуются JSON-библиотеками .NET, записи с `[<CLIMutable>]` часто проще классов (см. [Справочник по F#](./181.md)).

## Структуры и типы значений

```fsharp
[<Struct>]
type Point =
    struct
        val X: float
        val Y: float
        new(x, y) = { X = x; Y = y }
    end
```

`struct` уменьшает аллокации в горячих путях, но копируется по значению. Записи F# по умолчанию тоже структуры (`[<Struct>]` на record — опционально в новых версиях языка).

| Выбор | Подсказка |
|-------|-----------|
| Record / DU | доменная модель, `match`, иммутабельность |
| `class` | наследование, изменяемое состояние, interop |
| `struct` | малые неизменяемые значения, производительность |

## Интерфейсы

```fsharp
type IRepository =
    abstract member Get: int -> string option

type InMemoryRepository() =
    interface IRepository with
        member _.Get id =
            if id = 1 then Some "alpha" else None
```

Реализация через блок `interface ... with`. Несколько интерфейсов — несколько блоков. Явная реализация интерфейса (как в C#) поддерживается при необходимости скрыть метод от публичного API класса.

## Наследование и переопределение

```fsharp
type Animal() =
    abstract member Speak: unit -> string
    default _.Speak() = "..."

type Dog() =
    inherit Animal()
    override _.Speak() = "woof"
```

- `abstract` — требует переопределения в наследнике (если нет `default`);
- `override` — замена реализации;
- `default` — необязательная реализация в базовом типе.

Глубокие иерархии в F# встречаются редко; композиция функций и типов обычно выразительнее.

## Перечисления CLI и размеченные объединения

```fsharp
type Status =
    | Draft = 0
    | Published = 1
    | Archived = 2
```

Такой enum совместим с C# `enum`. Для доменной логики с данными в каждом случае предпочтительнее **DU**:

```fsharp
type DocumentState =
    | Draft of title: string
    | Published of publishedAt: System.DateTime
```

DU + `match` даёт исчерпывающую обработку; CLI-enum — когда контракт уже зафиксирован в .NET API.

## Статические члены

```fsharp
type MathConstants =
    static member Pi = 3.14159265
    static member CircleArea r = MathConstants.Pi * r * r
```

Аналог статических методов C#. Для набора чистых функций без состояния чаще достаточно **модуля** верхнего уровня.

---

## Объект `System.Object`

Все типы F# наследуют `obj`. Переопределение `ToString()`, `Equals()`, `GetHashCode()` возможно в классах; для записей и DU компилятор генерирует разумные реализации. При передаче в API, ожидающие `object`, приведение обычно не требуется.

## Рекомендации для общих solution

| Ситуация | Подход |
|----------|--------|
| Публичный API библиотеки для C# | `[<RequireQualifiedAccess>]` на модулях, понятные имена типов, `[<CLIMutable>]` на DTO |
| Скрыть детали | `private` DU, наружу — интерфейс или модуль с функциями |
| WPF / WinForms code-behind | классы с событиями допустимы; бизнес-логику держать в чистых функциях |
| ASP.NET Core | часто тонкие классы-обработчики + функциональное ядро |
