## Зачем нужен интерактивный режим

В компилируемых языках обычно цикл «написал → собрал → запустил». F# дополняет его **интерактивной средой** (F# Interactive, FSI): выражение вычисляется сразу, тип показывается в ответе, ошибка видна на конкретной строке. Это удобно для изучения синтаксиса, проверки формул, разбора API библиотеки и одноразовых задач автоматизации.

Полноценное приложение по-прежнему собирают через `dotnet build`, но многие идеи проще отладить в REPL, а затем перенести в `.fs` файлы проекта.

**Предварительно:** [F# в экосистеме .NET](./18.md) · [Первая программа на F#](./182.md).

## Запуск FSI

С установленным .NET SDK:

```bash
dotnet fsi
```

Приглашение `>` означает готовность принять выражение. Двойная точка с запятой `;;` завершает ввод многострочного фрагмента:

```fsharp
> let square x = x * x;;
val square : int -> int

> square 7;;
val it : int = 49
```

Значение последнего успешного выражения сохраняется в `it` — аналог «результата в консоли» в других REPL.

В Visual Studio или VS Code (расширение Ionide) тот же движок доступен из панели F# Interactive: выделенный фрагмент отправляется в сессию без перезапуска всего проекта.

## Что проверять в REPL

| Задача | Пример в FSI |
|--------|----------------|
| Вывод типа | `let f x y = x + y` → компилятор покажет `int -> int -> int` |
| Поведение `match` | Сопоставление с образцом на тестовых данных |
| Работа с коллекциями | `[1..5] \|> List.map ((*) 2)` |
| Вызов .NET API | `open System` и пробные вызовы `DateTime`, `Path` |
| Ошибки компиляции | Неполный `match` или несовместимые типы — сразу, без сборки solution |

Интерактивный режим использует тот же компилятор F#, что и проект: правила типов и сопоставления с образцом совпадают с «боевым» кодом.

## Скрипты `.fsx`

Файл с расширением `.fsx` — программа для FSI, а не отдельная сборка. Запуск:

```bash
dotnet fsi script.fsx
```

Типичные директивы в начале скрипта:

```fsharp
#r "nuget: Newtonsoft.Json, 13.0.3"
#load "SharedLogic.fs"
```

- `#r` — подключить сборку или пакет NuGet;
- `#load` — загрузить другой исходник F# в ту же сессию;
- `#I` — добавить каталог поиска сборок.

Скрипты подходят для миграций данных, отчётов, администрирования, генерации файлов: логика на F#, без создания консольного `.fsproj`, если не нужен отдельный исполняемый артефакт.

## REPL и проект: как сочетать

Рекомендуемый порядок:

1. В FSI проверить функцию или тип на малых примерах.
2. Перенести рабочий код в модуль проекта (`Types.fs`, `Core.fs`, …).
3. Собрать solution и прогнать тесты.

Если модуль уже есть в solution, его можно подтянуть в сессию:

```fsharp
#load "src/MyLib/Domain.fs"
open MyLib.Domain
```

Порядок `#load` должен повторять зависимости между файлами (см. [Структура F#-проекта](./190.md)).

## Ограничения

- Состояние FSI **накапливается**: повторное `let` с тем же именем создаёт новую привязку; старые определения не «откатываются» автоматически. При странных ошибках перезапустите сессию.
- Скрипты с `#r "nuget:..."` требуют сети при первом разрешении пакета (как обычный `dotnet restore`).
- Не всё из production-кода удобно в REPL: конфигурация DI, веб-хост, длительные фоновые задачи проще отлаживаются в проекте.
