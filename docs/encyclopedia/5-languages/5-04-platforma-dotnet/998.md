## FAQ — Часто задаваемые вопросы

Типичные сбои и ситуации, с которыми сталкиваются новички после раздела. Здесь — **что делать и где копать в главах**; определения для зачёта — в [чек-листе](./999).

<div class="faq-list">

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `dotnet` в терминале не найден после установки Visual Studio.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Нужен <strong>.NET SDK</strong>, а не только runtime; перезапустите терминал после установки. Проверьте `dotnet --list-sdks`. Подробнее здесь — [платформа .NET](./1.md), [оглавление](./intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Проект на .NET 8, а на машине только .NET 6 — "framework not found".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Установите нужный SDK/runtime или опубликуйте <strong>self-contained</strong> с нужной версией. Сверьте `TargetFramework` в `.csproj`. Подробнее здесь — [платформа .NET](./1.md), [архитектура](./12.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> .NET Framework 4.8 и современный .NET — в каком открывать чужой проект?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Смотрите <strong>тип проекта в `.csproj`</strong>: `net48` — Framework (Windows), `net8.0` — современный .NET. Миграция между ними — отдельная задача, не "просто обновить VS". Подробнее здесь — [история платформы](./11.md), [архитектура](./12.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `dotnet run` собирает, но приложение сразу закрывается — окно мелькнуло.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Консольное приложение <strong>завершилось</strong> (ошибка или конец `Main`). Запускайте из терминала или добавьте `Console.ReadLine()` для отладки. Подробнее здесь — [платформа .NET](./1.md), раздел [C# — первая программа](../5-05-csharp/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> NuGet restore падает — "Unable to load the service index".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Проверьте сеть, прокси, корпоративный firewall и источник пакетов в `nuget.config`. Временно очистите кэш: `dotnet nuget locals all --clear`. Подробнее здесь — [платформа .NET](./1.md), [справочник API](./183.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> ASP.NET Core API отдаёт 404, Swagger открывается.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Контроллер не зарегистрирован, неверный HTTP-метод или <strong>префикс маршрута</strong> `[Route("api/[controller]")]`. Сверьте URL в Swagger с тем, что вызывает клиент. Подробнее здесь — [ASP.NET](./172.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> DI: сервис null или "Cannot resolve scoped service from singleton".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> <strong>Scoped</strong> нельзя напрямую внедрять в Singleton — используйте `IServiceScopeFactory` или измените lifetime. Регистрируйте интерфейс в `Program.cs`. Подробнее здесь — [ASP.NET](./172.md), [архитектура](./12.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `async` метод "висит" — deadlock в UI или ASP.NET (старый код).</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Классическая ловушка — <strong>`.Result` или `.Wait()`</strong> на UI-потоке с захватом контекста. Используйте `await` до конца, `ConfigureAwait(false)` в библиотеках. Подробнее здесь — [F# async и task](./189.md), раздел [C#](../5-05-csharp/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> EF Core миграция применилась, таблиц в БД нет.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Подключились к <strong>другой строке connection</strong> (LocalDB vs PostgreSQL), или `EnsureDeleted` в dev. Проверьте `appsettings.Development.json` и логи `dotnet ef database update`. Подробнее здесь — [ADO.NET](./171.md), [EF Core в C#](../5-05-csharp/441).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `Nullable reference types` включили — половина проекта в warning CS8602.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Аннотации `?` и проверки на null <strong>не магия</strong> — постепенно исправляйте или `#nullable disable` в legacy-файлах. Новый код пишите с учётом NRT. Подробнее здесь — [архитектура](./12.md), [C#](../5-05-csharp/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `struct` vs `class` — когда boxing "съел" производительность?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Приведение struct к `interface` или `object` даёт <strong>boxing на кучу</strong>. Для горячих путей используйте generics с ограничением `where T : struct`. Подробнее здесь — [архитектура и типы](./12.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `Equals` и `==` дают разный результат для строк и своих классов.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Для ссылочных типов без переопределения <strong>`==` — ссылки</strong>, `Equals` может быть переопределён. Для value types и string правила другие. Подробнее здесь — [архитектура](./12.md), [C#](../5-05-csharp/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `dotnet publish` на Linux, на сервере Windows — не запускается.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Укажите RID: <strong>`-r win-x64`</strong> или `linux-x64`, выберите self-contained vs framework-dependent. Подробнее здесь — [платформа .NET](./1.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Конфиг из `appsettings.json` не подхватывается в Production.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> ASP.NET Core загружает <strong>цепочку конфигов</strong>: базовый файл, `appsettings.&#123;Environment&#125;.json`, переменные окружения. Проверьте `ASPNETCORE_ENVIRONMENT` и переопределения в Docker/K8s. Подробнее здесь — [ASP.NET](./172.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Middleware "не срабатывает" — запрос проходит мимо.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Порядок <strong>`app.Use*` критичен</strong>: ExceptionHandler до Routing, Authentication до Authorization. Новый middleware добавляйте в правильное место pipeline. Подробнее здесь — [ASP.NET](./172.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Blazor WASM грузится долго — первый заход "пустой экран" минуту.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Клиент скачивает <strong>runtime и сборки .NET</strong> в браузер. Используйте lazy load, AOT где доступно, CDN и loading UI. Подробнее здесь — [платформа .NET](./1.md), [оглавление](./intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> F#: "The type X is not compatible with type Y" в pipeline `|>`.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Проверьте порядок аргументов — pipe передаёт результат <strong>последним аргументом</strong> следующей функции. Часто помогает flip или промежуточная `let`. Подробнее здесь — [первая программа F#](./182.md), [императивные конструкции](./187.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> F# файлы в проекте — "type already defined" при смене порядка.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> В F# <strong>порядок файлов в `.fsproj` задаёт порядок компиляции</strong>. Типы должны быть объявлены раньше использования. Подробнее здесь — [структура F#-проекта](./190.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> C# и F# в одном solution — как вызывать код между языками?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Через <strong>ссылку на проект</strong> и общие .NET-сборки; F# вызывает C# без обёрток, из C# в F# — через public API модулей. Подробнее здесь — [F# в экосистеме](./18.md), [C# — о разделе](../5-05-csharp/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `System.Text.Json` не сериализует private set — свойство пропало из JSON.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> По умолчанию сериализуются <strong>public get</strong>. Используйте `[JsonInclude]`, DTO или Newtonsoft с другими правилами. Подробнее здесь — [справочник API](./183.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Docker-образ .NET раздувается до 2 GB — это нормально?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Базовый SDK-образ тяжёлый. Для prod используйте <strong>multi-stage build</strong> и runtime-образ `aspnet`/`runtime`, publish trim/AOT где уместно. Подробнее здесь — [платформа .NET](./1.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> xUnit тесты не видят `internal` классы основного проекта.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Добавьте в основной проект <strong>`InternalsVisibleTo("TestAssembly")`</strong> или тестируйте через public API. Подробнее здесь — [C#](../5-05-csharp/intro), [вопросы на собеседование](../5-05-csharp/474).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> "Could not load file or assembly" после обновления NuGet-пакета.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Конфликт версий транзитивных зависимостей. Проверьте `dotnet list package --outdated`, binding redirects в Framework или единый Central Package Management. Подробнее здесь — [платформа .NET](./1.md), [справочник](./183.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Kestrel слушает только localhost — с другого ПК API недоступен.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> По умолчанию dev-профиль привязан к <strong>127.0.0.1</strong>. В `launchSettings.json` укажите `applicationUrl` с `0.0.0.0` или настройте reverse proxy. В prod — nginx/IIS перед Kestrel. Подробнее здесь — [ASP.NET](./172.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Учу C#, F# и VB одновременно в одном solution — путаница в синтаксисе.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Платформа .NET мультиязычна, но новичку лучше <strong>один язык до первого working app</strong> — обычно C# или F# по маршруту в intro. Подробнее здесь — [оглавление](./intro), [F#](./18.md), [C#](../5-05-csharp/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> GC паузы "подлагивают" API — что смотреть первым?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Включите <strong>dotnet-counters / dotnet-gcdump</strong>, проверьте LOH, частые аллокации в hot path, размер кэшей. Настройка GC — для prod после метрик. Подробнее здесь — [платформа и CLR](./1.md), [архитектура](./12.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Visual Studio и VS Code — разные версии SDK, проект собирается только в одной IDE.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Сверьте `global.json` pin SDK и `dotnet --version` в обеих средах. Один репозиторий — один SDK через global.json или документируйте версию. Подробнее здесь — [версии C# и .NET](../5-05-csharp/48.md).</p>
</div>

### Частые поисковые запросы

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> .NET Framework, .NET Core и .NET — в чём разница?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> <strong>.NET Framework</strong> — legacy Windows-only; <strong>.NET Core</strong> — кроссплатформенное начало; <strong>.NET 5+</strong> — единая платформа (8, 9, 10). Новые проекты — на современный .NET. Подробнее здесь — [история](./11.md), [архитектура](./12.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> C# или F# — что учить на платформе .NET?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> <strong>C#</strong> — основной язык, больше вакансий и материалов; <strong>F#</strong> — функциональный стиль, data, DSL. Оба компилируются в один CLR. Подробнее здесь — [F# в экосистеме](./18.md), [C# — intro](../5-05-csharp/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> ASP.NET Core — что это простыми словами?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Кроссплатформенный <strong>веб-фреймворк</strong> для API, сайтов и MVC на .NET: Kestrel, middleware, DI, Razor/Minimal API. Подробнее здесь — [ASP.NET](./172.md), [платформа .NET](./1.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Entity Framework Core — tutorial для начинающих?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> EF Core — <strong>ORM для .NET</strong>: DbContext, миграции, LINQ к БД. Старт: модель → миграция → CRUD в сервисе. Подробнее здесь — [EF Core в C#](../5-05-csharp/441), [ADO.NET](./171.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> .NET 8 LTS — стоит ли на него переходить?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> LTS-версии — <strong>долгая поддержка</strong> для prod; .NET 8 — стабильный выбор до следующего LTS. Сверьте таблицу версий и политику команды. Подробнее здесь — [версии C# и .NET](../5-05-csharp/48.md), [история](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Kestrel в ASP.NET Core — что это?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> <strong>Встроенный веб-сервер</strong> .NET — принимает HTTP, передаёт в pipeline middleware. В prod часто за nginx/IIS; в dev слушает localhost. Подробнее здесь — [ASP.NET](./172.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Dependency Injection в .NET — как работает простыми словами?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Контейнер <strong>создаёт и подставляет зависимости</strong> в конструктор (Transient/Scoped/Singleton). Регистрация в `Program.cs`, не `new` для сервисов. Подробнее здесь — [ASP.NET](./172.md), [архитектура](./12.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> LINQ в C# — что это и зачем?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Language Integrated Query — <strong>запросы к коллекциям и БД</strong> единым синтаксисом (`Where`, `Select`). Читаемее циклов для фильтрации и проекций. Подробнее здесь — [C# — intro](../5-05-csharp/intro), [справочник API](./183.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Blazor — веб на C# без JavaScript?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Blazor — UI на <strong>C# и Razor</strong>: WASM в браузере или Server через SignalR. JS всё ещё нужен для interop, но логика UI — на C#. Подробнее здесь — [платформа .NET](./1.md), [оглавление](./intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Команды dotnet CLI — основные для новичка?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> <strong>`dotnet new`</strong>, `dotnet build`, `dotnet run`, `dotnet test`, `dotnet publish`, `dotnet ef`. SDK включает CLI для всего жизненного цикла. Подробнее здесь — [платформа .NET](./1.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> NuGet — как установить пакет в .NET проект?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `dotnet add package ИмяПакета` или через UI Visual Studio; версии фиксируются в `.csproj`. Аналог pip/npm для .NET. Подробнее здесь — [платформа .NET](./1.md), [справочник](./183.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> .NET или Java — что выбрать для карьеры?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Java — широкий enterprise-рынок; .NET — сильны Microsoft-стек, Azure, Windows-legacy и современный cross-platform. Оба LTS и востребованы. Подробнее здесь — [intro .NET](./intro), [Java — intro](../5-03-java/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> .NET MAUI — кроссплатформенные приложения?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> MAUI — <strong>один код для Windows, macOS, iOS, Android</strong> на C# и XAML (преемник Xamarin). Подробнее здесь — [платформа .NET](./1.md), [оглавление](./intro).</p>
</div>

<div class="faq-item">

## Что запомнить

Платформа .NET — это современная, кроссплатформенная и открытая экосистема для разработки приложений любого типа — от консольных утилит до веб-сервисов, мобильных приложений, микросервисов и облачных решений. Она объединяет в себе компиляторы, среду выполнения, библиотеки и инструменты, обеспечивая высокую производительность, безопасность и удобство разработки.

Основные компоненты платформы:
- **CLR (Common Language Runtime)** — среда выполнения, управляющая памятью, безопасностью, исключениями и жизненным циклом объектов;
- **CIL (Common Intermediate Language)** — промежуточный язык, в который транслируется исходный код на этапе компиляции;
- **JIT-компилятор** — компонент, преобразующий CIL в машинный код непосредственно перед выполнением;
- **BCL (Base Class Library)** — стандартная библиотека, предоставляющая классы для работы с файлами, сетью, коллекциями, датами, строками и многим другим;
- **NuGet** — система управления пакетами, позволяющая подключать сторонние и официальные библиотеки;
- **SDK и CLI (`dotnet`)** — набор инструментов командной строки для создания, сборки, тестирования и публикации проектов.

Эволюция платформы прошла три ключевых этапа:
1. **.NET Framework** — Windows-only, закрытый, исторически первый;
2. **.NET Core** — кроссплатформенный, модульный, открытый;
3. **.NET 5+** — единая унифицированная платформа, объединившая лучшие черты предшественников.

Современный .NET поддерживает множество типов приложений:
- **ASP.NET Core** — для веб-приложений и API;
- **WinForms / WPF** — для классического desktop UI на Windows; [примеры с разбором (Lab)](/lab/Примеры/1138);
- **MAUI** — для кроссплатформенных десктопных и мобильных приложений;
- **Blazor** — для интерактивных веб-интерфейсов на C#;
- **gRPC**, **SignalR**, **Minimal APIs** — для современных сервисов и интеграций.

Три основных правила эффективной работы с .NET:
1. Использовать последнюю LTS-версию платформы для стабильности и поддержки;
2. Следовать принципам чистой архитектуры, внедрения зависимостей и асинхронного программирования;
3. Активно применять инструменты диагностики, логирования и мониторинга (Application Insights, Serilog, OpenTelemetry).

Три фундаментальных момента:
- .NET — это не только язык C#, но и целая платформа с поддержкой F#, visual-basic и других языков;
- Архитектура .NET построена на принципах безопасности, изоляции и управляемого выполнения;
- Экосистема .NET активно развивается, включая облачные интеграции с Azure, поддержку контейнеров и Kubernetes.
