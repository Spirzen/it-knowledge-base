## Зачем CMake, если есть IDE

C++ редко запускают "двойным кликом по `.cpp`" как Python-скрипт. Цепочка такая:

1. **Компилятор** (`g++`, `clang++`, `cl`) превращает каждый `.cpp` в **объектный файл** (`.o` / `.obj`).
2. **Линкер** склеивает объектные файлы и библиотеки в **исполняемый файл** (`hello.exe`, `hello`).

В одном файле `main.cpp` можно вызвать вручную:

```bash
g++ main.cpp -o hello
```

Как только появляются **несколько** `.cpp`, **заголовки** в `include/` и разные ОС — ручные команды ломаются. **CMake** читает сценарий **`CMakeLists.txt`** и **генерирует** проект под вашу среду.

| Термин | Простыми словами |
|--------|------------------|
| **Цель (target)** | то, что собираем: программа `hello` или библиотека `greet` |
| **Генератор** | Ninja, Make, Visual Studio — кто реально вызывает компилятор |
| **Конфигурация** | Debug (отладка) или Release (оптимизации) |

Теория Debug/Release и статика/динамика: [Конфигурация и сборка](./1004.md).

## Идея "исходники отдельно от сборки"

```
hello-cmake/          ← храните в git
├── CMakeLists.txt
├── include/
│   └── greet.hpp
└── src/
    ├── main.cpp
    └── greet.cpp

hello-cmake/build/    ← генерируется, в git не кладут
```

| Команда | Смысл |
|---------|--------|
| `cmake -S . -B build` | **S**ource = корень с `CMakeLists.txt`; **B**uild = папка артефактов |
| `cmake --build build` | собрать всё, что описано в сценарии |
| `./build/hello` | запуск (Linux/macOS; на Windows путь может быть `build\Debug\hello.exe`) |

## CMakeLists.txt — построчно

```cmake
cmake_minimum_required(VERSION 3.20)
project(hello_cmake VERSION 0.1.0 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

add_executable(hello
    src/main.cpp
    src/greet.cpp
)

target_include_directories(hello PRIVATE include)
```

| Строка | Зачем |
|--------|--------|
| `cmake_minimum_required(VERSION 3.20)` | CMake ниже 3.20 остановится с ошибкой — защита от старых версий |
| `project(hello_cmake ... LANGUAGES CXX)` | имя проекта; `CXX` = язык C++ |
| `CMAKE_CXX_STANDARD 17` | включить стандарт C++17 для всех целей |
| `CMAKE_CXX_STANDARD_REQUIRED ON` | без C++17 сборка **прервётся**, а не "тихо" откатится к C++14 |
| `add_executable(hello ...)` | цель `hello` — исполняемый файл из перечисленных `.cpp` |
| `target_include_directories(hello PRIVATE include)` | при компиляции `hello` искать `#include "greet.hpp"` в `include/` |

**`PRIVATE`** у include-путей: каталог нужен **только** при сборке `hello`. Если позже сделаете библиотеку и подключите её к другим целям — различие `PRIVATE` / `PUBLIC` станет важным ([1004](./1004.md)).

## Исходники и заголовок

**Заголовок** — **объявление** (что есть функция):

```cpp
#pragma once
#include <string>

std::string greet(const std::string& name);
```

**`#pragma once`** — защита от повторного включения одного файла в одной единице трансляции.

**Реализация** — в `.cpp` (одно определение на всю программу):

```cpp
#include "greet.hpp"

std::string greet(const std::string& name) {
    return "Hello, " + name + "!";
}
```

**Точка входа:**

```cpp
#include "greet.hpp"
#include <iostream>

int main() {
    std::cout << greet("CMake") << '\n';
    return 0;
}
```

| `#include` | Где ищет |
|------------|----------|
| `"greet.hpp"` | каталоги из `target_include_directories` |
| `<iostream>` | системные пути компилятора |

Если положить **тело** `greet` в `.hpp` и подключить его из двух `.cpp`, линкер может выдать **duplicate symbol** — поэтому реализацию держат в одном `.cpp`.

## Сборка и запуск

```bash
cmake -S . -B build -G Ninja
cmake --build build
./build/hello
```

На Windows без Ninja CMake выберет Visual Studio или MSBuild. Путь к exe часто `build\Debug\hello.exe`.

**Release** (оптимизации):

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Для **multi-config** генераторов MSVC вместо `CMAKE_BUILD_TYPE` при сборке: `cmake --build build --config Release`.

## Подключение внешней библиотеки (кратко)

Учебный способ — **FetchContent** (скачать исходники при конфигурации):

```cmake
include(FetchContent)
FetchContent_Declare(
  fmt
  GIT_REPOSITORY https://github.com/fmtlib/fmt.git
  GIT_TAG 10.2.1
)
FetchContent_MakeAvailable(fmt)
target_link_libraries(hello PRIVATE fmt::fmt)
```

Цепочка для новичка:

1. **Объявили** зависимость (`FetchContent_Declare`).
2. **Сделали доступной** (`FetchContent_MakeAvailable`).
3. **Привязали** к цели (`target_link_libraries`).
4. В C++ подключили заголовок и вызвали API (`fmt::print(...)`).

В долгих проектах чаще **vcpkg** или **Conan** — стабильнее версии и кэш.

## Частые ошибки

| Ошибка | Что проверить |
|--------|----------------|
| `greet.hpp: No such file` | `target_include_directories` и файл в `include/` |
| Undefined reference to `greet` | `src/greet.cpp` в `add_executable` |
| Старая версия C++ | `CMAKE_CXX_STANDARD` и `REQUIRED ON` |
| Правки в `CMakeLists.txt` не срабатывают | снова `cmake -S . -B build` (реконфигурация) |
| Запускаю exe из корня, а он в `build/` | полный путь к собранному файлу |
