# phpMyAdmin — SQL, DDL и DML

<div class="article-tags">
  <span class="tag tag-required">ОБЯЗАТЕЛЬНО</span>
  <span class="tag tag-beginner">ДЛЯ НОВИЧКОВ</span>
</div>

<span class="complexity-badge">Разработчику</span>

После [установки и первого входа](./2) phpMyAdmin становится вашим визуальным клиентом к MySQL/MariaDB. Всё, что можно сделать в консоли `mysql` или в коде через [PDO](/encyclopedia/5-languages/5-07-php/160), здесь доступно через вкладки, формы и редактор SQL.

Ключевая привычка на старте — различать **DDL** (структура) и **DML** (данные). Это те же категории команд, что в [разделе SQL](/encyclopedia/3-data-markup/3-07-sql/intro) и в статье [DDL, DML, DCL, TCL](/encyclopedia/3-data-markup/3-07-sql/22):

| Категория | Расшифровка | Что меняет | Примеры |
|-----------|-------------|------------|---------|
| **DDL** | Data Definition Language | Схему — базы, таблицы, индексы | `CREATE`, `ALTER`, `DROP` |
| **DML** | Data Manipulation Language | Строки внутри таблиц | `INSERT`, `UPDATE`, `DELETE`, `SELECT` |
| **DCL** | Data Control Language | Права пользователей | `GRANT`, `REVOKE` |
| **TCL** | Transaction Control Language | Границы транзакций | `COMMIT`, `ROLLBACK` |

phpMyAdmin не добавляет новый язык — он отправляет обычный SQL на сервер от имени вошедшего пользователя MySQL. Видимые базы и разрешённые операции определяются привилегиями, выданными через `GRANT` (см. [статью 2](./2#режимы-аутентификации)).

## Где выполнять SQL

В интерфейсе есть несколько точек входа в редактор. Они отличаются **контекстом** — тем, какая база или таблица уже выбрана, и нужно ли писать `USE dbname` вручную.

| Место | Область действия | Как открыть |
|-------|------------------|-------------|
| Вкладка **SQL** на главной | Любые запросы к серверу | Верхнее меню после входа |
| Вкладка **SQL** у базы | Запросы в контексте БД (можно не писать `USE`) | Выбрать базу слева → SQL |
| Вкладка **SQL** у таблицы | Запросы к таблице; удобно для `SELECT` с фильтром | Таблица → SQL |
| **Консоль** | Быстрые запросы без смены страницы | Кнопка внизу или клавиша **`k`** |

### Что умеет редактор

В поле ввода можно:

- выполнить **один** или **несколько** запросов подряд (batch; теория bulk/chunk — [Пакетная работа с данными](/encyclopedia/3-data-markup/3-11-analiz-dannyh/433));
- **сохранить** текст в закладку (нужен [pmadb](./2#configuration-storage-pmadb));
- просмотреть **историю** текущего сеанса (и долговременную — при настроенном pmadb);
- подсветить синтаксис и получить подсказки по именам таблиц и столбцов в контексте выбранной базы.

Результат `SELECT` показывается таблицей с постраничной навигацией. После хранимых процедур или пакетного выполнения возможны **несколько result set** — phpMyAdmin выведет их последовательно.

### Пример — проверка соединения

```sql
SELECT VERSION();
SHOW DATABASES;
```

**Разбор построчно:**

- `SELECT VERSION();` — служебный запрос DML-класса (чтение). Возвращает версию сервера MySQL/MariaDB; полезно убедиться, что вы подключены к ожидаемому инстансу (сравните с [MySQL — практическая работа](/encyclopedia/3-data-markup/3-07-sql/889)).
- `SHOW DATABASES;` — метакоманда: список баз, к которым у текущего пользователя есть доступ. Не показывает чужие базы, если нет привилегии `SHOW DATABASES` или права на конкретную схему.

Оба запроса можно выполнить одним нажатием "Вперёд" — phpMyAdmin разделит их по `;` и выполнит по порядку.

## Управление базами данных

На уровне сервера вы работаете с **каталогом схем** (в MySQL база данных ≈ схема). Создание и удаление базы — операции **DDL**; просмотр списка таблиц и прав — смесь метаданных и **DCL**.

### Создание базы

**Через интерфейс**

1. Вкладка **Базы данных** (главная) или **Создать базу данных**.
2. Имя, кодировка (**utf8mb4** / **utf8mb4_unicode_ci** для новых проектов — полный Unicode, включая эмодзи; подробнее в [MySQL — типы и синтаксис](/encyclopedia/3-data-markup/3-07-sql/889#типы-данных-и-синтаксис)).
3. Подтвердить создание.

**Через SQL (DDL)**

```sql
CREATE DATABASE shop
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

**Разбор:**

- `CREATE DATABASE shop` — создаёт пустую схему `shop` без таблиц.
- `CHARACTER SET utf8mb4` — кодировка по умолчанию для текстовых столбцов в этой базе.
- `COLLATE utf8mb4_unicode_ci` — правила сравнения строк (сортировка, `ORDER BY`, уникальные индексы). `_ci` — case-insensitive, без учёта регистра.

Тот же DDL в консоли `mysql` или в миграции Laravel даст тот же результат — phpMyAdmin лишь отправляет текст на сервер.

### Операции с существующей базой

| Действие | Интерфейс | SQL (примеры) |
|----------|-----------|---------------|
| Просмотр списка таблиц | Структура базы | `SHOW TABLES;` |
| Переименование | Операции с БД | `RENAME` через создание копии / спец. инструменты |
| Удаление | Удалить базу | `DROP DATABASE shop;` |
| Права | Привилегии | `GRANT`, `REVOKE` |
| Обслуживание | Операции | `CHECK`, `OPTIMIZE`, `REPAIR` (зависит от движка) |

Удаление базы **безвозвратно** уничтожает все таблицы внутри — перед `DROP` делайте [экспорт](./4). На продакшене `DROP DATABASE` обычно запрещён для прикладных учёток; полные права есть только у администратора.

## Таблицы — DDL

**Таблица** — основной объект реляционной модели: именованный набор столбцов с типами и ограничениями. Создание и изменение таблицы меняет **метаданные** в словаре данных сервера (см. [Словарь данных и каталоги](/encyclopedia/3-data-markup/3-07-sql/105)).

### Создание таблицы

**Мастер (визуально)**

1. База → **Создать таблицу**.
2. Имя, число столбцов.
3. Для каждого столбца задайте:
   - **имя** — латиница, без пробелов; в коде PHP то же имя в запросах;
   - **тип** — `INT`, `VARCHAR`, `TEXT`, `DATETIME` и др. (шпаргалка — [MySQL — типы](/encyclopedia/3-data-markup/3-07-sql/889#типы-данных-и-синтаксис));
   - **длину** — для `VARCHAR(255)` и подобных;
   - **NULL / NOT NULL** — допускает ли столбец отсутствие значения;
   - **значение по умолчанию** — например `CURRENT_TIMESTAMP`;
   - **индексы** и **первичный ключ** (PRIMARY KEY).
4. **Движок** таблицы:
   - **InnoDB** — по умолчанию; транзакции, внешние ключи, блокировки на уровне строк;
   - **MyISAM** — устаревающий выбор без FK на уровне СУБД; иногда встречается в старых дампах.

**Вкладка "Структура" → SQL** или общая вкладка SQL:

```sql
CREATE TABLE users (
  id         INT UNSIGNED NOT NULL AUTO_INCREMENT,
  email      VARCHAR(255) NOT NULL,
  created_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_users_email (email)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**Разбор фрагмента:**

| Фрагмент | Назначение |
|----------|------------|
| `INT UNSIGNED NOT NULL AUTO_INCREMENT` | Целочисленный идентификатор без знака; сервер сам увеличивает значение при `INSERT` без `id` |
| `VARCHAR(255) NOT NULL` | Строка переменной длины до 255 символов; пустая строка допустима, `NULL` — нет |
| `DEFAULT CURRENT_TIMESTAMP` | При вставке без `created_at` подставится текущее время сервера |
| `PRIMARY KEY (id)` | Главный ключ строки; по нему строятся кластерный индекс InnoDB |
| `UNIQUE KEY uk_users_email (email)` | Второй email в таблицу не попадёт — ограничение уникальности |
| `ENGINE=InnoDB` | Движок с транзакциями и поддержкой внешних ключей |
| `DEFAULT CHARSET=utf8mb4` | Кодировка таблицы; согласована с `CREATE DATABASE` выше |

Полученный DDL можно скопировать в миграцию фреймворка или в репозиторий — это тот же текст, что показывает вкладка **Структура** → "Создание таблицы".

### Изменение структуры (DDL)

Эволюция схемы в живом проекте почти всегда идёт через `ALTER TABLE`. В phpMyAdmin каждое действие в форме "Структура" генерирует соответствующий SQL — удобно учиться, сравнивая кнопку и текст запроса.

| Задача | Интерфейс | SQL |
|--------|-----------|-----|
| Добавить столбец | Структура → Добавить | `ALTER TABLE ... ADD COLUMN ...` |
| Изменить тип | Изменить | `ALTER TABLE ... MODIFY COLUMN ...` |
| Удалить столбец | Удалить | `ALTER TABLE ... DROP COLUMN ...` |
| Индексы | Индексы | `ADD INDEX`, `DROP INDEX` |
| Внешние ключи (InnoDB) | Связи | `ADD CONSTRAINT ... FOREIGN KEY ...` |
| Переименовать таблицу | Операции | `RENAME TABLE old TO new;` |
| Удалить таблицу | Удалить | `DROP TABLE users;` |

Просмотр актуального **CREATE TABLE** — вкладка **Структура** → подраздел "Создание таблицы" (показать DDL). Это снимок текущей схемы; для сравнения версий на команде используют миграции или `mysqldump --no-data`.

Сложные изменения (составные индексы, частичные индексы в других СУБД) — в [Сложные индексы](/encyclopedia/3-data-markup/3-07-sql/884); для MySQL чаще хватает вкладки **Индексы**.

### Представления, процедуры, триггеры

На уровне базы доступны вкладки **Процедуры**, **События**, **Триггеры** (при поддержке сервера и правах). Операции:

- создать и изменить объект через форму или SQL;
- вызвать процедуру с параметрами;
- экспортировать определение в дамп;
- удалить объект (`DROP`).

Это тот же DDL/DML, что в [хранимых процедурах и триггерах](/encyclopedia/3-data-markup/3-07-sql/88), только с подсветкой синтаксиса в браузере. phpMyAdmin не компилирует процедуры сам — валидирует и передаёт на сервер.

## Данные в таблицах — DML

Когда схема готова, работа сдвигается к **строкам**: чтение, вставка, обновление, удаление. В терминологии SQL это **DML**; чтение (`SELECT`) иногда выделяют в отдельную категорию DQL — см. [категории команд](/encyclopedia/3-data-markup/3-07-sql/22#dql).

### Просмотр

Вкладка **Обзор** (Browse) — постраничный вывод строк:

- сортировка по клику на заголовок столбца;
- фильтр и поиск по таблице — горячие клавиши **`t`** (структура) и **`f`** (поиск);
- экспорт видимой выборки в CSV/SQL.

За кулисами phpMyAdmin строит `SELECT * FROM table LIMIT ... OFFSET ...` с учётом сортировки и фильтра. Для сложных условий переходите на вкладку **SQL** или [QBE](#query-by-example-qbe).

### Вставка

| Способ | Когда использовать |
|--------|-------------------|
| **Вставить** (Insert) | Одна строка, форма по столбцам; удобно вручную проверить ограничения |
| **SQL** | Массовая вставка, копирование из скрипта, импорт из другой среды |

```sql
INSERT INTO users (email) VALUES ('user@example.com');
```

**Разбор:**

- `INSERT INTO users` — целевая таблица.
- `(email)` — список столбцов; остальные берут значения по умолчанию (`created_at` заполнится `CURRENT_TIMESTAMP`, `id` — автоинкрементом).
- `VALUES ('user@example.com')` — одна новая строка. Несколько строк: `VALUES (...), (...), (...)`.

Массовую загрузку из файла удобнее делать через [импорт](./4); для тысяч строк из приложения — подготовленные запросы в [PDO](/encyclopedia/5-languages/5-07-php/160).

### Изменение

Два равноправных пути:

- **Изменить** (Edit) на строке в обзоре — правка полей в форме; phpMyAdmin сгенерирует `UPDATE` с `WHERE` по первичному ключу.
- Явный `UPDATE` во вкладке SQL — нужен для массовых правок и воспроизводимых скриптов:

```sql
UPDATE users SET email = 'new@example.com' WHERE id = 1;
```

**Разбор:**

- `SET email = '...'` — новое значение столбца.
- `WHERE id = 1` — **обязательный фильтр** при точечном изменении. `UPDATE` без `WHERE` затронет **все** строки таблицы.

В InnoDB такой `UPDATE` можно обернуть в транзакцию (`START TRANSACTION` … `COMMIT`) и откатить при ошибке — см. [Транзакции](/encyclopedia/3-data-markup/3-07-sql/77).

### Удаление

- Галочки строк → **Удалить** в обзоре — эквивалент `DELETE` с `WHERE id IN (...)`.
- Явный SQL:

```sql
DELETE FROM users WHERE id = 1;
```

`DELETE` убирает строки, **структура таблицы** остаётся. Для полной очистки без удаления определения таблицы:

```sql
TRUNCATE TABLE users;
```

<div class="callout callout--warning">
  <div class="callout-title">TRUNCATE и DELETE</div>

  <div class="callout-body">
  <code>TRUNCATE</code> сбрасывает таблицу быстро и часто сбрасывает <code>AUTO_INCREMENT</code>; в MySQL это DDL-подобная операция с неявным коммитом. <code>DELETE</code> без <code>WHERE</code> удалит все строки, но в транзакции InnoDB его можно откатить через <code>ROLLBACK</code>. На проде перед массовым удалением — <a href="./4">резервная копия</a>.

## Сводка DDL и DML в phpMyAdmin

| Категория | Команды / действия | Где в UI |
|-----------|-------------------|----------|
| **DDL** | `CREATE`/`ALTER`/`DROP` DATABASE, TABLE, INDEX, VIEW | Базы данных, Структура, SQL |
| **DML** | `SELECT`, `INSERT`, `UPDATE`, `DELETE` | Обзор, Вставить, SQL |
| **DCL** | `GRANT`, `REVOKE` | Учётные записи, привилегии |
| **TCL** | `START TRANSACTION`, `COMMIT`, `ROLLBACK` | SQL (InnoDB) |

## Query-by-example (QBE)

**QBE** — визуальный конструктор `SELECT`. Вы выбираете таблицы, поля и условия в сетке; phpMyAdmin собирает текст запроса.

Что полезно знать:

- вкладка **QBE** доступна на уровне базы;
- для соединения таблиц phpMyAdmin может **автоматически подставить JOIN** по настроенным связям (InnoDB FK или метаданные [pmadb](./4) для MyISAM);
- готовый запрос можно сразу выполнить или скопировать в редактор SQL для доработки (`GROUP BY`, подзапросы — [Подзапросы](/encyclopedia/3-data-markup/3-07-sql/108), [JOIN](/encyclopedia/3-data-markup/3-07-sql/55)).

QBE хорош для обучения: видно, как условие в ячейке превращается в фрагмент `WHERE`.

## Designer и целостность

**Designer** — графическая схема таблиц и связей на холсте. Координаты расположения блоков хранятся в pmadb (`pma__table_coords`), поэтому без configuration storage диаграмма не сохранится между сессиями.

Возможности:

- перетаскивание таблиц, линии связей между ключами;
- экспорт в **PDF** — документация структуры для команды или ТЗ;
- для **MyISAM** — проверка ссылочной целостности по метаданным phpMyAdmin (СУБД FK не enforced);
- для **InnoDB** — ограничения `FOREIGN KEY` проверяются сервером при `INSERT`/`UPDATE`/`DELETE`.

Designer дополняет, но не заменяет нормальное проектирование схемы: [реляционная модель](/encyclopedia/3-data-markup/3-07-sql/103), [нормализация](/encyclopedia/3-data-markup/3-07-sql/104).

## Связь с PHP-кодом

Объекты, которые вы создаёте в phpMyAdmin (база `shop`, таблица `users`, пользователь `app_user`), — те же имена, что в строке подключения приложения:

```php
$dsn = 'mysql:host=127.0.0.1;port=3306;dbname=shop;charset=utf8mb4';
$pdo = new PDO($dsn, 'app_user', 'secret', [
    PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
]);
```

**Соответствие полей:**

| phpMyAdmin | PHP (PDO) |
|------------|-----------|
| Имя базы `shop` | `dbname=shop` в DSN |
| Пользователь MySQL | второй аргумент `new PDO` |
| `utf8mb4` в DDL | `charset=utf8mb4` в DSN |
| Таблица `users`, столбец `email` | `INSERT INTO users (email) VALUES (?)` с привязкой параметров |

Подробнее — [PDO](/encyclopedia/5-languages/5-07-php/160) и [форма → БД](/encyclopedia/5-languages/5-07-php/161). phpMyAdmin удобен для **прототипирования схемы** и отладки данных на локальном стеке ([XAMPP, Open Server](/encyclopedia/5-languages/5-07-php/113)); в проде миграции чаще ведут через фреймворк (Laravel, Symfony), а не только ручной DDL в UI.

Типичный рабочий цикл:

1. Набросать таблицы в phpMyAdmin или выполнить `CREATE TABLE` в SQL.
2. Экспортировать структуру ([статья 4](./4)) в файл `.sql` для репозитория.
3. Подключить приложение через PDO и перенести DML в подготовленные запросы.
4. На проде — миграции и CI, phpMyAdmin только для экстренной диагностики (при жёстком ограничении доступа).
