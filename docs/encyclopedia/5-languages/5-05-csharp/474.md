### Формула сильного ответа на интервью

Для большинства технических вопросов хорошо работает структура из трёх шагов:

1. **Определение** — что это и зачем применяется.
2. **Практика** — где вы использовали это в проекте.
3. **Ограничения** — какие риски и компромиссы есть у подхода.

Пример для `async/await`: это модель неблокирующего I/O в .NET; использовал в API для внешних HTTP-вызовов и БД; избегаю `Result/Wait` и слежу за отменой через `CancellationToken`.

### Типы фильтров ASP.NET Core (вопрос 17)

В **Minimal API** аналог — **endpoint filters** (`IEndpointFilter`). Подробнее: [ASP.NET](./451), [справочник ASP.NET](./452).

### .NET Standard и BCL (вопрос 72)

- **.NET Standard** — *спецификация* общего API для библиотек (совместимость Framework / Core / Xamarin). Не среда выполнения.
- **BCL** (Base Class Library) — *реализация* `System.*` в конкретной платформе (.NET Framework, .NET 8/10, …).

Сейчас новые библиотеки обычно целятся в `net8.0` / `net10.0`, а не в `netstandard2.0`. Подробнее: [архитектура .NET](../5-04-platforma-dotnet/12).

### Маршалинг (вопрос 132)

**Маршалинг** — преобразование данных при переходе между управляемым кодом (CLR) и неуправляемым (Win32 API, COM, нативные DLL) — копирование строк, выравнивание структур, соглашения о вызовах. В .NET — **P/Invoke** (`DllImport`), **COM Interop**, атрибут `[MarshalAs]`. См. [справочник C#](./471), [производительность и нативные ресурсы](./41).

---

### lock и структуры (вопрос 134)

`lock` принимает **ссылочный** объект-синхронизатор. Значимый тип в `lock` вызовет **boxing** (аллокация в куче на каждый вход в блок) — технически компилируется, но для hot path это плохая практика. Используйте `lock` на `object`, `Mutex` или `SemaphoreSlim`, либо безлоковные структуры.

---

### Почему у GC три поколения (вопрос 136)

Эвристика **generational GC**: большинство объектов умирают молодыми. Gen 0/1 собираются часто и дёшево; Gen 2 — редко, для долгоживущих. Больше поколений даёт убывающую отдачу при росте сложности учёта; меньше — хуже разделение "молодых" и "старых". Подробнее: [сборщик мусора](../5-04-platforma-dotnet/12).

## Поведенческие вопросы (soft skills)

На Middle и Senior часто спрашивают про опыт работы в команде, помимо вопросов по CLR и LINQ. Удобная схема ответа — **STAR**:

- **S** (Situation) — контекст, команда, продукт.
- **T** (Task) — ваша задача и зона ответственности.
- **A** (Action) — что сделали лично, какие инструменты.
- **R** (Result) — измеримый итог или урок.

| Тема | Пример вопроса | На что смотрит интервьюер |
|------|----------------|---------------------------|
| Конфликт в команде | Разногласие по техническому решению | Факты, компромисс, итог для продукта |
| Дедлайн | Не успели в срок | Приоритизация, связь с PM, что отложили |
| Ошибка в prod | Сложный инцидент | Диагностика, постмортем, изменения в процессе |
| Менторство | Помощь джуну | Конкретные шаги, результат для человека |
| Обучение | Новый стек | План, pet-проект, сроки |
| Code review | Спорный PR | Аргументы, стандарты, тон общения |

Общая подготовка — [техническое собеседование](/encyclopedia/1-basics/1-26-karera-v-it-i-mify/4), [вопросы работодателю](/encyclopedia/1-basics/1-26-karera-v-it-i-mify/5).
