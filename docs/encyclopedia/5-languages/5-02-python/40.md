# if __name__ == "__main__" — точка входа при запуске файла

<div class="article-tags">
  <span class="tag tag-required">ОБЯЗАТЕЛЬНО</span>
  <span class="tag tag-beginner">ДЛЯ НОВИЧКОВ</span>
</div>

<span class="complexity-badge">Разработчику</span>

Конструкция `if __name__ == "__main__":` встречается почти в каждом учебном примере и во многих реальных проектах. Она отделяет **код, который должен выполниться при запуске файла**, от **определений**, которые другие программы могут импортировать.

См. также: [Первая программа](./16.md) · [жизненный цикл модуля](./11.md#zhiznennyy-tsikl-koda) · [шаблон скрипта в обзоре языка](./1.md) · [пример с requests](./39.md).

---

## Что делает эта конструкция

Проверка отвечает на один вопрос: **файл запущен как главная программа или подключён как модуль**.

| Переменная / значение | Смысл |
|-----------------------|-------|
| **`__name__`** | Специальная строковая переменная, которую Python задаёт каждому файлу при загрузке |
| **`"__main__"`** | Значение `__name__`, когда файл запускают напрямую: `python script.py` |
| **Имя файла без `.py`** | Значение `__name__`, когда файл импортируют: `import script` |

При **импорте** интерпретатор выполняет весь код верхнего уровня модуля — определения функций, классов и любые инструкции вне функций. Блок под `if __name__ == "__main__":` выполняется **только** при прямом запуске.

---

## Простой пример

Файл `test.py`:

```python
print(f"Меня зовут {__name__}")

if __name__ == "__main__":
    print("Я запущен как главная программа!")
else:
    print("Меня импортировали как модуль")
```

**Прямой запуск:**

```bash
python test.py
```

```text
Меня зовут __main__
Я запущен как главная программа!
```

**Импорт из другого процесса** (флаг `-c` — выполнить строку кода без `.py`-файла; для проверки среды достаточно `python -c "print('ok')"`):

```bash
python -c "import test"
```

```text
Меня зовут test
Меня импортировали как модуль
```

Ветка `else` в учебных примерах часто опускают — достаточно блока `if __name__ == "__main__":` с нужным кодом.

## Зачем это нужно

Представьте файл с полезными функциями и демонстрацией внизу:

```python
# calculator.py — без проверки __name__
def add(a, b):
    return a + b

def multiply(a, b):
    return a * b

print(add(5, 3))
print(multiply(4, 2))
```

При `import calculator` из другой программы интерпретатор сразу выполнит `print` — на экран уйдут `8` и `8`, хотя вы могли хотеть только вызвать `calculator.add(10, 20)`.

**С проверкой** демонстрация живёт в точке входа:

```python
# calculator.py
def add(a, b):
    return a + b

def multiply(a, b):
    return a * b

if __name__ == "__main__":
    print(add(5, 3))
    print(multiply(4, 2))
```

| Способ запуска | Поведение |
|----------------|-----------|
| `python calculator.py` | Показывает демонстрацию — удобно для ручной проверки |
| `import calculator` в `main.py` | Импортирует функции **без** лишнего вывода |

Тот же приём используют во [Flask](./341.md), [Tkinter](./311.md) ([примеры GUI](/lab/Примеры/1124)), [играх на Pygame](./312.md), [готовых мини-играх Pygame](/lab/Примеры/1132), [Panda3D](./318.md) и в [практикуме игр](/encyclopedia/9-spinoff/9-04-razrabotka-igr/praktikum-razrabotki-igr/intro):

```python
if __name__ == "__main__":
    app = App()
    app.run()
```

Без проверки импорт файла с классом `App` мог бы сразу открыть окно или запустить игровой цикл.

## Импорт и «код верхнего уровня»

При загрузке модуля Python проходит цепочку **Load → Compile → Execute** (см. [жизненный цикл кода](./11.md#zhiznennyy-tsikl-koda)). На этапе **Execute** выполняется каждая строка вне функций и классов.

```python
# game.py — без if __name__ == "__main__"
class Game:
    def __init__(self):
        print("Игра создана")

    def start(self):
        print("Игра запущена")

print("Создаю игру...")
game = Game()
game.start()
```

Строка `import game` в другом файле создаст объект и запустит игру — обычно это нежелательно.

**Вариант с точкой входа:**

```python
class Game:
    def __init__(self):
        print("Игра создана")

    def start(self):
        print("Игра запущена")

if __name__ == "__main__":
    print("Создаю игру...")
    game = Game()
    game.start()
```

Теперь `from game import Game` даёт только класс; запуск — через `python game.py`.

  <div class="callout-title">Связь с функцией main()</div>

  <div class="callout-body">
  Часто логику запуска выносят в <code>def main():</code>, а в блоке <code>if __name__ == "__main__":</code> вызывают <code>main()</code>. Так проще тестировать и читать файл — см. примеры в <a href="./16.md">Первой программе</a> (VS Code, PyCharm).

## Аналогия

Файл Python можно представить как **повара с рецептами** (функции и классы).

- При **`__name__ == "__main__"`** повар готовит своё блюдо для себя — это главная программа.
- При **импорте** повара зовут на чужую кухню: он отдаёт рецепты и инструменты, но **своё демо-блюдо не готовит**, пока его явно не попросят через прямой запуск файла.

---

## Когда писать проверку

| Ситуация | Нужен ли блок |
|----------|----------------|
| Файл только для `python script.py`, никогда не импортируют | Можно обойтись без него |
| Одноразовый скрипт «на сегодня» | По желанию |
| Библиотека, общий модуль, код для других | **Да** |
| Демо, тесты или CLI в том же файле, что и функции | **Да** |
| Автопроверка домашних заданий (`import student_module`) | **Да** |
| Единственный `main.py` всего приложения | Часто достаточно кода без обёртки, но привычка полезна |

<div class="callout callout--tip">
  <div class="callout-title">Хорошая привычка</div>

  <div class="callout-body">
  Даже в простых скриптах блок <code>if __name__ == "__main__":</code> делает файл гибче: завтра его можно импортировать, не переписывая структуру. В учебных проектах PyCharm и VS Code часто добавляют этот шаблон автоматически.
</div>
</div>

## Не путать с другими «__main__»

| Контекст | Что это |
|----------|---------|
| `if __name__ == "__main__":` | Условие «файл запущен напрямую» |
| `python -m http.server` | Запуск **пакета** через его `__main__.py` — см. [Первую программу](./16.md) |
| `Flask(__name__)` | Имя **текущего модуля** для поиска шаблонов — другое использование той же переменной |
| `logging.getLogger(__name__)` | Имя модуля в логах — тоже `__name__`, но без сравнения с `"__main__"` |

---

## Кратко

1. **`__name__`** — имя модуля; при `python file.py` оно равно `"__main__"`.
2. **`if __name__ == "__main__":`** — код ниже выполняется **только** при прямом запуске файла.
3. **Импорт** выполняет определения и весь код верхнего уровня **вне** этого блока.
4. **Пишите проверку**, когда файл содержит переиспользуемые функции или классы и при этом демо, CLI или запуск приложения.
