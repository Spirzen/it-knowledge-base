В TypeScript объекты описывают через **`interface`** и **`type`**, поведение инкапсулируют в **`class`** — как в JavaScript ES6, но с **проверкой контракта** и модификаторами на этапе компиляции. Ключевая идея раздела — **структурная типизация** (structural typing): совместимость определяется набором полей и методов, без привязки к имени типа. Удобный порядок — [типы и типизация](./10.md), эта статья, [коллекции](./19.md), [паттерны](./28.md). Таблицы — [Справочник — классы](/encyclopedia/5-languages/5-01-javascript/301#6-классы) и [интерфейсы](/encyclopedia/5-languages/5-01-javascript/301#5-интерфейсы) ([синтаксис](./8.md)).

### Теория и синтаксис TypeScript

| Понятие ООП | Как выражено в TypeScript |
|-------------|---------------------------|
| Контракт данных | `interface`, `type` — **структурная** совместимость (форма объекта) |
| Класс, АДТ | `class`; в runtime — прототип JS |
| Создание экземпляра | `new ClassName()`, фабрики, литералы объектов |
| Конструктор | `constructor(...)`; parameter properties |
| Инкапсуляция | `private` / `protected` / `public`; `#` в runtime |
| Наследование | `extends`; один базовый класс |
| Полиморфизм подтипов | переопределение методов; `implements` интерфейсов |
| Абстракция | `abstract class`, интерфейсы без реализации |
| Статика | `static` поля и методы на функции-конструкторе |
| Параметрический полиморфизм | [дженерики](./24.md) `class Repo<T>` |

Определения без привязки к языку — [раздел 4-08-oop](/encyclopedia/4-code-dev/4-08-oop/intro).

**Кратко для новичка:**

- **Класс** — шаблон с полями и методами; **`new`** создаёт экземпляр в памяти.
- **`interface` / `type`** — описание формы данных без реализации; TypeScript проверяет совпадение полей (структурная типизация).
- **Инкапсуляция** — скрытие полей через `private` или `#`; снаружи работают только методы.
- **Наследование** — `extends` переносит поля и методы родителя; **`override`** помечает переопределение.
- **Полиморфизм** — переменная типа `Shape` может ссылаться на `Circle`; вызов метода идёт по реальному классу объекта.

## Создание экземпляра и запись в переменные

### Литерал объекта (без `class`)

```ts
const point: { x: number; y: number } = { x: 10, y: 20 };
let p = point;   // копируется ссылка на тот же объект
p.x = 99;        // меняется и point.x
```

Разбор:
- `const point` — переменная **не переназначается** на другой объект; поля внутри менять можно.
- Присваивание `let p = point` копирует **ссылку**, без клонирования объекта (как в JS).
- Для DTO и API чаще используют именованный `interface` вместо inline-типа.

### Через `new` и конструктор класса

```ts
class User {
  constructor(
    public readonly id: string,
    public name: string,
  ) {}
}

const u1 = new User("u-1", "Анна");
const u2: User = u1;              // тот же экземпляр по ссылке
const u3 = new User("u-2", "Борис"); // другой объект
```

Разбор:
- `new User(...)` вызывает `constructor`, создаёт объект в куче, возвращает ссылку.
- Аннотация `: User` на переменной — проверка типа; в runtime это обычный объект.
- `readonly id` в parameter property — поле задаётся один раз в конструкторе.

### Фабричные функции

```ts
interface Product {
  sku: string;
  price: number;
}

function createProduct(sku: string, price: number): Product {
  return { sku, price };
}

const item = createProduct("A-1", 100);
```

Разбор:
- Фабрика возвращает объект, совместимый с `Product` **структурно** — `implements` не нужен.
- Популярный стиль в React/Node: поведение — функции, данные — plain objects + `type`.

### Порядок инициализации полей класса

```ts
class Demo {
  a = this.b + 1;  // поля инициализируются сверху вниз
  b = 10;
}
```

Разбор:
- Поля класса инициализируются **до** тела конструктора (с учётом `useDefineForClassFields` в `tsconfig`).
- В производном классе сначала инициализируются поля базового, затем производного, затем `constructor` производного (после `super()`).

## Конструкторы, все формы

### Обычный конструктор

```ts
class BankAccount {
  private balance: number;

  constructor(initial: number) {
    if (initial < 0) throw new Error("Отрицательный баланс");
    this.balance = initial;
  }

  deposit(amount: number): void {
    if (amount > 0) this.balance += amount;
  }

  getBalance(): number {
    return this.balance;
  }
}
```

Разбор:
- **Инвариант** (правило состояния, например "баланс ≥ 0") задают в конструкторе и методах — это **инкапсуляция поведения** ([инкапсуляция](/encyclopedia/4-code-dev/4-08-oop/3)).
- `private balance` недоступен снаружи; клиент вызывает только `deposit` / `getBalance`.

### Parameter properties (сокращение полей)

```ts
class Employee {
  constructor(
    public name: string,
    private salary: number,
    protected department: string,
  ) {}
}
```

Разбор:
- Модификатор в параметре конструктора **одновременно** объявляет поле класса и присваивает аргумент.
- Эквивалентно ручному `this.name = name` в теле конструктора.
- `protected department` виден в подклассах, но не снаружи.

### Перегрузка конструктора (сигнатуры)

```ts
class Point {
  constructor(x: number, y: number);
  constructor(coords: { x: number; y: number });
  constructor(xOrCoords: number | { x: number; y: number }, y?: number) {
    if (typeof xOrCoords === "number") {
      this.x = xOrCoords;
      this.y = y!;
    } else {
      this.x = xOrCoords.x;
      this.y = xOrCoords.y;
    }
  }
  x: number;
  y: number;
}
```

Разбор:
- Несколько **сигнатур** `constructor(...)` — только для типизации; реализация одна.
- В runtime остаётся один конструктор JS.

### Правило `super()` в наследнике

```ts
class Animal {
  constructor(public name: string) {}
}

class Dog extends Animal {
  constructor(name: string, public breed: string) {
    super(name);  // обязательно до использования this
    // this.breed = breed — уже сделано parameter property
  }
}
```

Разбор:
- В производном классе **до** обращения к `this` нужно вызвать `super(...)`.
- TypeScript проверяет это статически; иначе runtime-ошибка в JS.

## Объектный контракт через `interface` и `type`

Оба описывают **форму** объекта. Для учебных контрактов чаще начинают с `interface`:

```ts
interface Person {
  readonly id: string;
  name: string;
  age?: number;
}

const anna: Person = {
  id: "p-1",
  name: "Анна",
};
```

Разбор:

- `readonly` — поле нельзя переназначить после создания (поверхностно).
- `age?` — опциональное свойство (`age: number | undefined`).
- Различия `interface` и `type` (union, merge) — в [Синтаксис и пунктуация TypeScript](./8.md).

## Структурная типизация

**Структурная типизация** (structural typing) — TypeScript сравнивает типы по **набору полей**, без привязки к имени объявления (в отличие от номинальной модели C#/Java):

```ts
interface Point {
  x: number;
  y: number;
}

function distance(p: Point): number {
  return Math.hypot(p.x, p.y);
}

// Явный implements не нужен — форма совпала
distance({ x: 3, y: 4 });
```

| | TypeScript | C# (номинальный) |
|---|------------|------------------|
| Совместимость | Достаточно нужных полей | Совпадает именованный тип |
| Лишние поля | часто ошибка (excess property check) | зависит от сценария |
| `implements` | документирует намерение | обязателен для контракта |

Разбор:

- Структурность близка к **утиной типизации** (duck typing) в JS, но ошибки ловятся в IDE.
- `implements` в TS проверяет класс на соответствие контракту; для внешнего кода тип остаётся structural.

## Приватные поля JavaScript `#`

С ES2022 есть **настоящие** приватные поля runtime:

```ts
class Counter {
  #value = 0;

  increment(): void {
    this.#value += 1;
  }

  read(): number {
    return this.#value;
  }
}
```

Разбор:

- `#value` существует в **скомпилированном JS** и недоступен снаружи даже через `(obj as any)`.
- `private` в TS — в основном compile-time (кроме режимов с эмиссией `useDefineForClassFields` и т.д.).

В новых проектах для скрытия состояния чаще берут `#` или замыкания; `private` оставляют для совместимости с legacy.

## Статические члены

```ts
class IdGenerator {
  private static seq = 0;

  static next(prefix: string): string {
    IdGenerator.seq += 1;
    return `${prefix}-${IdGenerator.seq}`;
  }
}

console.log(IdGenerator.next("user"));
```

Разбор:

- `static` принадлежит **конструктору** функции-класса, у экземпляра его нет.
- Типизация как в C#, но без namespace-классов как в старом JS.

| Сценарий | Предпочтение |

class Clicker {

## Геттеры, сеттеры и вычисляемые свойства

```ts
class Rectangle {
  constructor(
    private _width: number,
    private _height: number,
  ) {}

  get width(): number {
    return this._width;
  }

  set width(value: number) {
    if (value <= 0) throw new Error("Ширина должна быть > 0");
    this._width = value;
  }

  get area(): number {
    return this._width * this._height;
  }
}
```

Разбор:
- `get` / `set` — синтаксический сахар: снаружи `rect.width = 5` вызывает сеттер.
- Вычисляемое свойство `area` без `set` — только для чтения.
- Подчёркивание в `_width` — соглашение о внутреннем поле; TS не запрещает доступ снаружи, если не `private`.

## Инкапсуляция через `private`, `protected`, `#`

### Уровни доступа

| Модификатор | Класс | Наследник | Внешний код | Runtime |
|-------------|-------|-----------|-------------|---------|
| `public` | да | да | да | да |
| `protected` | да | да | нет | да (в JS поле есть) |
| `private` | да | нет* | нет | compile-time** |
| `#field` | да | нет | нет | **настоящая** приватность |

\* В TS 4.3+ `private` в базовом классе не виден в подклассе (номинальная приватность на уровне типов).
\** После компиляции в JS поле `private` может существовать как обычное свойство.

```ts
class Base {
  protected secret = "base";
  private token = "hidden";
}

class Child extends Base {
  reveal() {
    return this.secret;  // OK
    // return this.token; // ошибка TS
  }
}
```

Разбор:
- `protected` — типичный выбор для расширяемого API базового класса.
- Для **секретов** (ключи, токены) предпочтительнее `#` или замыкания в фабрике.

## Наследование и переопределение

### `extends`, `super`, `override`

```ts
class Shape {
  constructor(protected color: string) {}

  describe(): string {
    return `фигура цвета ${this.color}`;
  }
}

class Circle extends Shape {
  constructor(color: string, public radius: number) {
    super(color);
  }

  override describe(): string {
    return `${super.describe()}, r=${this.radius}`;
  }

  area(): number {
    return Math.PI * this.radius ** 2;
  }
}
```

Разбор:
- `override` (TS 4.3+) — явная пометка переопределения; ошибка, если в базе нет такого метода.
- `super.describe()` — вызов реализации родителя.
- Полиморфная переменная: `const s: Shape = new Circle("red", 5); s.describe()` — вызовется `Circle.describe`.

### Один базовый класс, много интерфейсов

```ts
interface Serializable {
  toJSON(): unknown;
}

interface Identifiable {
  readonly id: string;
}

class Entity implements Identifiable, Serializable {
  constructor(public readonly id: string, public name: string) {}

  toJSON() {
    return { id: this.id, name: this.name };
  }
}
```

Разбор:
- Класс наследует **один** класс, но может `implements` **несколько** интерфейсов.
- Интерфейсы в TS не существуют в runtime — только проверка компилятора.

## Полиморфизм

### Структурный полиморфизм (утиная типизация и типы)

```ts
interface Drawable {
  draw(ctx: CanvasRenderingContext2D): void;
}

function renderAll(items: Drawable[], ctx: CanvasRenderingContext2D) {
  for (const item of items) {
    item.draw(ctx);
  }
}

// Класс без implements — всё равно подходит, если есть draw
class Label {
  constructor(private text: string) {}
  draw(ctx: CanvasRenderingContext2D) {
    ctx.fillText(this.text, 0, 0);
  }
}
```

Разбор:
- `renderAll` принимает всё, у чего есть `draw` с нужной сигнатурой.
- `implements Drawable` документирует намерение; для вызова `renderAll` достаточно совпадения формы метода `draw`.

### Полиморфизм через union и narrowing

```ts
type Payment = CardPayment | CashPayment;

interface CardPayment {
  kind: "card";
  last4: string;
}

interface CashPayment {
  kind: "cash";
  amount: number;
}

function total(p: Payment): number {
  switch (p.kind) {
    case "card":
      return 0; // комиссия отдельно
    case "cash":
      return p.amount;
  }
}
```

Разбор:
- Дискриминант `kind` — идиома TS вместо глубокой иерархии классов.
- Компилятор сужает тип в каждой ветке `switch`.

### `instanceof` (номинальный след в runtime)

```ts
if (error instanceof TypeError) {
  console.error(error.message);
}
```

Разбор:
- `instanceof` проверяет **цепочку прототипов** — работает для классов; для `interface` в runtime проверки нет.
- Для plain objects используют type guards: `"kind" in obj`.

## Абстракция через интерфейсы и абстрактные классы

### Когда `interface`, когда `abstract class`

| | `interface` | `abstract class` |
|---|-------------|------------------|
| Runtime | исчезает | остаётся класс |
| Поля с состоянием | только сигнатуры | можно общие поля |
| Общая реализация | нет | да (`mustFindById`) |
| Множественное наследование интерфейсов | да (`extends` нескольких) | один `extends` |

```ts
abstract class Repository<T extends { id: string }> {
  protected items = new Map<string, T>();

  abstract findById(id: string): T | undefined;

  mustFindById(id: string): T {
    const item = this.findById(id);
    if (!item) throw new Error(`Not found: ${id}`);
    return item;
  }
}
```

Разбор:
- Шаблонный метод `mustFindById` — общая логика в базе ([абстракция](/encyclopedia/4-code-dev/4-08-oop/2)).
- `findById` — контракт для подкласса (`InMemoryProductRepo`).

## Сравнение TypeScript с C# и Java

| Тема | TypeScript | C# / Java |
|------|------------|-----------|
| Модель типов | Структурная | Номинальная |
| Интерфейс + класс | `implements` опционален для совместимости | `implements` обязателен для контракта |
| Приватность runtime | `#` или соглашения | `private` в IL/JVM |
| Множественное наследование классов | нет | нет |
| Значимые типы | нет (есть примитивы) | `struct` в C# |
| Null | `T \| null`, `?` | nullable reference types / `Optional` |

## Частые ошибки

| Ошибка | Причина | Что делать |
|--------|---------|------------|
| Ожидали номинальность как в C# | другая модель | смотреть на форму объекта, не на имя класса |
| `private` виден в runtime | только TS | `#` или не экспортировать |
| Глубокая иерархия классов | хрупкий дизайн | композиция, [Паттерны в TypeScript](./28.md) |
| Лишние поля в литерале | excess property check | переменная + присвоение или индексная сигнатура |
| Дублирование `interface` и `class` | шум | один источник правды для полей |
| `implements` без нужды | церемония | достаточно structural match |
