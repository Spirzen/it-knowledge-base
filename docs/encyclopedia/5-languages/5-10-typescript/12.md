Операторы `if`, `switch`, `===`, `&&`, `??` в TypeScript **совпадают с JavaScript**, но ветки часто **сужают тип** — **narrowing** (сужение типа): компилятор запоминает результат проверки и разрешает доступ только к полям подходящей ветки union. Это связывает условия с системой типов и убирает целый класс ошибок доступа к полям. Статья логично следует за [переменными](./11.md); дальше — [циклы](./13.md) и [асинхронность](./17.md) с `LoadState`.

> База JS: [условия и циклы](/encyclopedia/5-languages/5-01-javascript/20). Discriminated unions — [Типы данных и типизация в TypeScript](./10.md).

## Сравнение и логика

```ts
const a = 5;
const b = "5";

console.log(a == b);  // true  — приведение типов
console.log(a === b); // false — предпочтительно в TS/JS
```

| Оператор | Назначение |
|----------|------------|
| `===` / `!==` | строгое сравнение без приведения |
| `&&`, `\|\|` | короткое замыкание; `\|\|` осторожно с `0` и `""` |
| `??` | значение по умолчанию только для `null` / `undefined` |
| `?.` | optional chaining |

```ts
const port = config.port ?? 3000;
const label = input || "по умолчанию"; // 0 и "" подставят значение по умолчанию
```

Разбор:

- Для дефолтов конфигурации в strict-коде чаще **`??`**, реже `||` (у `||` ложными считаются `0` и `""`).
- `?.` возвращает `undefined`, если левая часть `null`/`undefined` — тип результата учитывает это.

## `if` и сужение типов (narrowing)

### `typeof` для примитивов

```ts
function format(value: string | number): string {
  if (typeof value === "string") {
    return value.toUpperCase();
  }
  return value.toFixed(2);
}
```

Разбор:

- В ветке `string` компилятор **знает** тип `value`.
- После `if` в `else` остаётся `number`.

### Проверка на `null` / `undefined`

```ts
function len(text: string | null): number {
  if (text === null) {
    return 0;
  }
  return text.length;
}
```

### Truthiness — осторожно

```ts
function printCount(n: number | undefined): void {
  if (n) {
    // здесь n: number, но 0 отфильтрован!
    console.log(n);
  }
}
```

Разбор:

- `if (n)` отсекает `0` — для чисел лучше `n !== undefined && n !== null` или `n != null`.

## Оператор `in` для объектов

```ts
type Cat = { kind: "cat"; meow: () => void };
type Dog = { kind: "dog"; bark: () => void };
type Pet = Cat | Dog;

function speak(pet: Pet): void {
  if ("meow" in pet) {
    pet.meow();
  } else {
    pet.bark();
  }
}
```

Разбор:

- `in` проверяет **наличие свойства** в объекте и сужает union.
- Хорошо сочетается с полем-дискриминантом `kind`, но не заменяет его всегда.

## Discriminated union (дискриминируемое объединение)

**Discriminated union** (дискриминируемое объединение) — **union** вариантов с общим полем-**дискриминантом** (`kind`, `type`, `status`). По значению этого поля TypeScript сужает тип в `switch` / `if` и разрешает доступ только к полям соответствующей ветки.

Теория и пример с `Shape` — [Типы §discriminated union](./10.md#discriminated-union-дискриминируемое-объединение). Ниже — практика с `switch` и exhaustive check.

## Boolean-флаги и union состояний

Иногда состояние моделируют **несколькими boolean** (`isLoading`, `isError`, `hasData`). TypeScript **не запрещает** невозможные комбинации: `isLoading: true` и `isError: true` одновременно — типы не противоречат.

```ts
// Антипаттерн: возможны "мёртвые" состояния
type LoadFlags = {
  isLoading: boolean;
  isError: boolean;
  data?: User;
};

function renderFlags(s: LoadFlags): string {
  if (s.isLoading) return "Загрузка…";
  if (s.isError) return "Ошибка";
  return s.data?.name ?? "—"; // data может отсутствовать при isLoading=false
}
```

**Discriminated union** кодирует **взаимоисключающие** состояния одним полем:

```ts
type LoadState =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: User }
  | { status: "error"; message: string };

function renderState(s: LoadState): string {
  switch (s.status) {
    case "idle":
      return "Нажмите для загрузки";
    case "loading":
      return "Загрузка…";
    case "success":
      return s.data.name; // data гарантированно есть
    case "error":
      return s.message;
  }
}
```

| Подход | Плюсы | Минусы |
|--------|-------|--------|
| Несколько `boolean` | привычно из JS | невозможные комбинации, optional-поля без гарантий |
| Union с дискриминантом | исчерпывающий `switch`, точные поля | чуть больше кода при описании типа |
| Один `status: string` | просто | широкий тип, нет сужения |

Полный пример загрузки API — [Асинхронность §LoadState](./17.md).

## Утверждения типов (type assertions)

**Утверждение типа** — вы сообщаете компилятору: "считай это значение типом T". Проверка **слабее**, чем при аннотации с совместимым литералом: компилятор **верит** вам, runtime — нет.

| Форма | Пример | Когда уместно |
|-------|--------|---------------|
| `as` | `value as string` | после ручной проверки; DOM-элементы |
| Угловые скобки | `<string>value` | то же; **не** в `.tsx` (конфликт с JSX) |
| Non-null `!` | `el!.focus()` | вы **только что** проверили на null |
| `as const` | `"ok" as const` | сужение литерала, без обхода проверки |
| `satisfies` | `obj satisfies T` | проверка формы **без** расширения вывода |

```ts
const raw: unknown = JSON.parse('{"id":"1"}');

// Плохо без проверки
// const user = raw as User;

function isUser(v: unknown): v is User {
  return typeof v === "object" && v !== null && "id" in v;
}

if (isUser(raw)) {
  console.log(raw.id); // сужение — предпочтительно
}

// Допустимо после проверки структуры
const el = document.getElementById("app");
if (el) {
  (el as HTMLDivElement).style.display = "block";
}
```

**Аннотация** (`const x: string = "a"`) проверяет совместимость при присваивании. **Утверждение** (`x as string`) обходит проверку. Для внешних данных порядок: `unknown` → guard / Zod → узкий тип — [Рекомендации](./6.md).

Подробнее про `!` — раздел [Оператор `!` (non-null assertion)](#оператор--non-null-assertion) ниже. Сравнение с аннотацией при объявлении — [Переменные §аннотация и утверждение](./11.md#аннотация-и-утверждение).

## `if` и `switch`

| Критерий | `if` / `else if` | `switch` |
|----------|------------------|----------|
| 2–3 ветки | удобно | избыточно |
| Много вариантов union | длинно | читаемо |
| Exhaustive check | вручную | `default: never` |
| Диапазоны чисел | удобно | возможно, но реже |

## Тернарный оператор

```ts
const badge = user.role === "admin" ? "Админ" : "Пользователь";

const message =
  state.status === "error" ? state.message : "OK";
```

Разбор:

- Тернарник **выражение** — можно присваивать и возвращать.
- Вложенные тернарники быстро теряют читаемость — переходите на `switch` или функцию.

## Сужение с `Array.isArray` и пользовательскими guard

```ts
function isStringArray(value: unknown): value is string[] {
  return Array.isArray(value) && value.every((x) => typeof x === "string");
}

function process(raw: unknown): string[] {
  if (!isStringArray(raw)) {
    throw new Error("Expected string[]");
  }
  return raw.map((s) => s.trim());
}
```

Разбор:

- **`value is string[]`** — type predicate: после `if` тип сужен.
- Предпочтительнее `as string[]` для внешних данных — [Рекомендации по разработке на TypeScript](./6.md).

## Пример `parseInput`

```ts
function parseInput(raw: unknown): number | null {
  if (typeof raw === "number" && Number.isFinite(raw)) {
    return raw;
  }
  if (typeof raw === "string" && raw.trim() !== "") {
    const n = Number(raw);
    return Number.isFinite(n) ? n : null;
  }
  return null;
}
```

Разбор:

- Возврат `null` явно описывают в типе — вызывающий обязан обработать.
- Альтернатива — `throw` или `Result` — [Обработка ошибок в TypeScript](./27.md).

## Оператор `!` (non-null assertion)

```ts
function demo(element: HTMLElement | null): void {
  element!.focus(); // разработчик уверен, что элемент есть
}
```

Разбор:

- `!` **отключает** проверку на `null`/`undefined` — ошибка возможна в runtime.
- Используйте редко; лучше `if (element) element.focus()`.

## Частые ошибки

| Ошибка | Причина | Что делать |
|--------|---------|------------|
| Поле union недоступно | нет [сужения типа (narrowing)](#if-и-сужение-типов-narrowing) | `switch` по дискриминанту |
| `switch` без `break` в JS-стиле | fall-through редко нужен | `return` в ветках или `break` |
| `\|\|` для дефолта числа | `0` ложный | `??` |
| `as` вместо проверки | небезопасно | `typeof`, predicate |
| Забыли `default: never` | новый вариант union тихо проходит | exhaustive check |
| `==` вместо `===` | неявное приведение | строгое сравнение |

## Практика

1. Напишите `parseInput(raw: unknown): number | null` с `typeof` и проверкой `Number.isFinite`.
2. Опишите union `Notification` с полем `type` и `handle(n)` с `switch` + `never`.
3. Перепишите цепочку `if/else` на `switch` по `status` из [Асинхронное программирование в TypeScript](./17.md).
4. Добавьте type predicate `isUser` и функцию, принимающую `unknown`.
5. Найдите в проекте `||` для дефолта и замените на `??` там, где допустимы `0` и `""`.
