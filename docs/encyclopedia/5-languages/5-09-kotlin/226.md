## Flow в Kotlin

**Flow** — тип из `kotlinx.coroutines` для **асинхронной** последовательности значений. В отличие от `Sequence`, эмит и сбор могут переключать диспетчеры и приостанавливаться (`suspend`). В отличие от `SharedFlow`/`StateFlow`, обычный `flow { }` **холодный**: код внутри builder запускается заново при каждом новом `collect`.

База: [корутины](./222.md). Ленивые синхронные цепочки: [коллекции и Sequence](./225.md).

---

## Холодный Flow

```kotlin
import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

fun counter(): Flow<Int> = flow {
    for (i in 1..5) {
        delay(200)
        emit(i)
    }
}

suspend fun main() {
    counter().collect { println(it) }
}
```

Два подряд идущих `collect` на `counter()` выполнят цикл **дважды** — это ожидаемое поведение холодного потока.

## Горячие потоки для UI и состояния

| Тип | Назначение |
|-----|------------|
| `StateFlow<T>` | одно актуальное состояние (экран, настройки) |
| `SharedFlow<T>` | события: ошибки, одноразовые сигналы навигации |
| `channelFlow` | несколько продюсеров в одном Flow |

```kotlin
private val _uiState = MutableStateFlow(UiState.Loading)
val uiState: StateFlow<UiState> = _uiState.asStateFlow()

fun onDataLoaded(data: List<Item>) {
    _uiState.value = UiState.Success(data)
}
```

Подписчик в Compose: `uiState.collectAsStateWithLifecycle()`.

## Операторы (как у коллекций, но suspend)

```kotlin
repository.observeOrders()
    .map { orders -> orders.filter { it.isOpen } }
    .distinctUntilChanged()
    .catch { e -> emit(emptyList()); log(e) }
    .flowOn(Dispatchers.IO)
    .collect { openOrders -> render(openOrders) }
```

| Оператор | Роль |
|----------|------|
| `map` / `transform` | преобразование каждого значения |
| `filter` | отбор по условию |
| `take` / `drop` | ограничение длины потока |
| `first` / `single` | одно значение (с исключением, если не подходит) |
| `reduce` / `fold` | свёртка в одно значение |
| `flatMapConcat` / `Merge` / `flatMapLatest` | вложенные потоки |
| `debounce` / `sample` | сглаживание частых обновлений (поиск, ввод) |
| `distinctUntilChanged` | не эмитить подряд одинаковое |
| `catch` | обработка ошибок upstream |
| `flowOn` | смена диспетчера для upstream |
| `buffer` | декуплинг продюсера и потребителя |

`flatMapLatest` отменяет предыдущую вложенную работу — типично для поиска по мере ввода текста.

## Объединение потоков

```kotlin
val merged = merge(flowA, flowB)

val combined = combine(tempFlow, humidityFlow) { t, h ->
    Weather(t, h)
}
```

`merge` — любое значение из любого источника. `combine` — ждёт обновления **каждого** участника и строит результат из последних значений.

## Отмена и structured concurrency

Сбор Flow — suspend-функция. При отмене `coroutineScope` (уход с экрана, закрытие `viewModelScope`) цепочка `collect` прерывается, upstream получает `CancellationException`.

Не вызывайте блокирующий код внутри `flow { }` без `withContext(Dispatchers.IO)` — иначе заблокируете поток диспетчера.

## Тестирование

```kotlin
import kotlinx.coroutines.test.runTest
import org.junit.jupiter.api.Assertions.assertEquals
import org.junit.jupiter.api.Test

@Test
fun emitsFirstThree() = runTest {
    val items = counter().take(3).toList()
    assertEquals(listOf(1, 2, 3), items)
}
```

Для пошаговой проверки событий по мере прихода удобна библиотека Turbine (см. [экосистему](./10.md)).

## Flow и Sequence

| | Sequence | Flow |
|---|----------|------|
| Контекст | синхронный | корутины |
| Блокировка потока | да, если тяжёлая работа в цепочке | нет при правильных диспетчерах |
| Источник | память, файл, итератор | сеть, БД, таймеры, события UI |
| Повторный запуск | новый `asSequence()` | новый `collect` на холодном Flow |

Для офлайн-обработки файла на JVM часто достаточно [Sequence](./225.md). Для Room, Ktor, WebSocket, тикеров — Flow.
