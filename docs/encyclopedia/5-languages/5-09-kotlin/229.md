## Jetpack Compose — первый экран

### Где применяют Compose на Android

**Jetpack Compose** — способ строить интерфейс Android **на Kotlin-функциях**, а не в XML. Вы описываете "при таком состоянии экран выглядит так"; при изменении числа, текста или списка фреймворк **перерисовывает** только нужные части (**recomposition**).

Общий UI на нескольких платформах — [Compose Multiplatform](./224.md). Теория: [экосистема Kotlin](./10.md). Фоновая работа: [корутины](./222.md), [Flow](./226.md).

---

## Словарь терминов

| Термин | Простыми словами |
|--------|------------------|
| **Activity** | Окно приложения на Android; точка входа экрана. |
| **`@Composable`** | Функция, которая рисует UI. |
| **State (состояние)** | Данные, от которых зависит картинка (число счётчика, текст поля). |
| **`remember`** | Сохранить состояние между перерисовками. |
| **ViewModel** | Объект, который переживает поворот экрана и хранит данные экрана. |
| **`StateFlow`** | Поток "последнее значение состояния" для UI. |
| **NavHost** | Контейнер нескольких экранов и переходов между ними. |

---

### Что получится

Экран со счётчиком на Material3: `remember` для локального состояния и опционально **ViewModel**, чтобы счётчик **не сбрасывался** при повороте телефона.

### Разбор API

| API | Назначение |
|-----|------------|
| `@Composable` | Помечает функцию UI; вызывается только из Composable или `setContent`. |
| `remember { mutableStateOf(0) }` | Один раз создать состояние `0`, хранить между recomposition. |
| `by` | Делегат: писать `count++`, а не `count.value++`. |
| `mutableStateOf` | При изменении значения Compose планирует перерисовку. |
| `Column` | Вертикальная раскладка. |
| `Modifier.fillMaxSize().padding(24.dp)` | Размер и отступы. |

Без `remember` при каждой перерисовке `count` снова стал бы `0`.

## Как мыслить состоянием в Compose

Стабильная модель для большинства экранов:

| Категория состояния | Где хранить | Пример |
|---------------------|-------------|--------|
| Эфемерное UI-состояние | `remember` / `rememberSaveable` | открыт ли dropdown, текст фильтра |
| Состояние экрана | `ViewModel + StateFlow` | список заметок, загрузка, ошибка |
| Данные приложения | репозиторий + БД/сеть | профиль пользователя, каталог товаров |

Это помогает избежать хаоса, когда часть данных "живет" в Composable, а часть в сервисах.

## Разделение на `UiState` и `UiEvent`

```kotlin
data class NotesUiState(
    val isLoading: Boolean = false,
    val items: List<Note> = emptyList(),
    val error: String? = null
)

sealed interface NotesUiEvent {
    data class InputChanged(val value: String) : NotesUiEvent
    data object AddClicked : NotesUiEvent
    data class DeleteClicked(val id: Long) : NotesUiEvent
}
```

Разбор:
- `NotesUiState` хранит полный снимок данных, по которому экран рисует текущее состояние.
- `isLoading` отделяет реальную загрузку от ситуации "данных пока нет".
- `error` задаёт явный канал для сообщения об ошибке, а не скрытых side effect.
- `sealed interface NotesUiEvent` фиксирует закрытый набор пользовательских событий.
- Такой контракт упрощает обработку: на каждый event есть понятная ветка логики.

Такой контракт упрощает рост экрана — добавляется новый элемент UI, вы явно дописываете состояние и событие, не ломая старое поведение.

## Производительность и recomposition

Практические правила для списков:

- Передавайте в Composable только нужные данные, а не "весь большой объект".
- Используйте `key` в `LazyColumn`, как у вас уже сделано.
- Тяжёлые вычисления выносите в `remember(...) { ... }` или в `ViewModel`.
- Частые потоки ограничивайте `distinctUntilChanged()` на слое [Flow](./226.md).

```kotlin
val visibleItems by remember(notes) {
    mutableStateOf(notes.filter { it.text.isNotBlank() })
}
```

Разбор:
- `remember(notes)` пересчитывает выражение только когда меняется входной список `notes`.
- `filter { it.text.isNotBlank() }` отбрасывает пустые элементы до рендера.
- Делегат `by` делает чтение состояния лаконичным, без ручного `.value`.
- Подход полезен для лёгких вычислений; для сложных сценариев подойдёт `derivedStateOf`.

## Дополнительный сниппет — `rememberSaveable` для поворота

```kotlin
@Composable
fun NameInput() {
    var name by rememberSaveable { mutableStateOf("") }

    OutlinedTextField(
        value = name,
        onValueChange = { name = it },
        label = { Text("Имя") }
    )
}
```

Разбор:
- `rememberSaveable` сохраняет значение в `SavedState`, поэтому состояние переживает поворот.
- В отличие от `remember`, значение не теряется при пересоздании Activity.
- `mutableStateOf("")` создаёт наблюдаемое состояние, которое перерисовывает UI при изменении.
- `onValueChange` поддерживает однонаправленный поток данных от ввода к состоянию.
- Шаблон полезен для форм, фильтров и временного пользовательского ввода.

### Частые ошибки

| Симптом | Причина |
|---------|---------|
| `@Composable invocations can only happen...` | Вызов Composable из обычной функции |
| Счётчик сбрасывается при повороте | Только `remember`, нет ViewModel / `rememberSaveable` |
| Preview пустой | Нет обёртки `MaterialTheme` |
| Красный Gradle sync | Несовместимые версии Compose BOM и Kotlin |
