## FAQ — Часто задаваемые вопросы

Типичные сбои и ситуации, с которыми сталкиваются новички после раздела. Здесь — **что делать и где копать в главах**; определения для зачёта — в [чек-листе](./999.md).

<div class="faq-list">

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Переписал Java-класс на Kotlin, а при запуске снова падает с NullPointerException — разве Kotlin это убирает?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Kotlin убирает NPE только там, где типы помечены как non-null и вы не обходите проверки через платформенные типы из Java или `!!`. Смешанный проект чаще ломается на границе: Java вернула `null`, Kotlin ожидал `String`. Сначала пройдите nullable на границе и [Kotlin ↔ Java](./233.md). Подробнее здесь — [типы](./12.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Android Studio пишет "Gradle sync failed" сразу после открытия учебного проекта — с чего начать?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Проверьте JDK в настройках IDE, версию Android Gradle Plugin и доступ в интернет для скачивания зависимостей. Ошибка в логе Sync обычно указывает на конкретный модуль или репозиторий. Подробнее здесь — [что знать перед Kotlin](./1001.md), [первая программа](./2.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Пишу на Kotlin, но код выглядит как Java: геттеры, сеттеры, `if (x != null)` на каждом шагу.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Идиоматичный Kotlin опирается на `val`, свойства, `?.`, `?:`, `when` и data-классы вместо шаблонного кода. Перечитайте [основы](./11.md) и [синтаксис](./16.md), затем сравните свой фрагмент с примерами в [рекомендациях](./101.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Вызвал `delay(1000)` в обычной функции — компилятор ругается на suspend.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `delay` и другие suspend-функции работают только внутри корутины или другой suspend-функции. Оберните вызов в `runBlocking` (консоль) или `launch`/`async` в scope приложения. Подробнее здесь — [корутины](./222.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> На Android UI "замирает" на несколько секунд после нажатия кнопки.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Тяжёлую работу (сеть, БД, парсинг JSON) выносите с главного потока: `Dispatchers.IO` или `viewModelScope` + корутины. Блокировка main thread — частая причина ANR. Подробнее здесь — [корутины](./222.md), [Compose + Room](./231.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Запустил Ktor-сервер локально — "Address already in use".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Порт уже занят предыдущим запуском или другим сервисом. Завершите старый процесс, смените `port` в конфиге или найдите процесс через `netstat`/диспетчер задач. Подробнее здесь — [Ktor — первая программа](./221.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `lateinit property X has not been initialized` при открытии экрана.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `lateinit` требует присвоения до первого чтения (часто в `onCreate` или во ViewModel). Для однократной ленивой инициализации с thread-safety смотрите `by lazy`. Подробнее здесь — [основы](./11.md), [ООП](./15.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Сравниваю два data class через `==`, но в коллекции "дубликат" не находится.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `==` для data class сравнивает поля; в `Set`/`Map` важны согласованные `equals`/`hashCode` (для data class генерируются). Если класс обычный или поля изменяемые (`var`), поведение другое. Подробнее здесь — [ООП](./15.md), [коллекции](./225.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `when` без аргумента не компилируется — "branch is never reachable".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Для sealed-иерархий `when` должен быть исчерпывающим: либо все подтипы перечислены, либо есть `else`. После добавления нового подкласса компилятор снова укажет на пропуск. Подробнее здесь — [конструкции](./17.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Из Java не виден метод companion object — только статики Java.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Для вызова из Java пометьте метод `@JvmStatic` или обращайтесь к `Companion`. Имена и видимость на границе JVM описаны в [Kotlin ↔ Java](./233.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Добавил extension `fun String.foo()`, а в другом файле метод "не находится".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Extension нужно импортировать так же, как обычную функцию верхнего уровня. Он не меняет класс на JVM, а только синтаксический сахар. Подробнее здесь — [ООП](./15.md), [синтаксис](./16.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Compose перерисовывает экран бесконечно, лог сыпется тысячами recomposition.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Частая причина — новое состояние создаётся прямо в теле `@Composable` без `remember`/`mutableStateOf`, или в `LaunchedEffect` без ключей меняется state на каждом кадре. Стабилизируйте state и поднимайте его в ViewModel. Подробнее здесь — [Compose — первый экран](./229.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Room ругается: "Cannot access database on the main thread".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Запросы к БД выполняйте в фоне (`Dispatchers.IO`, `suspend` DAO, `flow` с правильным collector). Подробнее здесь — [Room + ViewModel](./231.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Сборка падает: "Kotlin JVM target 21" не совпадает с Java compile 17.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Выровняйте `jvmTarget`, `sourceCompatibility` и `targetCompatibility` в Gradle для всех модулей. Смешанный Java/Kotlin проект ломается при разных bytecode level. Подробнее здесь — [первая программа](./2.md), [Kotlin ↔ Java](./233.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> KMP: "Expected class has no actual declaration" для iOS.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Для каждого `expect` в common-модуле нужен `actual` в platform-модуле (androidMain, iosMain и т.д.). Проверьте структуру source sets и имена пакетов. Подробнее здесь — [Compose Multiplatform](./224.md), [экосистема](./10.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> JSON не сериализуется — "Serializer for class X is not found".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Подключите плагин `kotlinx.serialization`, аннотацию `@Serializable` и зависимость в Gradle; для полиморфизма настройте `Json` и дескрипторы. Подробнее здесь — [конструкции](./17.md), [экосистема](./10.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Тесты на Mockito проходят в Java-модуле, а в Kotlin — "cannot mock final class".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Классы Kotlin по умолчанию final; для моков используйте MockK или откройте класс/`mockito-inline`. Подробнее здесь — [тестирование](./223.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Файл `.kts` запускается иначе, чем `.kt` — почему нет `main`?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Скрипт Gradle/утилитный `.kts` исполняется как сценарий; для обычного приложения нужен `fun main()` в `.kt` или настройка задачи в Gradle. Подробнее здесь — [первая программа](./2.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> IntelliJ подсвечивает Kotlin красным, но проект на Java собирается.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Убедитесь, что в модуле включён Kotlin plugin, sources помечены как Kotlin, а не Java, и выполнен Gradle import. Иногда помогает Invalidate Caches. Подробнее здесь — [что знать перед Kotlin](./1001.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `Flow` в UI ничего не показывает, хотя в логе emit есть.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Cold Flow начинает работу при collect; проверьте lifecycle (Android: `repeatOnLifecycle`), не блокируйте collector и не создавайте несколько конкурирующих collect без `shareIn`. Подробнее здесь — [Flow](./226.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Использовал `GlobalScope.launch` — после закрытия Activity корутина всё ещё держит ссылку.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Привязывайте корутины к структурированному scope (`viewModelScope`, `lifecycleScope`, свой `CoroutineScope` с SupervisorJob). `GlobalScope` не отменяется вместе с экраном. Подробнее здесь — [корутины](./222.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `Sequence` vs `List` — обработал миллион элементов, память закончилась.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Цепочки на `List` создают промежуточные коллекции; для больших потоков данных используйте ленивый `Sequence` или `Flow`. Подробнее здесь — [коллекции и Sequence](./225.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Spring Boot на Kotlin: бин не создаётся, в логе "parameter 0 required a bean of type X".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Класс мог остаться `final` без `@Configuration`/`open` для CGLIB, или конструктор не помечен для injection. Сверьтесь с [Spring Boot на Kotlin](./232.md) и [Kotlin ↔ Java](./233.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `readln()` в Windows выводит кракозябры в консоли.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Задайте UTF-8 для JVM (`-Dfile.encoding=UTF-8`) или настройте кодировку терминала IDE. Подробнее здесь — [консольный ввод-вывод](./227.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Перехватил исключение, но приложение всё равно падает с "FATAL EXCEPTION".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> На Android необработанное исключение в другом потоке или в корутине без `CoroutineExceptionHandler` всё равно завершит процесс. Логируйте cause и обрабатывайте ошибки на границе UI. Подробнее здесь — [исключения](./171.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Не понимаю, идти в Android, Ktor или Spring — материалов слишком много.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Выберите **один** маршрут из [оглавления](./intro) и не смешивайте в первую неделю: Compose, Ktor или Spring. Общая база языка — [основы](./11.md)–[конструкции](./17.md), затем ветка по цели.</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `inline fun` с `reified` не компилируется в публичном API библиотеки.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Reified доступен только в `inline`-функциях на стороне вызывающего кода; для публичных ABI-stable API используйте обычные generics или отдельные фабрики. Подробнее здесь — [конструкции](./17.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Kotlin или Java для Android — что выбрать в 2025 году?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Для новых приложений Google рекомендует Kotlin; Java нужен, если вы поддерживаете legacy-код или учите enterprise-стек. Оба языка работают на JVM в одном проекте. Подробнее здесь — [о разделе](./intro), [экосистема](./10.md), [Kotlin ↔ Java](./233.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Как научиться Kotlin с нуля бесплатно?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Пройдите маршрут: [что знать перед Kotlin](./1001.md) → [первая программа](./2.md) → [основы](./11.md)–[конструкции](./17.md), затем одну ветку (Android, Ktor или Spring) из [оглавления](./intro). Подробнее здесь — [история и контекст](./1.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Чем Kotlin лучше Java — кратко для собеседования.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Меньше шаблонного кода, nullable-типы на этапе компиляции, data class, корутины вместо тяжёлых потоков, современный синтаксис при полной совместимости с Java. Подробнее здесь — [основы](./11.md), [синтаксис](./16.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Что такое корутины в Kotlin простыми словами?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Это легковесные задачи, которые можно приостанавливать (`suspend`) без блокировки потока — удобно для сети и UI. Запускают через `launch`/`async` в scope. Подробнее здесь — [корутины](./222.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Kotlin Multiplatform (KMP) — что это и зачем?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Общая бизнес-логика на Kotlin для Android, iOS, desktop и web с платформенным UI. Не заменяет полностью нативные SDK, но сокращает дублирование. Подробнее здесь — [Compose Multiplatform](./224.md), [экосистема](./10.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Ktor или Spring Boot на Kotlin для backend?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Ktor — лёгкий фреймворк JetBrains с корутинами; Spring — стандарт enterprise с огромной экосистемой. Для учебного API начните с [Ktor](./221.md), для корпоративного стека — [Spring Boot на Kotlin](./232.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Как установить Kotlin на Windows и запустить первую программу?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Проще всего через IntelliJ IDEA или Android Studio: JDK + плагин Kotlin, проект Gradle. Консольный `kotlinc` нужен реже. Подробнее здесь — [первая программа](./2.md), [что знать перед Kotlin](./1001.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Jetpack Compose на Kotlin — с чего начать новичку?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> После [основ](./11.md) и [корутин](./222.md) откройте [Compose — первый экран](./229.md), затем [Room + ViewModel](./231.md). Подробнее здесь — [оглавление Android-маршрута](./intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Nullable типы в Kotlin — как избежать NPE?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Тип `String?` явно допускает null; безопасный доступ `?.`, значение по умолчанию `?:`, проверка через `let`. Оператор `!!` — только когда null невозможен по логике. Подробнее здесь — [типы](./12.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Data class в Kotlin — зачем нужен?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Компилятор генерирует `equals`, `hashCode`, `toString`, `copy` и компоненты для деструктуризации — идеально для DTO и моделей. Подробнее здесь — [ООП](./15.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Kotlin Flow — чем отличается от RxJava и LiveData?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Flow — холодный асинхронный поток из корутин-экосистемы; проще интегрируется с `suspend` и structured concurrency. Подробнее здесь — [Flow](./226.md), [корутины](./222.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Как перевести Java-проект на Kotlin постепенно?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> В IntelliJ: Code → Convert Java File to Kotlin File по файлам; новые модули пишите на Kotlin, старые трогайте при правках. Следите за null на границе. Подробнее здесь — [Kotlin ↔ Java](./233.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Сколько времени учить Kotlin до первого Android-приложения?</p>

## Что запомнить

Kotlin — это статически типизированный, мультипарадигменный язык программирования, разработанный компанией JetBrains как современная альтернатива Java. Он полностью совместим с JVM, может компилироваться в JavaScript и нативный код (через Kotlin/Native), а также официально поддерживается Google для разработки Android-приложений.

Основные особенности Kotlin:
- **Полная взаимодействие с Java**: Kotlin-код может вызывать Java-библиотеки и наоборот без дополнительных прослоек;
- **Безопасность от null**: система типов различает nullable и non-nullable типы, что исключает `NullPointerException` на этапе компиляции;
- **Лаконичный и выразительный синтаксис**: меньше шаблонного кода благодаря data-классам, свойствам, расширениям и выводу типов;
- **Поддержка функционального программирования**: лямбды, высшие функции, операторы над коллекциями, `Sequence`;
- **Современные конструкции языка**: делегирование свойств, сопоставление с образцом (`when`), корутины для асинхронности;
- **Мультиплатформенность**: общий код может использоваться на Android, iOS, сервере, десктопе и в браузере через Kotlin Multiplatform.

Области применения Kotlin:
- **Android-разработка** — основной язык для мобильных приложений на платформе Google;
- **Серверная разработка** — Ktor, Spring Boot, Micronaut позволяют создавать высокопроизводительные сервисы;
- **Кроссплатформенные приложения** — общая бизнес-логика между платформами через Kotlin Multiplatform Mobile (KMM);
- **Скрипты и автоматизация** — исполняемые `.kts`-файлы;
- **Встраивание в существующие Java-проекты** — постепенный переход без переписывания всего кода.

Экосистема Kotlin включает:
- **IntelliJ IDEA и Android Studio** — лучшая поддержка IDE "из коробки";
- **Gradle и Maven** — системы сборки с плагинами для Kotlin;
- **Coroutines** — легковесная модель асинхронности без callback hell;
- **Kotlinx-библиотеки** — сериализация, HTML DSL, datetime, test;
- **Dokka** — генератор документации, аналог Javadoc.

Три основных правила эффективной работы с Kotlin:
1. Использовать неизменяемость по умолчанию (`val`, `List`, `data class`);
2. Применять корутины вместо потоков или RxJava для асинхронных задач;
3. Писать идиоматический Kotlin, а не "Java на Kotlin’е" — избегать сеттеров, геттеров, избыточных проверок на null.

Три фундаментальных момента:
- Kotlin — это не просто "лучший Java", а самостоятельный язык с собственной философией;
- Его сила — в безопасности, краткости и плавном внедрении в существующие проекты;
- Знание стандартной библиотеки Kotlin (`kotlin.*`, `kotlinx.*`) критически важно для эффективной разработки.
