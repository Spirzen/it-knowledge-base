## DSL и функции с получателем

**DSL** (предметно-ориентированный язык внутри Kotlin) — это API, который читается как мини-язык конфигурации. Основа: **лямбда с получателем** (`T.() -> Unit`), **extension-функции** и **infix**.

Теория синтаксиса: [синтаксические конструкции](./17.md). Примеры в продакшене: [Ktor Server](./221.md), [Ktor Client](./228.md), Gradle Kotlin DSL.

---

## Лямбда с получателем

Обычная лямбда получает аргумент:

```kotlin
val greet: (String) -> Unit = { name -> println("Hi, $name") }
```

С **receiver** внутри блока доступен `this` типа `T`:

```kotlin
fun buildString(block: StringBuilder.() -> Unit): String {
    val sb = StringBuilder()
    sb.block()
    return sb.toString()
}

val text = buildString {
    append("Hello")
    append(", ")
    append("Kotlin")
}
```

Стандартная библиотека: `buildList`, `buildMap`, `apply`, `run`, `with`.

```kotlin
val config = mutableMapOf<String, Any>().apply {
    put("host", "localhost")
    put("port", 8080)
}
```

## Extension-функция с receiver

```kotlin
class MenuBuilder {
    private val items = mutableListOf<String>()

    fun item(text: String) {
        items += text
    }

    fun build(): List<String> = items.toList()
}

fun menu(block: MenuBuilder.() -> Unit): List<String> =
    MenuBuilder().apply(block).build()

val lunch = menu {
    item("Суп")
    item("Салат")
    item("Чай")
}
```

Вызов `item` внутри `menu { }` выглядит как вложенный язык, хотя это обычные функции класса `MenuBuilder`.

## @DslMarker — защита от путаницы вложенности

Без маркера внутри блока `html { }` можно случайно вызвать функцию из другого DSL. Аннотация ограничивает видимость:

```kotlin
@DslMarker
annotation class HtmlTagMarker

@HtmlTagMarker
abstract class Tag {
    protected val children = mutableListOf<Tag>()
}

@HtmlTagMarker
class Body : Tag() {
    fun p(text: String) { /* ... */ }
}

@HtmlTagMarker
class Html : Tag() {
    fun body(block: Body.() -> Unit) {
        val b = Body()
        b.block()
        children += b
    }
}

fun html(block: Html.() -> Unit): Html = Html().apply(block)
```

Вложенный `body { p("…") }` корректен; вызов «чужого» тега на неверном уровне компилятор отклонит.

## Infix и операторы

```kotlin
infix fun Int.days(unit: String) = "$this $unit"

val period = 7 days "дней"
```

Операторные функции для своих типов:

```kotlin
data class Vec2(val x: Int, val y: Int)

operator fun Vec2.plus(other: Vec2) = Vec2(x + other.x, y + other.y)
```

Не перегружайте `+` семантически чуждыми операциями — иначе DSL теряет читаемость.

## Паттерн: `@Configure` для Ktor-подобного API

```kotlin
class RouteConfig {
    val routes = mutableListOf<Pair<String, () -> Unit>>()

    fun get(path: String, handler: () -> Unit) {
        routes += path to handler
    }
}

fun routing(block: RouteConfig.() -> Unit): RouteConfig =
    RouteConfig().apply(block)

val app = routing {
    get("/health") { println("ok") }
    get("/version") { println("1.0") }
}
```

Реальный Ktor расширяет ту же идею: `routing { get("/") { call.respondText("Hi") } }`.

## Gradle Kotlin DSL

`build.gradle.kts` — тот же приём:

```kotlin
dependencies {
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-core:1.8.1")
}
```

`dependencies { }` — функция с receiver типа `DependencyHandlerScope`.

## Когда не стоит писать свой DSL

| Ситуация | Лучше |
|----------|--------|
| Одноразовая настройка из 3 полей | data class + именованные аргументы |
| DSL только для тестов | `@Test` + обычные функции |
| Команда не знает Kotlin | плоский API или конфиг YAML/JSON |

DSL окупается, когда конфигурация **иерархическая** и **повторяется** (маршруты, UI-дерево, миграции схем).
