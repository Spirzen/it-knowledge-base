## Тестирование на Kotlin

На JVM тесты для Kotlin почти те же, что для Java — тот же байт-код, те же CI-отчёты. Отличие в **синтаксисе** и в моках: классы Kotlin по умолчанию `final`, а корутины — `suspend`.

Эта статья — короткий практический гид:

1. **JUnit 5 + MockK** — самый частый выбор в Android и Ktor.
2. **Kotest** — если хочется «по-котлиновски» (`shouldBe`, BDD-стили).
3. **testApplication** — HTTP-тесты Ktor без реального сетевого порта наружу.

Java-аналог с Mockito и MockMvc: [JUnit 5 в Java](/encyclopedia/5-languages/5-03-java/291.md). Корутины: [222.md](./222.md).

## JUnit 5 + MockK

`build.gradle.kts`:

```kotlin
dependencies {
    testImplementation("org.junit.jupiter:junit-jupiter:5.10.2")
    testImplementation("io.mockk:mockk:1.13.11")
    testImplementation("org.jetbrains.kotlinx:kotlinx-coroutines-test:1.8.1")
}
```

Пример: сервис с **suspend**-репозиторием (как Room или Ktor Client):

```kotlin
import io.mockk.*
import kotlinx.coroutines.test.runTest
import org.junit.jupiter.api.Assertions.assertEquals
import org.junit.jupiter.api.Test

interface UserRepo {
    suspend fun findName(id: Int): String
}

class UserService(private val repo: UserRepo) {
    suspend fun greet(id: Int) = "Hello, ${repo.findName(id)}!"
}

class UserServiceTest {

    private val repo = mockk<UserRepo>()
    private val service = UserService(repo)

    @Test
    fun greet() = runTest {
        coEvery { repo.findName(1) } returns "Ann"
        assertEquals("Hello, Ann!", service.greet(1))
        coVerify { repo.findName(1) }
    }
}
```

**Разбор построчно:**

- `mockk<UserRepo>()` — заглушка интерфейса; Mockito для этого часто требует `open` или inline.
- `runTest { }` — тестовый scope корутин: `delay` и `suspend` выполняются предсказуемо и быстро.
- `coEvery` / `coVerify` — аналог `when`/`verify`, но для **suspend**-методов.
- Обычный `every { }` для suspend **не** подойдёт — будет неочевидная ошибка.

```bash
./gradlew test
```

В IDEA: зелёная стрелка у класса `UserServiceTest` → Run.

## Kotest (кратко)

Kotest — тесты как спецификации на Kotlin:

```kotlin
import io.kotest.core.spec.style.FunSpec
import io.kotest.matchers.shouldBe

class CalculatorSpec : FunSpec({
    test("add") {
        Calculator().add(2, 3) shouldBe 5
    }
})
```

| Стиль | Когда |
|-------|--------|
| `FunSpec` | Простые кейсы |
| `DescribeSpec` / `BehaviorSpec` | BDD: given/when/then |
| `forAll` | Property-based (много случайных входов) |

Kotest можно миксовать с JUnit 5 в одном проекте — выберите один стиль на модуль, чтобы не путать команду.

## Android

Два уровня — не смешивайте в одном «быстром» тесте:

| Папка / зависимость | Где бежит |
|---------------------|-----------|
| `testImplementation` | JVM на компьютере (ViewModel, парсеры) |
| `androidTestImplementation` | Эмулятор или устройство (UI, Room с контекстом) |

Для корутин в ViewModel: `runTest`, `StandardTestDispatcher`, правила `MainDispatcherRule` — подробнее в [231 Room + ViewModel](./231.md).

## Ktor

Интеграционный тест модуля приложения без внешнего сервера:

```kotlin
import io.ktor.client.request.*
import io.ktor.http.*
import io.ktor.server.testing.*
import kotlin.test.Test
import kotlin.test.assertEquals

class HealthTest {
    @Test
    fun health() = testApplication {
        application { module() }  // ваша fun Application.module()
        client.get("/health").apply {
            assertEquals(HttpStatusCode.OK, status)
        }
    }
}
```

Зависимость: `testImplementation("io.ktor:ktor-server-test-host:$ktorVersion")`.

**Разбор:** `testApplication` поднимает движок в памяти; `client.get` — как Postman, но в коде. Удобно после [221 — первая программа Ktor](./221.md).

### Частые ошибки

| Симптом | Причина |
|---------|---------|
| `no answer found for suspend` | Нужен `coEvery`, не `every` |
| Тест висит | Нет `runTest` / забыт `advanceUntilIdle` |
| MockK не мокает класс | Класс не `open` и не interface — мокайте интерфейс |
| Ktor 404 в тесте | Не подключён `module()` или другой routing |
