## Spring Boot на Kotlin — первая программа

На JVM **Spring Boot** — популярный каркас для веб-сервисов, безопасности, работы с БД и облаком. **Kotlin** в Spring — полноценный язык: те же стартеры, что в Java, плюс `data class`, null-safety и короче контроллеры.

| Стек | Когда выбирать |
|------|----------------|
| [Ktor](./221.md) | Kotlin-native, явные маршруты, лёгкий старт |
| **Spring Boot + Kotlin** | Команда на Spring, нужны Security, Data JPA, Spring Cloud |

Java-версия сценария: [271.md](/encyclopedia/5-languages/5-03-java/271). Обзор Spring: [27.md](/encyclopedia/5-languages/5-03-java/27).

**Перед стартом:** [первая программа на Kotlin](./2.md).

## Словарь терминов

| Термин | Простыми словами |
|--------|------------------|
| **Spring** | Контейнер, который создаёт объекты (бины) и связывает зависимости. |
| **Spring Boot** | Spring + автоконфигурация + встроенный Tomcat — быстрый старт. |
| **Стартер** | Готовый набор зависимостей (`spring-boot-starter-web`). |
| **`@RestController`** | Класс с HTTP-методами, ответ — JSON. |
| **`@Service`** | Слой бизнес-логики. |
| **Dependency Injection** | Spring передаёт `HelloService` в конструктор контроллера. |

## Проект (Gradle Kotlin DSL)

[start.spring.io](https://start.spring.io): **Kotlin**, **Gradle**, **Spring Web**, Java **17**.



<ExternalCodeEmbed example="kotlin/kotlin-509-232-001" title="Проект (Gradle Kotlin DSL)" minHeight={336} />



Разбор:
- `org.springframework.boot` подключает задачи запуска и упаковки Spring-приложения.
- `io.spring.dependency-management` выравнивает версии зависимостей экосистемы Spring.
- `kotlin("plugin.spring")` автоматически открывает нужные классы для прокси/AOP.
- `toolchain` фиксирует Java 17 как стандарт сборки для всех разработчиков и CI.
- `spring-boot-starter-web` приносит MVC, Jackson и встроенный HTTP-сервер.

`kotlin("plugin.spring")` делает классы с аннотациями Spring **открытыми** для прокси — вручную писать `open` на каждый класс не нужно.

## Точка входа

```kotlin
package com.example.demo

import org.springframework.boot.autoconfigure.SpringBootApplication
import org.springframework.boot.runApplication

@SpringBootApplication
class DemoApplication

fun main(args: Array<String>) {
    runApplication<DemoApplication>(*args)
}
```

| Элемент | Смысл |
|---------|--------|
| `@SpringBootApplication` | Включить сканирование компонентов и автоконфигурацию. |
| `runApplication<DemoApplication>(*args)` | Kotlin-обёртка над `SpringApplication.run`. |
| `*args` | Распаковка массива аргументов в vararg. |

## Модель и сервис

```kotlin
data class HelloResponse(val message: String)

@Service
class HelloService {
    fun greet(name: String?): HelloResponse {
        val who = name?.trim().takeUnless { it.isNullOrEmpty() } ?: "мир"
        return HelloResponse("Привет, $who!")
    }
}
```

**Разбор `greet`:**

1. `name?.trim()` — если `name == null`, всё выражение `null`.
2. `takeUnless { it.isNullOrEmpty() }` — отбросить пустую строку после trim.
3. `?: "мир"` — значение по умолчанию.
4. `data class` — Jackson (JSON) сериализует поле `message` автоматически.

## Контроллер

```kotlin
@RestController
@RequestMapping("/api")
class HelloController(private val service: HelloService) {

    @GetMapping("/hello")
    fun hello(@RequestParam(required = false) name: String?): HelloResponse =
        service.greet(name)
}
```

| Аннотация | Роль |
|-----------|------|
| `@RestController` | Ответы методов → тело HTTP (JSON). |
| `@RequestMapping("/api")` | Префикс для всех методов класса. |
| `@GetMapping("/hello")` | Обработчик GET `/api/hello`. |
| `@RequestParam` | Параметр из query: `?name=Анна`. |
| Конструктор `HelloService` | **Constructor injection** — рекомендуемый стиль Spring. |

Сравнение с Ktor: в [221.md](./221.md) маршруты в блоке `routing { get(...) }`; в Spring — аннотации на методах.

## Запуск и проверка

```bash
./gradlew bootRun
curl -s "http://localhost:8080/api/hello?name=Анна"
```

Разбор:
- `./gradlew bootRun` запускает сервис через Gradle Wrapper без ручной сборки артефакта.
- Spring Boot по умолчанию поднимает HTTP-сервер на `localhost:8080`.
- `curl -s` отправляет запрос и печатает только ответ, без лишнего служебного вывода.
- Query-параметр `name=Анна` проверяет цепочку от контроллера до бизнес-метода.

В IDEA: Run `DemoApplicationKt`.

## Структура проекта для роста

Даже на первом сервисе полезно сразу разделить код по слоям:

| Пакет | Содержимое |
|-------|------------|
| `controller` | HTTP-эндпоинты и валидация входа |
| `service` | бизнес-правила |
| `repository` | доступ к БД и внешним системам |
| `dto` | модели запросов и ответов |
| `config` | настройки Spring, фильтры, бины |

Так проще вводить тесты, безопасность и мониторинг без крупного рефакторинга.

## HTTP-ошибки и единый формат ответа

Добавьте обработчик исключений, чтобы клиент всегда получал понятный JSON:

```kotlin
data class ErrorResponse(val code: String, val message: String)

@RestControllerAdvice
class GlobalExceptionHandler {
    @ExceptionHandler(IllegalArgumentException::class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    fun badRequest(e: IllegalArgumentException): ErrorResponse =
        ErrorResponse(code = "BAD_REQUEST", message = e.message ?: "Некорректный запрос")
}
```

Разбор:
- `@RestControllerAdvice` включает глобальную обработку исключений для REST-контроллеров.
- `@ExceptionHandler(...)` связывает тип ошибки с конкретным обработчиком ответа.
- `@ResponseStatus(HttpStatus.BAD_REQUEST)` фиксирует HTTP-код 400 для таких случаев.
- `ErrorResponse` задаёт единый JSON-формат ошибки для всех клиентов API.

Так API становится предсказуемым для frontend и мобильных клиентов.

## Конфигурация через `application.yml`

```yaml
server:
  port: 8080
spring:
  application:
    name: kotlin-demo
```

Разбор:
- `server.port` задаёт порт, на котором слушает встроенный сервер Spring Boot.
- `spring.application.name` определяет имя сервиса в логах и инфраструктурных инструментах.
- YAML-иерархия автоматически маппится на конфигурационные свойства Spring.
- Базовый файл удобно дополнять profile-настройками для dev и prod окружений.

Профили (`application-dev.yml`, `application-prod.yml`) помогают держать разные параметры для локальной разработки и продакшена.

## Тест контроллера



<ExternalCodeEmbed example="kotlin/kotlin-509-232-002" title="Тест контроллера" minHeight={336} />



Разбор:
- `@WebMvcTest` поднимает только web-слой, поэтому тесты выполняются быстрее полного контекста.
- `@MockBean` подменяет сервис и изолирует проверку поведения контроллера.
- `mockMvc.get(...)` имитирует HTTP-вызов без реального сетевого сокета.
- `andExpect` фиксирует API-контракт: ожидаемый статус и точное поле в JSON.

Тесты на уровне HTTP особенно полезны, если команда постепенно мигрирует с Java на Kotlin.

- Java-классы вызываются из Kotlin без обёрток.

## Дополнительный сниппет — POST с телом запроса

```kotlin
data class CreateUserRequest(val name: String)
data class UserResponse(val id: Long, val name: String)

@RestController
@RequestMapping("/api/users")
class UserController {
    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    fun create(@RequestBody req: CreateUserRequest): UserResponse {
        return UserResponse(id = 1L, name = req.name.trim())
    }
}
```

Разбор:
- `@PostMapping` связывает метод с HTTP POST-запросом на `/api/users`.
- `@RequestBody` просит Spring десериализовать JSON-тело в Kotlin `data class`.
- `@ResponseStatus(HttpStatus.CREATED)` выставляет код `201`, корректный для создания ресурса.
- Возврат `UserResponse` автоматически сериализуется в JSON через Jackson.
- Разделение `Request` и `Response` моделей делает API-контракт явным и устойчивым к изменениям.

### Частые ошибки

| Симптом | Причина |
|---------|---------|
| `Invalid bean definition` | Класс `final` без `plugin.spring` |
| 404 | Неверный `@RequestMapping` или порт |
| Кракозябры в JSON | UTF-8: `server.servlet.encoding.charset=UTF-8` в `application.properties` |
