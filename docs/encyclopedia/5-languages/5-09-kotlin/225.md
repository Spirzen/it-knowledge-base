## Коллекции и Sequence

#### Сводка операций по типам

**`MutableList`**:

| Действие | Метод |
|----------|--------|
| Добавить в конец | `add(value)` |
| Вставить по индексу | `add(index, value)` |
| Прочитать | `get(index)`, `[index]` |
| Заменить | `set(index, value)`, `[index] = value` |
| Удалить по индексу | `removeAt(index)` |

**`MutableMap`**:

| Действие | Метод |
|----------|--------|
| Добавить или заменить | `put(key, value)`, `[key] = value` |
| Прочитать | `get(key)`, `[key]` |
| Удалить | `remove(key)` |

**`MutableSet`**:

| Действие | Метод |
|----------|--------|
| Добавить | `add(value)` |
| Удалить | `remove(value)` |
| Проверить наличие | `contains(value)` |

Неизменяемые `listOf` / `mapOf` / `setOf` — те же операции чтения; изменение даёт новую коллекцию (`+`, `buildList`, копия в `mutable*`).

Стандартная библиотека Kotlin делит коллекции на **изменяемые** (`mutableListOf`, `mutableMapOf`) и **неизменяемые** (`listOf`, `mapOf`). Поверх `Iterable` есть **Sequence** — ленивая цепочка, где промежуточные шаги не материализуются, пока не вызван терминальный оператор.

Справочник функций: [встроенные функции](./162.md). Типы и объявления: [типы данных](./12.md).

## Когда что использовать

| Задача | Подход |
|--------|--------|
| Данные уже в памяти, цепочка из 2–3 шагов | `list.filter { }.map { }` |
| Большой файл, построчная обработка | `File(...).useLines { lines -> lines.asSequence()... }` |
| Несколько `filter`/`map` подряд на тысячах элементов | `.asSequence()` до `toList()` / `count()` |
| Нужен результат сразу и один проход | обычный `Iterable` |
| Побочные эффекты в цепочке | явный цикл или `forEach`, не «забытый» `map` |

**Правило:** `Sequence` окупается, когда цепочка длинная или источник ленивый (строки файла, генератор). Для коротких списков из десятков элементов разница незаметна, а код с `asSequence()` иногда только усложняет чтение.

## Неизменяемость и копии

```kotlin
val base = listOf(1, 2, 3)
val extended = base + 4           // новый List, base не меняется
val mutable = base.toMutableList()
mutable.add(4)                    // меняется только mutable
```

Операторы `+` и `-` для коллекций создают **новый** экземпляр. Это удобно для иммутабельного стиля, но на больших структурах даёт лишние аллокации — тогда лучше один `buildList { }` или `Sequence`.

```kotlin
val ids = buildList {
    addAll(source)
    add(newId)
}
```

## Sequence: ленивая цепочка

```kotlin
val result = (1..1_000_000)
    .asSequence()
    .filter { it % 2 == 0 }
    .map { it * it }
    .take(10)
    .toList()
```

Пока не вызван `toList()`, `count()`, `first()`, `reduce` и т.п., элементы не проходят всю цепочку целиком: обрабатывается по одному значению за шаг.

Чтение большого лога без загрузки всего файла в `List`:

```kotlin
import java.io.File

fun topErrors(path: String, limit: Int): List<String> =
    File(path).useLines { lines ->
        lines.asSequence()
            .filter { "ERROR" in it }
            .take(limit)
            .toList()
    }
```

## Общие операции

И `List`, и `Sequence` поддерживают одни и те же имена: `map`, `filter`, `flatMap`, `groupBy`, `distinct`, `sorted`, `fold`, `reduce`. Отличие — **момент выполнения**:

- у `List` каждый шаг строит новую коллекцию (eager);
- у `Sequence` шаги связаны итератором (lazy).

```kotlin
// Eager: три прохода по данным, три промежуточных списка
val names = users
    .filter { it.isActive }
    .map { it.name }
    .sorted()

// Lazy: один проход при toList()
val namesLazy = users.asSequence()
    .filter { it.isActive }
    .map { it.name }
    .sorted()
    .toList()
```

## Группировка и ассоциативные коллекции

```kotlin
data class Order(val region: String, val amount: Int)

val byRegion = orders.groupBy { it.region }
val totalByRegion = orders.groupingBy { it.region }
    .fold(0) { acc, order -> acc + order.amount }

val index = users.associateBy { it.id }
val pairs = listOf("a" to 1, "b" to 2).toMap()
```

`groupingBy` удобен, когда нужна агрегация без промежуточного `Map` списков.

## Типичные ошибки

1. **Вызвать терминальный оператор дважды на одном `Sequence`** — после `toList()` исходная последовательность исчерпана; создайте новую или сохраните результат.
2. **Держать открытый файл за пределами `useLines`** — sequence привязан к потоку; обрабатывайте внутри блока `useLines`.
3. **Путать `List` и `Array`** — `IntArray` не поддерживает `filter` из stdlib без `asList()` / цикла; для примитивов иногда выгоднее обычный `for`.
4. **Мутировать коллекцию во время итерации** — `ConcurrentModificationException`; копируйте или используйте индексы с конца.
