## Первая программа на Gin

### Где применяют Gin

**HTTP** — протокол, по которому браузер и мобильное приложение обращаются к серверу: метод (`GET`, `POST`, `DELETE`), URL (`/api/notes`), заголовки и тело (часто JSON).

**REST API** — набор URL + методов для работы с ресурсами (заметки, пользователи) без HTML-страниц. Клиент шлёт JSON, сервер отвечает JSON и кодом статуса (`200`, `201`, `404`).

**Gin** — популярный фреймворк поверх стандартного пакета Go **`net/http`**. Он упрощает маршруты, разбор JSON, группы URL и **middleware** (цепочка функций "до и после" handler).

Обзор Gin, Echo, Fiber: [Фреймворки и библиотеки Go](./19.md). Соседние туториалы: [Echo](./2413.md) · [Fiber](./2414.md). Тесты handlers: [Тестирование в Go](./192.md). Чистый `net/http`: [Пример микросервиса](./241.md).

---

### Что получится

Мини-сервис "Заметки" на порту **8080**: health-check, список заметок, создание и удаление. Данные в памяти (слайс), защита от гонок через **`sync.Mutex`**.

---

## Термины

| Термин | Простыми словами |
|--------|------------------|
| **Маршрут (route)** | Связка "метод + путь" → функция-обработчик |
| **Handler** | Функция, которая читает запрос и пишет ответ |
| **`gin.Context`** | Всё про текущий запрос: параметры URL, тело, ответ |
| **Middleware** | Прослойка: лог, recovery от паники, авторизация |
| **JSON-тег** | `json:"text"` — имя поля в JSON |
| **`binding`** | Правила проверки тела запроса (обязательное поле, длина) |
| **`:id` в пути** | Параметр, например `/notes/5` → `id = "5"` |

## REST API "Заметки"

Полный `main.go`:

```go
package main

import (
    "net/http"
    "strconv"
    "sync"

    "github.com/gin-gonic/gin"
)

type Note struct {
    ID   int    `json:"id"`
    Text string `json:"text" binding:"required,min=1,max=500"`
}

var (
    notes  []Note
    nextID = 1
    mu     sync.Mutex
)

func main() {
    r := gin.Default()

    r.GET("/health", func(c *gin.Context) {
        c.JSON(http.StatusOK, gin.H{"status": "ok"})
    })

    api := r.Group("/api")
    {
        api.GET("/notes", listNotes)
        api.POST("/notes", createNote)
        api.DELETE("/notes/:id", deleteNote)
    }

    r.Run(":8080")
}
```

---

### Структура `Note` и теги

```go
type Note struct {
    ID   int    `json:"id"`
    Text string `json:"text" binding:"required,min=1,max=500"`
}
```

- **`json:"id"`** — при `c.JSON` поле уйдёт в JSON как `"id"`, не `ID`.
- **`binding:"required,min=1,max=500"`** — при `ShouldBindJSON` Gin проверит: поле есть, длина текста от 1 до 500 символов.

---

### Память и mutex

```go
var (
    notes  []Note
    nextID = 1
    mu     sync.Mutex
)
```

Несколько HTTP-запросов обрабатываются **параллельно**. Без блокировки два `POST` могут одновременно менять `notes` и `nextID` — **гонка данных**. `mu.Lock()` / `defer mu.Unlock()` в handler гарантируют, что в один момент времени список меняет только одна горутина.

---

### `main` — маршруты и группа

| Строка | Смысл |
|--------|--------|
| `gin.Default()` | Роутер + встроенные middleware Logger и Recovery |
| `r.GET("/health", ...)` | GET → JSON `{"status":"ok"}` |
| `r.Group("/api")` | Префикс: реальные пути `/api/notes`, не `/notes` |
| `api.DELETE("/notes/:id", ...)` | `:id` — сегмент URL, читается через `c.Param("id")` |
| `r.Run(":8080")` | Слушает `http://127.0.0.1:8080` |

`gin.H{"status": "ok"}` — сокращение для `map[string]interface{}`.

---

### Handlers — разбор

**Список:**

```go
func listNotes(c *gin.Context) {
    mu.Lock()
    defer mu.Unlock()
    c.JSON(http.StatusOK, notes)
}
```

`defer mu.Unlock()` — разблокировка при выходе из функции, даже если позже добавите `return` с ошибкой.

**Создание:**

```go
func createNote(c *gin.Context) {
    var body Note
    if err := c.ShouldBindJSON(&body); err != nil {
        c.JSON(http.StatusBadRequest, gin.H{"error": err.Error()})
        return
    }
    mu.Lock()
    body.ID = nextID
    nextID++
    notes = append(notes, body)
    mu.Unlock()
    c.JSON(http.StatusCreated, body)
}
```

- `ShouldBindJSON(&body)` — читает тело запроса в struct и применяет `binding`-теги.
- При ошибке — `400 Bad Request` и **обязательный `return`**, иначе код пойдёт дальше с пустым телом.
- `201 Created` — стандартный код "ресурс создан".

**Удаление:**

```go
func deleteNote(c *gin.Context) {
    id, err := strconv.Atoi(c.Param("id"))
    // ...
    notes = append(notes[:i], notes[i+1:]...)
    c.Status(http.StatusNoContent)
}
```

`strconv.Atoi` — строка `"5"` → число `5`. Удаление из слайса: два `append` "вырезают" элемент по индексу. `204 No Content` — успех без тела ответа.

Запуск:

```bash
go run .
```

## Проверка через curl

```bash
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/api/notes
curl -X POST http://127.0.0.1:8080/api/notes \
  -H "Content-Type: application/json" \
  -d '{"text":"Изучить Gin"}'
curl -X DELETE http://127.0.0.1:8080/api/notes/1
```

| Команда | Что проверяет |
|---------|----------------|
| Первая | Сервер жив (`200`, JSON status) |
| Вторая | Пустой или текущий список заметок |
| POST | Создание; заголовок `Content-Type` нужен для JSON |
| DELETE | Удаление заметки с `id=1` |

В PowerShell кавычки в `-d` иногда экранируют иначе — удобно использовать одинарные снаружи для JSON.

## Свой middleware

**Middleware** в Gin — функция, возвращающая `gin.HandlerFunc`. Обычно вызывают `c.Next()` — передать управление следующему звену цепочки.

```go
func requestLogger() gin.HandlerFunc {
    return func(c *gin.Context) {
        c.Next()
        // после всех handler — статус уже известен:
        // c.Writer.Status(), c.Request.Method, c.Request.URL.Path
    }
}

// r.Use(requestLogger())
```

`gin.Default()` уже подключает лог запросов и **Recovery** (перехват паники, чтобы сервер не падал целиком).

## Graceful shutdown

При остановке процесса (Ctrl+C, деплой) обрывать активные запросы резко плохо. **Graceful shutdown** — дать handler’ам до N секунд завершиться.

```go
import (
    "context"
    "net/http"
    "os"
    "os/signal"
    "syscall"
    "time"
)

srv := &http.Server{Addr: ":8080", Handler: r}
go func() { _ = srv.ListenAndServe() }()

quit := make(chan os.Signal, 1)
signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
<-quit

ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
_ = srv.Shutdown(ctx)
```

| Часть | Смысл |
|-------|--------|
| `http.Server{Handler: r}` | Gin-роутер совместим с `http.Handler` |
| `signal.Notify` | Ожидание SIGINT/SIGTERM |
| `Shutdown(ctx)` | Прекращает приём новых соединений, ждёт текущие |

---

### Частые ошибки

| Симптом | Причина |
|---------|---------|
| `404` на POST | Неверный метод или путь без префикса `/api` |
| `bind` не заполняет struct | Нет `json:"..."` или неверный `Content-Type` |
| Паника в handler | Ошибка после `ShouldBindJSON` без `return` |
| Пустой список после двух POST | Гонка без `mutex` (в учебнике mutex есть — проверьте копии кода) |
