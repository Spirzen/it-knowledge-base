## FAQ — Часто задаваемые вопросы

Типичные сбои и ситуации, с которыми сталкиваются новички после раздела. Здесь — **что делать и где копать в главах**; определения для зачёта — в [чек-листе](./999.md).

<div class="faq-list">

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `go run main.go` пишет "package command-line-arguments is not a main package".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> В каталоге должен быть `package main` и функция `func main()`. Запускайте из корня модуля с `go.mod` или укажите пакет: `go run .`. Подробнее здесь — [первая программа](./24.md), [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Импортировал пакет, а компилятор: "imported and not used".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> В Go неиспользуемый импорт — ошибка. Удалите импорт или используйте идентификатор (временно `_` только если понимаете зачем). Подробнее здесь — [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Объявил `s := make([]int, 0)` и через `append` получаю странные индексы — slice "режет" не тот массив.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Срезы делят общий backing array; `append` может переаллоцировать, а вложенный slice после `[:n]` останется ссылаться на старый буфер. Копируйте явно `append([]T(nil), s...)`. Подробнее здесь — [основы](./11.md), [синтаксис](./14.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `panic: assignment to entry in nil map` при первом `m["key"] = 1`.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Нулевая map не готова к записи — нужен `make(map[K]V)` или литерал `map[K]V{}`. Чтение из nil map безопасно и вернёт zero value. Подробнее здесь — [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Цикл `for i, v := range slice` — внутри горутины все `v` одинаковые.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> До Go 1.22 переменная цикла переиспользовалась; передавайте копию: `v := v` внутри тела или параметр в `go func(v T)`. Подробнее здесь — [синтаксис и конкурентность](./14.md), [паттерны](./16.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Запустил тысячу `go func(){...}()` — процесс съел всю память.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Горутины дешёвые, но не бесплатны при бесконтрольном spawn. Ограничивайте worker pool, используйте семафор или пул через канал. Подробнее здесь — [паттерны](./16.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Программа зависла на отправке в канал — deadlock.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Небуферизованный канал блокирует, пока нет получателя; закрытый канал при отправке паникует. Проверьте пару send/receive, `select` и кто закрывает канал. Подробнее здесь — [синтаксис и конкурентность](./14.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `go mod tidy` не находит модуль с GitHub — timeout или 404.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Проверьте путь модуля, тег версии, `GOPROXY` и доступ к сети. Для приватных репозиториев настройте `GOPRIVATE` и git credentials. Подробнее здесь — [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Ошибка `cannot find package` в подпапке без go.mod.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> С Go Modules код живёт внутри модуля с `go.mod`; импортный путь должен совпадать с `module` + каталог. Выполните `go mod init` в корне проекта. Подробнее здесь — [первая программа](./24.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> HTTP-handler паникует, а клиент видит обрыв соединения без JSON-ошибки.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> В Go нет исключений — паника в handler роняет процесс, если нет `recover` в middleware. Возвращайте `error` из логики и мапьте в статус-код. Подробнее здесь — [веб на stdlib](./25.md), [Gin](./2412.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `json.Unmarshal` заполнил поля нулями, хотя JSON правильный.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Поля struct должны быть экспортируемы (с заглавной буквы) и совпадать по `json:"name"`. Вложенные объекты требуют вложенных struct. Подробнее здесь — [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Сравниваю два `[]byte` через `==` — компилятор не даёт.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Срезы сравнивают через `bytes.Equal` или цикл; `==` только для массивов фиксированной длины. Подробнее здесь — [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Метод с pointer receiver не вызывается у value — "cannot call pointer method".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Если метод с `*T`, у value типа `T` Go возьмёт адрес, но не наоборот для всех случаев с interface. Согласуйте receivers в типе. Подробнее здесь — [синтаксис](./14.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Интерфейс `nil`, но `err != nil` всё равно true.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Интерфейс хранит тип и значение: конкретный nil-pointer внутри non-nil interface даёт "загадочный" nil. Возвращайте явный `nil` error без typed nil. Подробнее здесь — [синтаксис](./14.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `defer` изменил переменную не так, как ожидал в цикле.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Аргументы `defer` вычисляются в момент регистрации, выполнение — при выходе из функции. В цикле передавайте копии в `defer f(x)`. Подробнее здесь — [синтаксис](./14.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Тест `go test` падает только на CI, локально зелёный.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Частые причины — гонки (`-race`), другая версия Go, зависимость от порядка выполнения тестов или таймингов. Запустите `go test -race ./...`. Подробнее здесь — [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `gofmt` переставил импорты — это "ломает" стиль команды?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Единый `gofmt`/`goimports` — норма в Go-сообществе; споры о форматировании не ведут. Настройте format on save в IDE. Подробнее здесь — [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Gin возвращает 404, хотя маршрут в коде есть.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Проверьте метод HTTP, trailing slash, группу роутов и порядок middleware. `NoRoute` перехватывает только несовпавшие пути. Подробнее здесь — [Gin](./2412.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> gRPC клиент: "connection refused" при localhost.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Сервер должен слушать тот же порт и протокол; для TLS — совпадение credentials. Сгенерированный код из `.proto` должен совпадать с версией на сервере. Подробнее здесь — [gRPC](./32.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Дженерик-функция: "type X does not satisfy constraint".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Ограничение (`constraints.Ordered`, свой interface) должно выполняться всеми type arguments. Упростите constraint или добавьте методы в тип. Подробнее здесь — [дженерики](./31.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Профилировщик pprof показывает пустой CPU profile.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Нужна нагрузка во время сбора и импорт `_ "net/http/pprof"` с HTTP endpoint или правильный `go test -cpuprofile`. Подробнее здесь — [профилирование](./35.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> WebSocket отключается через минуту за прокси.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Настройте ping/pong, таймауты и заголовки Upgrade на балансировщике. Подробнее здесь — [WebSocket](./34.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Cobra: подкоманда не видит флаг из root.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Флаги привязаны к конкретной `Command`; пробросьте PersistentFlags или определите флаг на родителе. Подробнее здесь — [CLI cobra/viper](./33.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Путаю `:=` и `=` — "no new variables on left side of :=". </p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `:=` объявляет хотя бы одну новую переменную в блоке; для присваивания уже объявленным используйте `=`. В package level только `var`. Подробнее здесь — [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Пришёл из Java/Python и жду исключений try/catch.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Идиома Go — возвращать `(T, error)` и проверять `if err != nil`. `panic` оставьте для невосстановимых сбоев. Подробнее здесь — [синтаксис](./14.md), [паттерны](./16.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Собрал бинарник на Windows, на Linux "Exec format error".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Нужна кросс-компиляция: `GOOS=linux GOARCH=amd64 go build`. Обычный build таргетит текущую ОС. Подробнее здесь — [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Не знаю, с чего начать в разделе — сразу Kubernetes или Gin?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Сначала [первая программа](./24.md) и [основы](./11.md), затем один углублённый трек из [оглавления](./intro): stdlib HTTP, Gin или CLI. Инфраструктурные проекты на Go приходят после понимания модулей и ошибок.</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Go или Golang — как правильно называется язык?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Официально язык называется Go; "Golang" — неформальное имя (в т.ч. домен golang.org). В документации и вакансиях встречаются оба варианта. Подробнее здесь — [о разделе](./intro), [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Как установить Go на Windows 10/11 и проверить установку?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Скачайте MSI с go.dev, добавьте `GOROOT`/`PATH`, выполните `go version`. Первый проект — `go mod init` и `go run`. Подробнее здесь — [первая программа](./24.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Go vs Python для backend — что выбрать?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Go даёт один статический бинарник, быстрый старт и встроенную конкурентность; Python — богатая ML/скриптовая экосистема. Для микросервисов и DevOps-утилит Go часто предпочтительнее. Подробнее здесь — [о разделе](./intro), [Gin](./2412.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Go vs Java — в чём разница для новичка?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Go проще синтаксис, нет JVM и исключений, зато нет generics-истории до 1.18 и меньше enterprise-фреймворков "из коробки". Подробнее здесь — [основы](./11.md), [синтаксис](./14.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Что такое goroutine простыми словами?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Легковесный поток выполнения, запускаемый через `go f()`; планировщик Go мультиплексирует их на OS-потоках. Обмен данными — через каналы. Подробнее здесь — [синтаксис и конкурентность](./14.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Как написать REST API на Go с нуля?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Начните с `net/http` в [веб на stdlib](./25.md), затем фреймворк [Gin](./2412.md) и контракты из [REST обзора](./24.md). Подробнее здесь — [маршрут в intro](./intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> go mod init — зачем нужен go.mod?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Файл объявляет имя модуля и версию Go; зависимости фиксируются в `go.sum`. Заменяет старый GOPATH для проектов. Подробнее здесь — [первая программа](./24.md), [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Сколько учить Go до первой работы junior?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> При базе программирования 1–2 месяца на синтаксис, модули, HTTP и тесты плюс пет-проект. Конкурентность и прод-паттерны — дольше. Подробнее здесь — [оглавление](./intro), [чек-лист](./999.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Kubernetes написан на Go — нужно ли учить Go DevOps-инженеру?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Для кастомных операторов, CLI и контрибуций — да; для базового kubectl/Helm достаточно YAML и концепций оркестрации. Go полезен для утилит. Подробнее здесь — [о разделе](./intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Обработка ошибок в Go без try catch — как правильно?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Идиома `if err != nil { return err }`; оборачивание через `%w` и `errors.Is`/`As`. Подробнее здесь — [синтаксис](./14.md), [паттерны](./16.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Slice и array в Go — в чём разница?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Array фиксированной длины; slice — дескриптор над массивом с `len` и `cap`. В API чаще slice. Подробнее здесь — [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Gin framework Go tutorial на русском — где начать?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> В разделе: [Gin](./2412.md) после [основ](./11.md) и [первой программы](./24.md). Подробнее здесь — [оглавление](./intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> gRPC на Go — как поднять сервис?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Опишите `.proto`, сгенерируйте код, реализуйте сервер и клиент на `google.golang.org/grpc`. Подробнее здесь — [gRPC](./32.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Дженерики в Go 1.18 — нужны ли начинающему?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> После базы типов и интерфейсов; для алгоритмов на `[]T` и map удобны type parameters. Подробнее здесь — [дженерики](./31.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> go test — как писать unit-тесты в Go?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Файл `*_test.go`, функции `TestXxx(t *testing.T)`, запуск `go test ./...`. Табличные тесты — идиома сообщества. Подробнее здесь — [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Профилирование Go приложения pprof — с чего начать?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> CPU и heap profile через `net/http/pprof` или `go test -cpuprofile`. Подробнее здесь — [профилирование](./35.md).</p>

## Что запомнить

Go (или Golang) — это компилируемый, статически типизированный язык программирования, разработанный в Google для создания надёжных, эффективных и масштабируемых систем. Он сочетает простоту синтаксиса, высокую производительность и встроенную поддержку конкурентности, что делает его популярным выбором для бэкенд-разработки, микросервисов, CLI-инструментов и облачной инфраструктуры.

Основные особенности Go:
- **Минималистичный синтаксис**: отсутствие наследования, исключений, перегрузки функций, шаблонов — всё ради простоты и предсказуемости;
- **Строгая статическая типизация** с выводом типа через `:=`;
- **Сборка мусора**: автоматическое управление памятью без ручного освобождения;
- **Встроенная конкурентность**: горутины и каналы как основные примитивы параллелизма;
- **Быстрая компиляция**: проекты собираются за секунды даже при большом объёме кода;
- **Единый исполняемый файл**: результат компиляции не требует внешних зависимостей;
- **Отличная стандартная библиотека**: HTTP-сервер, JSON, шифрование, тестирование, маршрутизация — всё "из коробки";
- **Поддержка кросскомпиляции**: сборка под любую ОС и архитектуру без дополнительных инструментов.
- **Дженерики (Go 1.18+)**: type parameters и constraints — [отдельная статья](./31.md).
- **gRPC и CLI**: protobuf-сервисы ([32.md](./32.md)), cobra/viper ([33.md](./33.md)).
- **Профилирование**: pprof, trace, fuzz — [35.md](./35.md).
- **WebSocket и observability**: [34.md](./34.md), Prometheus в [25.md](./25.md).

Области применения Go:
- **Веб-сервисы и API**: благодаря встроенному HTTP-стеку и фреймворкам (Gin, Echo, Fiber);
- **Микросервисы и облачные приложения**: Kubernetes, Docker, Prometheus, Terraform — все написаны на Go;
- **Инструменты DevOps и CLI-утилиты**: лёгкость развёртывания и отсутствие зависимостей;
- **Высоконагруженные системы**: обработка тысяч запросов в секунду с низкой задержкой;
- **Сетевые приложения**: TCP/UDP-серверы, прокси, брокеры сообщений.

Экосистема Go включает:
- **go toolchain**: компилятор, менеджер пакетов, тестовый фреймворк, профилировщик;
- **Go Modules**: система управления зависимостями, встроенная с версии 1.11;
- **gofmt**: форматирование кода по единому стандарту без обсуждений;
- **vet**, **lint**, **staticcheck**: инструменты анализа качества кода;
- **Delve**: мощный дебаггер для Go-приложений.

Три основных правила эффективной работы с Go:
1. Следовать идиоматическому стилю: использовать `errors` вместо исключений, избегать глобальных переменных, предпочитать композицию наследованию;
2. Писать тестируемый код: каждая функция должна покрываться unit-тестами (`*_test.go`);
3. Не усложнять: если решение выглядит громоздко, вероятно, оно нарушает дух языка.

Три фундаментальных момента:
- Go — это язык, где простота важнее выразительности;
- Его сила — в консистентности, скорости разработки и надёжности в продакшене;
- Знание модели конкурентности (goroutines + channels) критически важно для раскрытия потенциала языка.
