## Тестирование в Go

**Автотест** — программа, которая проверяет другую программу: вызывает функцию с известными входами и сравнивает результат с ожидаемым. Если результат другой — тест **проваливается**, и CI (сборка в GitHub Actions, GitLab и т.д.) помечает коммит как сломанный.

В Go тесты — часть экосистемы: отдельный пакет **`testing`** в стандартной библиотеке, команда **`go test`**, именование файлов `*_test.go`. Сторонний фреймворк для «простого unit-теста» обычно не нужен; для удобных проверок часто подключают **`testify`**, для HTTP — **`net/http/httptest`**.

Идиоматичный стиль в Go — **table-driven tests**: один тест-функция, таблица кейсов в слайсе, цикл с `t.Run` для каждой строки.

База: [Первая программа на Go](./24.md) · [Справочник по Go](./3.md) · [Фреймворки](./19.md) · HTTP: [Gin](./2412.md).

## Термины

| Термин | Простыми словами |
|--------|------------------|
| **Unit-тест** | Проверка одной функции или маленького модуля изолированно |
| **Пакет (`package`)** | Папка с Go-кодом; тесты лежат в том же пакете, что и код |
| **`testing.T`** | Объект «текущий тест»: сюда пишут ошибки (`Errorf`) и подтесты (`Run`) |
| **`got` / `want`** | Фактический результат и ожидаемый (принятые имена в сообщениях) |
| **Покрытие (coverage)** | Доля строк кода, которую хотя бы раз выполнили тесты |
| **Benchmark** | Замер скорости: сколько раз в секунду вызывается функция |
| **Fake / mock** | Подмена зависимости: fake — простая ручная реализация; mock — часто генерируемый |

## Именование и запуск

### Правила имён

- Файл: **`имя_test.go`** рядом с кодом, например `greeting.go` и `greeting_test.go`.
- Функция теста: **`Test` + заглавная буква + суффикс**, например `TestHello`, `TestAdd`.
- Пакет в тесте обычно **тот же**, что у кода (`package greeting`), чтобы видеть неэкспортируемые функции.

### Первый тест — построчно

```go
package greeting

import "testing"

func TestHello(t *testing.T) {
    got := Hello("Go")
    want := "Hello, Go!"
    if got != want {
        t.Errorf("Hello() = %q, want %q", got, want)
    }
}
```

| Строка | Смысл |
|--------|--------|
| `func TestHello(t *testing.T)` | Go находит все `Test*` и запускает их через `go test` |
| `got := Hello("Go")` | Вызываем тестируемую функцию |
| `want := "Hello, Go!"` | Ожидаемый ответ — задаём явно |
| `if got != want` | Сравнение; при несовпадении тест должен упасть |
| `t.Errorf(...)` | Сообщение об ошибке; `%q` печатает строку в кавычках |

Тест **не возвращает** `error` — он сообщает о провале через `t.Error` / `t.Fatal` (последний сразу останавливает тест).

### Команды

```bash
go test ./...              # все пакеты в дереве каталогов
go test -v ./pkg/greeting  # -v — подробный вывод (имена тестов)
go test -cover ./...       # процент покрытия по пакетам
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out   # HTML-отчёт в браузере
```

`./...` — идиома Go: «все пакеты от текущей папки вниз».

## Table-driven tests

Идея: **данные отделены от логики**. Добавить новый кейс — одна строка в таблице, без копирования всего тела теста.

```go
func TestAdd(t *testing.T) {
    tests := []struct {
        name string
        a, b int
        want int
    }{
        {"zeros", 0, 0, 0},
        {"positive", 2, 3, 5},
        {"negative", -1, 1, 0},
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            if got := Add(tt.a, tt.b); got != tt.want {
                t.Errorf("got %d, want %d", got, tt.want)
            }
        })
    }
}
```

**Разбор:**

- `[]struct { ... }` — анонимный тип «строка таблицы»: имя кейса, входы, ожидание.
- `for _, tt := range tests` — `_` пропускает индекс; `tt` — одна строка.
- `t.Run(tt.name, func(t *testing.T) { ... })` — **подтест** с именем `zeros`, `positive`… В отчёте и в IDE видно, какая строка упала.
- `if got := Add(...); got != tt.want` — короткое объявление `got` прямо в условии.

Такой стиль рекомендуют в [официальной документации](https://go.dev/wiki/TableDrivenTests) и в коде стандартной библиотеки.

## testify — удобные проверки

Пакет **`github.com/stretchr/testify`** не заменяет `testing`, а добавляет читаемые assert-функции.

```bash
go get github.com/stretchr/testify
```

```go
import (
    "testing"
    "github.com/stretchr/testify/assert"
    "github.com/stretchr/testify/require"
)

func TestHelloAssert(t *testing.T) {
    assert.Equal(t, "Hi, Ann", Hello("Ann"))
    require.NotEmpty(t, Hello("x"))
}
```

| Функция | Поведение |
|---------|-----------|
| `assert.Equal` | При провале — ошибка в лог, **тест идёт дальше** |
| `require.NotEmpty` | При провале — **сразу стоп** теста (как `t.Fatal`) |

Используйте `require`, когда дальнейшие строки бессмысленны без успешной проверки (например, после создания временного файла).

Другие полезные вызовы: `assert.NoError`, `assert.Len`, `assert.Contains` — меньше шаблонного `if err != nil`.

## HTTP handler — httptest

**Handler** — функция, которая принимает запрос и пишет ответ. Тестировать «живой» сервер на порту 8080 не обязательно: пакет **`httptest`** даёт фейковый запрос и запись ответа в память.

```go
func TestHealthHandler(t *testing.T) {
    req := httptest.NewRequest(http.MethodGet, "/health", nil)
    rec := httptest.NewRecorder()

    HealthHandler(rec, req)

    assert.Equal(t, http.StatusOK, rec.Code)
    assert.Contains(t, rec.Body.String(), "ok")
}
```

| Часть | Назначение |
|-------|------------|
| `NewRequest` | Имитация GET `/health` без сети |
| `NewRecorder` | «Буфер» ответа: код статуса, заголовки, тело |
| `HealthHandler(rec, req)` | Вызов handler как в `net/http` |
| `rec.Code` | HTTP-код, например `200` |
| `rec.Body.String()` | Тело ответа текстом |

Для [Gin](./2412.md) маршрутизатор сам пишет в recorder:

```go
router := gin.New()
router.GET("/health", healthHandler)
router.ServeHTTP(rec, req)
```

Так тестируют маршруты и middleware без `go run` и без `curl`.

## Моки через интерфейсы

Go **не генерирует моки в языке**. Паттерн: зависимость описывают **интерфейсом**, в тесте подставляют **fake** — простую структуру с нужным поведением.

```go
type UserStore interface {
    Save(name string) error
}

type fakeStore struct {
    saved []string
}

func (f *fakeStore) Save(name string) error {
    f.saved = append(f.saved, name)
    return nil
}

func TestService_Register(t *testing.T) {
    store := &fakeStore{}
    svc := NewService(store)
    require.NoError(t, svc.Register("Ann"))
    assert.Equal(t, []string{"Ann"}, store.saved)
}
```

**Логика для новичка:**

1. `NewService(store)` принимает `UserStore` — любую реализацию.
2. В продакшене — реальная БД; в тесте — `fakeStore`, который только запоминает имена в слайс.
3. Проверяем: сервис вызвал `Save` с `"Ann"` и не вернул ошибку.

Для больших проектов генерируют моки: **`mockgen`** (gomock), **`moq`**. На старте достаточно ручного fake.

## Benchmark (замер скорости)

Имя функции: **`Benchmark` + имя**, аргумент `*testing.B`.

```go
func BenchmarkHello(b *testing.B) {
    for i := 0; i < b.N; i++ {
        Hello("bench")
    }
}
```

`b.N` подбирает `go test` так, чтобы замер был стабильным. Запуск:

```bash
go test -bench=. -benchmem ./...
```

`-benchmem` — аллокации памяти на итерацию (полезно при оптимизации).

## Примеры и гонки

**Пример (`Example*`)** — код в документации, который тоже проверяется `go test`:

```go
func ExampleHello() {
    fmt.Println(Hello("World"))
    // Output: Hello, World!
}
```

Комментарий `// Output:` — ожидаемый stdout; несовпадение = провал теста.

**Детектор гонок** — флаг `-race` при `go test`: ловит одновременную запись в одну переменную из разных горутин без синхронизации. Обязателен для кода с `go` и `mutex`.

## CI (непрерывная интеграция)

Минимальный шаг в GitHub Actions:

```yaml
- uses: actions/setup-go@v5
  with:
    go-version: '1.22'
- run: go test -race -coverprofile=coverage.out ./...
```

| Флаг | Зачем |
|------|--------|
| `-race` | Гонки данных в многопоточном коде |
| `-coverprofile=...` | Артефакт покрытия для отчётов или порогов в CI |

Порог «не ниже 80% coverage» задают политикой команды; сам по себе процент не гарантирует качество тестов.

### Частые ошибки

| Симптом | Причина |
|---------|---------|
| `no test files` | Файл не `*_test.go` или функция не `TestXxx` |
| Тест в другом пакете не видит `hello` | Нужен `package greeting_test` и импорт пакета — отдельная тема для black-box тестов |
| Падает только на CI | Разный часовой пояс, пути, отсутствие `-race` локально |
| `httptest` пустое тело | Handler не вызван или не тот метод/URL |
