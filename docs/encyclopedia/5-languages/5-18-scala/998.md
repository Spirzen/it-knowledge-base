## FAQ — Часто задаваемые вопросы

Типичные сбои и ситуации, с которыми сталкиваются новички после раздела. Здесь — **что делать и где копать в главах**.

<div class="faq-list">

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `scala-cli run` падает с "Unsupported class file major version" — JDK вроде установлен.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Версия <strong>JDK должна быть не ниже</strong>, чем требует Scala (для Scala 3 — JDK 17+). Проверьте `java -version` и `JAVA_HOME`; sbt/scala-cli могут подхватить другую Java из PATH. Подробнее здесь — [первая программа](./7.md), [архитектура JVM](./3.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Первый запуск sbt качает полинтернета — это нормально?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> sbt тянет <strong>Scala, zinc, зависимости</strong> в локальный кэш (`~/.ivy2`, `~/.sbt`). Последующие сборки быстрее; для учебных скриптов проще `scala-cli`. Подробнее здесь — [первая программа](./7.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> "Could not find an implicit value for ExecutionContext" при `Future`.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `Future` требует неявный <strong>ExecutionContext</strong> в области видимости (`import scala.concurrent.ExecutionContext.Implicits.global` или свой пул). Без него компилятор не знает, где выполнять callback. Подробнее здесь — [архитектура JVM](./3.md), [функции](./6.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `option.get` бросил `NoSuchElementException` — Option же "безопасный".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `get` на `None` — <strong>намеренно аварийный</strong>. Используйте `getOrElse`, `fold`, pattern matching или `match`. Подробнее здесь — [типы и match](./4.md), [приложения](./103.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Перепутал `val` и `var` — объект "меняется", хотя объявил val.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `val` запрещает <strong>переприсвоение ссылки</strong>; mutable-коллекция внутри всё ещё меняется. Для неизменяемого состояния — `immutable.Seq`, обновление через `:+` / `updated`. Подробнее здесь — [основы](./2.md), [типы](./4.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Java-библиотека вернула null — NPE в Scala-коде.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> На границе JVM оборачивайте в <strong>`Option(...)`</strong> или используйте `@Nullable` аннотации и сразу `Option`. Scala 3 улучшает null-safety, но Java interop остаётся зоной риска. Подробнее здесь — [архитектура JVM](./3.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `case class` vs обычный `class` — когда что?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `case class` даёт <strong>equals/hashCode, copy, unapply</strong> для pattern matching — идеален для DTO и ADT. Обычный class — для инкапсуляции, наследования, mutable state. Подробнее здесь — [типы и match](./4.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Компилятор: "match may not be exhaustive" — вроде все case покрыты.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Для <strong>sealed hierarchy</strong> нужны все подтипы; для `String`/`Int` — default `_`. Включите `-Xfatal-warnings` на учебном проекте. Подробнее здесь — [типы и match](./4.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> For-comprehension выглядит как цикл, а внутри Option/Future — как читать?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Это синтаксический сахар над <strong>`flatMap`/`map`</strong>: каждый `<-` — шаг, который может "оборваться" (None/ failed Future). Перепишите for в `.flatMap` для понимания. Подробнее здесь — [функции](./6.md), [приложения](./103.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Создал `Future { ... }`, но код внутри не выполняется.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `Future` ленив до первого callback и нужен <strong>ExecutionContext</strong>; в `main` программа может завершиться раньше. Используйте `Await.result` в учебных примерах или `scala-cli` с `@main` и явным ожиданием. Подробнее здесь — [архитектура](./3.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Новичку советуют Akka/Play — стоит ли начинать с них?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Сначала <strong>язык и stdlib</strong>: [основы](./2.md), [типы](./4.md), [приложения](./103.md). Akka/Spark — после понимания JVM, Future и неизменяемости. Подробнее здесь — [оглавление](./intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Tutorial на Scala 2, а у меня Scala 3 — `object App`, `_` для wildcard.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Scala 3: <strong>`@main` вместо App</strong>, `_` в типах заменён на `?`, новый синтаксис indent. Смотрите [официальный migration guide](https://docs.scala-lang.org/scala3/guides/migration/compatibility.html) и статьи раздела с пометкой Scala 3. Подробнее здесь — [история](./1.md), [первая программа](./7.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `@main def run()` не находится как точка входа в sbt.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> В sbt укажите <strong>`Compile / run / mainClass`</strong> или используйте `scala-cli run file.scala`. Для sbt-проекта иногда проще `object Main extends App` (2.x) или явный `mainMethod` в build.sbt. Подробнее здесь — [первая программа](./7.md), [приложения](./103.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> "Type inference failed" на простом `val xs = List(1,2,3).map(...)".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Компилятор не сузил <strong>общий тип</strong> (часто из-за смешения `Int`/`Double` или polymorphic map). Добавьте явный тип `val xs: List[Int] = ...` или `.map((x: Int) => ...)`. Подробнее здесь — [типы](./4.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Как "обновить" элемент в immutable `List`?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Создаётся <strong>новая структура</strong>: `list.updated(i, v)` или `list.patch`. Для частых обновлений по ключу — `Map` или `Vector`. Подробнее здесь — [основы](./2.md), [типы](./4.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Маленький скрипт на scala-cli жрёт много RAM — JVM так устроена?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> JVM стартует с <strong>heap по умолчанию</strong>; для CLI можно `-Xmx256m`. Для одноразовых утилит scala-cli нормален; для продакшена настраивают GC и limits. Подробнее здесь — [архитектура JVM](./3.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `Either` — Left это ошибка или успех? Путаю каждый раз.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Конвенция Scala: <strong>`Left` — ошибка, `Right` — успех</strong> (Right = "правильный"). В своём API зафиксируйте тип `Either[String, A]` и придерживайтесь. Подробнее здесь — [типы](./4.md), [приложения](./103.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Строка `s"$name age"` vs `f"$pi%.2f"` — когда f-string?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `s` — <strong>интерполяция</strong>; `f` — форматирование как `printf`. Для логов и UI чаще `s`; для чисел с точностью — `f`. Подробнее здесь — [основы](./2.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Несколько trait с одинаковым методом — откуда берётся реализация?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Сработает <strong>linearization (C3)</strong> — порядок mixin в объявлении class. При конфликте нужен явный `super` или override. Подробнее здесь — [основы ООП в Scala](./2.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `lazy val` в многопоточке инициализировался дважды — возможно?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `lazy val` по spec <strong>thread-safe при первой инициализации</strong>; гонки возможны, если внутри side effects. Для тяжёлой инициализации используйте `lazy val` осознанно или explicit lock. Подробнее здесь — [архитектура](./3.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Рекурсия без `@tailrec` — StackOverflowError на большом n.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> JVM не оптимизирует хвост без аннотации <strong>`@tailrec`</strong> (и truly tail call). Перепишите на цикл или fold; компилятор предупредит, если tailrec невозможен. Подробнее здесь — [функции](./6.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `Source.fromFile` — файл не закрывается, дескriptor leak.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Оборачивайте в <strong>`Using.resource(Source.fromFile(...)) { ... }`</strong> или `scala.util.Using`. Подробнее здесь — [приложения](./103.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Implicit conversion "магически" превращает Int в RichInt — это ещё актуально?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> В Scala 3 <strong>implicit conversions</strong> ограничены; предпочитайте extension methods и given instances. Старые туториалы с `implicit def` читайте с осторожностью. Подробнее здесь — [история](./1.md), [функции](./6.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> HTTP-сервер из [приложений](./103.md) не отвечает с другого компьютера в сети.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `InetSocketAddress(8080)` слушает <strong>все интерфейсы</strong>, но firewall может блокировать. Проверьте URL, bind address и что процесс жив. Подробнее здесь — [приложения](./103.md), [HTTP в энциклопедии](/encyclopedia/2-system-network/2-09-osnovy-integratsionnogo-vzaimodeystviya/118).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Пришёл из Java — Scala кажется "Java с лишним синтаксисом".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Выигрыш — в <strong>композиции и типах</strong>: `Option`, `match`, for-comprehension, case class. Пишите новый код в functional style, Java interop подключайте точечно. Подробнее здесь — [основы](./2.md), [Java](/encyclopedia/5-languages/5-03-java/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> uPickle/Jason decode падает на поле — как отладить JSON-модель?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Сверьте <strong>имена полей case class</strong> с JSON (camelCase vs snake), defaults для optional. В circe — `decodeAccumulating` для списка ошибок. Подробнее здесь — [приложения](./103.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Куда двигаться после консольных примеров — Spark, Akka или Android?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Зависит от цели: <strong>данные — Spark</strong> ([архитектура](./3.md)); concurrent services — Akka/Pekko; Android — Kotlin чаще, Scala возможен. База раздела одинакова. Подробнее здесь — [оглавление](./intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Scala с нуля — как начать учить язык на JVM?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> JDK 17+, <strong>scala-cli или sbt</strong>, первая программа с `@main`. Маршрут — [первая программа](./7.md) → [основы](./2.md). Подробнее здесь — [оглавление](./intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Scala 3 vs Scala 2 — что учить новичку в 2025?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Раздел ориентирован на <strong>Scala 3</strong>: `@main`, given/using, улучшенный match. Старый код 2.x читается с migration guide. Подробнее здесь — [история](./1.md), [первая программа](./7.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Scala или Java — что выбрать для backend?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Java — <strong>максимум вакансий и фреймворков</strong>; Scala — FP, Spark, Akka, выразительные типы. Оба на JVM, interop прямой. Подробнее здесь — [основы](./2.md), [Java](/encyclopedia/5-languages/5-03-java/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Scala или Kotlin — в чём разница?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Kotlin — <strong>прагматичный JVM для Android/backend</strong>; Scala — глубже FP, case class/match, for-comprehension, Spark. Подробнее здесь — [оглавление](./intro), [Kotlin](/encyclopedia/5-languages/5-09-kotlin/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Как установить Scala на Windows — scala-cli vs sbt?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Скачайте <strong>Coursier/scala-cli</strong> или sbt; нужен JDK 17+. Проверка: `scala --version`. Подробнее здесь — [первая программа](./7.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Apache Spark Scala tutorial — нужен ли Scala для Spark?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Spark API есть на <strong>Scala, Java, Python</strong>; Scala — "родной" DSL и типы для data pipeline. Сначала основы языка, потом [архитектура JVM](./3.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> case class Scala example — зачем нужен?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Immutable data + <strong>copy, equals, unapply</strong> для pattern matching одной строкой. DTO и ADT в idiomatic Scala. Подробнее здесь — [типы и match](./4.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Pattern matching Scala — как разобрать Option?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> <strong>`x match { case Some(v) => ...; case None => ... }`</strong> — исчерпывающие ветки. Предпочтительнее `.get`. Подробнее здесь — [типы и match](./4.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> for comprehension Scala Option Future — что это?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Синтаксический сахар над <strong>flatMap/map</strong> для цепочек шагов с коротким замыканием при None/failed Future. Подробнее здесь — [функции](./6.md), [приложения](./103.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> implicit vs given Scala 3 — что изменилось?</p>

</div>

<div class="faq-item">

</div>

## Что запомнить

Scala — **мультипарадигмальный** язык на JVM (и Scala.js/Native) — функциональный стиль (`map`, `Option`, immutability) с ООП и мощной системой типов. В разделе ориентир — **Scala 3**.

Основные особенности:
- **`val`/`var`, case class, pattern matching** — модель данных;
- **For-comprehension** — работа с `Option`, `Future`, коллекциями;
- **JVM interop** — Java-библиотеки и null на границе;
- **Инструменты** — sbt, scala-cli, Metals IDE.

Области — бэкенд (Akka/Pekko), big data (Spark), DSL и библиотеки (Cats, ZIO — за рамками базового курса).

Три правила:
1. Предпочитайте **immutable** API и явные типы ошибок (`Option`/`Either`);
2. На границе с Java **оборачивайте null**;
3. Осваивайте **язык до фреймворка** — Play/Akka после [приложений](./103.md).
