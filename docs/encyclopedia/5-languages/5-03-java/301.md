## Шпаргалка — десять вопросов, которые встречаются чаще всего

| Вопрос | Суть ответа (30 секунд) | Где углубиться |
|--------|-------------------------|----------------|
| JVM, JDK, JRE? | **JDK** — компилятор и инструменты; **JRE** — среда только для запуска (устарело как отдельная поставка); **JVM** — виртуальная машина, исполняет bytecode | [Основы](./1.md), [JVM](./23.md) |
| `==` и `equals`? | `==` сравнивает ссылки (для объектов) или значения (примитивы); `equals` — логическое равенство, переопределяют вместе с `hashCode` | [ООП](./18.md), [Строки](./296.md) |
| `ArrayList` или `LinkedList`? | `ArrayList` — быстрый доступ по индексу O(1), медленная вставка в середину; `LinkedList` — вставка O(1) при известном узле, медленный random access | [Коллекции](./24.md) |
| checked и unchecked? | **Checked** — обязаны обработать или `throws` (`IOException`); **unchecked** — наследники `RuntimeException`, компилятор не заставляет | [Исключения](./21.md) |
| `final`? | Константа ссылки (объект можно менять внутри, если поля не final), запрет наследования класса / переопределения метода | [ООП](./18.md), [Ключевые слова в Java](./141.md) |
| Поток: `start()` или `run()`? | `start()` — JVM создаёт новый поток и вызывает `run()`; прямой `run()` — обычный вызов метода в текущем потоке | [JVM и потоки](./23.md) |
| `synchronized` и `volatile`? | `synchronized` — взаимное исключение + видимость; `volatile` — видимость без блокировки, без атомарности `i++` | [JVM, память и потоки](./23.md), [Асинхронность в Java](./298.md) |
| immutable? | Объект, состояние которого после создания не меняется; `String`, правильно спроектированный record / final-поля | [Типы](./15.md), [Современные конструкции Java](./300.md) |
| interface и abstract class? | Интерфейс — контракт, множественное наследование типов; abstract — частичная реализация, поля состояния, один родитель-класс | [ООП](./18.md) |
| Stream API? | Декларативные операции над коллекциями: промежуточные (filter, map) ленивые, терминальные (collect) запускают цепочку | [Stream API в Java](./295.md) |

## Шаблон ответа, который нравится интервьюеру

Для большинства вопросов по Core Java отлично работает структура из трёх шагов:

1. Короткое определение термина.
2. Мини-пример из практики или 2-3 строки кода.
3. Ограничение, типичная ошибка или компромисс.

Пример для "чем `HashMap` отличается от `TreeMap`":

- `HashMap` даёт быстрый доступ по хешу без сортировки ключей;
- `TreeMap` хранит ключи в отсортированном виде;
- если нужен упорядоченный вывод, берут `TreeMap`, если важнее скорость и порядок не нужен, чаще выбирают `HashMap`.

## Что часто недоговаривают кандидаты

| Вопрос | Частая недосказанность | Что стоит добавить |
|---|---|---|
| `equals` и `hashCode` | Говорят только про `equals` | Уточнить контракт: равные объекты обязаны иметь одинаковый hash |
| `volatile` | Описывают как "ускоряет" | Пояснить, что это про видимость, не про атомарность |
| `ArrayList` vs `LinkedList` | Только Big-O из учебника | Добавить, что cache locality у `ArrayList` часто даёт выигрыш в реальном CPU |
| Checked / unchecked | Только определения | Добавить, где на практике используют runtime-исключения |

## Мини-блок "кодом, а не словами"

Если просят объяснить тему, короткий фрагмент кода обычно сильно усиливает ответ:

```java
Map<String, Integer> map = new HashMap<>();
map.put("A", 1);
map.put("A", 2); // ключ тот же, значение заменилось
System.out.println(map.get("A")); // 2
```

По этому примеру легко и уверенно объяснить:
- ключи в `Map` уникальны;
- повторный `put` перезаписывает значение;
- поведение связано с `equals` и `hashCode`.
