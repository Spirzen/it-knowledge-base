## Jenkins Pipeline — первый Jenkinsfile

**Jenkins** — сервер CI/CD. **Pipeline** описывается на **Groovy** в файле `Jenkinsfile` в корне репозитория — тот же язык, что в [Gradle DSL](./11.md), с другим API Jenkins.

Эта статья — **declarative** pipeline (рекомендуемый стиль): этапы `stage`, агент `agent`, блоки `post`.

Groovy в pipeline: [основы § Jenkins](./11.md) · тесты: [Spock](./21.md) · Java-сборка: [Maven](/encyclopedia/5-languages/5-03-java/12).

---

### Jenkinsfile - pipeline as code вместо freestyle job

| Freestyle job в UI | Pipeline as Code |
|------------------|------------------|
| Настройка в браузере | `Jenkinsfile` в Git, ревью в PR |
| Сложно воспроизвести | Одинаково на ветках |

---

### Что получится

При push Jenkins: клонирует репозиторий → `./gradlew test` (или `mvn test`) → публикует статус. Ниже — минимальный шаблон под JVM-проект.

---

## Минимальный Jenkinsfile

Положите в **корень** репозитория:

```groovy
pipeline {
    agent any

    options {
        timestamps()
        timeout(time: 20, unit: 'MINUTES')
    }

    stages {
        stage('Checkout') {
            steps {
                checkout scm
            }
        }

        stage('Build & Test') {
            steps {
                sh './gradlew test --no-daemon'
            }
        }
    }

    post {
        always {
            junit '**/build/test-results/test/*.xml'
        }
        success {
            echo 'Сборка успешна'
        }
        failure {
            echo 'Сборка упала — смотрите лог stage'
        }
    }
}
```

**Разбор:**

- `agent any` — любой доступный агент (узел Jenkins с JDK/Gradle).
- `checkout scm` — Git из настроек multibranch pipeline.
- `sh` — shell на Linux-агенте; на Windows: `bat './gradlew.bat test'`.
- `junit` — подхватывает XML от Gradle/Maven для графика тестов.

Для **Maven** замените stage:

```groovy
sh 'mvn -B test'
// junit: '**/target/surefire-reports/*.xml'
```

---

## Подключение в Jenkins

1. **New Item** → **Pipeline** (или Multibranch Pipeline).
2. **Pipeline script from SCM** → Git → URL репозитория.
3. **Script Path:** `Jenkinsfile`.
4. Сохранить → **Build Now**.

При Multibranch Pipeline Jenkins сам находит `Jenkinsfile` на каждой ветке.

---

## Credentials (кратко)

Секреты не хранят в `Jenkinsfile` в открытом виде:

```groovy
environment {
    DOCKER_TOKEN = credentials('docker-hub-token-id')
}
```

В Jenkins: **Manage Jenkins → Credentials** → добавить Secret text / Username+password → id совпадает с `credentials('...')`.

## Declarative и scripted

| Declarative | Scripted (`node { }`) |
|-------------|-------------------------|
| Структура `pipeline { stages { } }` | Произвольный Groovy |
| Проще читать новичкам | Гибче, сложнее |

Для старта — **declarative**; при необходимости внутри `script { }` вставляют Groovy-код.

---

### Частые ошибки

| Симптом | Причина |
|---------|---------|
| `gradlew: not found` | Нет wrapper в репо — закоммитьте `gradlew` |
| JDK не та версия | Tool JDK в Jenkins Global Tool Configuration |
| `checkout` пустой | Не настроен SCM в job |
| Тесты зелёные, job красный | Неверный путь в `junit` |

### Что попробовать

1. Stage `Docker build` после тестов (если есть Dockerfile).
2. Параллельные stages: `parallel { stage('Unit'){...} stage('Lint'){...} }`.
3. [Spock](./21.md)-тесты в том же `./gradlew test`.
