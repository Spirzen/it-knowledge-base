## FAQ — Часто задаваемые вопросы

Типичные сбои и ситуации, с которыми сталкиваются новички после раздела. Здесь — **что делать и где копать в главах**; определения для зачёта — в [чек-листе](./999.md).

<div class="faq-list">

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> В Java `str1 == str2` сравнивает ссылки, в Groovy в скрипте "работает по-другому".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> В Groovy `==` вызывает `equals` для объектов; для идентичности ссылок — `is`. Смешение стилей в одном файле — частый источник багов. Подробнее здесь — [Groovy и Java](./20.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `groovy hello.groovy` — "unable to access jarfile" или Groovy не найден.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Установите SDKMAN/Groovy distribution или запускайте через Gradle `groovy` task; проверьте `groovy -v` и JAVA_HOME. Подробнее здесь — [первая программа](./2.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> В Jenkinsfile красное подчёркивание, но pipeline на сервере работает.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> IDE не всегда знает CPS DSL Jenkins; ориентируйтесь на Declarative/Scripted синтаксис из документации и [Jenkins Pipeline](./22.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `MissingPropertyException: No such property: implementation` в Gradle.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Строка `implementation` — метод делегата dependencies block, а не переменная; скрипт должен выполняться в контексте Gradle, не как голый `.groovy`. Подробнее здесь — [Gradle DSL](./23.md), [основы — делегирование](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Добавил зависимость в `build.gradle`, Sync прошёл, импорт в Java всё ещё красный.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Обновите Gradle project в IDE, проверьте configuration (`implementation` vs `api`) и что модуль тот же. Подробнее здесь — [Gradle DSL](./23.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> GString `"Value: $obj"` вызвал NPE, хотя `obj` был не null в отладчике.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Интерполяция вызывает `toString`; если поле внутри null, упадёт при сборке строки. Используйте `?.` или Elvis. Подробнее здесь — [Groovy и Java](./20.md), [типы](./12.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Забыл `def` — переменная "исчезла" между строками скрипта.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Без `def` имя может уйти в binding script как property; в методах класса нужны типы или `def` для локальных. Подробнее здесь — [первая программа](./2.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `@CompileStatic` включил — половина динамических фич перестала работать.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Статическая компиляция отключает часть MetaClass-магии; типизируйте явно или оставьте dynamic участок без `@CompileStatic`. Подробнее здесь — [особенности](./16.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Вызвал Java-метод из Groovy — "unable to resolve class".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Проверьте import, classpath модуля и что Java-класс скомпилирован. Groovy видит те же JAR, что и Java-модуль. Подробнее здесь — [Groovy и Java](./20.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Spock: тест падает с "Too few invocations" на mock.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Уточните `then:` блок, количество вызовов и аргументы; interaction testing в Spock строже, чем ручные stub. Подробнее здесь — [Spock](./21.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `where:` таблица в Spock — странные типы в параметрах.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Колонки должны совпадать по порядку с параметрами метода; используйте `@Unroll` для читаемых имён. Подробнее здесь — [Spock](./21.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Closure передали в Java — получил `groovy.lang.Closure` и Java не компилируется.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Java не знает замыкания Groovy; на границе используйте SAM interface, `Runnable` или вызывайте Groovy только из Groovy-слоя. Подробнее здесь — [Groovy и Java](./20.md), [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `list*.id` вернул список с null — элементы были?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Spread-оператор вызывает свойство/метод на каждом элементе; null в списке даёт null в результате. Подробнее здесь — [операторы](./13.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `1..10` включил 10, а `1..&lt;10` — нет: off-by-one в цикле.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Диапазоны в Groovy бывают inclusive и exclusive на правом конце; сверьтесь с задачей. Подробнее здесь — [циклы](./14.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Пытаюсь учить Groovy без Java — Gradle непонятен с первого дня.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Минимум JVM и Java ([первая программа Java](/encyclopedia/5-languages/5-03-java/13)) сильно ускоряет вход; Groovy в проде почти всегда рядом с Java/Kotlin. Подробнее здесь — [что знать перед Groovy](./1001.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `metaClass` добавил метод — в unit-тесте Java его нет.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Runtime MetaClass действует в том же Groovy-рантайме; чистый JUnit без Groovy rule не увидит расширение. Подробнее здесь — [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> AST transformation не сработала — аннотация есть, кода нет.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Проверьте подключение transform в compile classpath, порядок компиляции и совместимость с `@CompileStatic`. Подробнее здесь — [конструкции](./18.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> В Grails контроллер "магически" находит view — не могу найти файл.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Соглашения имен `views/controller/action.gsp`; при кастомном имени укажите render явно. Grails — legacy-ветка, см. [конструкции и фреймворки](./18.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Grape в скрипте скачал JAR, но corporate proxy режет загрузку.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Настройте Maven settings.xml с proxy или перенесите зависимости в Gradle/Maven проект. Подробнее здесь — [конструкции](./18.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Jenkins: "Scripts not permitted to use method X" — sandbox.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Админ должен одобрить signature в Script Approval или переписать шаг на approved plugin. Подробнее здесь — [Jenkins Pipeline](./22.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Путаю `collect` и `collectMany` — вложенный список вместо плоского.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `collect` сохраняет один элемент на вход; `collectMany`/`flatten` сглаживают. Подробнее здесь — [типы](./12.md), [циклы](./14.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> В Kotlin DSL `build.gradle.kts` — старый Groovy `build.gradle` не читается.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Синтаксис другой, идеи те же: plugins, dependencies, tasks. Для legacy Android-репозиториев Groovy DSL всё ещё встречается — см. [Gradle Groovy DSL](./23.md) и [Kotlin DSL](/encyclopedia/5-languages/5-09-kotlin/230).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `as` cast упал с `ClassCastException` на JSON map.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `as` жёстко приводит тип; для Map из JsonSlurper используйте типизированный DTO или `as Type`. Подробнее здесь — [типы](./12.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Скрипт `.groovy` в CI выполняется, локально — другая версия Groovy.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Зафиксируйте версию в Gradle wrapper, Docker-образе Jenkins agent или `sdkman`. Подробнее здесь — [первая программа](./2.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Хочу писать всё приложение на Groovy в 2025 — стоит ли?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Для нового продукта чаще выбирают Java/Kotlin; Groovy остаётся силён в сборке, тестах и скриптах. Оцените задачу по [оглавлению](./intro), не по моде.</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `println` в Gradle build выводит тысячи строк при каждом Sync.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Логика в `build.gradle` выполняется на конфигурационной фазе; выносите в task `doLast` или используйте `--info` точечно. Подробнее здесь — [Gradle DSL](./23.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Category класс перестал работать после рефакторинга пакетов.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `@Category` нужно применять в scope `use(XXX) { }`; постоянные расширения — через `metaClass` или extension module. Подробнее здесь — [ООП](./15.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Что такое Groovy язык простыми словами?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Динамический язык на JVM с синтаксисом, близким к Java, для скриптов, Gradle, тестов Spock и Jenkins Pipeline. Подробнее здесь — [о разделе](./intro), [история](./1.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Groovy vs Java — в чём разница?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Groovy короче, динамичнее, с замыканиями и DSL; Java — строже типы и основной язык enterprise. Подробнее здесь — [Groovy и Java](./20.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Как читать build.gradle на Groovy — учебник для новичка?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Начните с [Gradle Groovy DSL](./23.md) и [делегирования замыканий](./11.md) — так понятны блоки `dependencies { }`. Подробнее здесь — [маршрут intro](./intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Gradle Kotlin DSL или Groovy DSL — что учить?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Новые проекты часто на `.kts`; legacy Android и старые репо — Groovy. Для чтения чужих скриптов Groovy всё ещё нужен. Подробнее здесь — [Gradle DSL](./23.md), [Kotlin DSL](/encyclopedia/5-languages/5-09-kotlin/230).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Spock framework tutorial — тесты на Groovy?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Spock пишут на Groovy поверх JUnit; given/when/then и data tables. Подробнее здесь — [Spock](./21.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Jenkinsfile Groovy pipeline пример — где разобрать синтаксис?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Declarative и Scripted pipeline в [Jenkins Pipeline](./22.md); база Groovy — [основы](./11.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Нужно ли учить Groovy Android-разработчику?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Достаточно читать `build.gradle` и типовые задачи; писать приложение на Groovy не обязательно. Подробнее здесь — [Gradle DSL](./23.md), [intro](./intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Groovy установка Windows — как запустить скрипт?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> SDKMAN, дистрибутив Apache Groovy или Gradle wrapper; `groovy script.groovy` при настроенном JAVA_HOME. Подробнее здесь — [первая программа](./2.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> GString интерполяция Groovy — как вставить переменную в строку?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Двойные кавычки: `"Hello, $name"` или `"${user.name}"`; одинарные — без интерполяции. Подробнее здесь — [Groovy и Java](./20.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Groovy safe navigation ?. — аналог optional?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `obj?.field` вернёт null, если `obj` null; вместе с Elvis `?:` для значения по умолчанию. Подробнее здесь — [типы](./12.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> @CompileStatic Groovy — зачем включать?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Проверка типов на этапе компиляции и скорость ближе к Java; для прод-кода вне скриптов. Подробнее здесь — [особенности](./16.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Grails framework — жив ли в 2025?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Нишевый и legacy; новый веб на JVM чаще Spring Boot/Ktor. Grails — в [конструкции и фреймворки](./18.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Groovy closure delegate owner — что это для Gradle?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Делегирование замыканий направляет вызовы `implementation` в объект DependencyHandler. Подробнее здесь — [основы](./11.md), [Gradle DSL](./23.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Вызов Java из Groovy и наоборот — как?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Groovy видит Java-классы напрямую; из Java Groovy-классы с явными сигнатурами. Динамика из Java сложнее. Подробнее здесь — [Groovy и Java](./20.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Сколько учить Groovy если уже знаю Java?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Базовый синтаксис и Gradle — 1–2 недели; Spock/Jenkins — по задаче. Подробнее здесь — [Groovy и Java](./20.md), [чек-лист](./999.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Groovy collect findAll each — шпаргалка?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `each` — обход, `collect` — map, `findAll` — filter; в [справочнике](./3.md) и [циклах](./14.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> JsonSlurper Groovy parse JSON — пример?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `new JsonSlurper().parseText(json)` или `parse(file)`; результат — Map/List. Подробнее здесь — [типы](./12.md), [конструкции](./18.md).</p>
</div>

<div class="faq-item">

  <p class="faq-a"><span class="faq-label">Ответ.</span> Читаемые спецификации, таблицы данных, моки без бойлерплейта JUnit. Подробнее здесь — [Spock](./21.md).</p>
</div>

<div class="faq-item">

  <p class="faq-a"><span class="faq-label">Ответ.</span> Структурированный курс — этот раздел: [intro](./intro), [справочник](./3.md). Англ. docs — groovy-lang.org.</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Groovy скрипт без class — как устроен?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Компилятор оборачивает код в Script subclass; binding хранит переменные. Подробнее здесь — [первая программа](./2.md).</p>
</div>

## Что запомнить

Groovy — динамический объектно-ориентированный язык для JVM с синтаксисом, близким к Java. Большая часть Java-кода компилируется как Groovy без изменений, но есть отличия (`==`, `in`, `as`, перегрузка `[]`, ключевые слова Groovy). Классы Groovy с явными сигнатурами методов можно вызывать из Java; динамические возможности (`metaClass`, `methodMissing`) из Java недоступны без рантайма Groovy. Подробная таблица: [Groovy и Java](/encyclopedia/5-languages/5-12-groovy/20).

Основные особенности Groovy:
- **Синтаксическая лаконичность**: отсутствие обязательных точек с запятой, скобок, модификаторов доступа, типов переменных;
- **Динамическая и статическая типизация**: по умолчанию — динамическая, но можно включить статическую проверку через `@TypeChecked` или `@CompileStatic`;
- **Расширяемость**: возможность добавлять методы к существующим классам через метапрограммирование (`ExpandoMetaClass`, категориальные методы);
- **Поддержка функционального стиля**: замыкания, операторы над коллекциями (`collect`, `findAll`, `each`), безопасная навигация (`?.`);
- **Встроенные DSL-возможности**: естественный синтаксис для создания внутренних предметно-ориентированных языков;
- **Скриптовая природа**: файлы `.groovy` могут выполняться как скрипты без объявления класса.

Области применения Groovy:
- **Автоматизация сборки и CI/CD**: основной язык для Gradle;
- **Тестирование**: используется в Spock Framework, Geb, REST Assured для написания выразительных спецификаций и тестов;
- **Скрипты администрирования и ETL**: благодаря простоте работы с JSON, XML, файлами и базами данных;
- **Расширение Java-приложений**: внедрение динамического поведения без перекомпиляции;
- **Прототипирование и быстрая разработка**: особенно в сочетании с Grails (веб-фреймворк, аналог Rails для JVM).

Экосистема Groovy включает:
- **Gradle** — система сборки, где Groovy (и Kotlin DSL) используются для описания проектов;
- **Spock** — фреймворк для спецификаций и тестов с поддержкой BDD;
- **Grails** — full-stack веб-фреймворк на основе Spring Boot и Hibernate;
- **Grape** — встроенный менеджер зависимостей для скриптов;
- **AST Transformations** — мощный механизм компиляционного метапрограммирования.

Три основных правила эффективной работы с Groovy:
1. Использовать его как "более выразительную Java" — сохранять читаемость, избегая избыточного метапрограммирования;
2. Применять статическую типизацию (`@CompileStatic`) в производственном коде для повышения производительности и надёжности;
3. Писать тестируемый код — даже в скриптах выделять логику в функции и классы.

Три фундаментальных момента:
- Groovy — это не замена Java, а её элегантное расширение для задач, где важна скорость разработки;
- Его сила — в гибкости: от однострочного скрипта до полноценного enterprise-приложения;
- Знание Java остаётся необходимым — Groovy строится на той же платформе и использует те же библиотеки.
