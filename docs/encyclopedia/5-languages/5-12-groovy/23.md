## Gradle Groovy DSL — первая сборка

Android и половина enterprise-репозиториев до сих пор хранят **`build.gradle`** на **Groovy**, а не `build.gradle.kts`. Чтобы читать чужие проекты, нужно понимать блоки `plugins`, `dependencies` и **почему** `implementation` внутри `{ }` — это не магия, а [делегирование замыканий](./11.md).

Java-аналог на Kotlin DSL: [Gradle — практический старт](/encyclopedia/5-languages/5-03-java/292). Maven: [структура и сборки Java](/encyclopedia/5-languages/5-03-java/12).

---

### Зачем Groovy DSL, если есть Kotlin DSL

| Groovy `build.gradle` | Kotlin `build.gradle.kts` |
|-----------------------|---------------------------|
| Исторически в Android | Новые модули часто KTS |
| Больше примеров в сети | Строгая типизация IDE |
| Тот же Gradle под капотом | Тот же Gradle под капотом |

---

### Что получится

Проект `hello-groovy-gradle`: `./gradlew build`, JAR, unit-тест. Понимание, что пишете в `build.gradle`.

---

## Создание проекта

```bash
mkdir hello-groovy-gradle && cd hello-groovy-gradle
gradle init
```

Выберите: **application**, **Java**, **Groovy** build script, **JUnit Jupiter**.

Появятся `gradlew`, `settings.gradle`, `build.gradle`.

---

## settings.gradle

```groovy
rootProject.name = 'hello-groovy-gradle'
```

Имя корневого проекта — влияет на имя JAR.

---

## build.gradle (разбор по блокам)

```groovy
plugins {
    id 'java'
    id 'application'
}

group = 'com.example'
version = '1.0.0'

repositories {
    mavenCentral()
}

dependencies {
    implementation 'org.apache.groovy:groovy:4.0.21'
    testImplementation 'org.junit.jupiter:junit-jupiter:5.10.2'
}

application {
    mainClass = 'com.example.App'
}

java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(17)
    }
}

tasks.named('test') {
    useJUnitPlatform()
}
```

| Блок | Назначение |
|------|------------|
| `plugins` | Подключает Java, упаковку application, задачи `run` |
| `repositories` | Откуда качать JAR (Maven Central) |
| `dependencies` | **DSL**: методы `implementation` — см. [11.md](./11.md) |
| `application.mainClass` | Точка входа для `gradlew run` |
| `java.toolchain` | JDK 17 без ручного JAVA_HOME в скрипте |

## Исходники

`src/main/java/com/example/App.java`:

```java
package com.example;

public class App {
    public static void main(String[] args) {
        System.out.println("Hello from Gradle Groovy DSL");
    }
}
```

## Команды

```bash
./gradlew tasks          # список задач
./gradlew compileJava    # компиляция
./gradlew test           # тесты
./gradlew run            # запуск main
./gradlew build          # compile + test + jar
```

**Разбор:** `gradlew` — wrapper: фиксирует версию Gradle в `gradle/wrapper/gradle-wrapper.properties`. Коммитьте wrapper в Git.

---

## Своя задача (task)

```groovy
tasks.register('hello') {
    group = 'custom'
    description = 'Печать приветствия'
    doLast {
        println "Gradle task hello"
    }
}
```

```bash
./gradlew hello
```

`doLast` — closure, выполняется в конце задачи. Так же устроены внутренние задачи плагинов.

---

## Multi-module (набросок)

`settings.gradle`:

```groovy
rootProject.name = 'parent'
include 'api', 'service'
```

У каждого подпроекта свой `build.gradle`. Зависимость между модулями:

```groovy
dependencies {
    implementation project(':api')
}
```

### Частые ошибки

| Симптом | Причина |
|---------|---------|
| `Could not find method implementation()` | Не применён плагин `java` |
| Unsupported class file major version | Toolchain ниже версии байткода |
| `gradlew` не найден | Запускаете `gradle` без wrapper в CI |
