## FAQ — Часто задаваемые вопросы

Типичные сбои и ситуации, с которыми сталкиваются новички после раздела. Здесь — **что делать и где копать в главах**; определения для зачёта — в [чек-листе](./999.md).

<div class="faq-list">

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Xcode: "Signing requires a development team" — проект не запускается на iPhone.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> В Signing &amp; Capabilities выберите Apple ID team (бесплатный аккаунт подходит для учебного устройства). Bundle Identifier должен быть уникальным. Подробнее здесь — [первая программа](./20.md), [жизненный цикл](./21.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Симулятор запустился, экран чёрный — SwiftUI Preview тоже пустой.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Проверьте `@main` App struct, что root View добавлен в `WindowGroup`, нет ли раннего `fatalError` в init. Пересоберите Clean Build Folder. Подробнее здесь — [первая программа](./20.md), [фреймворки](./15.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `Fatal error: Unexpectedly found nil while unwrapping an Optional`.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Сработал force unwrap `!` на `nil`. Замените на `if let`, `guard let` или обработку ошибки. Подробнее здесь — [типы](./13.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> IBOutlet в storyboard был, после переименования свойства — краш при тапе.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Связь в Interface Builder отвалилась; переподключите outlet или перейдите на SwiftUI без storyboard. Подробнее здесь — [первая программа](./20.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `let` константа — "Cannot assign to value: 'self' is immutable" в методе struct.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Метод, меняющий struct, пометьте `mutating`; для class достаточно обычного метода. Подробнее здесь — [ООП](./102.md), [данные](./16.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Выбрал `class` для модели SwiftUI — предупреждения про published state.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Для простых моделей UI чаще `struct` + `ObservableObject`/`@Observable`; class нужен при shared reference и ARC. Подробнее здесь — [ООП](./102.md), [фреймворки](./15.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Замыкание в `Task { }` держит ViewController — утечка памяти.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Capture list `[weak self]` или разорвите цикл; проверьте Instruments Leaks. Подробнее здесь — [async](./17.md), [ООП](./102.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `async` URLSession вызвали без `await` — предупреждение или странный Future.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Вызов suspend-функции только с `await` в async-контексте; из sync UI — `Task { await ... }`. Подробнее здесь — [async](./17.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Codable: ключ в JSON `user_name`, в struct `userName` — decode nil.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Задайте `CodingKeys` или `keyDecodingStrategy.convertFromSnakeCase`. Подробнее здесь — [данные](./16.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> SwiftUI List не обновляется при изменении массива.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Массив должен быть `@State`/`@Observable` с публикацией изменений; для class-модели — `Identifiable` и новый instance или mutation через observable. Подробнее здесь — [фреймворки](./15.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `@StateObject` vs `@ObservedObject` — данные сбрасываются при навигации.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Владелец долгоживущей модели — родитель с `@StateObject`; дочерний view получает `@ObservedObject`. Подробнее здесь — [фреймворки](./15.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Playground завис на "Running" бесконечно.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Остановите выполнение, упростите цикл, проверьте live view; тяжёлые примеры лучше в обычном target. Подробнее здесь — [интерактивное изучение](./22.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `spm` не резолвит пакет — "checksum of artifact changed".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Обновите Package.resolved, сбросьте кэш пакетов в Xcode File → Packages. Версию зафиксируйте по tag. Подробнее здесь — [экосистема](./10.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> CocoaPods и SPM в одном проекте — дубли символов при линковке.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Для новых проектов предпочтите SPM; миграция с Pods поэтапная. Подробнее здесь — [экосистема](./10.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `guard let` внутри `else` снова требует unwrap — запутался в потоке.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> После успешного `guard let x` переменная `x` доступна ниже по функции; в `else` нужен выход (`return`/`throw`). Подробнее здесь — [типы](./13.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Pattern matching в `switch` — "Switch must be exhaustive".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Добавьте `default` или все case enum; для tuple — все комбинации. Подробнее здесь — [pattern matching](./24.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Extension добавил метод, но protocol witness не видит его в generic коде.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Ограничения protocol и where clause решают видимость; иногда нужен wrapper protocol. Подробнее здесь — [ООП](./102.md), [pattern matching](./24.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `@MainActor` на ViewModel — вызов из background thread ругается.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> UI обновляйте на main; тяжёлую работу в `Task.detached`, затем `await MainActor.run`. Подробнее здесь — [async](./17.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Linux: `swift build` не находит Foundation Networking.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Не все Apple-фреймворки на Linux; серверный Swift опирается на swift-corelibs-foundation и Vapor/другие пакеты. Подробнее здесь — [экосистема](./10.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Пришёл с Kotlin — жду data class, получаю struct и mutating.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Value semantics в Swift — через struct; копирование и COW отличаются от JVM. Подробнее здесь — [данные](./16.md), [Kotlin — о разделе](/encyclopedia/5-languages/5-09-kotlin/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Property wrapper `@AppStorage` не синхронизируется между View.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Ключ UserDefaults должен совпадать; для сложного state — Observable model. Подробнее здесь — [property wrappers](./25.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Trailing closure передан не тому параметру — компилятор молчит, логика неверна.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> При нескольких closure используйте метки параметров и скобки. Подробнее здесь — [параметры](./23.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `try!` в init View — приложение падает у пользователей без тестового JSON.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Загрузку ресурсов делайте с `do/catch` и fallback UI; `try!` только для заведомо валидных bundle-файлов. Подробнее здесь — [данные](./16.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Preview в Xcode 16: "Cannot preview in this file".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `#Preview` макрос должен быть в том же target, что SwiftUI view; проверьте platform и зависимости. Подробнее здесь — [первая программа](./20.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Combine pipeline не отменяется — подписка живёт после dismiss.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Храните `AnyCancellable` в Set и отменяйте в `onDisappear`/`deinit`. Для нового кода часто проще `async`/`await`. Подробнее здесь — [async](./17.md), [экосистема](./10.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Нет Mac — можно ли учить Swift только по статьям?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Базу языка — на Linux/online playground; UIKit/SwiftUI полноценно требуют Xcode на macOS. Планируйте доступ к Mac или облачный CI для сборки. Подробнее здесь — [что нужно знать перед Swift](./1001.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Objective-C библиотека в проекте — bridging header не видит символы.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Проверьте `import` в bridging header, linking framework и modulemap. Подробнее здесь — [история](./1.md), [экосистема](./10.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Смешиваю UIKit и SwiftUI в одном экране — layout "плывёт".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `UIHostingController` и `UIViewRepresentable` требуют явных constraints; начните с чистого SwiftUI для учебного экрана. Подробнее здесь — [фреймворки](./15.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Как установить Swift и Xcode на Mac для новичка?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> App Store → Xcode (включает Swift toolchain); проверка `swift --version` в Terminal. Подробнее здесь — [первая программа](./20.md), [что нужно знать](./1001.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Swift для iOS с нуля — бесплатный курс на русском?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Маршрут раздела: [основы](./11.md)–[управление](./14.md) → [первая программа](./20.md) → [SwiftUI](./15.md). Подробнее здесь — [intro](./intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Swift vs Objective-C — что учить в 2025?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Новые проекты — Swift; Objective-C нужен для legacy и чтения старых API. Подробнее здесь — [история](./1.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Swift vs Kotlin для мобильной разработки?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Swift — экосистема Apple; Kotlin — Android и KMP. Один язык на обе платформы без KMP не даёт. Подробнее здесь — [Kotlin — о разделе](/encyclopedia/5-languages/5-09-kotlin/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Optional Swift — что такое if let guard let?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Безопасное извлечение значения из `T?`; `guard let` — ранний выход. Избегайте `!` в учебном коде. Подробнее здесь — [типы](./13.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> SwiftUI tutorial для начинающих — с чего начать?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> [первая программа](./20.md) с обзором SwiftUI, затем [фреймворки](./15.md) и [жизненный цикл](./21.md). Подробнее здесь — [intro](./intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> struct vs class Swift — когда что использовать?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Struct — value type по умолчанию для моделей; class — наследование, shared state, ARC. Подробнее здесь — [ООП](./102.md), [данные](./16.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> async await Swift — как вызвать сеть?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `URLSession` с async API или `Task { let data = try await ... }`; UI обновляйте на MainActor. Подробнее здесь — [async](./17.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Codable JSON Swift — encode decode пример?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `struct User: Codable` + `JSONEncoder`/`JSONDecoder`; ключи через `CodingKeys`. Подробнее здесь — [данные](./16.md).</p>
</div>

<div class="faq-item">

<div class="faq-item">

</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Swift Playground на iPad или Mac — зачем?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Быстрые эксперименты без полного проекта. Подробнее здесь — [интерактивное изучение](./22.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> @State @Binding @ObservedObject SwiftUI — разница?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> `@State` — локальное состояние view; `@Binding` — ссылка на чужое; `@ObservedObject`/`@StateObject` — внешняя модель. Подробнее здесь — [фреймворки](./15.md), [property wrappers](./25.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Protocol oriented programming Swift — что это?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Поведение через протоколы и extension вместо глубоких иерархий классов. Подробнее здесь — [ООП](./102.md).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Swift на Windows/Linux без Mac — возможно ли?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Swift open source на Linux; полноценный SwiftUI/iOS — только с Xcode на macOS. Подробнее здесь — [экосистема](./10.md), [что нужно знать](./1001.md).</p>
</div>

<div class="faq-item">

<div class="faq-item">

</div>

<div class="faq-item">

  <p class="faq-a"><span class="faq-label">Ответ.</span> SwiftUI — для новых экранов и курсов; UIKit — legacy и тонкий контроль. Подробнее здесь — [фреймворки](./15.md).</p>
</div>

<div class="faq-item">

  <p class="faq-a"><span class="faq-label">Ответ.</span> `switch` с associated values и `where`; должен быть исчерпывающим. Подробнее здесь — [pattern matching](./24.md).</p>

<div class="faq-item">

<div class="faq-item">

</div>

## Что запомнить

Swift — это современный, безопасный и высокопроизводительный язык программирования, разработанный Apple для создания приложений на платформах iOS, macOS, watchOS, tvOS и visionOS. Он сочетает в себе лучшие практики системного и объектно-ориентированного программирования с элементами функционального стиля, обеспечивая как выразительность, так и надёжность.

Основные особенности Swift:
- **Строгая статическая типизация с мощным выводом типов** — компилятор автоматически определяет типы, но не допускает неопределённости;
- **Безопасность по умолчанию** — отсутствие неинициализированных переменных, обязательная обработка ошибок, защита от переполнения;
- **Поддержка значимых типов (`struct`) и ссылочных типов (`class`)** — разработчик может выбирать модель памяти явно;
- **Современные конструкции языка**: опционалы, сопоставление с образцом, замыкания, расширения, протоколы с расширениями;
- **Потребление памяти без сборщика мусора** — управление памятью осуществляется через ARC (Automatic Reference Counting);
- **Высокая производительность** — близка к C++ благодаря LLVM-компилятору и отсутствию рантайм-накладных расходов.

Области применения Swift:
- **Мобильная разработка под iOS/iPadOS** — основной язык для App Store;
- **Десктопные приложения под macOS**;
- **Серверная разработка** — через фреймворки Vapor, Kitura (менее распространено, но возможно);
- **Системное программирование** — особенно в экосистеме Apple (например, драйверы, утилиты);
- **Кроссплатформенные проекты** — с использованием Swift Package Manager и Linux-совместимости.

Экосистема Swift включает:
- **Xcode** — официальная IDE с интегрированным отладчиком, интерфейсным конструктором (Interface Builder) и инструментами анализа;
- **Swift Package Manager (SPM)** — встроенный менеджер зависимостей и сборки;
- **CocoaPods / Carthage** — альтернативные системы управления пакетами (устаревают в пользу SPM);
- **SwiftUI** — декларативный фреймворк для построения пользовательских интерфейсов;
- **Combine** — фреймворк для реактивного программирования;
- **Playgrounds и REPL** — интерактивное изучение без полного приложения ([подробнее](/encyclopedia/5-languages/5-14-swift/22)).

Три основных правила эффективной работы с Swift:
1. Предпочитать значимые типы (`struct`, `enum`) ссылочным (`class`), если не требуется совместное состояние или наследование;
2. Использовать опционалы и обработку ошибок вместо принудительного развёртывания (`!`);
3. Писать код, ориентируясь на протоколы, а не на конкретные реализации — "программирование на основе протоколов".

Три фундаментальных момента:
- Swift — это язык, где безопасность и производительность достигаются через дизайн, а не через внешние инструменты;
- Его сила — в согласованности: каждая конструкция языка служит чёткой цели и работает предсказуемо;
- Знание фреймворков Apple (Foundation, UIKit, SwiftUI) так же важно, как и знание самого языка.
