## Простые приложения на Rust

Rust подходит для надёжных утилит: компилятор ловит ошибки владения до запуска, `cargo` собирает бинарник и тесты. Примеры ниже — на **стандартной библиотеке**; для HTTP в продакшене чаще берут [Axum](./201.md), но для старта достаточно понять `Result`, `match` и работу с файлами.

Порядок: после [первой программы](./20.md) и [типов с владением](./13.md).

---

### Как запускать примеры из главы

1. Для примеров с `rand` / `serde`: `cargo new demo && cd demo`, вставьте код в `src/main.rs`, добавьте зависимости в `Cargo.toml`.
2. **Команда:** `cargo run`
3. Один файл без Cargo: `rustc src/main.rs && ./main` (Linux/macOS) или `main.exe` (Windows).

Проверка: `rustc --version`, `cargo --version`.

## Генератор паролей

### Как запустить

- **Проект:** `cargo new password && cd password`
- **Cargo.toml:** `rand = "0.8"`
- **Команда:** `cargo run`
- **Результат:** одна строка — пароль из 16 символов.

```rust
use rand::Rng;
use rand::seq::SliceRandom;

fn generate_password(len: usize) -> String {
    const CHARSET: &[u8] = b"ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789!@#$%";
    let mut rng = rand::thread_rng();
    (0..len)
        .map(|_| CHARSET[rng.gen_range(0..CHARSET.len())] as char)
        .collect()
}

fn main() {
    println!("{}", generate_password(16));
}
```

Разбор:
- Функция `generate_password(len: usize) -> String` принимает длину и возвращает уже собранную строку пароля, поэтому контракт функции ясен по сигнатуре.
- Константа `CHARSET` хранится как `&[u8]`, это удобный формат для случайного выбора индекса и последующего приведения байта к `char`.
- `rand::thread_rng()` создает генератор случайных чисел, привязанный к текущему потоку выполнения.
- Цепочка `(0..len).map(...).collect()` строит пароль декларативно: для каждой позиции выбирается случайный символ и затем все символы собираются в `String`.
- Внутри `gen_range(0..CHARSET.len())` верхняя граница не включается, что защищает от выхода за пределы массива.
- На проде такой пример обычно усиливают криптостойким источником случайности (`OsRng`) и проверкой политики сложности пароля.

В `Cargo.toml`: `rand = "0.8"`. Для паролей в продакшене предпочтительнее `rand` с `OsRng` / crate `getrandom`.

## Сортировщик текстового файла

### Как запустить

- **Файл:** `src/main.rs` в проекте `cargo new sort_file`
- **Подготовка:** `input.txt` в корне проекта; путь в `sort_file(...)`.
- **Команда:** `cargo run`
- **Результат:** `output.txt` с отсортированными строками.

```rust
use std::fs;
use std::io;

fn sort_file(input: &str, output: &str) -> io::Result<()> {
    let mut lines: Vec<String> = fs::read_to_string(input)?
        .lines()
        .map(str::trim)
        .filter(|s| !s.is_empty())
        .map(String::from)
        .collect();
    lines.sort();
    fs::write(output, lines.join("\n") + "\n")?;
    Ok(())
}

fn main() -> io::Result<()> {
    sort_file("input.txt", "output.txt")?;
    println!("Готово: output.txt");
    Ok(())
}
```

Разбор:
- `sort_file(input, output) -> io::Result<()>` показывает стандартный шаблон для I/O-функций, где ошибка явно возвращается наружу.
- `fs::read_to_string(input)?` считывает весь файл в память и сразу пробрасывает `io::Error`, если чтение не удалось.
- Цепочка `.lines().map(str::trim).filter(...).map(String::from)` сначала очищает строки, затем убирает пустые и только после этого материализует их в `Vec<String>`.
- `lines.sort()` сортирует строки in-place по лексикографическому порядку, без создания второй коллекции.
- `fs::write(...)` записывает результат обратно в файл, а добавление `+ "\n"` сохраняет перевод строки в конце файла.
- `fn main() -> io::Result<()>` вызывает `sort_file` и пробрасывает ошибки через `?`, поэтому пример сразу запускается через `cargo run`.
- Такой пример удобно расширять выбором регистра (case-sensitive/case-insensitive) и сортировкой по кастомному компаратору.

## Консольный калькулятор

### Как запустить

- **Команда:** `cargo run` (проект с этим `main`)
- **Нужно:** терминал; ввод вида `10 + 3` или по строкам — как в коде.
- **Результат:** `= 13.0` или сообщение об ошибке.

```rust
use std::io::{self, Write};

fn calc(a: f64, b: f64, op: char) -> Result<f64, String> {
    Ok(match op {
        '+' => a + b,
        '-' => a - b,
        '*' => a * b,
        '/' if b == 0.0 => return Err("деление на ноль".into()),
        '/' => a / b,
        _ => return Err(format!("неизвестный оператор: {op}")),
    })
}

fn main() -> io::Result<()> {
    let stdin = io::stdin();
    loop {
        print!("a op b (q): ");
        io::stdout().flush()?;
        let mut line = String::new();
        stdin.read_line(&mut line)?;
        let line = line.trim();
        if line == "q" { break; }
        let mut parts = line.split_whitespace();
        let a: f64 = parts.next().ok_or("a?")?.parse().map_err(|_| "a?")?;
        let op = parts.next().ok_or("op?")?.chars().next().ok_or("op?")?;
        let b: f64 = parts.next().ok_or("b?")?.parse().map_err(|_| "b?")?;
        match calc(a, b, op) {
            Ok(v) => println!("= {v}"),
            Err(e) => eprintln!("{e}"),
        }
    }
    Ok(())
}
```

Разбор:
- Функция `calc(a, b, op)` изолирует арифметическую бизнес-логику от кода ввода-вывода, что упрощает тестирование.
- Внутри `match op` каждая операция описана отдельной веткой, а `return Err(...)` мгновенно прерывает вычисление в невалидных сценариях.
- Условная ветка `'/' if b == 0.0` показывает guard в `match`: оператор совпал, но дополнительно проверяется условие.
- Цикл `loop` в `main` реализует интерактивный режим калькулятора до команды `q`.
- Разбор ввода через `split_whitespace()` и `parse()` делает формат команды строгим и предсказуемым.
- `stdout().flush()?` принудительно выводит приглашение перед чтением, чтобы пользователь видел prompt сразу.

## Трекер задач в JSON (serde)

### Как запустить

- **Cargo.toml:** `serde = { version = "1", features = ["derive"] }`, `serde_json = "1"`
- **Команда:** `cargo run`
- **Результат:** файл `tasks.json` в каталоге проекта.

```rust
use serde::{Deserialize, Serialize};
use std::fs;

#[derive(Debug, Serialize, Deserialize)]
struct Task {
    id: u64,
    title: String,
    done: bool,
}

const DB: &str = "tasks.json";

fn load() -> Vec<Task> {
    fs::read_to_string(DB)
        .ok()
        .and_then(|s| serde_json::from_str(&s).ok())
        .unwrap_or_default()
}

fn save(tasks: &[Task]) -> std::io::Result<()> {
    fs::write(DB, serde_json::to_string_pretty(tasks)?)
}

fn main() -> std::io::Result<()> {
    let mut tasks = load();
    tasks.push(Task {
        id: 1,
        title: "Изучить Rust".into(),
        done: false,
    });
    save(&tasks)?;
    Ok(())
}
```

Разбор:
- `#[derive(Serialize, Deserialize)]` автоматически добавляет сериализацию и десериализацию, поэтому структуру `Task` легко сохранять в JSON и читать обратно.
- `const DB: &str = "tasks.json"` централизует имя файла-хранилища и убирает магические строки из функций.
- В `load()` цепочка `ok().and_then(...).unwrap_or_default()` преобразует ошибки чтения и парсинга в "пустой список", сохраняя простоту для учебного сценария.
- `save(tasks: &[Task])` принимает срез, а не `Vec`, поэтому функция не зависит от конкретного контейнера и не требует владения коллекцией.
- `serde_json::to_string_pretty(tasks)?` формирует читаемый JSON, удобный для ручной проверки и ревью.
- В практическом приложении к этому примеру обычно добавляют уникальные `id`, обновление задач и явное логирование ошибок чтения.

`Cargo.toml`: `serde = { version = "1", features = ["derive"] }`, `serde_json = "1"`.

## Минимальный HTTP-сервер (hyper / tiny_http альтернатива — std через TcpListener)

### Как запустить

- **Команда:** `cargo run`
- **Проверка:** в другом терминале `curl http://127.0.0.1:3000/` — JSON в ответе.
- **Остановка:** `Ctrl+C`.

```rust
use std::io::{Read, Write};
use std::net::{TcpListener, TcpStream};

fn handle(mut stream: TcpStream) -> std::io::Result<()> {
    let mut buf = [0u8; 1024];
    let n = stream.read(&mut buf)?;
    let req = String::from_utf8_lossy(&buf[..n]);
    let body = r#"{"ok":true}"#;
    let response = format!(
        "HTTP/1.1 200 OK\r\nContent-Type: application/json\r\nContent-Length: {}\r\n\r\n{}",
        body.len(),
        body
    );
    stream.write_all(response.as_bytes())
}

fn main() -> std::io::Result<()> {
    let listener = TcpListener::bind("127.0.0.1:3000")?;
    for stream in listener.incoming().flatten() {
        let _ = handle(stream);
    }
    Ok(())
}
```

Разбор:
- `TcpListener::bind("127.0.0.1:3000")?` поднимает локальный TCP-сервер и возвращает ошибку, если порт занят или недоступен.
- В `for stream in listener.incoming().flatten()` цикл принимает входящие соединения, пропуская ошибочные элементы без падения процесса.
- `handle(mut stream: TcpStream)` читает сырой HTTP-запрос в буфер, затем формирует ответ вручную через строку статуса и заголовки.
- `String::from_utf8_lossy` позволяет безопасно логировать/разбирать входные байты даже при неидеальной кодировке запроса.
- Заголовок `Content-Length` вычисляется из длины `body`, чтобы клиент понимал, сколько байтов читать в ответе.
- Этот код полезен как учебная модель HTTP поверх TCP, а для production обычно переходят на `axum`/`actix-web`.

Для учебного API дальше переходите на [Axum](./201.md).

## Обход каталога

### Как запустить

- **Команда:** `cargo run` из каталога, который нужно сканировать (измените путь в `scan(...)`).
- **Результат:** кортеж `(число_файлов, байты)`.

```rust
use std::fs;
use std::path::Path;

fn scan(dir: &Path, ext: &str) -> std::io::Result<(usize, u64)> {
    let mut files = 0usize;
    let mut bytes = 0u64;
    for entry in fs::read_dir(dir)? {
        let entry = entry?;
        let path = entry.path();
        if path.is_dir() {
            let (f, b) = scan(&path, ext)?;
            files += f;
            bytes += b;
        } else if path.extension().and_then(|e| e.to_str()) == Some(ext.trim_start_matches('.')) {
            files += 1;
            bytes += entry.metadata()?.len();
        }
    }
    Ok((files, bytes))
}
```

Разбор:
- Рекурсивная функция `scan(dir, ext)` обходит дерево каталогов в глубину и возвращает агрегированный результат `(количество_файлов, общий_размер)`.
- `fs::read_dir(dir)?` отдает итератор по директории, а `entry?` внутри цикла обрабатывает ошибки доступа к отдельным элементам.
- Проверка `path.is_dir()` разделяет ветки: либо рекурсивный обход подпапки, либо обработка файла.
- Условие по `path.extension()` фильтрует файлы по расширению, а `trim_start_matches('.')` позволяет передавать `ext` в двух форматах.
- Размер файла берется через `entry.metadata()?.len()`, после чего суммируется в общий счетчик `bytes`.
- Такой пример удобно расширить ограничением глубины обхода, исключениями по директориям и параллельным сканированием.

## Характерный пример для Rust — `Result` и `match`

### Как запустить

- **Команда:** `cargo run` или `rustc main.rs && ./main`
- **Результат:** для `8080` — `8080`; для `abc` и `0` — сообщения об ошибке.

```rust
fn parse_port(s: &str) -> Result<u16, String> {
    let port: u16 = s.parse().map_err(|_| "порт должен быть числом".to_string())?;
    if port == 0 {
        return Err("порт не может быть 0".into());
    }
    Ok(port)
}

fn main() {
    for input in ["8080", "abc", "0"] {
        match parse_port(input) {
            Ok(p) => println!("{input} → {p}"),
            Err(e) => println!("{input}: {e}"),
        }
    }
}
```

Разбор:
- `parse_port` демонстрирует идиоматичную валидацию: сначала парсинг строки в число, затем доменное ограничение `port != 0`.
- `s.parse().map_err(|_| "...".to_string())?` преобразует техническую ошибку парсинга в понятное сообщение для пользователя.
- Возврат `Result<u16, String>` делает ошибочный путь частью API функции, а не скрытым побочным сценарием.
- `match parse_port(input)` в `main` наглядно разделяет успешный и неуспешный путь, что упрощает диагностику.
- Перебор массива `["8080", "abc", "0"]` показывает проверку как корректного значения, так и двух разных классов ошибок.
- Этот шаблон удобно переносить в CLI и серверы, где входные параметры всегда требуют строгой валидации.

Ошибки — часть сигнатуры; это отличает Rust от языков с исключениями "на всё".

Мини-сниппет: аргументы командной строки без внешних библиотек:

```rust
use std::env;

fn main() {
    let mut args = env::args().skip(1);
    let input = args.next().unwrap_or_else(|| "input.txt".into());
    let output = args.next().unwrap_or_else(|| "output.txt".into());
    println!("{input} -> {output}");
}
```

Разбор:
- `env::args()` возвращает итератор строк: первый элемент — имя программы, дальше аргументы пользователя.
- `.skip(1)` убирает путь к исполняемому файлу из разбора.
- `unwrap_or_else(|| ...)` задаёт значения по умолчанию, если аргумент не передан.
- Такой каркас легко расширить вызовом `sort_file(&input, &output)?` из примера выше.
