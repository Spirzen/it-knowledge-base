## FFI на практике в Rust

**FFI** (Foreign Function Interface) — вызов кода с C-совместимым ABI: системные библиотеки, legacy DLL, драйверы, SDK. Компилятор Rust **не проверяет** контракт на границе: неверный тип или время жизни указателя — неопределённое поведение. Поэтому весь `unsafe` сжимают в тонкий слой, наружу отдают safe API.

Концепции: [справочник, раздел FFI](./3.md) · [системное программирование](./111.md) · сборка: [Cargo и build.rs](./204.md).

---

## Два направления

| Направление | Задача |
|-------------|--------|
| Rust → C | экспорт `extern "C"` функций, `cdylib` |
| C → Rust | `extern "C" { fn ... }`, линковка через `build.rs` |

Соглашение **`extern "C"`** — стабильный ABI для вызова из C, не «язык C» как таковой.

## Вызов C из Rust

`native/add.c`:

```c
int add(int a, int b) {
    return a + b;
}
```

`build.rs`:

```rust
fn main() {
    cc::Build::new().file("native/add.c").compile("native_add");
    println!("cargo:rerun-if-changed=native/add.c");
}
```

`Cargo.toml`:

```toml
[build-dependencies]
cc = "1"
```

`src/lib.rs`:

```rust
use std::ffi::c_int;

extern "C" {
    fn add(a: c_int, b: c_int) -> c_int;
}

/// Safe-обёртка: контракт C-функции проверен вручную один раз.
pub fn add_safe(a: i32, b: i32) -> i32 {
    unsafe { add(a, b) }
}
```

Правила safe-обёртки:

- документировать предусловия (указатель не null, длина буфера);
- не отдавать наружу «сырые» указатели с неясным lifetime;
- преобразовывать коды ошибок C в `Result`.

## Структуры с C-совместимым layout

```rust
#[repr(C)]
pub struct Point {
    pub x: f64,
    pub y: f64,
}
```

`#[repr(C)]` фиксирует порядок полей как в C. Без него компилятор может переупорядочить поля — ABI сломается.

Строки **не** передают как `&str` через границу. Используют:

- `*const c_char` + `CStr` / `CString`;
- длину + указатель на байты (контракт «кто владеет буфером»).

```rust
use std::ffi::{CStr, CString};
use std::os::raw::c_char;

pub fn to_c_string(s: &str) -> CString {
    CString::new(s).expect("строка без внутреннего NUL")
}

pub unsafe fn from_c_str(ptr: *const c_char) -> Option<&'static str> {
    if ptr.is_null() {
        return None;
    }
    CStr::from_ptr(ptr).to_str().ok()
}
```

`'static` здесь оправдан только если C гарантирует вечное хранение строки — иначе lifetime должен быть явным параметром обёртки.

## Экспорт Rust для C

`src/lib.rs`:

```rust
#[no_mangle]
pub extern "C" fn rust_add(a: i32, b: i32) -> i32 {
    a + b
}
```

`Cargo.toml`:

```toml
[lib]
crate-type = ["cdylib", "rlib"]
```

Сборка даёт `libnative_add.so` / `.dll`. C-код объявляет:

```c
int rust_add(int a, int b);
```

**Паника через FFI** — неопределённое поведение для C. На границе ловят `catch_unwind` или возвращают код ошибки, никогда не «роняют» C-стек.

## bindgen: заголовки → Rust

Для больших SDK вручную не пишут сотни `extern`. Генератор **bindgen** читает `.h` и создаёт модуль.

`build.rs` (упрощённо):

```rust
fn main() {
    let bindings = bindgen::Builder::default()
        .header("wrapper.h")
        .parse_callbacks(Box::new(bindgen::CargoCallbacks::new()))
        .generate()
        .expect("bindgen failed");

    let out = std::path::PathBuf::from(std::env::var("OUT_DIR").unwrap());
    bindings
        .write_to_file(out.join("bindings.rs"))
        .unwrap();
}
```

В `lib.rs`:

```rust
mod ffi {
    include!(concat!(env!("OUT_DIR"), "/bindings.rs"));
}
```

Поверх сгенерированного модуля пишут **ручные** safe-типы — bindgen не делает API безопасным автоматически.

---

## cbindgen: Rust → заголовок C

Если Rust — ядро, а потребители на C++, нужен `.h`. **cbindgen** сканирует `pub extern "C"` и генерирует заголовок в `build.rs` или отдельной задаче (`cargo xtask`).

## Ошибки на границе

| Проблема | Последствие |
|----------|-------------|
| Неверный `repr` | чтение «чужой» памяти |
| Use-after-free указателя | UB |
| Паника в callback C | крах процесса |
| Разный allocator (free в C для Rust-alloc) | heap corruption |

Решение: явные владельцы буферов, `Box::into_raw` / `from_raw` парами, документированные пары create/destroy.

---

## Windows и COM (обзор)

Для Win32 и WinRT используют crate вроде **windows** / **windows-sys** — тысячи `extern` уже сгенерированы. Прикладной код всё равно оборачивает в safe-типы; прямой вызов из бизнес-логики редок.

Выбор GUI-стека (Tauri, Slint, нативные биндинги) — [GUI на Windows](./206.md).

## Чек-лист перед merge

1. Весь `unsafe` в одном-двух модулях с тестами и `#[cfg(test)]`.
2. `build.rs` объявляет `rerun-if-changed` для исходников C.
3. CI собирает целевые платформы (Linux / Windows / macOS), где нужен FFI.
4. Для библиотеки — `miri` и sanitizers на критичных обёртках, где возможно.
5. Документация: кто освобождает память и в каком потоке вызывать API.
