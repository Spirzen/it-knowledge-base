## Cargo — workspace, features и профили

**Cargo** — единая точка сборки, зависимостей и тестов. После [первой программы](./20.md) следующий шаг — понимать, как устроен **реальный** репозиторий: несколько crate в workspace, опциональные возможности через features, разные профили оптимизации.

Обзор инструментов: [фреймворки и Cargo](./15.md) · детали синтаксиса: [справочник](./3.md).

## Один пакет: bin и lib

Типичный сервис:

```
my-app/
  Cargo.toml
  src/
    main.rs      # бинарник
    lib.rs       # библиотека (логика, тесты)
```

`Cargo.toml`:

```toml
[package]
name = "my-app"
version = "0.1.0"
edition = "2021"

[dependencies]
serde = { version = "1", features = ["derive"] }

[[bin]]
name = "my-app"
path = "src/main.rs"
```

Часто вся логика в `lib.rs`, а `main.rs` только вызывает `my_app::run()`. Так проще писать [интеграционные тесты](./202.md) в `tests/`.

Библиотека для FFI или плагина:

```toml
[lib]
crate-type = ["cdylib"]  # .dll / .so / .dylib
```

## Workspace (монорепозиторий)

Несколько связанных crate в одном репозитории:

```
acme/
  Cargo.toml          # [workspace]
  crates/
    core/
      Cargo.toml
      src/lib.rs
    api/
      Cargo.toml
      src/main.rs
```

Корневой `Cargo.toml`:

```toml
[workspace]
resolver = "2"
members = [
    "crates/core",
    "crates/api",
]

[workspace.package]
edition = "2021"
version = "0.1.0"

[workspace.dependencies]
serde = { version = "1", features = ["derive"] }
tokio = { version = "1", features = ["full"] }
```

В `crates/api/Cargo.toml`:

```toml
[package]
name = "acme-api"

[dependencies]
acme-core = { path = "../core" }
tokio = { workspace = true }
serde = { workspace = true }
```

Команды из корня:

```bash
cargo build -p acme-api
cargo test --workspace
cargo run -p acme-api
```

Преимущества: одна блокировка версий (`Cargo.lock`), общие зависимости, переиспользование кода без публикации на crates.io.

## Features (условная сборка)

Features включают опциональный код и транзитивные зависимости.

```toml
[dependencies]
reqwest = { version = "0.12", optional = true }

[features]
default = ["http"]
http = ["dep:reqwest"]
```

В коде:

```rust
#[cfg(feature = "http")]
pub fn fetch(url: &str) -> Result<String, reqwest::Error> {
    reqwest::blocking::get(url)?.text()
}
```

Сборка:

```bash
cargo build --no-default-features
cargo build --features http
cargo test --all-features
```

**Важно:** feature должны быть **аддитивными**. Не полагайтесь на «выключение» чужой feature — другой crate может её снова включить.

Для взаимоисключающих режимов документируйте один «главный» feature или разделяйте crate.

## Профили: dev и release

По умолчанию в `Cargo.toml`:

```toml
[profile.dev]
opt-level = 0
debug = true

[profile.release]
opt-level = 3
lto = "thin"
codegen-units = 1
```

| Команда | Профиль | Назначение |
|---------|---------|------------|
| `cargo build` | `dev` | быстрая итерация |
| `cargo build --release` | `release` | продакшен |
| `cargo test` | `test` (как dev + debug) | тесты |

Кастомный профиль для CI-бенчмарков:

```toml
[profile.bench]
inherits = "release"
debug = true
```

## Зависимости: версии и features

```toml
[dependencies]
anyhow = "1"
thiserror = "2"

[dev-dependencies]
tokio = { version = "1", features = ["rt", "macros"] }

[build-dependencies]
cc = "1"
```

- **Semver** на crates.io: `1.2.3` — совместимые обновления в рамках major.
- `cargo update` обновляет записи в `Cargo.lock`.
- В библиотеках не включайте лишние default-features зависимостей — уменьшает время сборки у потребителей.

## build.rs (скрипт сборки)

Файл `build.rs` в корне пакета выполняется **до** компиляции. Типичные задачи:

- компиляция C/C++ через `cc`;
- генерация кода (`bindgen`, protobuf);
- передача путей компилятору через `cargo:rustc-link-search`.

Минимальный пример с нативной библиотекой:

```rust
// build.rs
fn main() {
    cc::Build::new()
        .file("native/add.c")
        .compile("native_add");

    println!("cargo:rerun-if-changed=native/add.c");
}
```

Подробнее про связывание с C — [FFI на практике](./205.md).

## Полезные команды

```bash
cargo tree -p my-app          # граф зависимостей
cargo check                   # быстрая проверка без линковки
cargo doc --open              # локальная документация
cargo clippy -- -D warnings
cargo fmt
```
