# OBS — стрим и запись экрана

<div class="article-tags">
  <span class="tag tag-required">ОБЯЗАТЕЛЬНО</span>
  <span class="tag tag-beginner">ДЛЯ НОВИЧКОВ</span>
</div>

<span class="complexity-badge">Всем</span>

**OBS Studio** (Open Broadcaster Software) — бесплатная программа с открытым исходным кодом. Она захватывает изображение с экрана или камеры, микширует звук и либо сохраняет файл на диск, либо отправляет поток на Twitch, YouTube, VK Video и другие площадки.

Теория кодеков, CDN и истории стриминга — в [Онлайн-контент и стриминг](./12) и [Видео](./1). Здесь — практическая настройка с нуля, от первой записи до продвинутых сцен и устранения типичных сбоев.

---

## Словарь

Базовые термины, которые встретятся в интерфейсе OBS и настройках площадок.

- **Сцена (Scene)** — набор источников, который видит зритель в один момент. Примеры: урок, игра, пауза, заставка.
- **Источник (Source)** — один слой сцены: окно программы, весь экран, камера, картинка, текст, браузер.
- **Сцена-коллекция (Scene Collection)** — группа сцен для разных форматов. Отдельная коллекция для курса, стрима, подкаста с видео.
- **Профиль (Profile)** — набор настроек Output, Video, Audio. Удобно хранить профиль для записи и отдельный для стрима.
- **Битрейт (bitrate)** — сколько данных в секунду уходит в поток или в файл. Влияет на качество картинки и размер файла.
- **Кодек** — способ сжатия видео. В OBS чаще всего **H.264**, **H.265 (HEVC)** или **AV1**. Подробнее — [Видео](./1).
- **Контейнер** — формат файла, в котором лежит сжатое видео. **MKV**, **MP4**, **MOV**.
- **Энкодер** — программа или блок GPU, который сжимает кадры в реальном времени. **x264**, **NVENC**, **AMF**, **QSV**, **AV1**.
- **Декодер** — обратная операция: воспроизведение сжатого потока. Нужен зрителю и монтажной программе.
- **Stream Key** — секретный ключ канала. По нему OBS подключается к серверу площадки. Никому не показывайте.
- **Ingest URL** — адрес сервера приёма потока. Иногда называют RTMP URL или Server URL.
- **RTMP** — протокол передачи потока от OBS к серверу площадки. Стандарт для Twitch, YouTube, VK Video.
- **Keyframe (ключевой кадр, I-frame)** — полный кадр без ссылки на предыдущие. Чем реже ключевые кадры, тем меньше битрейт, но сложнее перемотка и восстановление при обрыве.
- **Keyframe interval (GOP)** — расстояние между ключевыми кадрами в секундах. Для стрима обычно 2 секунды.
- **CRF (Constant Rate Factor)** — режим качества для записи в файл. Чем меньше число, тем выше качество и больше размер. Диапазон для H.264 — примерно 18–28.
- **CBR (Constant Bitrate)** — постоянный битрейт. Стандарт для прямого эфира.
- **VBR (Variable Bitrate)** — переменный битрейт. Чаще для записи, реже для стрима.
- **FPS (кадры в секунду)** — 30 для учебного контента, 60 для динамичных игр и плавного курсора.
- **Разрешение (resolution)** — 1280×720 (720p), 1920×1080 (1080p), 2560×1440 (1440p).
- **Downscale filter** — уменьшение разрешения перед кодированием. Снижает нагрузку на CPU и GPU.
- **Buffer (буфер кодирования)** — запас кадров в памяти. При перегрузке растёт и появляются пропуски кадров.
- **Dropped frames** — кадры, которые OBS не успел отправить. Главный признак слабого интернета или завышенного битрейта.
- **Encoding lag** — задержка кодирования на вашем ПК. Признак слабого CPU или GPU.
- **Rendering lag** — задержка отрисовки сцены. Часто из-за тяжёлых фильтров или слабой видеокарты.
- **Audio Mixer** — панель громкости дорожек. Микрофон, рабочий стол, музыка — отдельные ползунки.
- **Monitor (аудио)** — прослушивание дорожки в наушниках без вывода в эфир. Нужно для проверки звука.
- **Filters (фильтры)** — цепочка обработки на источнике. Шумоподавление, хромакей, обрезка, цветокоррекция.
- **Transition (переход)** — анимация смены сцены. Fade, Cut, Stinger.
- **Stinger** — переход с коротким видео и прозрачностью. Логотип канала на смене сцен.
- **Studio Mode** — режим предпросмотра. Сцена в эфире и следующая сцена видны одновременно.
- **Virtual Camera** — виртуальная веб-камера. OBS отдаёт картинку в Zoom, Teams, Discord.
- **NDI** — передача видео и звука по локальной сети между двумя ПК без физического захвата карты.
- **Restreaming** — одновременная отправка одного потока на несколько площадок через сервис-посредник.
- **Overlay** — графика поверх основного изображения. Веб-камера, чат, таймер, логотип.
- **Browser Source** — источник на базе встроенного браузера. Виджеты чата, оповещения донатов, таймеры.
- **Replay Buffer** — кольцевой буфер последних секунд. Сохраняет клип по горячей клавише без полной записи.
- **Multitrack Recording** — запись нескольких аудиодорожек в один файл. Голос, музыка, игра — раздельно для монтажа.

## Требования к железу

OBS работает на слабом ноутбуке, но качество и стабильность сильно зависят от компонентов. Ниже ориентиры для учебного контента, код-стримов и игр.

### Процессор (CPU)

- **Минимум** — 4 ядра, 8 потоков. Intel i5 десятого поколения, AMD Ryzen 5 3600 и новее.
- **Комфортно** — 6–8 ядер. Нужно при программном кодировании **x264** и нескольких источниках с фильтрами.
- **Нагрузка** — захват экрана, микширование аудио, фильтры, кодирование. При **x264** нагрузка на CPU максимальная.
- **Совет** — если CPU слабый, включите аппаратный энкодер (**NVENC**, **AMF**, **QSV**).

### Видеокарта (GPU)

- **Минимум** — встроенная графика Intel UHD для записи 720p30 без игр.
- **Комфортно** — дискретная NVIDIA GTX 1660 и новее, AMD RX 580 и новее. Аппаратное кодирование и Game Capture.
- **Для игр в 1080p60** — RTX 3060, RX 6600 XT и выше. Игра и OBS делят ресурсы GPU.
- **Драйвер** — обновите до последней версии с сайта NVIDIA, AMD или Intel. Без свежего драйвера энкодер может отсутствовать в списке.

### Оперативная память (RAM)

- **Минимум** — 8 ГБ. Хватит для записи урока с одним окном IDE.
- **Комфортно** — 16 ГБ. Стрим, браузер с чатом, IDE, Discord одновременно.
- **Для тяжёлых сцен** — 32 ГБ. Несколько Browser Source, виртуальные машины, игры с высоким потреблением RAM.

### Микрофон

- **Встроенный микрофон ноутбука** — только для тестов. Много шума и эха.
- **USB-микрофон начального уровня** — Fifine, Maono, Blue Snowball. Достаточно для уроков и подкастов.
- **XLR с аудиоинтерфейсом** — Shure SM7B, Rode PodMic. Нужен фантомный блок или интерфейс с предусилителем.
- **Петличка** — для ходьбы по кадру и вебинаров. Rode Wireless GO, Hollyland Lark.
- **Поп-фильтр и микрофонная стойка** — снижают взрывные согласные и удары по столу.

### Веб-камера

- **Встроенная камера ноутбука** — 720p, мягкая картинка. Подойдёт для углового окошка на стриме.
- **USB 1080p** — Logitech C920, C922, Razer Kiyo. Стандарт для IT-стримов.
- **Камера с HDMI + карта захвата** — Sony, Canon в режиме clean HDMI. Максимальное качество, выше цена.
- **Освещение** — кольцевая лампа или софтбокс важнее дорогой камеры. Лицо должно быть ровно освещено.

### Интернет для стрима

- **Минимум исходящий канал** — 5 Мбит/с стабильно для 720p30.
- **1080p30** — 8–10 Мбит/с с запасом 20–30%.
- **1080p60** — 12–15 Мбит/с.
- **Подключение** — Ethernet предпочтительнее Wi-Fi. Проверьте скорость на [speedtest.net](https://www.speedtest.net/) в часы, когда обычно стримите.

### Накопитель

- **SSD** — запись идёт без рывков. HDD может давать пропуски при длинных сессиях.
- **Свободное место** — час 1080p при CRF 20 занимает 4–12 ГБ в зависимости от динамики картинки. Держите 50+ ГБ свободными.

### Два монитора

- Один экран — сцена OBS и рабочие окна.
- Второй экран — чат, шпаргалки, презентация для зрителей.
- OBS может захватывать только второй монитор, чтобы панели программы не попали в кадр.

## Установка

1. Скачайте [OBS Studio](https://obsproject.com/) под вашу ОС. Windows, macOS, Linux — один и тот же интерфейс с небольшими отличиями в захвате экрана.
2. При первом запуске мастер спросит цель:
   - **Optimize for recording** — если нужны уроки и ролики в файл;
   - **Optimize for streaming** — если главное — прямой эфир;
   - **I will only be using Virtual Camera** — если OBS будет камерой для Zoom и Discord.
3. Мастер предложит базовое разрешение и FPS. Позже всё меняется в **Settings → Video**.
4. Обновите драйвер видеокарты — аппаратное кодирование сильно снижает нагрузку на процессор.
5. На Windows установите [Visual C++ Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist), если OBS не запускается.
6. На macOS выдайте разрешения: **Запись экрана**, **Камера**, **Микрофон** — в **Системные настройки → Конфиденциальность**.

### Папки и резервные копии

- **Scene Collection** и **Profile** экспортируются через меню **Scene Collection → Export** и **Profile → Export**.
- Сохраните копию после настройки сцен. Переустановка OBS не удалит профили, но бэкап спасает при смене ПК.
- Записи по умолчанию лежат в **Videos** (Windows) или **Movies** (macOS). Проверьте путь в **Settings → Output → Recording Path**.

## Обзор интерфейса OBS

Главное окно OBS делится на панели. Каждая отвечает за свой этап цепочки от захвата до эфира.

### Preview (предпросмотр)

- Большая область по центру. Показывает, как выглядит текущая сцена.
- Красная рамка **Edit Transform** — масштаб и положение источника.
- Правый клик по источнику в превью — **Transform**, **Order**, **Filters**.
- Кнопка **Resize Output (Source Size)** — подогнать выход под размер источника.

### Scenes (сцены)

- Список слева внизу. Одна активная сцена в эфире или в записи.
- Кнопки **+** и **−** — добавить и удалить сцену.
- Перетаскивание меняет порядок в списке, на эфир не влияет.
- Двойной клик — переименовать. Имена вроде `Урок`, `Пауза`, `BRB` ускоряют работу с горячими клавишами.

### Sources (источники)

- Список слоёв активной сцены. Нижний слой — фон, верхний — передний план.
- Иконка глаза — скрыть источник без удаления.
- Иконка замка — запретить случайное смещение.
- **+** открывает меню типов: Display Capture, Window Capture, Game Capture, Video Capture Device, Image, Text, Browser, Media Source и другие.

### Audio Mixer (микшер)

- Каждая аудиодорожка — отдельный фейдер.
- Зелёная зона — нормальный уровень. Жёлтая — громко. Красная — клиппинг, искажение.
- Шестерёнка у дорожки — **Advanced Audio Properties**: моно, трек записи, синхронизация.
- Кнопка **⚙** внизу — **Advanced Audio Properties** для всех источников сразу.

### Scene Transitions (переходы)

- Между Scenes и Controls. По умолчанию **Fade** 300 ms.
- Выпадающий список — тип перехода. Кнопка **−** — длительность.
- **+** — добавить Stinger, Slide, Luma Wipe.
- **Quick Transitions** в Studio Mode — разные переходы для разных пар сцен.

### Controls (управление)

- **Start Streaming** / **Stop Streaming** — прямой эфир.
- **Start Recording** / **Stop Recording** — запись в файл.
- **Start Replay Buffer** — кольцевой буфер.
- **Start Virtual Camera** — виртуальная камера для Zoom, Teams, Discord.
- **Studio Mode** — раздельный предпросмотр и программа.
- **Settings** — все глобальные параметры.

### Status Bar (строка состояния)

- **CPU** — загрузка процессора OBS.
- **Dropping Frames** — процент потерянных кадров при стриме. Должен быть 0% или близко.
- **Bitrate** — фактический битрейт потока.
- **FPS** — кадры кодирования. Просадка ниже целевого FPS — признак перегрузки.

### Dock-панели (доки)

- Меню **View → Docks** — чат Twitch, Streamlabs, пользовательские виджеты.
- Док можно открепить и вынести на второй монитор.
- **Stats** — детальная статистика: encoding lag, render lag, пропуски кадров.

### Меню File

- **Show Recordings** — открыть папку записей.
- **Show Profile Folder** — файлы настроек профиля.
- **Export** — резервная копия всей конфигурации.

### Settings — краткая карта разделов

- **General** — язык, системный трей, предупреждения.
- **Stream** — сервис, сервер, ключ.
- **Output** — запись, стрим, Replay Buffer, энкодер, битрейт.
- **Audio** — частота дискретизации, каналы.
- **Video** — базовое и выходное разрешение, FPS, фильтр масштабирования.
- **Hotkeys** — горячие клавиши.
- **Advanced** — процесс-приоритет, цветовой формат, задержка захвата.

## Первая запись экрана

Пошаговый маршрут для записи урока или демо без стрима.

1. Создайте сцену **Урок** в панели Scenes.
2. В блоке **Sources** нажмите **+**:
   - **Display Capture** — весь экран. Простой вариант, захватывает всё на мониторе.
   - **Window Capture** — одно окно (IDE, браузер). Меньше лишнего в кадре.
   - **Game Capture** — для игр и некоторых полноэкранных приложений.
3. Снова **+** → **Audio Input Capture** — микрофон. Выберите устройство из списка.
4. При необходимости **+** → **Audio Output Capture** — звук с рабочего стола (музыка, системные звуки).
5. Откройте **Settings → Video**:
   - **Base (Canvas) Resolution** — разрешение монитора.
   - **Output (Scaled) Resolution** — 1920×1080 или 1280×720.
   - **FPS** — 30 для кода, 60 для игр.
6. Откройте **Settings → Output → Recording**:
   - формат **MKV** — файл не бьётся при сбое питания;
   - формат **MP4** — удобнее сразу заливать на YouTube;
   - кодек **H.264** — максимальная совместимость;
   - кодек **AV1** — меньший размер при поддержке железа.
7. Нажмите **Start Recording** → работайте → **Stop Recording**.

Путь к файлу — **Settings → Output → Recording Path**. Уровни громкости смотрите в **Audio Mixer** — пики в жёлтой зоне, без постоянного захода в красную.

Подробнее про звук — [Аудио](./11).

## Запись — углублённая настройка

### MKV и восстановление после сбоя

- **MKV** пишет метаданные по мере записи. При обрыве питания или краше OBS файл часто можно открыть и использовать почти до последней секунды.
- **MP4** записывает индекс в конце файла. Обрыв сессии часто даёт нечитаемый файл.
- **Рабочий порядок** — пишите в MKV, после сессии конвертируйте в MP4 через **File → Remux Recordings**. Конвертация быстрая, без перекодирования.
- **Автоматическое разбиение** — в **Settings → Output → Recording** включите **Split File** по времени или размеру. Длинные вебинары безопаснее хранить кусками по 30–60 минут.

### MP4 напрямую

- Используйте MP4, если запись короткая и ПК стабилен.
- Перед важной сессией закройте лишние программы и проверьте свободное место на диске.
- Не записывайте на сетевой диск NAS — задержки записи дают пропуски кадров.

### CRF для записи

- Режим **Quality** с параметром **CRF** доступен при энкодере **x264** и **x265** в разделе Recording.
- **CRF 18** — высокое качество, большие файлы. Архив исходников, монтаж с цветокоррекцией.
- **CRF 20–22** — баланс для YouTube-уроков.
- **CRF 23–28** — черновики, быстрые демо, внутренние созвоны.
- CRF не задаёт фиксированный размер файла. Динамичная игра даёт больший файл, чем статичный слайд.

### Keyframe interval при записи

- Для файла keyframe interval менее критичен, чем для стрима.
- Значение **0** или **auto** в OBS — энкодер выбирает сам.
- Для стрима задайте **2** секунды вручную в **Output → Streaming → Advanced**.

### Раздельные аудиодорожки

- **Settings → Output → Recording** — включите несколько **Audio Track**.
- В **Advanced Audio Properties** у каждого источника отметьте, в какой трек он пишется.
- Трек 1 — микрофон. Трек 2 — рабочий стол. Трек 3 — музыка. В DaVinci Resolve и Audacity дорожки разделены.
- Контейнер **MKV** надёжнее для multitrack, чем MP4.

### Replay Buffer

- **Settings → Output → Replay Buffer** — включите и задайте длительность 30–120 секунд.
- Горячая клавиша **Save Replay** — сохраняет последние N секунд без полной записи.
- Удобно для стримов: поймали смешной момент или баг в live-кодинге.

### Профили записи — готовые пресеты

| Задача | Разрешение | FPS | Энкодер | CRF / битрейт |
|--------|------------|-----|---------|----------------|
| Урок IDE | 1080p | 30 | x264 или NVENC | CRF 20 |
| Демо браузера | 1080p | 30 | NVENC | CRF 21 |
| Игровой клип | 1080p | 60 | NVENC | CRF 18–20 |
| Быстрый скринкаст | 720p | 30 | x264 veryfast | CRF 23 |
| Архив вебинара | 1080p | 30 | x264 slow | CRF 18 |

## Первая трансляция

Краткий путь до живого эфира. Детальная настройка площадок — в следующем разделе.

1. На Twitch, YouTube или другой площадке откройте настройки канала и скопируйте **Stream Key**.
2. В OBS — **Settings → Stream** → выберите сервис и вставьте ключ.
3. **Settings → Output → Streaming**:
   - **Encoder** — на слабом CPU лучше **NVENC** / **AMF** / **QSV**, чем программный **x264**;
   - **Bitrate** — ориентиры:
     - 720p30 — 2500–4000 Kbps;
     - 1080p30 — 4500–6000 Kbps;
     - 1080p60 — 6000–8000 Kbps.
4. **Settings → Video** — выходное разрешение совпадает с тем, что обещаете зрителю.
5. Проверьте уровни в **Audio Mixer**. Голос читается, музыка фоном.
6. Нажмите **Start Streaming**. Статус подключения — в правом нижнем углу.
7. Откройте страницу канала в режиме инкогнито и убедитесь, что картинка и звук доходят.

**Задержка (latency)** зависит от площадки и битрейта. Для live-кодинга часто хватает 720p — текст в IDE читается, канал загружается меньше. Протоколы доставки — в [стриминге](./12).

## Стрим на Twitch — пошагово

1. Зарегистрируйте аккаунт на [twitch.tv](https://www.twitch.tv/).
2. В [Twitch Creator Dashboard](https://dashboard.twitch.tv/) откройте **Settings → Stream**.
3. Скопируйте **Primary Stream key**. Не публикуйте его в чате и на стриме.
4. В OBS **Settings → Stream**:
   - **Service** — Twitch;
   - **Server** — автоматически или ближайший ingest;
   - **Stream Key** — вставьте ключ.
5. **Settings → Output → Streaming**:
   - **Video Encoder** — NVENC H.264 или x264;
   - **Bitrate** — 4500–6000 Kbps для 1080p30 Partner-аккаунт; 6000 Kbps максимум для большинства;
   - **Keyframe Interval** — 2;
   - **Preset** — P5 (NVENC) или veryfast (x264).
6. **Settings → Video** — **Output Resolution** 1920×1080 или 1280×720, **FPS** 30 или 60.
7. Добавьте Browser Source с виджетом чата Twitch — URL из dashboard.
8. **Start Streaming**. В dashboard появится зелёный индикатор **Live**.
9. Укажите категорию и теги — **Software and Game Development** для код-стримов.
10. После эфира VOD сохраняется автоматически 14–60 дней в зависимости от подписки.

### Twitch — типичные лимиты

- Максимальный битрейт для не-партнёров — часто 8000 Kbps, рекомендуется не превышать 6000.
- Разрешение до 1080p60. 4K ingest поддерживается не всегда.
- Аудио — 48 kHz, стерео. OBS по умолчанию настроен верно.

## Сравнение энкодеров

| Энкодер | Тип | Плюсы | Минусы | Когда выбирать |
|---------|-----|-------|--------|----------------|
| **x264** | CPU | Гибкая настройка, хорошее качество на среднем битрейте | Высокая нагрузка на CPU | Слабая GPU, запись в файл с CRF |
| **x265 (HEVC)** | CPU | Меньший размер файла при том же качестве | Тяжёлое кодирование, слабая поддержка в старых плеерах | Архив записей, не для стрима |
| **NVENC (H.264)** | GPU NVIDIA | Низкая нагрузка на CPU, стабильный стрим | Чуть хуже детализация на низком битрейте | Игры, 1080p60, слабый CPU |
| **NVENC (HEVC)** | GPU NVIDIA | Экономия битрейта | Не все зрители декодируют | Эксперименты, не основной стрим |
| **NVENC AV1** | GPU RTX 40+ | Отличное сжатие, будущий стандарт | Требует новую карту, высокая нагрузка на GPU | Запись, YouTube с AV1 |
| **AMF (H.264/HEVC)** | GPU AMD | Аппаратное кодирование на Radeon | Качество сильно зависит от версии драйвера | ПК с AMD GPU |
| **QSV (H.264/HEVC)** | GPU Intel | Работает на встроенной графике Intel | Среднее качество, ограничения по разрешению | Ноутбук без дискретной GPU |
| **Apple VT** | macOS | Нативная интеграция на Mac | Меньше тонкой настройки | MacBook, iMac |
| **SVT-AV1** | CPU | Открытый AV1, хорошее качество | Очень тяжёлый для live | Запись, не realtime |
| **AOM AV1** | CPU/GPU | Максимальное сжатие в файле | Не для слабых ПК | Оффлайн-конвертация |

### Preset и tuning

- **x264 preset** — ultrafast, veryfast, fast, medium, slow. Для стрима — veryfast или faster. Для записи — medium или slow.
- **NVENC preset** — P1 (быстрее) … P7 (качественнее). Баланс — P4 или P5.
- **Tune** для x264 — **zerolatency** снижает задержку для стрима.

## Битрейт по разрешению и FPS

Ориентиры для **CBR** при стриме. Запись в CRF не использует фиксированный битрейт.

### Таблица стриминга

| Разрешение | FPS | Минимум Kbps | Рекомендуется Kbps | Нужен upload Мбит/с |
|------------|-----|--------------|---------------------|---------------------|
| 854×480 | 30 | 1500 | 2000–2500 | 3 |
| 1280×720 | 30 | 2500 | 3000–4500 | 5 |
| 1280×720 | 60 | 3500 | 4500–6000 | 7 |
| 1920×1080 | 30 | 4500 | 5000–6000 | 8 |
| 1920×1080 | 60 | 5500 | 6000–8000 | 10 |
| 2560×1440 | 60 | 9000 | 12000–15000 | 18 |

### Калькулятор на практике

1. Узнайте скорость **исходящего** канала. Speedtest показывает upload отдельно.
2. Выделите OBS не более **70%** от стабильного upload. Остальное — Discord, обновления, чат.
3. Пример: upload 10 Мбит/с → битрейт OBS около 7000 Kbps максимум. Безопаснее 5500 Kbps.
4. Динамичный контент (игры) требует больше битрейта, чем статичный код. При том же разрешении добавьте 500–1000 Kbps для игр.
5. Если **Dropped Frames** растёт — снижайте битрейт шагами по 500 Kbps, пока индикатор не станет зелёным.

### Запись в файл — ориентиры CRF

| Разрешение | FPS | CRF x264 | Примерный размер 1 час |
|------------|-----|----------|-------------------------|
| 720p | 30 | 20–23 | 1–3 ГБ |
| 1080p | 30 | 18–22 | 3–8 ГБ |
| 1080p | 60 | 18–20 | 6–15 ГБ |
| 1440p | 60 | 18–20 | 10–25 ГБ |

Точный размер зависит от движения в кадре. IDE с редкими переключениями вкладок сжимается сильнее, чем шутер.

## Звуковая цепочка

Чистый звук важнее резкости картинки. Зритель терпит 720p, но быстро уходит при неразборчивом голосе. Детали форматов — [Аудио](./11).

### Базовая схема

1. **Источник** — микрофон, Desktop Audio, Media Source.
2. **Фильтры на источнике** — Gain, Noise Suppression, Compressor.
3. **Audio Mixer** — баланс громкости дорожек.
4. **Глобальные фильтры** — через VST на Windows (см. ниже).
5. **Выход** — стрим 160 Kbps AAC, запись PCM или AAC в multitrack.

### Рекомендуемая цепочка фильтров на микрофоне

| Порядок | Фильтр | Настройка |
|---------|--------|-----------|
| 1 | Noise Suppression | RNNoise или NVIDIA Noise Removal |
| 2 | Noise Gate | Close −32 dB, Open −26 dB, Attack 5 ms, Hold 200 ms |
| 3 | Compressor | Ratio 3:1, Threshold −18 dB, Attack 6 ms, Release 60 ms |
| 4 | Gain | +3…+6 dB если голос тихий. Без клиппинга в красную зону |
| 5 | Limiter | Ceiling −1 dB — защита от пиков |

Порядок важен: сначала убираем шум, потом выравниваем громкость.

### VST-плагины

- На Windows установите [obs-vst2-plugin](https://github.com/obsproject/obs-vst) или встроенную поддержку VST3 в новых версиях OBS.
- Популярные плагины — ReaPlugs (бесплатно), TDR Nova, RX Voice De-noise.
- Добавление: правый клик по микрофону → **Filters** → **+** → **VST 2.x Plug-in**.
- Не перегружайте цепочку — каждый плагин добавляет задержку.

### Мониторинг

- **Advanced Audio Properties** → **Audio Monitoring** → **Monitor and Output** — слышите себя в наушниках.
- **Monitor Only** — звук только вам, зрители не слышат (удобно для метронома или щелчков).
- Используйте наушники при мониторинге, иначе микрофон ловит звук из колонок — эхо.

### Синхронизация аудио и видео

- **Sync Offset** в **Advanced Audio Properties** — сдвиг в миллисекундах. Камера часто отстаёт на 20–80 ms.
- Если голос раньше губ — отрицательное смещение. Если позже — положительное.
- **Settings → Advanced → Video** — **Video Delay** для всей картинки, если отстаёт только видео с карты захвата.

### Desktop Audio и приложения

- **Application Audio Capture** (Windows 10 22H2+) — звук одного приложения без всего рабочего стола.
- **Audio Output Capture** — весь системный микс. Проще, но шум уведомлений попадает в эфир.
- Отключите звуки Discord и Telegram при стриме или вынесите их на отдельную дорожку с низкой громкостью.

### Музыка и фон

- Отдельный **Media Source** или **VLC Video Source** для фоновой музыки.
- Громкость музыки −20…−30 dB относительно голоса.
- Для стрима музыка должна быть без нарушения авторских прав — см. раздел про лицензии ниже.

## Сцены, коллекции и переходы

### Scene Collections

- Меню **Scene Collection → New** — создайте `Курс Python`, `Еженедельный стрим`, `Подкаст`.
- Переключение коллекции меняет все сцены и источники. Профиль Output может остаться тем же.
- Экспорт коллекции — JSON-файл. Перенос на другой ПК за минуту.

### Именование и порядок

- Префикс номерами: `01 Урок`, `02 Демо`, `99 BRB`. Горячие клавиши проще запомнить.
- Сцена **Starting Soon** — заставка до начала.
- Сцена **BRB** — перерыв с таймером.
- Сцена **Ending** — финальная заставка с ссылками.

### Transitions

- **Cut** — мгновенная смена. Для быстрых переключений код/чат.
- **Fade** — плавное затемнение 300–500 ms. Универсальный вариант.
- **Swipe** — сдвиг кадра. Динамичный стиль.
- **Stinger** — короткое WebM с альфа-каналом. Логотип пролетает по экрану.
- **Luma Wipe** — маска по яркости. Нужен чёрно-белый файл маски.

### Stinger — как подключить

1. Подготовьте WebM с прозрачным фоном. Разрешение совпадает с выходом OBS.
2. **Scene Transitions → + → Stinger**.
3. Укажите файл, **Transition Point** — кадр, где сцена меняется (обычно середина клипа).
4. Отметьте **Swap Scenes** если нужно.

### Studio Mode

- Кнопка **Studio Mode** в Controls.
- Слева — предпросмотр следующей сцены. Справа — эфир.
- **Transition** применяется вручную когда готовы.
- Исключает случайный показ рабочего стола при переключении.

## Фильтры на видеоисточниках

Правый клик по источнику → **Filters** → **+**.

### Chroma Key (хромакей)

- Убирает однотонный фон — зелёный или синий экран.
- **Key Color** — пипеткой выберите фон.
- **Similarity** — насколько близкие оттенки удалять. Начните с 400–500.
- **Smoothness** — смягчение краёв.
- **Spill Reduction** — убирает зелёный отблеск на волосах и одежде.
- Освещение фона равномерное, без складок — меньше артефактов.

### Color Correction

- **Brightness**, **Contrast**, **Gamma** — базовая коррекция.
- **Saturation** — насыщенность. Не переборщите на веб-камере.
- **Color Key** — альтернатива хромакею для простых фонов.
- LUT через **Apply LUT** (плагин или Color Correction Filter в новых версиях).

### Crop / Pad

- **Crop/Pad Filter** — обрезка чёрных полос, скрытие панели задач в Display Capture.
- Пиксельные значения или проценты. Фиксируйте область захвата окна через **Window Capture** когда возможно.

### Sharpen

- Лёгкое повышение резкости для мягкой веб-камеры. **0.08–0.15** — осторожно, шум усиливается.

### Scroll

- Прокрутка длинного текста или титров. Редко нужно в IT-контенте.

### Image Mask / Blend

- Скругление углов веб-камеры через маску PNG.
- **Image Mask/Blend** — белая область видна, чёрная прозрачна.

### Применение к группе

- **Group** источников — фильтр на группу влияет на все слои внутри. Удобно для overlay с камерой и рамкой.

## Несколько мониторов и два ПК

### Один ПК, два монитора

- **Display Capture** выбирает конкретный монитор в свойствах.
- Рабочие окна на мониторе 2, OBS на мониторе 1 — зрители не видят ваши панели.
- **Projector** — **Right-click Preview → Windowed Projector** выводит сцену на выбранный монитор для вас.

### Два ПК — схема

- **Игровой ПК** — игра или тяжёлое приложение.
- **Стриминговый ПК** — OBS, кодирование, отправка потока.
- Связь между ними:
  - **Capture Card** — HDMI с игрового в стриминговый. Золотой стандарт, нулевая нагрузка на игровой при кодировании на втором.
  - **NDI** — по Ethernet. Бесплатный плагин OBS-NDI. Нужна гигабитная сеть.
  - **Parsec / Moonlight** — удалённый рабочий стол. Больше задержка, проще для тестов.

### Настройка с карты захвата

1. Игровой ПК → HDMI → карта захвата → стриминговый ПК.
2. В OBS стримингового ПК — **Video Capture Device**.
3. Разрешение и FPS — максимум, который поддерживает карта (1080p60 или 4K30).
4. **Audio** с карты — звук игры. Микрофон подключён к стриминговому ПК.

### Dual PC без второй мышки

- KVM-переключатель или программный **Barrier** / **Synergy** — одна клавиатура на оба ПК.

Стрим киберспорта и турниров — [Киберспорт](/encyclopedia/9-spinoff/9-03-igrovaya-industriya/125).

## Restreaming и мультиплатформа

Один эфир на Twitch, YouTube и VK одновременно — через сервис-посредник или несколько выходов.

### Сервисы restream

- [restream.io](https://restream.io/), [castr.io](https://castr.io/), [streamyard.com](https://streamyard.com/) — принимают один поток от OBS и раздают на несколько площадок.
- Плюсы — одна настройка OBS, единая аналитика, мультичат в одном окне.
- Минусы — дополнительный хоп, иногда +5–10 секунд задержки, платные тарифы для HD.

### Настройка через Restream

1. Зарегистрируйтесь и подключите каналы Twitch, YouTube, VK.
2. Скопируйте **RTMP URL** и **Stream Key** из dashboard Restream.
3. В OBS **Settings → Stream** → **Custom** → вставьте данные Restream.
4. Битрейт — по лимиту самой строгой площадки. Обычно 4500 Kbps безопасно.

### Несколько выходов в OBS 30+

- **Settings → Output → Streaming** — кнопка **Add** для второго сервиса (экспериментальная функция, версия OBS может отличаться).
- Нагрузка на upload удваивается при двух независимых RTMP. Restream экономит исходящий канал.

### Анонсы

- Расписание на всех площадках заранее. Текст и обложка под каждую аудиторию.
- Ссылки в [Discord и Telegram](/encyclopedia/9-spinoff/9-10-internet-kultura/135) — за час и за пять минут до эфира.

## Музыка и авторские права

Нарушение лицензии — мут VOD, страйки на YouTube, бан на Twitch. Для IT-стримов музыка часто фоном, но правила те же.

### Что нельзя без разрешения

- Коммерческие треки из Spotify, Apple Music, личной коллекции MP3.
- Саундтреки игр и фильмов в записи, которая останется на платформе.
- Ремиксы и каверы без лицензии на платформе стриминга.

### Что можно

- **YouTube Audio Library** — бесплатные треки с указанием условий.
- **Twitch Soundtrack** — отдельная дорожка музыки, VOD без музыки (где доступно).
- **Epidemic Sound**, **Artlist** — подписка для стримеров.
- Собственные биты и музыка с лицензией Creative Commons — проверьте тип CC (NC, SA).
- Музыка из игр, которую вы стримите — обычно разрешена в контексте геймплея, не как отдельный плейлист.

### Практика для учебных стримов

- Фоновая музыка тихо или без неё. Речь главнее.
- Если играете трек — ожидайте, что VOD могут затронуть. Запись урока без музыки безопаснее для YouTube.
- VK и YouTube применяют Content ID. Музыка может монетизироваться правообладателем, а не вами.

### Дисклеймер

- Материал носит ознакомительный характер. Для коммерческих проектов читайте лицензию каждого трека и правила площадки.

## Пять готовых пресетов сцен для IT-контента

Каждый пресет — отдельная сцена или мини-коллекция. Копируйте структуру и подставляйте свои источники.

### 1. Урок (lesson)

**Цель** — запись курса, скринкаст IDE, минимум отвлечений.

**Источники**

- **Window Capture** — окно IDE на весь кадр.
- **Audio Input Capture** — микрофон с цепочкой Noise Suppression → Compressor → Gain.
- **Image** — тонкая рамка или водяной знак канала в углу (опционально).
- **Text (GDI+)** — заголовок урока вверху, мелкий шрифт.

**Настройки**

- 1080p30, CRF 20, MKV, x264 medium или NVENC.
- Микрофон −12 dB пик, музыка отсутствует.

**Горячие клавиши**

- Скрыть/показать рамку камеры если добавите webcam позже.
- Pause Recording на перерыв.

---

### 2. Code review (разбор кода)

**Цель** — live-разбор репозитория, переключение между файлами и браузером.

**Источники**

- **Window Capture** — IDE, 70% кадра слева.
- **Window Capture** — браузер GitHub/GitLab, 30% справа или вторая сцена.
- **Video Capture Device** — веб-камера 320×180 в правом нижнем углу.
- **Browser Source** — виджет таймера или список PR.

**Сцены**

- `CR IDE` — только код.
- `CR Split` — код + GitHub.
- `CR Cam Full` — камера на весь экран для вступления.

**Настройки**

- Стрим 720p60 или 1080p30, NVENC, 4500 Kbps.
- Шрифт IDE увеличен на 2–4 pt для читаемости на телефоне.

---

### 3. Gaming (игровой стрим с IT-уклоном)

**Цель** — игровой контент, dev-log, геймджем. Стрим киберспорта — [Киберспорт](/encyclopedia/9-spinoff/9-03-igrovaya-industriya/125).

**Источники**

- **Game Capture** — режим **Capture specific window** или **Hook** для полноэкранной игры.
- **Video Capture Device** — камера, круглая маска.
- **Image** — overlay с ником и соцсетями.
- **Browser Source** — алерты подписчиков (StreamElements, Streamlabs).

**Сцены**

- `Game` — основная игра.
- `BRB` — заставка с музыкой из разрешённого плейлиста.
- `Chatting` — камера крупно, игра свёрнута.

**Настройки**

- 1080p60, NVENC P5, 6000–8000 Kbps.
- Game Capture **Limit capture framerate** совпадает с FPS сцены.
- Два аудио: игра + микрофон. Discord на отдельной дорожке тише.

---

### 4. Podcast (подкаст с видео)

**Цель** — разговорный формат, несколько участников, минимум экрана.

**Источники**

- **Video Capture Device** — основная камера, средний план.
- **Image** — фон студии или размытый офис.
- **Audio Input Capture** — микрофон ведущего.
- **Audio Input Capture** — второй микрофон или NDI-аудио гостя.
- **Media Source** — заставка с названием выпуска.

**Сцены**

- `Intro` — заставка 10 секунд.
- `Talk` — оба участника в кадре через маски или два Video Capture.
- `Outro` — ссылки и призыв подписаться.

**Настройки**

- 1080p30, запись CRF 20, акцент на звук 48 kHz.
- Multitrack — каждый микрофон на свой трек.
- Освещение важнее разрешения.

---

### 5. Webinar (вебинар)

**Цель** — презентация, слайды, Q&A, демо по запросу.

**Источники**

- **Window Capture** — PowerPoint, Google Slides в режиме окна.
- **Video Capture Device** — докладчик в углу.
- **Text** — таймер сессии и хештег.
- **Browser Source** — форма вопросов или чат платформы.

**Сцены**

- `Slides` — слайды на весь экран, камера мала.
- `Demo` — Window Capture браузера или IDE.
- `Q&A` — камера крупно, слайды скрыты.
- `Hold` — заставка при технической паузе.

**Настройки**

- Стрим 1080p30, 5000 Kbps. Запись дублируется в MKV.
- Virtual Camera в Zoom если часть аудитории в конференции, OBS ведёт картинку для стрима на YouTube/VK.
- **Studio Mode** — переключение слайдов без показа панели презентации.

## Энциклопедия troubleshooting

Симптом → причина → решение. Более двадцати типичных ситуаций.

| # | Симптом | Вероятная причина | Что сделать |
|---|---------|-------------------|-------------|
| 1 | Чёрный экран в записи игры | Display Capture вместо Game Capture | Замените на Game Capture, режим Administrator для OBS |
| 2 | Чёрный экран на macOS | Нет разрешения Screen Recording | Системные настройки → Конфиденциальность → Запись экрана |
| 3 | Dropped Frames 5%+ | Битрейт выше upload | Снизьте bitrate на 500 Kbps, смените ingest-сервер |
| 4 | Dropped Frames при низком битрейте | Wi-Fi нестабилен | Ethernet, отключите VPN |
| 5 | Encoding lag красный | CPU перегружен x264 | NVENC/AMF/QSV или снизьте разрешение |
| 6 | Rendering lag | Тяжёлые фильтры, 4K canvas | Упростите сцену, Bilinear scale |
| 7 | Звук отстаёт от видео | Разная задержка устройств | Sync Offset в Advanced Audio Properties |
| 8 | Видео отстаёт от звука | Карта захвата | Video Delay в Advanced или sync на карте |
| 9 | Микрофон не слышно | Неверное устройство или mute | Проверьте Audio Input Capture и Windows Sound Settings |
| 10 | Эхо в наушниках | Мониторинг через колонки | Monitor only в наушники, отключите прослушивание в Windows |
| 11 | Роботизированный голос | Двойной Noise Suppression | Один RNNoise, уберите дубли в VST и OBS |
| 12 | Огромный файл записи | CRF слишком низкий или 1080p60 | CRF 22, 1080p30 для слайдов |
| 13 | MP4 не открывается | Обрыв записи | Пишите MKV, Remux после сессии |
| 14 | OBS вылетает при старте | Плагин несовместим | Запуск в Safe Mode — удержите Shift |
| 15 | Virtual Camera не в списке Zoom | Камера не запущена | Start Virtual Camera до входа в конференцию |
| 16 | Картинка растянута | Неверное соотношение сторон | Edit Transform → Fit to Screen |
| 17 | Текст в IDE размыт | Слишком низкий битрейт | 4500+ Kbps для 1080p или крупнее шрифт |
| 18 | FPS в игре просел | OBS на том же GPU | NVENC, ограничьте preview FPS, dual PC |
| 19 | Два источника одного окна | Дубли Window Capture | Один источник, кроп вместо второго захвата |
| 20 | Browser Source пустой | Блокировка CORS или JS | Обновите URL, снимите галку Shutdown when not visible для теста |
| 21 | Stinger зависает | Неверный Transition Point | Подберите кадр переключения вручную |
| 22 | NVENC не в списке | Старый драйвер | Обновите NVIDIA Studio или Game Ready |
| 23 | Красный квадрат вместо камеры | Камера занята другим приложением | Закройте Zoom, Telegram, перезапустите OBS |
| 24 | Задержка эфира 60+ сек | Норма для HLS Twitch | Ожидайте лаг чата, используйте низкую задержку на YouTube |
| 25 | VOD без звука Twitch | Soundtrack на отдельной дорожке | Музыка только из разрешённых источников Twitch |
| 26 | Рывки курсора в записи | Capture framerate mismatch | Совпадите FPS сцены и захвата |
| 27 | Шум вентилятора в микрофон | Направленный микрофон | Gate, микрофон дальше от корпуса, режим тихой работы ПК |

### Диагностика в один клик

- **Help → Log Files → View Current Log** — ошибки устройств и плагинов.
- **Stats** dock — encoding/rendering lag в реальном времени.
- **View → Always on Top** — OBS поверх игры для контроля без Alt+Tab.

## FAQ

**Нужен ли платный OBS?**

Нет. OBS Studio полностью бесплатен. Streamlabs Desktop — отдельный форк на базе OBS с другим интерфейсом.

**x264 или NVENC для учебного стрима?**

При карте NVIDIA 1660 и новее — NVENC. При слабой GPU и мощном CPU — x264 veryfast.

**720p или 1080p для кода?**

720p30 при upload ниже 6 Мбит/с. 1080p30 при хорошем канале и крупном шрифте IDE.

**MKV или MP4?**

MKV для записи, Remux в MP4 после. MP4 только для коротких сессий.

**Какой CRF для YouTube?**

18–22. Проверьте один фрагмент перед длинным курсом.

**Почему лагает превью, эфир нормальный?**

Preview нагружает GPU. **Right-click Preview → Enable Preview** отключите или снизьте разрешение preview.

**Можно ли стримить без карты захвата с двух ПК?**

Да, через NDI по сети. Игровой ПК отправляет, стриминговый принимает NDI Source.

**Как скрыть рабочий стол при Alt+Tab?**

Отдельная сцена BRB, Game Capture вместо Display, или захват одного окна.

**OBS видит микрофон, звука нет в файле**

Проверьте Tracks в Advanced Audio Properties — трек 1 включён для Recording.

**Как записать только микрофон без видео?**

Отключите все видеоисточники или используйте Profile только с аудио — не рекомендуется, лучше отдельный Audacity.

**Virtual Camera и стрим одновременно?**

Да. Start Streaming и Start Virtual Camera работают параллельно.

**Сколько RAM нужно для Browser Source чата?**

50–150 МБ на виджет. Закрывайте лишние Browser Source вне эфира.

**HEVC на Twitch?**

Обычно H.264. HEVC — тестовые режимы, проверяйте dashboard.

**AV1 для стрима в 2025?**

YouTube принимает. Twitch и VK — ориентируйтесь на H.264 для совместимости.

**Как уменьшить задержку?**

Меньший keyframe interval, zerolatency tune, сервер ingest ближе к вам, проводной интернет.

**Где хранить Stream Key?**

Только в OBS Settings. При утечке — сбросьте ключ в dashboard площадки.

**Нужен ли зелёный экран?**

Нет. AI Background Removal или размытый офис через StreamFX. Зелёный экран даёт чище край.

**Как тестировать без зрителей?**

Запись локально или **Twitch Bandwidth Test** с отдельным ключом. YouTube — скрытая трансляция.

**OBS тормозит на ноутбуке**

Питание от сети, высокая производительность в Windows, 720p, NVENC/QSV, отключите preview.

**Где FAQ по платформам?**

Дополнительные ответы — в [итогах раздела](./2).

## Чек-лист перед эфиром

- Сцены переключаются горячими клавишами.

- Stream Key актуален, ключ не светился на стриме.
- Dropped Frames 0% в тестовом стриме 2 минуты.
- BRB-сцена и заставка готовы.
- Анонс в Discord/Telegram — [Discord и Telegram для IT](/encyclopedia/9-spinoff/9-10-internet-kultura/135).
