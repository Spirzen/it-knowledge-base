# MIT App Inventor

<div class="article-tags">
  <span class="tag tag-required">ОБЯЗАТЕЛЬНО</span>
  <span class="tag tag-beginner">ДЛЯ НОВИЧКОВ</span>

<span class="complexity-badge">Начальный уровень</span>


**MIT App Inventor** — бесплатная среда от MIT для создания мобильных приложений **без набора текстового кода**. Логика строится из блоков; проект можно собрать в **APK** и установить на Android (через компanion-приложение или экспорт).

Проект изначально создавался компанией Google, а сейчас поддерживается Массачусетским технологическим институтом (MIT). Платформа использует блочный язык программирования (похожий на Scratch), благодаря чему разработка доступна детям, студентам и новичкам без опыта написания текстового кода.

Путеводитель: [Инструменты и среды](//tools/development/1).

## Как устроена среда

Процесс создания приложения разделен на две основные части - дизайнер и редактор блоков. 

| Часть | Назначение |
|-------|------------|
| **Designer** (дизайнер) | Раскладка кнопок, текста, картинок на экране |
| **Blocks** (блоки) | События и действия: "при нажатии → сделать" |
| **Эмулятор / телефон** | Проверка через MIT AI2 Companion |

> Дизайнер (Designer): Визуальный редактор интерфейса. Сюда перетаскиваются кнопки, текстовые поля, изображения, а также скрытые компоненты (сенсоры, GPS, Bluetooth).

Работа здесь происходит по принципу WYSIWYG («что видишь, то и получишь») — вы просто перетаскиваете элементы мышкой на виртуальный экран смартфона. Рабочее пространство Дизайнера разделено на четыре основные панели, которые используются слева направо - палитра, просмотр, компоненты, свойства.

```
┌──────────────────────────────────────────────────────────────────────────┐
│                             ПАНЕЛЬ ДИЗАЙНЕРА                             │
├───────────────┬──────────────────────┬───────────────────┬───────────────┤
│ 1. ПАЛИТРА    │ 2. ПРОСМОТР          │ 3. КОМПОНЕНТЫ     │ 4. СВОЙСТВА   │
│ (Palette)     │ (Viewer)             │ (Components)      │ (Properties)  │
│               │                      │                   │               │
│ [Кнопка]     │ ┌──────────────────┐ │ Screen1           │ Кнопка1       │
│ [Текст]       │ │ [   Текст    ]   │ │  ├── Кнопка1      │  • Текст: "ОК"│
│ [Изображение] │ │ [   Кнопка   ]   │ │  └── Картинка1    │  • Цвет: Синий│
│ [Сенсор]      │ └──────────────────┘ │                   │  • Размер: 14 │
└───────────────┴──────────────────────┴───────────────────┴───────────────┘
```

> Редактор блоков (Blocks Editor): Пространство для логики приложения. Программирование происходит путем сборки пазлов из цветных блоков, которые задают условия, циклы и математические операции.

Вместо написания текстового кода (как в Java или Python) вы собираете программу из цветных блоков, которые соединяются друг с другом как детальки конструктора LEGO. Рабочий стол разделен на две основные части:

```
┌────────────────────────────────────────────────────────────────────────┐
│                              РЕДАКТОР БЛОКОВ                           │
├──────────────────────────────┬─────────────────────────────────────────┤
│ 1. ПАЛИТРА БЛОКОВ (Blocks)   │ 2. РАБОЧАЯ ОБЛАСТЬ (Viewer)             │
│                              │                                         │
│  ▼ Встроенные (Built-in)     │   ┌──────────────────────────────────┐  │
│    ├─ Control (Управление)   │   │  Когда Кнопка1.Нажата делать:    │  │
│    ├─ Logic (Логика)         │   │  ┌─────────────────────────────┐ │  │
│    └─ Math (Математика)      │   │  │ Присвоить Надпись1.Текст    │ │  │
│                              │   │  │ значение "Привет!"          │ │  │
│  ▼ Компоненты экрана         │   │  └─────────────────────────────┘ │  │
│    └─ Кнопка1, Надпись1      │   └──────────────────────────────────┘  │
└──────────────────────────────┴─────────────────────────────────────────┘
```

Сайт: [appinventor.mit.edu](https://appinventor.mit.edu/) — вход через Google-аккаунт.

## Первый проект — кнопка и надпись

1. **Создать проект** → пустой экран `Screen1`.
2. В Designer перетащите **Button** и **Label**.
3. Перейдите в **Blocks**, выберите компонент `Button1`.
4. Соберите цепочку:

   - блок `when Button1.Click`
   - внутрь: `set Label1.Text to` → текст "Привет!"

5. Подключите телефон: установите **MIT AI2 Companion**, отсканируйте QR с экрана "Connect → AI Companion".
6. Нажмите кнопку на телефоне — надпись меняется.

Тот же принцип, что в [Scratch](./3): **событие → действие**.

## Полезные компоненты

| Компонент | Пример использования |
|-----------|---------------------|
| `TextBox` | Ввод имени, ответа на вопрос |
| `ListPicker` | Выбор из списка |
| `Camera` | Сделать фото по кнопке |
| `Sound` | Воспроизвести звук |
| `TinyDB` | Сохранить настройку на телефоне |
| `Clock` | Таймер, игра с интервалом |

Для викторины: `TinyDB` хранит счёт; `Clock` ограничивает время на ответ.

## От блоков к "настоящему" коду

Главная сила MIT App Inventor не в том, что он позволяет быстро «склепать» приложение, а в том, что он наглядно и без лишней рутины закладывает фундамент профессиональной разработки. По сути, визуальный конструктор убирает сложный синтаксис, обнажая чистую архитектуру, на которой строятся современные мобильные и веб-платформы. 

В традиционном обучении коду (например, консольные программы на Python) код выполняется линейно: от первой строчки к последней. В реальной жизни приложения так не работают. Они «ждут». App Inventor сразу учит мыслить категориями событий:
- Программа не знает, когда пользователь нажмет кнопку, встряхнет телефон или когда придет ответ из интернета.
- Золотые блоки `when ... do` — это и есть слушатели событий (Event Listeners). Смартфон постоянно находится в режиме ожидания, и как только событие происходит, триггерится конкретный обработчик. Это напрямую готовит к работе с `addEventListener` в JavaScript или `@interface` / `setOnClickListener` в Android Studio.

Разделение на Designer и Blocks — это чистая концепция разделения интерфейса и логики (близкая к паттерну MVC — Model-View-Controller).


App Inventor готовит к идеям **событийной модели** и **UI** — экраны, обработчики, состояние. Дальше по сложности — [Python](./6), [JavaScript](./7) или [Flutter](/encyclopedia/5-languages/5-22-dart/311.md) для кроссплатформенных приложений.

## Ограничения

- Ориентация в первую очередь на **Android** (iOS через отдельные обходные пути ограничен).
- Сложные 3D-игры и тяжёлая графика — в [Godot и Construct 3](/encyclopedia/9-spinoff/9-11-dlya-detey/2-video-games/27.md).
- Нужен интернет для облачной среды; офлайн — отдельная установка App Inventor на ПК.

При всей своей простоте и образовательной ценности, MIT App Inventor — это закрытая «песочница». Для создания масштабных коммерческих продуктов он не подходит из-за ряда серьезных архитектурных и технических ограничений.

Блоки не компилируются в чистый машинный код (как C++ или Kotlin). Они превращаются в промежуточный код на языке Scheme, который выполняется внутри специальной виртуальной машины (Kawa). Из-за этого тяжелые приложения, 3D-игры или сложные вычисления будут сильно тормозить. Когда логика приложения разрастается, экран Блоков превращается в огромный лабиринт, в котором тяжело ориентироваться. В текстовом коде проект можно разбить на сотни файлов и классов. В App Inventor вы привязаны к конкретному экрану.

Платформа не поддерживает системы контроля версий (например, Git). Два разработчика не могут одновременно редактировать один и тот же экран — проект просто перезапишет данные другого человека.

Максимальный размер готового проекта (файла .aia) на официальном сервере ограничен 30 МБ (в редких случаях лимит увеличивают до 50 МБ). Вы не сможете зашить внутрь приложения тяжелую графику, длинные видео или аудио треки.

Официально рекомендуется создавать не более 10 экранов на одно приложение. При превышении этого количества среда начинает жестко зависать, а само приложение на телефоне может вылетать из-за нехватки памяти. Для обхода этого ограничения приходится имитировать экраны через скрытие и показ контейнеров (Layouts).

Элементы интерфейса выглядят довольно устаревшими и стандартными. Создать кастомные анимации, сложные градиенты, скругления элементов "на лету" или плавные переходы между экранами стандартными средствами практически невозможно. Сложно сделать интерфейс, который будет одинаково идеально смотреться на маленьком смартфоне, вытянутом экране с «челкой» и на большом планшете.

Исторически платформа создавалась под Android. Поддержка iOS появилась намного позже, и до сих пор многие компоненты (особенно работа с Bluetooth, некоторыми датчиками и сторонними расширениями) на iPhone либо не работают, либо работают нестабильно. Выгрузить приложение в Google Play или Apple App Store можно, но процесс компиляции и подписи ключей в формате `.aab` (требуемом Google) часто вызывает технические сложности у новичков.

Когда базовых возможностей перестает хватать, продвинутые разработчики используют Расширения (Extensions — файлы `.aix`). Это куски настоящего текстового кода на Java, которые пишутся в сторонних средах и загружаются в App Inventor как новые блоки. С их помощью можно добавить продвинутую графику, работу с базами данных типа SQLite или глубокие настройки системы.
