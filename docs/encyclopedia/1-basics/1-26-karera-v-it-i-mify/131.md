---

## До старта (5 вопросов рекрутеру)

- [ ] Срок: календарные или рабочие дни; можно ли +1–2 дня при форс-мажоре
- [ ] Ожидаемые часы: ориентир **3–8 ч** для junior — норма; **20+ ч** без оплаты — обсудить scope
- [ ] Формат сдачи: GitHub (invite), архив, деплой
- [ ] Стек: обязательный / желательный; допустимы ли замены
- [ ] Обратная связь при отказе: да / нет

---

## Красные флаги — можно отказаться

| Сигнал | Действие |
|--------|----------|
| "Сделайте модуль нашего продукта" | Вежливый отказ или ссылка на портфолио |
| Нет срока и критериев | Запросить письменно; без ответа — не начинать |
| Конкурс идей стартапа | Отказ |
| Только закрытый доступ без правил по IP | Уточнить договорённости |

## Scope в README (шаблон)

```markdown
## Сделано
- …

## Отложено (вне срока / nice-to-have)
- …

## Нужно ещё ~N часов для
- …
```

---

## Минимум репозитория (разработка)

- [ ] `README.md` — запуск с нуля за 5–10 минут
- [ ] `.env.example`, секреты в `.gitignore`
- [ ] Зафиксированные версии зависимостей
- [ ] Тесты: happy path + 1–2 негативных сценария
- [ ] 3+ осмысленных коммита
- [ ] Линтер/форматтер прогнан

---

## Чек-лист перед отправкой

### Общее

- [ ] Запуск проверил "с чистого листа" (друг или новая VM)
- [ ] Ссылка открывается; для приватного repo — доступ выдан
- [ ] Сопроводительное письмо на 5–10 предложений (см. ниже)

---

### Аналитика / data

- [ ] SQL/ноутбук воспроизводится; источник данных описан
- [ ] Выводы с цифрами, без общих фраз

---

### QA

- [ ] Приоритеты: smoke / regression
- [ ] Баг-репорты: шаги, ожидание, факт, окружение

---

### DevOps

- [ ] `docker build` и `compose up` проходят
- [ ] CI зелёный на сдаваемом коммите

---

## Сопроводительное письмо (скелет)

1. Ссылка на repo / деплой.
2. Что из ТЗ сделано (списком).
3. Известные ограничения и что отложено.
4. Сколько времени ушло (по желанию).
5. Готовность разобрать на созвоне и дописать код live.

---

## После отправки

- [ ] Срок соблюдён; при задержке — предупредили заранее
- [ ] Готовы изменить код из тестового на [техническом интервью](./4)
- [ ] При отказе — один вежливый запрос feedback

## Частые ошибки перед отправкой

- Положили секреты в репозиторий.
- Не проверили запуск "с нуля" на чистой среде.
- Не описали, что сознательно не вошло в scope.
- Отправили без сопроводительного сообщения.

Короткая финальная проверка этих четырех пунктов экономит много отказов "по процессу", а не по навыкам.
