## FAQ — Часто задаваемые вопросы

Типичные затыки при разработке и отладке веб-приложений — "почему у меня не работает".

<div class="faq-list">

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> На localhost всё ок, на сервере белый экран — с чего начать?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Откройте <strong>консоль браузера и Network</strong> на проде — часто 404 на `bundle.js` или неверный `base` path. Проверьте, что статика задеплоена и пути совпадают с конфигом сборки. Подробнее здесь — [типы веб-приложений](/encyclopedia/1-basics/1-23-frontend-i-bekend/8).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> В консоли `Access-Control-Allow-Origin` — кто должен чинить, фронт или бэк?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> CORS — политика <strong>браузера</strong>; заголовки `Access-Control-Allow-*` выставляет сервер или прокси. Фронт "обойти" CORS не может (кроме dev-proxy). Подробнее здесь — [фронтенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/1).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> SPA — обновил страницу на `/profile` — 404 от nginx.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Сервер ищет файл `/profile`, которого нет — нужен <strong>fallback на index.html</strong> для client-side routing. Настраивается на веб-сервере/CDN. Подробнее здесь — [типы веб-приложений](/encyclopedia/1-basics/1-23-frontend-i-bekend/8).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Postman возвращает 200, `fetch` в браузере — ошибка.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Postman не применяет CORS и cookies как браузер. Сравните <strong>URL, метод, заголовки, credentials</strong> во вкладке Network. Подробнее здесь — [фронтенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/1).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> "Фронтендер говорит, API сломано; бэкендер — у меня 200".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Сверьте <strong>контракт</strong> — формат JSON, коды ошибок, поля. Один trace id в логах обеих сторон быстрее споров. Подробнее здесь — [бэкенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/2).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> С чего начать новичку — HTML или сразу React?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Базовый <strong>HTML/CSS/JS и DOM</strong> — иначе фреймворк "магия". После — компонентный подход и один фреймворк углублённо. Подробнее здесь — [фронтенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/1).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Вёрстка "плывёт" только в Safari на iPhone.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Проверьте <strong>flex/grid, vh units, date inputs</strong> — Safari имеет свои баги. DevTools remote debugging или BrowserStack. Подробнее здесь — [фронтенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/1).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `npm run build` падает с "JavaScript heap out of memory".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Увеличьте лимит Node (`NODE_OPTIONS=--max-old-space-size=4096`), упростите bundle, проверьте циклические импорты. На CI — больше RAM агента. Подробнее здесь — [фронтенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/1).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> JWT "протух" — пользователя выкидывает каждые 15 минут.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Нужен <strong>refresh token</strong> или silent renew; храните access коротким, refresh — HttpOnly cookie. Подробнее здесь — [бэкенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/2).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Cookie не уходит на API с другого домена.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Нужны `SameSite=None; Secure`, `credentials: 'include'` в fetch и CORS с конкретным origin, не `*`. Подробнее здесь — [фронтенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/1).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Mixed Content — страница HTTPS, API HTTP.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Браузер <strong>блокирует</strong> активный mixed content. Поднимите API на HTTPS или прокси через тот же origin. Подробнее здесь — [сеть для бэкенда](/encyclopedia/1-basics/1-23-frontend-i-bekend/6).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `.env` работает локально, на проде переменные пустые.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Vite/Webpack вшивают env на <strong>этапе сборки</strong> — задайте secrets в CI/CD и hosting panel. Не коммитьте `.env` с ключами. Подробнее здесь — [бэкенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/2).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Нужен ли nginx, если есть Node/Express?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> В проде часто <strong>reverse proxy</strong> — TLS, gzip, rate limit, статика. Node слушает localhost:3000, nginx — 443. Подробнее здесь — [Linux для бэкенда](/encyclopedia/1-basics/1-23-frontend-i-bekend/5).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Docker "упаковал бэкенд" — фронт туда же?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Часто <strong>отдельные контейнеры</strong> — static nginx + api + db. Multi-stage build для фронта: build → nginx image. Подробнее здесь — [бэкенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/2).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Страница грузится 8 секунд — пользователь винит "сервер медленный".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Разделите <strong>TTFB и размер bundle</strong> в DevTools Lighthouse. Часто виноваты тяжёлые JS-картинки без lazy load, а не только API. Подробнее здесь — [метрики](/encyclopedia/1-basics/1-23-frontend-i-bekend/3).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> API отвечает 500 — фронт показывает "undefined is not an object".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Фронт должен обрабатывать <strong>ошибки и пустые тела</strong>; параллельно смотрите stack trace на сервере и correlation id. Подробнее здесь — [наблюдаемость](/encyclopedia/1-basics/1-23-frontend-i-bekend/9).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Full-stack — это "знаю всё сразу"?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Это <strong>умение связать</strong> клиент и сервер end-to-end; глубину обычно наращивают по одной стороне, понимая смежную. Подробнее здесь — [intro](/encyclopedia/1-basics/1-23-frontend-i-bekend/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> SSR vs CSR — сайт-визитка тормозит на первом экране.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Для SEO и быстрого FCP визитке подойдёт <strong>SSG или SSR</strong>; тяжёлый SPA без нужды — лишний JS. Подробнее здесь — [типы приложений](/encyclopedia/1-basics/1-23-frontend-i-bekend/8).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> GraphQL "лучше REST" — мигрировать в учебном проекте?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> GraphQL решает <strong>overfetch/underfetch</strong>, но добавляет сложность схемы и кэша. Для первого API REST проще. Подробнее здесь — [бэкенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/2).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Мобильное приложение — это фронтенд или отдельный мир?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> UI на устройстве — клиент; тот же <strong>бэкенд API</strong> часто обслуживает web и mobile. React Native/Flutter — другой стек рендера, те же контракты. Подробнее здесь — [мобильные приложения](/encyclopedia/1-basics/1-19-programma/3).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> База "лежит рядом" с API в одном процессе — норм для прода?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Для учебного MVP — да; в проде БД <strong>отдельный сервис</strong> с бэкапами и пулом соединений. Подробнее здесь — [бэкенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/2).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Логи на сервере есть, в браузере "ничего не понятно" — как связать?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Передавайте <strong>X-Request-ID / trace id</strong> с фронта или генерируйте на gateway — один id в логах FE (console) и BE. Подробнее здесь — [наблюдаемость](/encyclopedia/1-basics/1-23-frontend-i-bekend/9).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Письма "не отправляются" из формы регистрации.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> SMTP, SPF/DKIM, попадание в spam — зона <strong>бэкенда и инфра</strong>. Проверьте очередь и логи mailer. Подробнее здесь — [исходящая почта](/encyclopedia/1-basics/1-23-frontend-i-bekend/7).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Хочу только "красивую кнопку" — это фронтенд без бэкенда?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Статическая вёрстка — да; как только нужны <strong>логин, данные, оплата</strong> — нужен сервер и БД. Подробнее здесь — [intro](/encyclopedia/1-basics/1-23-frontend-i-bekend/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> WebSocket чат работает у разработчика, на проде обрывается.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Прокси/nginx должен поддерживать <strong>Upgrade: websocket</strong>, таймауты idle. Load balancer без sticky session ломает long-lived соединения. Подробнее здесь — [сеть](/encyclopedia/1-basics/1-23-frontend-i-bekend/6).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> p99 latency вырос — пользователи "не замечают", чинить?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Среднее скрывает <strong>хвост медленных запросов</strong> — именно они бесят. Смотрите перцентили и SLO. Подробнее здесь — [метрики](/encyclopedia/1-basics/1-23-frontend-i-bekend/3).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Junior "full-stack" на собеседовании — реалистичные ожидания?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Часто ждут <strong>один стек глубже</strong> + базовое понимание второй стороны. Матрица компетенций помогает честно оценить пробелы. Подробнее здесь — [компетенции](/encyclopedia/1-basics/1-23-frontend-i-bekend/4).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> TypeScript ругается, `npm run dev` с `--ignore-build-errors` — так жить?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Временный костыль для прототипа; в CI <strong>сборка должна падать</strong> на type errors. Иначе баги уедут в прод. Подробнее здесь — [фронтенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/1).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Что такое фронтенд простыми словами?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Всё, что видит пользователь в браузере — <strong>HTML, CSS, JavaScript</strong>, интерфейс и запросы к API. Подробнее здесь — [фронтенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/1).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Что такое бэкенд backend?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Серверная часть — <strong>API, БД, бизнес-логика</strong>, авторизация, интеграции. Подробнее здесь — [бэкенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/2).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Frontend vs backend — в чём разница?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Клиент (браузер) vs сервер; связаны через <strong>HTTP/API</strong>. Подробнее здесь — [intro](/encyclopedia/1-basics/1-23-frontend-i-bekend/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> HTML CSS JavaScript — зачем все три?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> <strong>HTML</strong> — структура, <strong>CSS</strong> — вид, <strong>JS</strong> — поведение. Подробнее здесь — [фронтенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/1), [HTML](/encyclopedia/3-data-markup/3-09-html/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Что такое REST API?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> HTTP-методы (GET, POST…) и URL для обмена <strong>JSON</strong> между клиентом и сервером. Подробнее здесь — [бэкенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/2).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> CORS error fetch — как исправить?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Сервер должен отдать <strong>Access-Control-Allow-Origin</strong>; на dev — proxy в Vite/Webpack. Подробнее здесь — [фронтенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/1), [Fetch / axios — типовые запросы](/lab/Примеры/1145) (раздел CORS).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> React Vue Angular — что выбрать новичку?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Сначала чистый JS/DOM; затем один фреймворк глубоко — React популярен на рынке. Подробнее здесь — [фронтенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/1), [JavaScript](/encyclopedia/5-languages/5-01-javascript/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> SPA single page application — что это?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Одна HTML-страница, маршруты меняет <strong>JavaScript</strong> без полной перезагрузки. Подробнее здесь — [типы приложений](/encyclopedia/1-basics/1-23-frontend-i-bekend/8).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> SSR vs CSR vs SSG — разница?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> <strong>CSR</strong> — рендер в браузере; <strong>SSR</strong> — HTML на сервере; <strong>SSG</strong> — статика при сборке. Подробнее здесь — [типы приложений](/encyclopedia/1-basics/1-23-frontend-i-bekend/8).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> JWT токен — что это в вебе?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Подписанный токен для <strong>аутентификации</strong> без сессии на сервере; храните безопасно. Подробнее здесь — [бэкенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/2).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Full stack developer — кто это?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Разработчик, который делает и <strong>клиент, и сервер</strong> end-to-end. Подробнее здесь — [intro](/encyclopedia/1-basics/1-23-frontend-i-bekend/intro), [компетенции](/encyclopedia/1-basics/1-23-frontend-i-bekend/4).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Nginx зачем нужен веб-сервер?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> <strong>Reverse proxy</strong>, статика, TLS, балансировка перед Node/Python. Подробнее здесь — [Linux](/encyclopedia/1-basics/1-23-frontend-i-bekend/5).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Docker для веб-разработки — с чего начать?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Отдельные контейнеры api + db + nginx; docker-compose для локали. Подробнее здесь — [бэкенд](/encyclopedia/1-basics/1-23-frontend-i-bekend/2).</p>
</div>

## Что запомнить

Фронтенд и бэкенд — две стороны одного приложения. Пользователь видит клиент; сервер обеспечивает правила, данные и интеграции.

---

### Фронтенд

- Клиентская логика — UI, состояние, запросы к API, CORS, a11y — см. [Фронтенд](./1.md).
- Дизайн и вёрстка — часть цепочки, но не замена инженерной роли frontend-разработчика.
- Деплой зависит от типа приложения (статика, SPA, SSR) — [типы веб-приложений](./8.md).

---

### Бэкенд

- API, БД, очереди, безопасность, масштабирование — [Бэкенд](./2.md).
- Практика на сервере: [Linux](./5.md), [сеть](./6.md), [почта](./7.md).
- Карта навыков: [матрица компетенций](./4.md).

---

### Связка и качество

- Контракт API (форматы, коды ошибок, идемпотентность) согласуют обе команды.
- Метрики и SLO — [метрики производительности](./3.md); эксплуатация в проде — [наблюдаемость](./9.md).
- Самопроверка: [чек-лист](./99.md).

**Full-stack** объединяет обе стороны; даже при узкой специализации понимание смежной области ускоряет отладку и снижает "разрыв" между фронтом и бэком.
