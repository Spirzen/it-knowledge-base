## Назначение

Практический обзор **сетевых адаптеров в Windows** — что видит пользователь в "Сетевых подключениях", чем физический NIC отличается от виртуального, как менять параметры и что делать, если интернет пропал после правок. Теория MAC, DHCP и модели OSI — в [основах сети](./1.md) и [сетевых устройствах](./21.md#nic-adapter); диагностика сбоев — в [сетевых подключениях и диагностике](/encyclopedia/2-system-network/2-06-sistemnoe-administrirovanie/6).

**Где открыть настройки:**

| Способ | Что откроется |
| :--- | :--- |
| `Win + R` → `ncpa.cpl` | Классические "Сетевые подключения" — список адаптеров |
| **Параметры → Сеть и Интернет** | Wi‑Fi, Ethernet, VPN, сброс сети (см. [Windows 11 — настройка](/encyclopedia/2-system-network/2-01-operatsionnaya-sistema/415#parametry-sistemy)) |
| **Диспетчер устройств → Сетевые адаптеры** | Драйверы, отключение устройства, обновление |
| PowerShell | `Get-NetAdapter`, `Get-NetIPAddress`, `Get-DnsClientServerAddress` |

## Словарь терминов

Краткие определения, которые встречаются в свойствах адаптера и в именах устройств.

| Термин | Что это |
| :--- | :--- |
| **Адаптер** | Логический сетевой интерфейс в Windows — то, что отображается отдельной строкой в `ncpa.cpl`. За ним стоит железо или программный драйвер. |
| **NIC** (Network Interface Card) | Сетевой интерфейс: аппаратный чип или его программная эмуляция. "Карта" — историческое имя отдельной платы в слоте; сегодня NIC часто встроен в материнскую плату. |
| **NDIS-драйвер** | Драйвер по стандарту **Network Driver Interface Specification** — единый API Microsoft для всех сетевых адаптеров. Стек TCP/IP общается с NIC только через NDIS. |
| **Контроллер, чип и шина** | **Чип** — микросхема, которая кодирует/декодирует кадры Ethernet или Wi‑Fi. **Контроллер** — тот же чип в роли устройства на плате. **Шина** — как чип подключён к ПК: PCIe, USB, M.2. В диспетчере устройств имя часто содержит шину: "Realtek PCIe GbE". |
| **GbE** (Gigabit Ethernet) | Ethernet со скоростью линии **1 Гбит/с** (1000 Мбит/с). В имени адаптера "GbE" означает гигабитный порт. |
| **Эмуляция Ethernet** | Программная подача интерфейса как обычного Ethernet-NIC, хотя физически трафик уходит в туннель или гипервизор. Пример — TAP-адаптер для OpenVPN. |
| **Туннель** | Логический канал, в который **инкапсулируются** пакеты одного протокола внутри другого (например IP внутри UDP VPN). Для ОС туннель часто выглядит как отдельный адаптер. |
| **Miniport-драйвер** | Узкий NDIS-драйвер, управляющий одним виртуальным или физическим портом. VPN-клиенты и Hyper-V создают свои miniport-ы. |
| **Изолированная сеть** | Сегмент, недоступный из интернета и часто — из основной LAN хоста. Пример: VirtualBox Host-Only, внутренняя сеть ВМ без маршрута наружу. |
| **vEthernet** | Виртуальный Ethernet-порт Hyper-V на хосте Windows. Имя вида `vEthernet (Default Switch)` — подключение хоста к **виртуальному коммутатору**. |
| **Виртуальный коммутатор** | Программный L2-коммутатор (Hyper-V, VMware), к которому подключаются ВМ и хост. Распределяет кадры между портами так же, как физический switch. |
| **Сетевой мост** | Объединение двух адаптеров в один L2-сегмент: кадры прозрачно проходят между ними. Включение "Драйвера моста" и выделение bridge-интерфейса связывает, например, Wi‑Fi и Ethernet. |
| **Loopback** | Интерфейс "на самого себя": пакеты не выходят на провод. `127.0.0.1` — IP loopback; **KM-TEST Loopback Adapter** — искусственный Ethernet-NIC для тестов. |
| **APIPA** | Автоадрес `169.254.x.x`, который Windows выдаёт сама, если **DHCP не ответил**. В UI — "Неопознанная сеть" / "Ограниченная связь"; интернета обычно нет. |
| **Граница сети/хоста** | Деление IP-адреса на **сетевую часть** (общая для всех узлов подсети) и **хостовую** (уникальный номер узла). Задаётся **маской подсети** — см. [справочник CIDR](./619.md). |
| **Резолвер** | Компонент, который **преобразует имя в IP** (DNS-резолвер) или NetBIOS-имя в IP (WINS). В свойствах IPv4 поля "Предпочитаемый DNS" — адреса резолверов. |
| **WINS** | Устаревший сервис разрешения **NetBIOS-имён** в IP. В современных доменах заменён DNS; в свойствах адаптера остался для совместимости. |
| **OpenVPN** | Протокол и клиент VPN с открытым исходным кодом. На Windows ставит виртуальный **TAP-адаптер** — эмуляцию Ethernet для туннеля. |
| **WireGuard** | Современный лёгкий VPN-протокол. Использует драйвер **Wintun** вместо TAP; трафик идёт через виртуальный интерфейс туннеля. |

> **VPN — частная сеть. Правовая оговорка**  
> **VPN** (Virtual Private Network) — это **виртуальная частная сеть**: логический сегмент поверх общего канала, с шифрованием и контролем доступа. Корпоративный VPN даёт доступ к внутренним ресурсам компании; домашний — к своей NAS или лаборатории.  
> В Российской Федерации **недопустимо** использовать VPN и иные средства **для обхода блокировок** и доступа к информации из единого реестра запрещённых сайтов. Статья описывает устройство адаптеров в образовательных и административных целях — без инструкций по обходу ограничений. Подробнее — [VPN](./613.md).

## Физический и виртуальный адаптер

**Сетевой адаптер** (NIC) — интерфейс между операционной системой и сетью. Windows показывает каждый логический интерфейс отдельной "иконкой" в `ncpa.cpl`, хотя за ним может стоять и железо, и программный драйвер.

| Тип | Что это | Примеры в списке подключений |
| :--- | :--- | :--- |
| **Физический** | Чип и разъём на плате, в модуле M.2 или USB-донгле; передаёт кадры по кабелю или радиоканалу | "Realtek PCIe GbE", "Intel(R) Wi-Fi 6", "Bluetooth Device (Personal Area Network)" |
| **Виртуальный** | Программный интерфейс, созданный VPN, гипервизором, контейнером или службой виртуализации | "TAP-Windows Adapter V9", "Cisco AnyConnect", "Hyper-V Virtual Ethernet Adapter", "vEthernet (WSL)" |

Физический адаптер имеет **аппаратный MAC-адрес** (часто прошит в EEPROM). Виртуальный получает MAC от драйвера или гипервизора; при конфликте MAC в одном сегменте LAN возникают сбои ARP — см. [MAC-адрес](./1.md#mac-adres).

Один ПК обычно имеет **несколько адаптеров одновременно**: встроенный Ethernet, Wi‑Fi, Bluetooth PAN, плюс виртуальные от VPN и Docker/WSL. Маршрутизатор Windows выбирает, через какой интерфейс отправить пакет, по таблице маршрутизации и **метрике** интерфейса.

## Как создать виртуальный адаптер в Windows

Виртуальный NIC не появляется "сам" — его создаёт **установленное ПО** или **мастер добавления оборудования**. Ниже — типичные способы.

### 1. Тестовый loopback-адаптер (Microsoft KM-TEST)

Нужен для отладки сетевых служб без реального кабеля.

1. `Win + R` → `hdwwiz.exe` (или **Диспетчер устройств** → меню **Действие** → **Установить старое устройство**).
2. **Установить оборудование вручную** → **Сетевые адаптеры**.
3. Производитель **Microsoft** → **Microsoft KM-TEST Loopback Adapter**.
4. После установки в `ncpa.cpl` появится новый Ethernet-интерфейс; ему можно вручную задать IP из любой тестовой подсети.

Удаление: **Диспетчер устройств** → ПКМ по адаптеру → **Удалить устройство** (при необходимости — с удалением драйвера).

### 2. Hyper-V — vEthernet и виртуальный коммутатор

1. Включите компонент **Hyper-V** (Панель управления → Программы → Компоненты Windows).
2. **Диспетчер Hyper-V → Диспетчер виртуальных коммутаторов** → создайте switch типа **Внешний**, **Внутренний** или **Частный**.
3. Windows добавит **vEthernet (имя switch)** в `ncpa.cpl` — это порт хоста на виртуальном коммутаторе.

Внешний switch привязывает ВМ к физическому NIC; внутренний — только связь хост ↔ ВМ; частный — только между ВМ.

### 3. TAP-адаптер через OpenVPN

Установка [OpenVPN](https://openvpn.net/) или пакета с TAP-драйвером добавляет **TAP-Windows Adapter V9**. Клиент поднимает туннель — адаптер получает IP из частной сети VPN-провайдера или корпоративного концентратора.

### 4. WireGuard (Wintun)

Клиент [WireGuard](https://www.wireguard.com/) ставит драйвер **Wintun**. Интерфейс появляется при активации туннеля в приложении; отдельной иконки в `ncpa.cpl` может не быть — проверяйте `Get-NetAdapter` в PowerShell.

### 5. VirtualBox / VMware

- **VirtualBox**: **Файл → Настройки → Сеть** → Host-Only Adapter создаёт "VirtualBox Host-Only Ethernet Adapter".
- **VMware Workstation**: виртуальные сети VMnet0/1/8 создают **VMware Virtual Ethernet Adapter**.

### 6. WSL 2 и Docker Desktop

При первом запуске WSL 2 или Docker появляется **vEthernet (WSL)** или **vEthernet (DockerNAT)** — bridge к виртуальной машине лёгкого гипервизора. Удалять вручную не стоит: сломается контейнерная сеть.

## LAN, WLAN, Ethernet, Wi‑Fi и смежные технологии

Термины описывают **среду** и **протокол**, а не отдельный пункт меню Windows — но в диспетчере устройств и в подписях адаптеров они встречаются постоянно.

| Термин | Смысл | Связь с адаптером в Windows |
| :--- | :--- | :--- |
| **LAN** (Local Area Network) | Локальная проводная или беспроводная сеть в здании | Любой активный NIC с адресом из RFC 1918 |
| **WLAN** (Wireless LAN) | Беспроводная LAN по IEEE 802.11 | Адаптер Wi‑Fi в разделе "Сеть и Интернет → Wi‑Fi" |
| **Ethernet** | Семейство стандартов проводной LAN (витая пара, оптика) | "Ethernet", "GbE", "2.5GbE" в имени адаптера |
| **Wi‑Fi** | Пользовательское имя WLAN; радиоканал 2,4 / 5 / 6 ГГц | Отдельный Wi‑Fi адаптер или комбо Wi‑Fi + Bluetooth |
| **VLAN** (Virtual LAN) | Логическое разделение одного физического сегмента по метке 802.1Q | В Windows — через драйвер NIC (VLAN ID в свойствах "Дополнительно") или коммутатор; не путать с виртуальным адаптером VPN |
| **Bluetooth** | Краткодистанционная PAN; не замена Wi‑Fi для интернета | "Bluetooth Device (Personal Area Network)" — редко используется для выхода в интернет |
| **USB** | Шина подключения; сетевой адаптер может быть USB-Ethernet или USB-Wi‑Fi | Отдельное устройство в "Сетевые адаптеры" с пометкой USB |

Подробнее про Wi‑Fi и Bluetooth как технологии — [Беспроводные сети](./71.md).

## Как менять настройки и на что они влияют

### Порядок действий

1. **`ncpa.cpl`** → ПКМ по нужному адаптеру.
2. **Отключить** / **Включить** — мгновенно рвёт линк без удаления конфигурации.
3. **Состояние** — скорость линка, счётчики пакетов; кнопка **Сведения** → физический MAC.
4. **Свойства** → список компонентов (IPv4, клиент Microsoft, QoS…) — см. [ниже](#komponenty-privyazki).
5. **Протокол TCP/IPv4 → Свойства** — DHCP или статический адрес, DNS, метрика.
6. **Настроить → Дополнительно** — offload, энергосбережение, VLAN ID, Wake-on-LAN — см. [расширенные свойства](#dopolnitelno-adaptera).
7. **Переименовать** — удобно в PowerShell-скриптах (`Rename-NetAdapter`).

Перед правками на рабочем ПК сделайте скриншот окна IPv4 или экспорт:

```powershell
Get-NetIPConfiguration -All | Format-List
```

### Что влияет на интернет в первую очередь

| Настройка | Если задано неверно |
| :--- | :--- |
| Снята галочка **IPv4** | Нет IP — нет маршрута в сеть |
| Статический IP **не из подсети роутера** | Нет связи с шлюзом |
| Неверный **основной шлюз** | Пакеты не уходят за пределы LAN |
| Неверные **DNS** | Сайты по имени не открываются, `ping 8.8.8.8` при этом может работать |
| Адаптер **отключён** | Полная потеря связи по этому интерфейсу |
| **APIPA** `169.254.x.x` | DHCP не сработал — проверьте кабель, Wi‑Fi, роутер |
| VPN с **низкой метрикой** | Весь трафик уходит в туннель; при обрыве VPN — "нет интернета" |
| Отключён **EEE** / сбой драйвера | Реже — обрывы линка, низкая скорость |

Профиль "Общедоступная сеть" **сам по себе** интернет не блокирует — меняются только правила брандмауэра для входящих подключений.

## Если интернет пропал из-за настроек адаптера

Действуйте сверху вниз — от простого к радикальному.

### Шаг 1. Проверить, жив ли интерфейс

```cmd
ipconfig /all
ping 192.168.1.1
ping 8.8.8.8
nslookup example.com
```

- Нет IP или `169.254.x.x` → проблема DHCP или отключённый адаптер.
- Ping шлюза не проходит → кабель, Wi‑Fi, неверная статика.
- Ping IP проходит, имена нет → DNS.
- Ничего не проходит → шлюз, VPN-маршрут или отключён IPv4.

### Шаг 2. Вернуть автоматические настройки

**IPv4 → Свойства** → включить **Получить IP-адрес автоматически** и **Получить DNS автоматически** → OK.

```cmd
ipconfig /release
ipconfig /renew
ipconfig /flushdns
```

В PowerShell:

```powershell
Set-NetIPInterface -InterfaceAlias "Ethernet" -Dhcp Enabled
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ResetServerAddresses
```

### Шаг 3. Включить адаптер и сбросить метрику

В `ncpa.cpl` — **Включить**, если интерфейс серый. У VPN, оставшегося после удаления клиента, — **Отключить** или удалить.

### Шаг 4. Откатить компоненты и "Дополнительно"

- Включите обратно **Протокол Интернета версии 4**.
- В **Дополнительно** верните **Energy-Efficient Ethernet** / **Green Ethernet** в значение по умолчанию или отключите, если обрывы начались после их включения.

### Шаг 5. Драйвер

**Диспетчер устройств** → ПКМ по NIC → **Откатить драйвер** (если доступно) или **Обновить** с сайта OEM.

### Шаг 6. Сброс сети Windows

**Параметры → Сеть и Интернет → Дополнительные сетевые параметры → Сброс сети** (или **Состояние → Сброс сети** в части сборок). Удалит профили Wi‑Fi и переустановит стек; **статические IP придётся ввести заново**. Подробнее — [Параметры системы](/encyclopedia/2-system-network/2-01-operatsionnaya-sistema/415#parametry-sistemy).

### Шаг 7. Диагностика по runbook

Трассировка, `netsh`, таблица маршрутов — в [Сетевые подключения и диагностика](/encyclopedia/2-system-network/2-06-sistemnoe-administrirovanie/6).

## Драйверы сетевых адаптеров

Драйвер сетевого адаптера — модуль ядра (файлы `.sys`) и пользовательская часть, которая переводит запросы стека TCP/IP в команды чипу NIC. Без корректного драйвера адаптер в `ncpa.cpl` может быть серым, с жёлтым восклицательным знаком в диспетчере устройств или с именем "Сетевой адаптер" без производителя.

### Цифровая подпись

Windows (начиная с 64-bit Vista/7) по умолчанию загружает только **подписанные** драйверы режима ядра. Подпись подтверждает, что пакет драйвера не изменён после сборки издателем. При установке неподписанного драйвера система блокирует загрузку; обход — режим **Отключить обязательную проверку подписи драйверов** в меню восстановления (Startup Settings) — только для отладки, не для постоянной эксплуатации.

Проверка в PowerShell (от администратора):

```powershell
Get-WindowsDriver -Online -All | Where-Object ProviderName -match 'Realtek|Intel'
```

### Категории и виды

| Категория | Назначение |
| :--- | :--- |
| **Мини-порт** (miniport) | Основной NDIS-драйвер NIC — Ethernet, Wi‑Fi, WWAN |
| **Фильтр** (filter driver) | Промежуточный слой: QoS, WFP, антивирус, VPN |
| **Протокол** | Привязка к адаптеру: "Клиент для сетей Microsoft", "Протокол Интернета версии 4" |
| **Служба** | Вспомогательная логика в стеке (не путать со службой Windows) |

Обновление: **Диспетчер устройств → Сетевой адаптер → Обновить драйвер**; для OEM-ноутбуков — пакет с сайта производителя; для серверных NIC — с сайта Intel/Broadcom/Mellanox. Центр обновления Windows иногда предлагает драйверы в **Необязательных обновлениях** — см. [Параметры системы](/encyclopedia/2-system-network/2-01-operatsionnaya-sistema/415#parametry-sistemy).

## Физические адаптеры — Gigabit, Realtek и другие

В списке подключений и диспетчере устройств имена отражают **чип и шину**, а не только скорость:

| Пример имени | Что за устройство |
| :--- | :--- |
| **Realtek PCIe GbE Family Controller** | Встроенный или дискретный Gigabit Ethernet на PCI Express |
| **Realtek USB GbE Family Controller** | USB 3.0 — Ethernet (док-станция, переходник) |
| **Intel(R) Ethernet Connection I219-V** | Встроенный GbE на чипсете Intel |
| **Intel(R) Wi-Fi 6 AX201** | Встроенный Wi‑Fi 6 |
| **Killer E3100G 2.5 Gigabit** | 2,5 Гбит/с Ethernet (маркетинговое имя поверх чипа Qualcomm/Atheros) |
| **Broadcom NetXtreme** | Серверные и desktop GbE/10GbE |

**Gigabit** (1 Гбит/с) — типичная скорость порта на материнских платах последних 15 лет; **2,5G / 5G / 10G** — следующие ступени (нужен совместимый коммутатор и кабель Cat5e+). Скорость согласования видна в **Состояние → Скорость** (через свойства адаптера) или в `Get-NetAdapter | Select Name, LinkSpeed`.

Realtek — один из самых частых вендоров **бюджетного GbE** на потребительских платах; драйверы идут с Windows Update или с [realtek.com](https://www.realtek.com). При нестабильной ссылке админы нередко откатывают версию драйвера или отключают энергосберегающие опции в "Дополнительно" (см. ниже).

## Виртуальные адаптеры — VPN, гипервизоры, эмуляторы

Виртуальный адаптер появляется после установки ПО, которому нужен **собственный L2/L3 интерфейс** в стеке Windows:

| Имя / источник | Зачем создаётся |
| :--- | :--- |
| **TAP-Windows Adapter V9** | OpenVPN — эмуляция Ethernet для туннеля |
| **Wintun** | WireGuard — легковесный виртуальный интерфейс |
| **Cisco AnyConnect Virtual Miniport** | Корпоративный VPN Cisco |
| **SonicWall NetExtender**, **Check Point**, **Fortinet** | VPN вендоров — свои miniport-драйверы |
| **Hyper-V Virtual Ethernet Adapter** / **vEthernet (Default Switch)** | Виртуальный коммутатор Hyper-V для ВМ и контейнеров |
| **VirtualBox Host-Only Network** | Изолированная сеть между хостом и ВМ VirtualBox |
| **VMware Virtual Ethernet Adapter** | Сети VMware Workstation (VMnet) |
| **DockerNAT**, **vEthernet (WSL)** | Сетевой мост WSL 2 / Docker Desktop к хосту |
| **Microsoft KM-TEST Loopback Adapter** | Тестовый loopback (добавляется вручную) |

После удаления VPN или гипервизора "хвосты" TAP/miniport иногда остаются в `ncpa.cpl` — их можно удалить через **Установка и удаление программ** или "Удалить устройство" в диспетчере с галочкой "Удалить программы драйверов". Несколько активных VPN одновременно часто конфликтуют по маршрутам — см. [VPN](./613.md).

<span id="svoystva-ipv4"></span>

## Свойства сети — IPv4, DHCP, DNS

**ПКМ по адаптеру → Свойства → Протокол Интернета версии 4 (TCP/IPv4) → Свойства** — главный экран адресации.

### DHCP и автоматическое получение IP

При выборе **Получить IP-адрес автоматически** и **Получить адрес DNS-сервера автоматически** интерфейс запрашивает параметры у **DHCP-сервера** (обычно на роутере). Срок аренды, шлюз и DNS приходят в одном ответе DHCP ACK.

Если DHCP недоступен, Windows назначает **APIPA** — адрес из `169.254.0.0/16` ("ограниченная связь"). Таблица специальных диапазонов — [справочник IP](./619.md#special-ipv4).

### Статическая настройка

| Поле | Назначение |
| :--- | :--- |
| **IP-адрес** | Уникальный адрес узла в подсети (например `192.168.1.50`) |
| **Маска подсети** | Граница сети/хоста (часто `255.255.255.0` = `/24`) |
| **Основной шлюз** | Маршрутизатор для трафика вне подсети (часто `.1` в домашней LAN) |
| **Предпочитаемый DNS-сервер** | Первый резолвер для имён |
| **Альтернативный DNS-сервер** | Резервный резолвер при недоступности первого |

Публичные DNS (1.1.1.1, 8.8.8.8 и др.) — в [справочнике](./619.md). В корпоративной сети DNS лучше брать **только с DHCP** или с внутренних серверов — иначе ломается разрешение внутренних имён Active Directory.

### Дополнительно (кнопка внизу окна IPv4)

- **Метрика интерфейса** — чем **меньше** число, тем **выше приоритет** при выборе маршрута по умолчанию, если несколько адаптеров активны. Типичный сценарий: Ethernet `10`, Wi‑Fi `50`, VPN `1` (чтобы весь трафик шёл в туннель).
- **Основной DNS-суффикс** — домен по умолчанию для коротких имён (`server` → `server.corp.local`).
- **Суффикс подключения DNS** — суффикс, привязанный к этому интерфейсу (в DHCP может приходить option 15).

PowerShell-аналог:

```powershell
Get-NetIPConfiguration -InterfaceAlias "Ethernet"
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses ("192.168.1.1","1.1.1.1")
```

<span id="wins-netbios"></span>

## WINS, NetBIOS и LMHOSTS

Эти механизмы относятся к **устаревшему именованию NetBIOS** в сетях Windows. В современных доменах Active Directory основной резолвинг — **DNS**, но пункты всё ещё видны в свойствах IPv4 → Дополнительно → вкладка **WINS**.

| Элемент | Назначение |
| :--- | :--- |
| **WINS** (Windows Internet Name Service) | Сервер разрешения имён NetBIOS в IP (наследие NT4 / ранних доменов) |
| **Адреса WINS-серверов** | Один или два сервера (редко нужны без legacy-среды) |
| **Протокол LMHOSTS** | Файл `%SystemRoot%\System32\drivers\etc\lmhosts` — статическая таблица NetBIOS-имён |
| **NetBIOS через TCP/IP** | Режим: по умолчанию (с DHCP), включён, выключен; влияет на широковещание имён в LAN |

Для домашней сети и чистого DNS обычно достаточно **отключить NetBIOS через TCP/IP** на интерфейсе интернета (снижает лишний шум в LAN). В корпоративной среде политику задаёт GPO — не меняйте без согласования с админами.

<span id="komponenty-privyazki"></span>

## Компоненты в свойствах адаптера

**Свойства адаптера** (не путать с IPv4) — список **служб и протоколов**, привязанных к NIC. Порядок для исходящего трафика: сверху вниз (в старых версиях Windows можно было менять стрелками; в Windows 10/11 порядок фиксирован, но компоненты включаются галочками).

| Компонент | Назначение |
| :--- | :--- |
| **Клиент для сетей Microsoft** | Доступ к файлам и принтерам по SMB в LAN (NetBIOS/ Direct SMB) |
| **Общий доступ к файлам и принтерам для сетей Microsoft** | Публикация ресурсов хоста в сети (ответ на запросы SMB) |
| **Планировщик пакетов QoS** | Приоритизация исходящих потоков по политикам Group Policy / приложений |
| **Протокол Интернета версии 4 (TCP/IPv4)** | Основной стек IPv4 — обязателен для типичного интернета |
| **Протокол Интернета версии 6 (TCP/IPv6)** | IPv6; отключение иногда используют при диагностике "зависаний" на битом v6 у провайдера |
| **Драйвер моста** | Прозрачное объединение нескольких адаптеров в сетевой мост (L2) |
| **Вложенная виртуализация сети** | Поддержка виртуализации внутри гостевых ВМ Hyper-V |
| **Протокол мультиплексора сетевого адаптера** | NIC Teaming — объединение нескольких физических NIC в один логический (серверы) |
| **Драйвер протокола LLDP** | Link Layer Discovery Protocol — обмен информацией о соседях с коммутатором |
| **Отвечающее устройство обнаружения топологии** / **Ответчик обнаружения топологии** | Протоколы **LLTD** — карта сети в "Центре сети и общего доступа" (legacy) |
| **Расширяемый виртуальный коммутатор Hyper-V** | Виртуальный коммутатор Hyper-V на этом физическом порту |

Снятие галочки **"Клиент для сетей Microsoft"** отключает доступ к `\\server\share`, но **не** отключает интернет по HTTP. Снятие **IPv4** полностью лишает адаптер IP-адресации.

<span id="profili-seti"></span>

## Частная, домашняя и общественная сеть

**Профиль сети** (network location) определяет **брандмауэр Windows** и правила обнаружения устройств — не путать с SSID Wi‑Fi.

| Профиль в UI | Поведение брандмауэра |
| :--- | :--- |
| **Частная сеть** (Private) | Разрешено обнаружение ПК, общий доступ к файлам/принтерам в доверенной LAN |
| **Общедоступная сеть** (Public) | Строгие правила; ПК "невидим" для соседей — кафе, аэропорт, гостевой Wi‑Fi |
| **Доменная сеть** (Domain) | В домене AD; политики с контроллера домена |

В Windows 10/11 при первом подключении система спрашивает: "Доверяете ли вы этой сети?". **Домашняя сеть** в бытовом языке обычно означает **частный профиль** на домашнем Wi‑Fi/Ethernet.

Смена профиля: **Параметры → Сеть и Интернет → Wi‑Fi / Ethernet → свой адаптер → Профиль сети**; или PowerShell:

```powershell
Get-NetConnectionProfile
Set-NetConnectionProfile -InterfaceAlias "Wi-Fi" -NetworkCategory Private
```

<span id="dopolnitelno-adaptera"></span>

## Расширенные свойства адаптера ("Дополнительно")

**Свойства адаптера → Настроить → Дополнительно** — параметры **чипа и драйвера** (названия зависят от вендора). Типичные пункты и смысл:

| Параметр | Что делает |
| :--- | :--- |
| **ARP Offload** | Часть обработки ARP на NIC — снижает нагрузку на CPU |
| **AutoDetach** | Отсоединение от сети при простое (мобильные сценарии) |
| **Energy-Efficient Ethernet (EEE)** | Снижение потребления на неактивном линке — иногда вызывает нестабильность с старыми коммутаторами |
| **Green Ethernet** | Аналогичные энергосберегающие режимы Realtek |
| **Interrupt Moderation Rate** | Пакетирование прерываний — выше производительность, выше задержка |
| **IPv4 Checksum Offload** | Контрольная сумма IPv4 на NIC |
| **TCP/UDP Checksum Offload** | Контрольные суммы транспортного уровня на NIC |
| **Large Send Offload (LSO)** / **TCP Segmentation Offload** | Сегментация больших TCP-пакетов на NIC |
| **JumboPacket** | Кадры > 1500 байт (нужен Jumbo Frames на всём пути) |
| **Packet Priority** / **802.1p** | Приоритетные метки QoS на исходящих кадрах |
| **VLAN ID** | Метка 802.1Q на исходящем трафике (корпоративные сети) |
| **MAC Passthrough** / **Locally Administered Address** | Подмена MAC (виртуализация, клонирование) |
| **Wake on Magic Packet** | Включение ПК по "магическому" UDP-пакету (Wake-on-LAN) |
| **Wake on pattern match** | Пробуждение по шаблону в кадре |
| **Wake on link change** | Реакция на подключение/отключение кабеля |
| **WOL Link Power Saving** | Энергосбережение линка при WoL |
| **SelectiveSuspend** / **SSIdleTimeout** | USB-адаптеры: отключение порта при простое |
| **NS Offload** | Offload Neighbor Discovery (IPv6) |

При "обрывах" Gigabit на Realtek/Intel первым делом пробуют отключить **EEE/Green Ethernet** и обновить драйвер. Offload почти всегда оставляют **включённым** — отключение нагружает CPU на высокой скорости.
