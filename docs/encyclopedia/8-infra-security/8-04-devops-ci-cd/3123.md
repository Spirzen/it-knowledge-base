# E2E-тесты и CI с Playwright и GitHub Actions

<div class="article-tags">
  <span class="tag tag-required">ОБЯЗАТЕЛЬНО</span>
</div>

<span class="complexity-badge">Разработчику</span>
<span class="complexity-badge">Тестировщику</span>

**E2E (end-to-end)** тесты проверяют приложение **глазами пользователя**: открытие страницы, клик, заполнение формы, ожидание ответа API. **Playwright** — кроссбраузерный фреймворк (Chromium, Firefox, WebKit) от Microsoft. **GitHub Actions** — CI/CD в репозитории GitHub: сборка, тесты, деплой по событиям.

База: [DevOps и CI/CD](/encyclopedia/8-infra-security/8-04-devops-ci-cd/intro), [тестирование в проекте](/encyclopedia/7-project/7-05-testirovanie/intro), [Git](/encyclopedia/4-code-dev/4-11-rabota-s-git/intro).

## Пирамида тестирования и место E2E

| Уровень | Скорость | Стабильность | Что ловит |
|---------|----------|--------------|-----------|
| Unit | Высокая | Высокая | Логика функции |
| Integration | Средняя | Средняя | БД, API, очереди |
| E2E | Низкая | Ниже | Сломанный UX, регресс в цепочке |

Много E2E — **хрупкий pipeline** (flaky из-за таймингов). Правило: критичные **сценарии** (логин, оплата, создание заказа), не каждая кнопка.

## Playwright: минимум

```javascript
// Пример: проверка заголовка после перехода
import { test, expect } from '@playwright/test';

test('главная открывается', async ({ page }) => {
  await page.goto('https://example.com');
  await expect(page).toHaveTitle(/Example/);
});
```

Ключевые идеи:

- **Автоожидание** — меньше `sleep`, больше `expect` с retry.
- **Селекторы** — предпочитайте `data-testid`, роли ARIA; хрупкие XPath по DOM-дереву ломаются при рефакторинге UI.
- **Параллельный запуск** — шарды в CI ускоряют прогон.
- **Трассировка** — при падении сохраняется trace для разбора.

Playwright работает с SPA (React, Vue) и классическим SSR.

## GitHub Actions: workflow для тестов

Типичный `.github/workflows/e2e.yml`:

- **on**: `pull_request`, `push` в `main`;
- **jobs**: `checkout` → `setup-node` → `npm ci` → `npx playwright install --with-deps` → `npx playwright test`;
- **артефакты**: отчёт HTML при failure.

Секреты (URL staging, test user) — в **GitHub Secrets**, не в YAML в открытом виде.

Связь с [защитой веток](/encyclopedia/8-infra-security/8-03-zabota-o-kode-i-dannyh/intro): merge только при зелёном CI.

## Flaky tests: как снижать

- фиксированные тестовые данные или seed;
- изоляция тестов (отдельный пользователь на тест);
- запрет зависимости от продакшен API без mock;
- quarantine: помечать нестабильные тесты и чинить, не отключать весь suite.

## Итоги

Playwright закрывает **пользовательский сценарий**; GitHub Actions — **автоматический прогон** на каждый PR. Вместе они поднимают уверенность в релизе без ручного «потыкайте форму».
