# Удалённая команда — чек-лист

Используйте список на retro или аудите процессов. Отмечайте честно: цель — найти **2–3 улучшения**, а не получить 100% галочек с первого раза.

См. [основную статью](./1) и [итоги](./998).

---

## Async-first и коммуникация

- [ ] В wiki описано правило **async-first**: когда писать, когда звонить.
- [ ] Есть согласованный **SLA ответа** в чате (например, рабочий день в TZ автора).
- [ ] Блокеры фиксируются в **тикете** с assignee и @mention, не только в DM.
- [ ] После sync-встреч публикуется **summary** (решения, action items, ссылки).
- [ ] @channel используется только для инцидентов и критичных объявлений.
- [ ] Длинные обсуждения идут в **тредах**, не в общем потоке канала.

---

## Часовые пояса и overlap

- [ ] У каждого участника в профиле/календаре указан **часовой пояс**.
- [ ] Определено **overlap window** (2–4 ч) и оно известно команде.
- [ ] Общие встречи ставятся **в overlap**, не в крайние часы одного региона.
- [ ] Время recurring-встреч **ротируется** раз в 1–2 месяца (где применимо).
- [ ] Дедлайны указываются в **UTC** или с явной TZ (MSK, CEST и т.д.).
- [ ] Учтён переход на летнее/зимнее время в EU в календарях.

---

## Документация и источник правды

- [ ] Архитектурные решения есть в **ADR/wiki**, не только в записи звонка.
- [ ] Статус задачи живёт в **трекере**, не "готово" только в чате.
- [ ] Есть страница wiki **"Как мы работаем"** (ритуалы, инструменты, SLA).
- [ ] [Онбординг-пакет](/encyclopedia/7-project/7-09-bazy-znaniy-i-zadachniki/24) актуален и доступен без офиса.
- [ ] API и интеграции описаны так, что backend в MSK и QA в EU читают одно и то же.

---

## Daily и ритуалы

- [ ] Daily **≤ 15 минут** sync или есть рабочий **async daily** в канале.
- [ ] Формат daily зафиксирован: вчера / сегодня / блокеры.
- [ ] Planning и refinement имеют **agenda заранее** (async-вопросы до созвона).
- [ ] Demo записывается или сопровождается release notes для отсутствующих.

[Ежедневные стендапы](/encyclopedia/7-project/7-02-komanda-i-upravlenie/111)

---

## Инструменты

- [ ] Чат с **тредами** — основной канал обсуждений.
- [ ] **Трекер** — единый источник задач и статусов.
- [ ] **Wiki** — процессы, runbook, глоссарий.
- [ ] Git + CI — PR и review без обхода процесса "потому что удалёнка".

---

## Онбординг и язык

- [ ] Онбординг работает **без** физического офиса (доступы, buddy, первая задача с DoR).
- [ ] Buddy назначается в **том же или соседнем TZ** на 2–4 недели.
- [ ] Критичные **runbook** для on-call доступны на языке **всех** дежурных или с bilingual summary.
- [ ] Термины продукта собраны в [глоссарии](/encyclopedia/7-project/7-04-analitika/1231).
- [ ] Язык тикетов и wiki согласован (RU/EN) и задокументирован.

---

## On-call и инциденты

- [ ] Handoff между регионами описан с временем в **UTC**.
- [ ] Runbook связан с [инцидентами](/encyclopedia/7-project/7-21-incidenty-i-ekspluatatsiya/intro).
- [ ] Инциденты не требуют "всех online" вне on-call — есть эскалация.

---

## Безопасность и границы

- [ ] Соблюдается [политика ИБ](/encyclopedia/8-infra-security/8-07-informatsionnaya-bezopasnost/intro) (VPN, секреты на созвонах).
- [ ] Нет культуры ответа **24/7** вне инцидентов.
- [ ] [Политика ИИ/Copilot](/encyclopedia/7-project/7-24-ii-v-proektnom-protsesse/1) доступна всем TZ в wiki.

---

## Связь с доставкой

- [ ] [DoR](/encyclopedia/7-project/7-25-dostavka-i-gotovnost/1) в шаблоне тикета — задачу можно взять async.
- [ ] [DoD](/encyclopedia/7-project/7-25-dostavka-i-gotovnost/2) проверяется в CI/review, не только на demo live.

## Оценка зрелости (ориентир)

| Галочек | Уровень |
|---------|---------|
| &lt; 40% | Старт: overlap + SLA + summary после встреч |
| 40–70% | Рабочая удалёнка: усилить DoR и онбординг |
| &gt; 70% | Зрелая распределённая команда: точечные улучшения |

## Быстрая самопроверка (5 минут)

1. Overlap window записан в wiki?  
2. Summary после последнего planning был?  
3. Один runbook on-call доступен на языке всех дежурных?

Если нет на два из трёх — начните с [статьи 1](./1), раздел overlap и documentation-first.
