# Найм в команду разработки — портрет и вакансия

<div class="article-tags">
  <span class="tag tag-required">ОБЯЗАТЕЛЬНО</span>
</div>

<span class="complexity-badge">Руководителю</span>

Найм — цепочка: **портрет** → **вакансия** → отбор → интервью → оффер → **онбординг** → испытательный срок. Успех измеряется тем, остался ли человек продуктивным через 6–12 месяцев, а не скоростью закрытия вакансии в ATS.

Со стороны **соискателя** процесс разобран в [HR и рекрутинг](/encyclopedia/1-basics/1-26-karera-v-it-i-mify/6). Здесь — задачи **тимлида и техлида** до первого собеседования.

После выхода — [Первые 90 дней тимлида](./141) и онбординг сотрудника в [этапах роста](/encyclopedia/1-basics/1-26-karera-v-it-i-mify/3#онбординг).

---

## Воронка найма

```mermaid
flowchart LR
  A[Портрет] --> B[Вакансия]
  B --> C[Отклики / ATS]
  C --> D[Скрининг HR]
  D --> E[Техинтервью]
  E --> F[Финал / культура]
  F --> G[Оффер]
  G --> H[Онбординг]
  H --> I[Испытательный срок]
```

Тимлид влияет на **A–E** и **H** сильнее всего.

---

## Шаг 1 — портрет кандидата

Составьте **до** текста вакансии (с HR или без — но для себя обязательно).

---

### Техническая часть

Разделите навыки:

| Категория | Пример |
|-----------|--------|
| **Обязательно** | 3+ года Java, Spring, прод с PostgreSQL |
| **Желательно** | Kafka, опыт в финтехе |
| **Будет плюсом** | доклады, open source |

Укажите **реальные задачи** первых 3 месяцев: "поддержка сервиса отчётности", "интеграция с API банка" — так кандидат и интервьюеры понимают контекст.

---

### Личностные и командные качества

- Работа в условиях неполных требований.
- Умение оспаривать оценку **с аргументами**, а не саботажем.
- Готовность к code review и парным разборам.

Избегайте размытых "стрессоустойчивый, коммуникабельный" без привязки к поведению.

---

### Зарплатная вилка

- Диапазон **в объявлении** (где позволяет политика компании) сужает нерелевантные отклики.
- Сверка с внутренними грейдами — чтобы не обидеть текущую команду.
- Ориентиры рынка — [IT в России](/encyclopedia/1-basics/1-04-kak-vidyat-it-obychnye-lyudi/7), [рынок труда](/encyclopedia/1-basics/1-26-karera-v-it-i-mify/10).

---

### Мотивация, которую вы можете закрыть

Честно отметьте: удалёнка, продукт, стек, рост до Senior, отсутствие легаси — или наоборот "есть легаси, зато стабильность". Скрытый негатив всплывает на испытательном сроке.

---

## Шаг 2 — структура вакансии

Вакансия — **зеркало хорошего резюме**: структура, конкретика, достижения команды, честные условия.

---

### Рекомендуемые блоки

1. **Кто мы / продукт** — 3–5 предложений, кому помогает система.
2. **Чем предстоит заниматься** — задачи, а не только "разработка ПО".
3. **Стек** — основной и смежный.
4. **Ожидания** — must / nice to have списком.
5. **Условия** — формат работы, вилка, этапы отбора.
6. **Бонусы** — ДМС, обучение — если есть.

---

### Связь с ATS

Ключевые слова из вакансии должны **совпадать** с тем, что ищет HR в резюме ([как работает ATS](/encyclopedia/1-basics/1-26-karera-v-it-i-mify/6)). Тимлид даёт HR список синонимов: "Kubernetes" и "K8s", "PostgreSQL" и "Postgres".

## Шаблон (скелет)

```text
[Название роли], [уровень грейда]

О продукте:
…

Задачи:
- …
- …

Стек: …

Обязательно:
- …

Будет плюсом:
- …

Условия: [формат], [вилка или "обсудим"], [этапы: HR → тех → финал]

Как откликнуться: …
```

Адаптируйте под площадку (hh.ru, Habr Career, Telegram). На русском языке для локального рынка — см. [английский в IT](/encyclopedia/1-basics/1-30-angliyskiy-yazyk/4).

## Типовые ошибки в тексте

| Ошибка | Последствие |
|--------|-------------|
| Простыня без структуры | Отсев сильных кандидатов |
| "Знать всё" (20 технологий must) | Шумные отклики или пустота |
| Нет вилки при перегретом рынке | Сотни нерелевантных резюме |
| Скрытый негатив (релизы ночью) | Быстрый уход после оффера |
| Дискриминирующие формулировки | Репутационные и юридические риски |
| Копипаст чужой вакансии | Несоответствие реальным задачам |

**Хороший признак:** по тексту можно представить **первый месяц** работы. **Плохой:** только "требуется опыт работы в команде".

---

## Роль тимлида после публикации

| Этап | Действие лида |
|------|----------------|
| Скрининг HR | 15-минутный бриф: что отсеивать жёстко |
| Техинтервью | Единый чек-лист, калибровка с вторым интервьюером |
| Финал | Культура команды, ожидания по испытательному сроку |
| Онбординг | Buddy, доступы, цели на 30/60/90 дней |

Испытательный срок — **явные критерии успеха** в письме до выхода: "владеет модулем X", "ведёт ревью", "закрыл два инцидента с постмортемом".

---

## Внутренний найм и "выращивание"

Часто тимлидов и Senior **берут изнутри**: меньше риска по культуре, выше лояльность. С рынка нанимают при дефиците или новом стеке. Обе модели требуют **прозрачности** для команды, чтобы не было ощущения "любимчика".
