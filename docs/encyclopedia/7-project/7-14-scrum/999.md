# Scrum — чек-лист самопроверки

---

Пройдите блоки честно: "да" — только если есть **наблюдаемое поведение** за последние 2–3 спринта, а не в регламенте на полке.

---

## Роли

- [ ] Есть **один** Product Owner с правом **менять порядок** Product Backlog.
- [ ] PO доступен для уточнений **в течение спринта** (не "раз в квартал").
- [ ] Scrum Master **не** ведёт таск-трекер вместо команды и **не** раздаёт задачи всем.
- [ ] Developers **сами** берут работу из Sprint Backlog и отвечают за DoD.
- [ ] Размер Scrum Team **≤ 10** (или есть явное масштабирование на несколько команд).

---

## Спринт и инкремент

- [ ] Длина спринта **фиксирована** (например, всегда 2 недели).
- [ ] В конце спринта есть **рабочий** инкремент по **Definition of Done**.
- [ ] На Sprint Review **показывают** продукт, а не слайды "готовность 73%".
- [ ] В спринт **не** добавляют scope без отмены Sprint или согласия команды на пересмотр цели.
- [ ] **Velocity** считают по **завершённым** points, не по "начатым".

---

## События

- [ ] Sprint Planning заканчивается **Sprint Goal** и понятным Sprint Backlog.
- [ ] Daily ≤ **15 мин**, фокус на **Sprint Goal**, не статус-рапорт директору.
- [ ] Retrospective даёт **1–3 конкретных** улучшения в следующем спринте.
- [ ] Refinement бэклога идёт **регулярно**, а не только в первый день спринта.

---

## Прозрачность и потери

- [ ] Доска отражает **реальность** (обновляется ежедневно).
- [ ] WIP ограничен: у человека **не** пять задач "в работе".
- [ ] "Почти готово" **не** считается Done.
- [ ] Блокеры с Daily **снимает** SM или команда в известный срок.
- [ ] Сверхурочки — **исключение**, а не способ "закрыть спринт".

---

## Заказчик и организация

- [ ] Заказчик (или делегат) **бывал** на Review хотя бы раз за спринт.
- [ ] Руководство **не** обходит PO, напрямую забрасывая задачи в спринт.
- [ ] Есть **автотесты / CI**, поддерживающие DoD (для software-команд).

---

## Интерпретация

| Баллы "да" | Скорее всего |
|------------|--------------|
| Большинство | Рабочий Scrum или близкий гибрид |
| Половина | **Scrum-театр** — усилить 2–3 слабых блока ([Внедрение](./7)) |
| Меньше трети | Заявленный Scrum **не** совпадает с практикой; начните с [11 шагов внедрения](./7) |
