## Три разных слова — три разных процесса

На приёмке путают:

| Термин | Что это |
|--------|---------|
| **Испытания** | Проверка по **ПМИ** / тест-плану: «соответствует ТЗ?» |
| **Удостоверение качества** | **Доказательная база**, что качество достигнуто (отчёты, метрики, 25010) |
| **Сертификация** | **Независимая** оценка по регламенту (орган, стандарт) → **сертификат** |

Для внутреннего продукта достаточно **испытаний + акта**. Для **ГИС, ОПК, медицины, ФСТЭК** — часто нужна **формальная сертификация** процесса и/или продукта.

## Организация испытаний

### Виды (типичная последовательность)

| Этап | Кто | Цель |
|------|-----|------|
| **Модульные / интеграционные** | Разработка, QA | Техническая готовность |
| **Системные** | QA | Система в целом |
| **Приёмочные (UAT)** | Заказчик | Бизнес-сценарии |
| **Государственные / квалификационные** | Комиссия | Соответствие контракту и норматам |

**Программа и методика испытаний (ПМИ)** фиксирует **что, как, чем, когда** и **критерии успеха**.

### Завершение испытаний

Пакет для приёмки обычно включает:

- протоколы испытаний по каждому сценарию;
- перечень **открытых дефектов** с классификацией (blocker / major / minor);
- **матрицу трассировки** ТЗ → ПМИ → результат;
- версию ПО (baseline) и комплект документации;
- **акт** или **мотивированный отказ**.

:::info Критерий «сдали»
Часто: **нет дефектов класса 1**, дефекты класса 2 — с планом устранения и сроками, **все обязательные** сценарии ПМИ — pass.
:::

## Удостоверение качества

**Quality assurance** в смысле гл. 2.8 — **совокупность доказательств**:

- выполнение процессов по [12207](/encyclopedia/7-project/7-12-konstruirovanie-po/1);
- метрики по [ISO 25010](./2);
- результаты [SCM-аудита](./3);
- отчёты статического анализа, coverage, нагрузки, ИБ.

Заказчик или auditor смотрит: **можно ли доверять** выводу «качество обеспечено», а не только «100 тестов зелёные».

## Сертификация технологических процессов

**Сертификация процессов** — подтверждение, что организация **стабильно** производит ПО по требованиям стандарта.

| Модель / стандарт | Что оценивают |
|-------------------|---------------|
| **ISO 9001** | Система менеджмента качества (не только IT) |
| **CMMI appraisal** | Зрелость процессов разработки ([уровни в SDLC](/encyclopedia/7-project/7-03-metodologiya-i-zhiznennyy-tsikl-po/1)) |
| **ISO/IEC 15504 (SPICE)** | Компетентность отдельных процессов |
| **Отраслевые** | DO-178C, IEC 62304, ГОСТ Р 56939 (ИБ) |

Для **подрядчика** сертификат процессов — аргумент в тендере: «мы умеем повторять результат».

## Сертификация готового продукта

**Сертификация продукта** — конкретная версия ПО или изделия проходит оценку в **аккредитованной** лаборатории или ведомстве.

Примеры контекста в РФ:

- **ФСТЭК / ФСБ** — защита информации;
- **Минцифры / реестр** — отечественное ПО, ГИС;
- **Медрегулятор** — Software as Medical Device.

Требования: **комплект документации**, **стенд**, **исходники** (иногда), **повторяемая сборка** ([SCM](./3)).

## Акт приёмки и юридический контур

В госконтракте (44-ФЗ, 223-ФЗ) приёмка — **этап контракта**:

1. Исполнитель направляет **уведомление о готовности**.
2. Заказчик (или комиссия) проводит **экспертизу** в срок по контракту.
3. Подписывается **акт** или **мотивированный отказ** с перечнем замечаний.
4. Без акта — **нет оплаты** и **нет перехода прав** (если так в договоре).

Agile внутри команды **не отменяет** акт на milestone «релиз 1.0» в гибридной модели ([гос. методологии](/encyclopedia/7-project/7-03-metodologiya-i-zhiznennyy-tsikl-po/2)).

## Связь с экономикой проекта

- **Стоимость сертификации** закладывают в смету **отдельной строкой** (человеко-месяцы + лаборатория).
- **Повторные испытания** после провала — типичный **риск** для [COCOMO PCON и DOCU](./1).
- **Досрочная приёмка** без полного ПМИ — экономия сейчас, **штраф** на сопровождении потом.

---

## Типичные ошибки

1. **ПМИ написали после разработки** — сценарии подогнаны под код.
2. **Нет baseline** — нельзя идентифицировать, что сдавали.
3. **Путают демо и приёмочные испытания** — «показали на ноутбуке» ≠ протокол.
4. **Игнорируют NFR на приёмке** — только happy path UI.
