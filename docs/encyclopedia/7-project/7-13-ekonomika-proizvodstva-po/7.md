## Почему «квалификация» — часть экономики

Заказной проект срывают реже «не те библиотеки», чем **не та команда**: архитектор не держал контракт с заказчиком, аналитик не умеет в ГОСТ-ТЗ, QA не строит трассировку к ПМИ. В **COCOMO II** это напрямую бьёт по **PCAP, ACAP, LTEX** — множители трудоёмкости ([статья COCOMO](./1)).

Глава 1.2 учебника про **подготовку коллектива** — про **минимальный набор компетенций** для производства **сложного заказного** комплекса программ.

## Заинтересованные лица и «перевод» требований

Перед набором команды фиксируют **stakeholders** и их ожидания ([116](/encyclopedia/7-project/7-04-analitika/116)):

| Stakeholder | Что важно | Кто в команде «переводит» |
|-------------|-----------|---------------------------|
| Заказчик-бизнес | ROI, сроки | PM, BA |
| ИТ-заказчик | Интеграции, эксплуатация | SA, architect |
| Регулятор / ИБ | Соответствие нормам | SA, security, tech writer |
| Конечные пользователи | Удобство, ошибки | BA, UX, QA |
| Поддержка после сдачи | Runbook, логи | DevOps, SA |

**Подготовка коллектива** начинается с **общего понимания**, кто принимает решения и что считается успехом.

## Руководитель проекта (PM)

**Свойства, без которых заказной проект буксует:**

- ведение **контракта**: сроки, change request, акты;
- **риск-менеджмент** (срок, бюджет, scope);
- коммуникация с **не-IT** заказчиком;
- понимание **SDLC** и границ Agile vs Waterfall.

**Квалификация (ориентир):** опыт Fixed Price / госконтрактов, PMBOK или PRINCE2 на уровне терминов, умение читать ТЗ и ПМИ.

Подробнее — [Основы управления IT-проектами](/encyclopedia/7-project/7-02-komanda-i-upravlenie/1).

## Архитектор / ведущий проектировщик

**Отвечает за** целостность комплекса программ:

- границы подсистем, NFR, технологический стек;
- **декомпозиция** и **reuse** ([103](/encyclopedia/7-project/7-06-proektirovanie-i-arhitektura/103));
- ADR, согласование с [ISO 25010](./2);
- оценка **сложности** для [COCOMO / планирования](/encyclopedia/7-project/7-12-konstruirovanie-po/4).

**Ошибка архитектора** — самая дорогая ([о разделе «Проект»](/encyclopedia/7-project/7-06-proektirovanie-i-arhitektura/intro)).

## Аналитики (BA / SA)

| Роль | Фокус | Для заказного ПО обязательно |
|------|-------|------------------------------|
| **BA** | Бизнес-процесс, ценность | Интервью, BPMN, приоритеты |
| **SA** | Техническая спецификация | ТЗ/спецификация, API, трассировка, NFR |

Подготовка: [аналитика](/encyclopedia/7-project/7-04-analitika/intro), [ТЗ по ГОСТ](/encyclopedia/7-project/7-04-analitika/121).

## Разработчики (конструирование)

**Не только синтаксис языка:**

- модульность, [связность/сцепление](/encyclopedia/7-project/7-12-konstruirovanie-po/2);
- unit-тесты, code review, [SCM](./3);
- чтение чужого кода и **легаси**;
- для компонентов комплекса — **интерфейсы** и контракты.

Для **компонентов сложного комплекса** часто выделяют **tech lead модуля** — мини-архитектор внутри сервиса.

## QA / инженеры по качеству

- [тест-дизайн](/encyclopedia/7-project/7-05-testirovanie/127), уровни [111](/encyclopedia/7-project/7-05-testirovanie/111);
- **трассировка** к ТЗ и ПМИ;
- [white-box](/encyclopedia/7-project/7-05-testirovanie/130) на критичных модулях;
- участие в **приёмочных** и [сертификации](./6).

---

## Технические писатели

На заказном проекте с ГОСТ **не «nice to have»**:

- ТЗ, ПМИ, руководства ([7-08](/encyclopedia/7-project/7-08-tehnicheskoe-pismo/intro));
- синхронизация версий с [SCM](./3).

---

## Организатор производства (глава 1.2)

Роль близка к **Release manager / PMO**:

- план [PERT/CPM](/encyclopedia/7-project/7-12-konstruirovanie-po/4);
- координация подрядчиков;
- **CMMI**-подобные процессы ([SDLC](/encyclopedia/7-project/7-03-metodologiya-i-zhiznennyy-tsikl-po/1)).

## Как готовить коллектив к проекту

1. **Kick-off** с заказчиком — цели, stakeholders, критерии приёмки.
2. **Обучение домену** — финансы, медицина, телеком (2–4 недели погружения).
3. **Единый глоссарий** — термины на русском/английском ([1-30](/encyclopedia/1-basics/1-30-angliyskiy-yazyk/4)).
4. **Пилот процессов** — SCM, CI, шаблоны документов до «массового» кода.
5. **Парное усиление** — senior + middle на критичных модулях.
6. **Ретроспектива компетенций** — чего не хватило на первом релизе.
