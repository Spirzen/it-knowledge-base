# Kanban — чек-лист самопроверки

---

Пройдите блоки **честно**: галочка "да" — только если есть **наблюдаемое поведение** за последние 2–4 недели, а не формулировка в Confluence без практики.

Сравнение с нормативной базой — [Kanban Guide](https://kanbanguide.scrum.org/). Теория — [раздел Kanban](./intro).

---

## Поток и доска

- [ ] Все типы работы **видны** на одной или связанных досках (включая ad-hoc из чатов).
- [ ] Есть колонка или состояние **Ready** отдельно от большого Backlog.
- [ ] У каждой колонки In Progress (и при необходимости Review/QA) есть **WIP-лимит**.
- [ ] При превышении WIP команда **останавливает старт**, а не давит "быстрее".
- [ ] Есть явная **политика** перехода между колонками (Definition of Done на шаг).
- [ ] Колонки описывают **состояние работы**, а не имена людей.
- [ ] Доска в [Jira/YouTrack](/encyclopedia/7-project/7-09-bazy-znaniy-i-zadachniki/21) обновляется **ежедневно** и отражает реальность.

---

## Pull-система

- [ ] Исполнители **сами берут** задачи из Ready (pull), а не только получают push сверху.
- [ ] При полном WIP команда **сначала помогает** завершить review/QA/blocked.
- [ ] PO/PM упорядочивает Ready; команда не перескакивает очередь без политики.
- [ ] Нет негласного правила "у каждого должна быть задача в In Progress".

---

## Blocked и зависимости

- [ ] Состояние **Blocked** используется с **причиной** и **датой** следующей проверки.
- [ ] Blocked обсуждаются на daily **первыми**.
- [ ] Задачи не висят в In Progress неделями без Blocked-метки.

---

## Приоритеты и классы обслуживания

- [ ] Используются **классы обслуживания** (expedite, fixed date, standard, intangible) или эквивалент.
- [ ] Инциденты P1 проходят через **expedite** с правилом ограничения (обычно один поток).
- [ ] Классы обслуживания **понятны** PO, support и команде.
- [ ] Не больше **20–30%** тикетов с максимальным приоритетом.
- [ ] После expedite проводится **postmortem** или аналог.
- [ ] Для fixed date задач проверяется **реалистичность** даты через cycle time.

---

## Метрики

- [ ] Считается **cycle time** завершённых задач (хотя бы выборочно или отчётом).
- [ ] Понимаете разницу **lead time** и **cycle time** в своём контексте.
- [ ] Знаете **throughput** команды (Done за неделю) за последний месяц.
- [ ] Раз в месяц смотрят **CFD** или аналог отчёта по накоплению WIP.
- [ ] Метрики **разбиты** по типу работы (не смешивают INC и epic).
- [ ] Нет KPI "закрыть N тикетов" без учёта качества и класса.

---

## Cadence и улучшение

- [ ] Есть **replenishment** (наполнение Ready) на регулярной основе.
- [ ] Есть **delivery review** или аналог — разбор Done и метрик.
- [ ] Ретроспектива / review потока **регулярны** (не только "настроили доску год назад").
- [ ] За последний квартал **меняли** хотя бы одну политику или WIP по данным.

---

## Support и инциденты (если применимо)

- [ ] P1 критерии **документированы** ([7.21](/encyclopedia/7-project/7-21-incidenty-i-ekspluatatsiya/intro)).
- [ ] INC связаны с dev-задачами или одна доска для смешанного потока.
- [ ] Есть **runbooks** для частых сценариев ([wiki 7.09](/encyclopedia/7-project/7-09-bazy-znaniy-i-zadachniki/22)).
- [ ] Hotfix проходит **DoD** (PR, rollback plan).
- [ ] SLA/MTTR **отслеживаются**, нарушения ведут к улучшениям, а не к скрытым авралам.

---

## Культура и организация

- [ ] Руководство **не обходит** WIP массовым push.
- [ ] "Срочно" в Slack **попадает** на доску с классом, а не остаётся вне системы.
- [ ] Команда может **объяснить новичку** WIP и pull за 5 минут.
- [ ] Intangible/техдолг имеет **зарезервированную** ёмкость (WIP или %).
- [ ] Процесс согласован с [методологией проекта](/encyclopedia/7-project/7-03-metodologiya-i-zhiznennyy-tsikl-po/4) — нет противоречия "Kanban на словах, waterfall в отчётах" без объяснения.

---

## Интерпретация результатов

| Доля "да" | Скорее всего |
|-----------|--------------|
| **Большинство** (≥ 70%) | Рабочий Kanban или зрелый Scrumban |
| **Половина** (40–69%) | Kanban-**декорация** — усилить WIP, классы, метрики ([главы 2–4](./2)) |
| **Меньше трети** (< 40%) | Доска в Jira **без** потока; начните с [STATIK](./6) и [быстрого старта](./intro) |

---

## Чек-лист "один день"

Минимум для эксперимента:

- [ ] Нарисовать as-is поток на белой доске или Jira.
- [ ] Один WIP-лимит на In Progress.
- [ ] Три политики перехода (Ready, Review, Done).
- [ ] Blocked с обязательной причиной.
- [ ] Через 10 Done задач — посчитать median cycle time.
