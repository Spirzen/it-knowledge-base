## Главное за восемь глав

1. **Kanban** — управление **потоком**, не календарь спринтов. Нормативная база — [Kanban Guide](https://kanbanguide.scrum.org/).
2. **WIP-лимиты** важнее красивых колонок. Без лимита pull-система не работает.
3. **Метрики** (lead time, cycle time, throughput, CFD) показывают реальность; velocity в points не обязательна.
4. **Классы обслуживания** (expedite, fixed date, standard, intangible) отделяют инцидент от фичи без хаоса.
5. **Политики** на доске должны быть явными: DoR, DoD, Blocked, expedite.
6. **STATIK** — старт с текущего процесса, не с идеальной доски из книги.
7. **Support и on-call** — естественная среда Kanban; см. [7.21](/encyclopedia/7-project/7-21-incidenty-i-ekspluatatsiya/intro).
8. **Инструменты** ([7.09](/encyclopedia/7-project/7-09-bazy-znaniy-i-zadachniki/intro)) помогают, но не заменяют договорённости.

Сравнение процессов — [Как выбрать процесс](/encyclopedia/7-project/7-03-metodologiya-i-zhiznennyy-tsikl-po/4). Диагностика — [чек-лист](./999).

## Kanban, Scrum и Waterfall (сводка)

| | Waterfall | Scrum | Kanban |
|---|-----------|-------|--------|
| Единица планирования | Фаза | Спринт | Поток / карточка |
| Ритм | Вехи | 1–4 недели | Непрерывный + cadence |
| Ограничение работы | План фазы | Sprint scope | WIP |
| Прогноз | Экспертная оценка | Velocity | Cycle time percentiles |
| Прерывания | Change request | Ограничены | Expedite policy |
| Роли | PM, аналитики | PO, SM, Dev | Не prescribed |
| Лучший контекст | Регуляторика, фазы | Новый продукт | Support, смешанный поток |

## FAQ

<div class="faq-list">

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> У нас колонки To Do / Done — это Kanban?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Только если есть <strong>WIP-лимиты, явные политики вытягивания и измерение потока</strong>. Иначе — просто доска. Подробнее — <a href="./2">глава 2</a>, <a href="./999">чек-лист</a>.</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Kanban без оценок в story points — как планировать?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Через <strong>прогноз по throughput и cycle time</strong> (перцентили 85%), а не обещание фиксированных points. Roadmap — на размере epics; операционный прогноз — на метриках. Подробнее — <a href="./4">метрики</a>.</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Можно ли совмещать Kanban и Scrum?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Да — <strong>Scrumban</strong>: спринт как контейнер отчётности, WIP и pull внутри. См. <a href="./5">глава 5</a>.</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Сколько expedite можно одновременно?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Правило по умолчанию — <strong>один</strong> expedite на поток. Больше — только с явной эскалацией и пониманием, что standard work останавливается. См. <a href="./3">классы обслуживания</a>.</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Что такое CFD и зачем она команде?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> <strong>Cumulative Flow Diagram</strong> — накопительная диаграмма задач по колонкам во времени. Расширение полосы In Progress показывает рост WIP; помогает решить, ужесточать ли лимиты. См. <a href="./4">метрики</a>.</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Чем lead time отличается от cycle time?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> <strong>Lead time</strong> — от создания запроса до Done (включая ожидание в очереди). <strong>Cycle time</strong> — от начала работы (In Progress) до Done. Клиент видит lead time; команда оптимизирует cycle time и очередь.</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Нужен ли Scrum Master для Kanban?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> [Kanban Guide](https://kanbanguide.scrum.org/) не требует роли SM, но нужен кто-то (тимлид, flow coach), кто следит за WIP, cadence и метриками — иначе процесс деградирует.</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Kanban подходит только для поддержки?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Нет. Поддержка — типичный кейс, но product-команды с частыми прерываниями тоже используют Kanban или Scrumban. См. <a href="./5">матрицу выбора</a>.</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Как начать завтра без тренинга?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Визуализировать всю работу, один WIP на In Progress, политика Blocked, через 2 недели — cycle time 10 задач. Roadmap — <a href="./6">STATIK</a> и <a href="./intro">быстрый старт</a>.</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Заменяет ли Kanban ITSM и CAB?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Нет. Доска управляет <strong>потоком команды</strong>; change advisory board и SLA остаются в [ITSM](/encyclopedia/7-project/7-16-itsm-i-it-uslugi/intro). См. <a href="./7">глава 7</a>.</p>
</div>

## Одна фраза для коллеги

Kanban — это когда команда **видит** всю работу, **ограничивает** незавершёнку, **вытягивает** задачи по правилам и **улучшает** процесс по времени прохождения карточек, а не по ощущению "все заняты".
