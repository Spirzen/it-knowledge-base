## Git — минимум для тестировщика

QA-инженер работает с Git так же, как разработчик — хранит автотесты, коллекции Postman, чек-листы в Markdown, конфиги CI.

| Задача QA | Команда / действие | Где подробнее |
|-----------|-------------------|---------------|
| Склонировать репозиторий с тестами | `git clone` | [Как работать с Git](/encyclopedia/4-code-dev/4-13-osnovy-raboty-s-git/112) |
| Создать ветку под задачу | `git checkout -b feature/QA-123-login-tests` | [Ветвление](/encyclopedia/4-code-dev/4-13-osnovy-raboty-s-git/113) |
| Зафиксировать изменения | `git add` → `git commit` | [Как работать с Git](/encyclopedia/4-code-dev/4-13-osnovy-raboty-s-git/112) |
| Отправить на review | `git push` → Pull Request | [Ветвление и слияние в Git](/encyclopedia/4-code-dev/4-13-osnovy-raboty-s-git/113) |
| Подтянуть свежий main | `git pull` / `git fetch` + merge | [Как работать с Git](/encyclopedia/4-code-dev/4-13-osnovy-raboty-s-git/112) |
| Не коммитить секреты | `.gitignore`, env-файлы | [Файл .gitignore](/encyclopedia/4-code-dev/4-13-osnovy-raboty-s-git/116) |

**Шпаргалка на каждый день** — [12 команд Git](/encyclopedia/4-code-dev/4-13-osnovy-raboty-s-git/115#12-komand).

Запуск тестов в пайплайне после push — [DevOps и CI/CD](/encyclopedia/8-infra-security/8-04-devops-ci-cd/intro).

HTTP — язык общения браузера, мобильного клиента и Postman с сервером. Без него сложно читать Network в DevTools и оформлять баг-репорты.

| Тема | Минимум | Статья |
|------|---------|--------|
| Методы | GET, POST, PUT/PATCH, DELETE | [Тестирование и анализ API](./2.md) |
| Коды ответа | 2xx успех, 4xx клиент, 5xx сервер | [Ручное тестирование веб-приложений](./128.md), [Тестирование и анализ API](./2.md) |
| Заголовки | `Content-Type`, `Authorization`, `Cookie` | [Тестирование и анализ API](./2.md) |

## Алгоритмы — для собеседований и логики

Для **ручного QA** алгоритмы не обязательны. Для **автоматизатора** и **собеседований** в крупные компании полезен базовый набор задач на массивы, строки и хеш-таблицы.

| Паттерн | Пример задачи | Зачем QA |
|---------|---------------|----------|
| Подсчёт частот | Сколько раз встречается символ в строке | Парсинг логов, группировка багов |
| Два указателя | Есть ли дубликат в отсортированном массиве | Проверка уникальности id |
| Хеш-таблица (dict / Map) | Найти пару чисел с заданной суммой | Быстрый поиск в тестовых данных |
| Стек / очередь | Проверка скобочной последовательности | Валидация JSON, XML |
| Бинарный поиск | Найти элемент в отсортированном списке | Поиск в больших логах |

**Практика**

- [LeetCode Easy](https://leetcode.com/problemset/) — 20–30 задач уровня Easy достаточно для старта.
- [Задачник лаборатории](/lab/questions/intro) — вопросы по смежным темам (SQL, сети, языки).
- Связь с тест-дизайном: [эквивалентные классы и границы](./127.md) — та же логика "разбить пространство входов".

## Soft skills — часть работы QA

Тестировщик много **общается** — уточняет требования, спорит о severity, пишет понятные баг-репорты, участвует в ретро.

| Навык | Проявление в QA | Материал |
|-------|---------------|----------|
| Ясная письменная речь | Баг-репорт, тест-кейс | [Документация тестировщика](./119.md) |
| Уточняющие вопросы | Анализ ТЗ до тестирования | [Аналитика](/encyclopedia/7-project/7-04-analitika/intro) |
| Обратная связь без конфликта | Обсуждение "баг или фича" | [Soft skills в IT](/encyclopedia/1-basics/1-04-kak-vidyat-it-obychnye-lyudi/6) |
| Работа в Agile-команде | Daily, ретро, приоритеты | [Scrum](/encyclopedia/7-project/7-14-scrum/intro) |
| Коммуникация со стейкхолдерами | Приёмка, UAT spec | [127 аналитики](/encyclopedia/7-project/7-04-analitika/127) |

## Английский — для документации и карьеры

Идеальный C1 не нужен для старта. Достаточно **читать** документацию и **понимать** термины в Jira, Confluence, Stack Overflow.

| Уровень | Что делать | Материал |
|---------|------------|----------|
| Старт | 50 базовых терминов QA и HTTP | [Английский в IT](/encyclopedia/1-basics/1-30-angliyskiy-yazyk/intro) |
| Чтение | Документация pytest, Selenium, Postman | [Практикум чтения](/encyclopedia/1-basics/1-30-angliyskiy-yazyk/5) |
| Собеседование | Описать последний проект 2–3 минуты | [Карьера в IT](/encyclopedia/1-basics/1-26-karera-v-it-i-mify/1) |

Типичные термины в работе — *test case*, *regression*, *assertion*, *endpoint*, *payload*, *staging*, *flaky test*, *severity*, *priority*.

## Три языка для автотестов — как выбрать

| Язык | Когда выбирают | Практикум | Фреймворки |
|------|----------------|-----------|------------|
| **Python** | Старт в автоматизации, ML/данные рядом | [Подготовка среды и создание первого теста](./1011.md)–[Проверка надежности под нагрузкой](./1014.md) | pytest, Playwright, requests |
| **Java** | Enterprise, Android, банки, REST Assured в стеке | [Практикум Java — JUnit и REST Assured](./1015.md) | JUnit 5, TestNG, Selenium, REST Assured |
| **JavaScript** | Фронтенд-команда, React/Vue, Postman-скрипты | [Практикум JavaScript — Playwright и Jest](./1016.md) | Jest, Playwright, Cypress |

Один язык для старта достаточен. Паттерны (Arrange–Act–Assert, Page Object, фикстуры) переносятся между языками. Углублённый Playwright (архитектура, Allure, портфолио) — [Playwright](./1182.md).
