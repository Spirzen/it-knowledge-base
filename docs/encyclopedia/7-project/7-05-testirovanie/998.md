## Главная мысль раздела

Качество — это не "один прогон в конце спринта", а **система**: требования → тест-дизайн → проверки на разных уровнях → артефакты → обратная связь. Тестирование **даёт информацию о рисках**; решение "выпускать или нет" принимает команда на основе этой информации и бизнес-контекста.

## Термины, которые должны не путаться

| Термин | Смысл в одной фразе | Где подробнее |
|--------|---------------------|---------------|
| Ошибка (mistake) | Человек ошибся при проектировании или коде | [Основы](./1.md), [Классификация](./111.md) |
| Дефект (defect) | Несоответствие в артефакте (код, ТЗ) | там же |
| Сбой (failure) | Пользователь увидел поломку в рантайме | там же |
| Верификация | "Собрали ли правильно по ТЗ?" (в т.ч. review) | [Основы](./1.md) |
| Валидация | "То ли сделали для пользователя?" (запуск, UAT) | [Основы](./1.md) |
| Retest / confirmation | Перепроверили **конкретный** исправленный баг | [Классификация](./111.md) |
| Регрессия | Старое не сломали после изменений | [Классификация](./111.md), [Автоматизация](./115.md) |
| Smoke / sanity | Короткий прогон после сборки / точечного фикса | [Классификация](./111.md) |
| Стаб / мок / фейк | Способы подменить зависимости в тестах | [Объекты](./117.md) |

## Уровни проверок (лестница)

Снизу вверх — **больше скорости и изоляции**, сверху — **ближе к пользователю и дороже в поддержке**:

1. **Unit** — функция/класс, моки и стабы, миллисекунды. [Юнит-тестирование](./120.md), практика [1011](./1011.md).
2. **Integration** — стык модулей, API, БД, очереди. [Интеграционное](./121.md).
3. **UI** — проверка интерфейса и его поведения (не всегда сквозной бизнес-путь). [E2E и системное](./114.md), [Ручное веб-тестирование](./128.md).
4. **System** — продукт целиком по спецификации (не обязательно через UI). [E2E и системное](./114.md).
5. **E2E** — сквозной сценарий "как в жизни". [E2E](./114.md), практика [1013](./1013.md).
6. **UAT / приёмка** — заказчик и бизнес. [Классификация](./111.md).

Пирамида: **много** unit, **меньше** integration/API, **мало** E2E — см. [Автоматизация](./115.md).

## Типичные ошибки новичка (проверьте себя)

- Путают **QA** (процессы) и **автотесты** (один из инструментов).
- Называют перепроверку бага "верификацией" — правильнее **retest** ([111](./111.md) vs [1](./1.md)).
- Пишут UI-автотесты до API и unit — долгий и хрупкий регресс.
- Используют `sleep()` вместо явных ожиданий — флейки ([114](./114.md), [1013](./1013.md)).
- Считают **100 % покрытия кода** гарантией качества ([126](./126.md)).
