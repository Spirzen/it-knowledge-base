Самопроверка процесса. Подробности — [глава 1](./1), [итоги и FAQ](./998).

---

## Scope и трекер

- [ ] Запросы вне backlog **фиксируются** в трекере, не только в чатах.
- [ ] Есть порог, когда мелочь → полноценный **change request**.
- [ ] Baseline scope (договор, ТЗ, релиз) **зафиксирован** и доступен команде.
- [ ] Признаки **scope creep** обсуждаются на ретро — не норма.

---

## Change request

- [ ] Шаблон CR с полями: описание, обоснование, влияние, альтернативы, решение.
- [ ] Крупные изменения имеют **оценку влияния** на срок/стоимость (BA/SA).
- [ ] Утверждающий (**PO / заказчик**) явно фиксирует решение.
- [ ] При fixed price CR ведёт к **допсоглашению**, где нужно по договору.
- [ ] Отклонённые CR закрываются с **причиной**, не зависают.

---

## PO и trade-off

- [ ] PO/заказчик **явно** принимает trade-off (что снимаем из scope).
- [ ] Нет практики "обход PO через чат к разработчику".
- [ ] Изменение в середине спринта — пересмотр **цели спринта** с PO.
- [ ] [PM](/encyclopedia/7-project/7-19-produktovye-roli/1) не подменяет подпись заказчика на CR в аутсорсе.

---

## CAB и production

- [ ] Prod-релизы критичных систем имеют **rollback-план**.
- [ ] Известен регламент **CAB** (окна, tier, emergency).
- [ ] Emergency hotfix при P1 не ждёт CAB месяц — есть **post-facto** процесс.
- [ ] Релиз связан с тикетом/CR — аудит "что выкатили".

---

## Роли

- [ ] BA даёт дельту требований; SA — техвлияние на CR.
- [ ] Разработчик знает: не стартовать без приоритета PO.
- [ ] Юрист/аккаунт подключается к CR при fixed price по правилу.

---

## Контексты

- [ ] **Продукт** — trade-off в backlog документирован (комментарий эпика).
- [ ] **Аутсорс** — граница scope в [договоре](/encyclopedia/7-project/7-01-obschee-o-biznese/3) понятна команде.
- [ ] **Госсектор** — правки ТЗ связаны с допсоглашением и планом релиза.
- [ ] **ITSM** — заявки бизнеса проходят владельца услуги (внутренний PO).

## Красные флаги

- [ ] "Всё входит в fixed price" — scope не определён.
- [ ] CAB есть, emergency tier нет — P1 ждёт согласования неделю.
- [ ] PO узнаёт о новом scope на демо.
- [ ] Нет учёта неплановых часов в T&M.
- [ ] Rollback ни разу не пробовали на stage.

Три и более — воркшоп с PM и [PO](/encyclopedia/7-project/7-19-produktovye-roli/intro).

---

## Минимальный план за спринт

1. Шаблон CR в wiki или Jira.
2. Порог "когда CR обязателен" — одна страница.
3. Чек-лист релиза + rollback.
4. Ретро: сколько задач пришло без PO в прошлом спринте.
