## 1. Три слоя веб-страницы

**Вопрос.** Чем отличаются роли **HTML**, **CSS** и **JavaScript**?

<details>
<summary>Подсказка</summary>

HTML — структура и смысл; CSS — оформление; JavaScript — поведение и работа с DOM/API. — [глава 5](./5.md).

</details>

---

## 2. Клиент и сервер

**Вопрос.** Чем **клиент** отличается от **сервера** в типичном веб-приложении?

<details>
<summary>Подсказка</summary>

Клиент у пользователя (браузер), инициирует запрос. Сервер в дата-центре или на localhost, обрабатывает запрос и отдаёт ответ. Оба общаются по HTTP.

</details>

---

## 3. Части HTTP-запроса

**Вопрос.** Что такое **HTTP-запрос** и из каких частей он состоит?

<details>
<summary>Подсказка</summary>

Метод, URL (path + query), заголовки, тело (опционально). Пример: `GET /api/tasks HTTP/1.1` + headers.

</details>

---

## 4. Статус-коды

**Вопрос.** Что означают коды **200**, **404**, **401**, **500**?

<details>
<summary>Подсказка</summary>

200 — успех; 404 — ресурс не найден; 401 — нет авторизации; 500 — ошибка на сервере.

</details>

---

## 5. JSON и сериализация

**Вопрос.** Для чего нужен **JSON** и что такое **сериализация**?

<details>
<summary>Подсказка</summary>

JSON — текстовый формат обмена данными. Сериализация — объект в памяти → строка JSON; десериализация — обратно.

</details>

---

## 6. CRUD и HTTP

**Вопрос.** Как методы HTTP соотносятся с **CRUD**?

<details>
<summary>Подсказка</summary>

POST — create; GET — read; PUT/PATCH — update; DELETE — delete.

</details>

## 7. REST

**Вопрос.** Сформулируйте **REST** в одном предложении.

<details>
<summary>Подсказка</summary>

Стиль API: ресурсы с URI, операции HTTP-методами, stateless сервер, корректные статус-коды.

</details>

## 8. CORS

**Вопрос.** Почему `fetch` из браузера может упасть с **CORS**, а `curl` — нет?

<details>
<summary>Подсказка</summary>

CORS — политика браузера. curl не браузер и не применяет CORS к ответу.

</details>

**Вопрос.** Чем **HTTPS** отличается от **HTTP**?

<details>
<summary>Подсказка</summary>

HTTPS = HTTP + шифрование TLS. Защита от перехвата на сети — [611 HTTPS](/encyclopedia/2-system-network/2-03-set-i-internet/611).

## 13. Query и body

**Вопрос.** Когда параметры передают в **query**, а когда в **body**?

<details>
<summary>Подсказка</summary>

Query в URL — часто GET, фильтры. Body — POST/PUT/PATCH, создание и изменение с JSON.

</details>

## 14. Архитектура веб-приложения

**Вопрос.** Опишите разницу между SPA и MPA. Где хранить заказы пользователей?

<details>
<summary>Подсказка</summary>

SPA рисует интерфейс в браузере и запрашивает данные с API. MPA получает готовые HTML-страницы с сервера при каждом переходе. Заказы и персональные данные хранят в SQL (транзакции, бэкапы). `localStorage` подходит для настроек интерфейса. Подробно — [глава 4](./4.md).

</details>

## 16. Статика, CMS и своё приложение

**Вопрос.** Когда достаточно статического сайта, когда WordPress, когда писать своё API?

<details>
<summary>Подсказка</summary>

Статика — визитка и лендинг. CMS — блог, сайт с админкой для заказчика. Своё приложение — личный кабинет, заказы, уникальная логика. — [главы 4 и 6](./4.md).

</details>

## 17. MERN и LAMP

**Вопрос.** Расшифруйте **MERN** и **LAMP**. Что общего и чем отличаются?

<details>
<summary>Подсказка</summary>

MERN: MongoDB, Express, React, Node.js — JS на клиенте и сервере. LAMP: Linux, Apache, MySQL, PHP — классика PHP-хостинга. — [глава 4](./4.md).

</details>

## 18. Веб-дизайн

**Вопрос.** Чем **wireframe** отличается от готового mockup? Что даёт **доступность** (a11y) разработчику?

<details>
<summary>Подсказка</summary>

Wireframe — схема без финального дизайна. Mockup — цвета, шрифты, близко к итогу. Доступность (a11y) — семантика, `alt`, фокус с клавиатуры; помогает всем пользователям и SEO. Подробно — [глава 7](./7.md).

</details>

4. Опишите CRUD для сущности "задача" — четыре HTTP-запроса своими словами.
