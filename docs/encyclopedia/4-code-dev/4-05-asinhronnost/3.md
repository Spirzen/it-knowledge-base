## Учебная задача — скачать несколько страниц

Реальный HTTP в примерах заменён на `sleep` — так проще увидеть разницу во времени без сети и сервера.

| Страница (учебный URL) | Имитация задержки сети |
|------------------------|------------------------|
| `https://example.com/page1` | 2.0 с |
| `https://example.com/page2` | 3.5 с |
| `https://example.com/page3` | 1.5 с |
| `https://example.com/page4` | 2.5 с |
| `https://example.com/page5` | 1.0 с |

При **последовательном** запуске задержки **складываются** — около **10.5 с**.

При **параллельном** (потоки, `asyncio`, горутины) все пять "загрузок" идут одновременно — время близко к **3.5 с** (самая долгая страница).

```text
Последовательно:  [====page1====][======page2======][==page3==]...  → ~10.5 с

Параллельно:      [====page1====]
                  [======page2======]                              → ~3.5 с
                  [==page3==]
                  [====page4====]
                  [=page5=]
```

В продакшене вместо `sleep` будет [HTTP-запрос](/encyclopedia/2-system-network/2-09-osnovy-integratsionnogo-vzaimodeystviya/118) — логика выбора инструмента та же.

## Java — потоки, пул, гонки, синхронизация

В Java наглядно видны **жизненный цикл потока**, [гонка данных](./11) на общем счётчике и **синхронизация** на примере банковского счёта.

<ExternalCodeEmbed example="java/code-405-3-002" title="Java — ParallelismDemo (потоки, гонка, synchronized, пул)" minHeight={480} />

### Блоки демо-программы

- **Простые потоки** — `Thread.start()`, `join()`, чередование строк в консоли.
- **Гонка данных** — десять потоков делают `sharedCounter++` без защиты; ожидали 10 000, получают меньше.
- **Синхронизация** — методы `BankAccount` помечены `synchronized`; баланс остаётся корректным.
- **Runnable** — одна задача, два потока с разными именами.
- **Пул потоков** — `ExecutorService` переиспользует потоки вместо `new Thread` на каждую задачу.

Интерактив — [жизненный цикл потока](https://play.spirzen.ru/p/embed/code-dev/thread-lifecycle-demo/) (аналог на Python `threading`).

API и выбор между platform threads и virtual threads — [Асинхронность в Java](/encyclopedia/5-languages/5-03-java/298#praktikum-parallelizm-v-java). Память JVM и `synchronized` — [JVM и потоки](/encyclopedia/5-languages/5-03-java/23).

## C# — async, Task и Parallel

В .NET разные инструменты закрывают разные виды ожидания и вычислений.

- **`async` / `await`** — поток освобождается на время I/O ([HTTP](/encyclopedia/5-languages/5-05-csharp/42), БД, файл).
- **`Task.WhenAll`** — несколько независимых асинхронных операций стартуют сразу.
- **`Task.Run`** — тяжёлая CPU-работа уходит в [пул потоков](./1#создание-потоков-внутри-одного-процесса).
- **`Parallel.ForEach`** — цикл распределяется по ядрам CPU.

<ExternalCodeEmbed example="csharp/code-405-3-003" title="C# — сравнение sync, async и Parallel" minHeight={360} />

| Ситуация | Подходящий API |
|----------|----------------|
| HTTP, БД, файлы | `async`/`await`, `Task.WhenAll` |
| Долгий расчёт в окне WPF/MAUI | `Task.Run` + `Dispatcher` / `MainThread` |
| Параллельная обработка списка файлов | `Parallel.ForEach` |
| Общий счётчик из нескольких потоков | `lock`, `Interlocked`, `ConcurrentDictionary` |

Подробнее — [статья про async и многопоточность в C#](/encyclopedia/5-languages/5-05-csharp/39#praktikum-posledovatelnoe-i-parallelnoe-vypolnenie). Класс `Thread` — [391](/encyclopedia/5-languages/5-05-csharp/391), `Task` — [392](/encyclopedia/5-languages/5-05-csharp/392).

## PHP — запрос за запросом и параллельный cURL

Классическая схема **PHP-FPM**

- один входящий HTTP-запрос;
- один процесс (или воркер);
- код в скрипте идёт сверху вниз.

Если внутри скрипта пять раз вызвать `file_get_contents` в цикле, задержки **суммируются**. Параллельные исходящие HTTP в одном скрипте — через **`curl_multi_*`**.

С PHP 8.1 есть встроенные **[Fibers](https://www.php.net/manual/ru/class.fiber.php)**. Для долгоживущих воркеров и высокой нагрузки — **Swoole**, **RoadRunner**, **ReactPHP** — обзор в [экосистеме PHP](/encyclopedia/5-languages/5-07-php/10).

## Итоги

1. Определите тип нагрузки — [I/O-bound](#словарь-перед-практикумом) или [CPU-bound](#словарь-перед-практикумом).
2. Для I/O используйте async, потоки (где GIL не мешает), горутины или корутины — главное, чтобы один поток не простаивал в ожидании сети.
3. Для CPU — процессы или пул с числом воркеров около числа ядер; в Python для CPU потоки почти не дают ускорения.
4. При общей памяти между потоками нужны `lock`, `synchronized`, атомики — иначе [гонки](./11).
5. Для изоляции плагинов и фоновых задач — отдельный [процесс](./13) или очередь сообщений.
