## FAQ — Часто задаваемые вопросы

Типичные сбои при организации проекта, работе в IDE и выборе фреймворка, плюс **формулировки, как их ищут в Google** — с кратким ответом и ссылкой на главу. Определения для зачёта — в [чек-листе](./999).

<div class="faq-list">

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Открыл папку с кодом в VS Code — подсветки нет, Run не работает, "это не проект".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Редактор видит <strong>файлы</strong>, а не структуру сборки, пока нет `package.json`, `.csproj`, `pyproject.toml` или аналога. Создайте проект через CLI или шаблон IDE, затем откройте корень с манифестом. Подробнее здесь — [проект](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/1), [IDE](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/10).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `npm install` падает с EACCES, EPERM или "peer dependency conflict".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Не ставьте глобально от root; используйте <strong>локальный каталог проекта</strong>, актуальный Node LTS и lock-файл (`package-lock.json`). При конфликте версий читайте сообщение npm — часто помогает обновление одной зависимости. Подробнее здесь — [проект](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/1), [зависимости](/encyclopedia/4-code-dev/4-09-zavisimosti/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `dotnet build` успешен, `dotnet run` — "Could not find executable".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Проверьте <strong>OutputType и StartupObject</strong> в `.csproj`, что вы в каталоге нужного проекта, а не только solution. Для веб-проектов entry point — другой профиль запуска. Подробнее здесь — [проект](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/1), [сборка](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/102).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> IDE подчёркивает код красным, но программа всё равно запускается.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Анализатор IDE смотрит на <strong>другой SDK или неполный контекст</strong> (нет восстановленных пакетов). Выполните restore/build; если ошибка только в IDE — перезагрузите language server. Подробнее здесь — [IDE](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/10).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Точка останова серая — отладчик "не останавливается".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Запущена <strong>Release-сборка без символов</strong>, другой процесс или код не попадает в бинарник (условная компиляция). Переключите конфигурацию на Debug, убедитесь, что debug attach к нужному процессу. Подробнее здесь — [IDE](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/10), [отладка](/encyclopedia/4-code-dev/4-06-arhitektura-vypolneniya/112).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Две версии одной библиотеки в проекте — странные ошибки типов и "method not found".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Классический <strong>dependency hell</strong>. Смотрите дерево зависимостей (`npm ls`, NuGet graph), выравнивайте версии через lock и overrides. Подробнее здесь — [зависимости](/encyclopedia/4-code-dev/4-09-zavisimosti/intro), [проект](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/1).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> `create-react-app` / `dotnet new` создал "лес" папок — куда класть свой код?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Фреймворк задаёт <strong>конвенцию каталогов</strong> — `src/`, `Controllers/`, `app/`. Не ломайте структуру без нужды; новые файлы кладите туда, где лежат аналоги из документации. Подробнее здесь — [фреймворк](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/11), [архитектура](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/112).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Обновил фреймворк на мажорную версию — половина туториалов и плагинов перестала работать.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Читайте <strong>migration guide</strong>, обновляйте по шагам, держите тесты. Фиксируйте версии в lock-файле; на учебном проекте иногда проще создать новый шаблон и перенести код. Подробнее здесь — [фреймворк](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/11), [сборка](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/102).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Путаю Visual Studio Code и Visual Studio — установил "не то".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> VS Code — <strong>лёгкий редактор</strong> с расширениями; Visual Studio — полная IDE под .NET/C++ на Windows. Для Python/JS часто хватает VS Code + расширения; для больших .NET solution — Visual Studio. Подробнее здесь — [IDE](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/10).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Открыл `.sln`, проекты серые "unloaded" — solution сломан?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Пути к `.csproj` в solution <strong>относительные</strong> — при переименовании папки или клонировании не туда ссылки рвутся. Reload project или правьте пути в `.sln` / через IDE. Подробнее здесь — [проект](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/1).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Закоммитил `node_modules` — репозиторий раздулся до гигабайт.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> В Git хранят <strong>манифест и lock</strong>, а не скачанные пакеты. Добавьте `node_modules/` в `.gitignore`, удалите из истории через `git filter-repo` или начните чистую ветку на учебном проекте. Подробнее здесь — [проект](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/1).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Debug работает, Release падает на сервере.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Разные <strong>флаги оптимизации, переменные окружения и конфиги</strong>. Сравните `appsettings.Production.json`, connection strings и сборку с теми же символами на staging. Подробнее здесь — [сборка](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/102), [оптимизация](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/3).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Локально через Docker всё ок, без контейнера — "connection refused".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> В compose сервисы видят друг друга по <strong>имени контейнера</strong>; на хосте нужен `localhost` и проброшенный порт. Проверьте `.env` и не хардкодьте внутренние DNS-имена docker-сети. Подробнее здесь — [сборка](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/102), [запуск](/encyclopedia/1-basics/1-035-bazovaya-informatika/208).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Переменные из `.env` не подхватываются при запуске из IDE.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Настройте <strong>launch profile</strong> или Run Configuration с путём к `.env`; некоторые IDE не читают dotenv автоматически. Дублируйте критичные ключи в user secrets для локальной разработки. Подробнее здесь — [IDE](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/10), [проект](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/1).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Библиотека или фреймворк — что выбрать для первого сайта?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Библиотеку <strong>вызываете вы</strong> (HTTP-клиент, UI-компонент); фреймворк задаёт каркас и жизненный цикл (Django, Spring). Для учебного CRUD быстрее старт с фреймворком по туториалу экосистемы. Подробнее здесь — [библиотека](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/101), [фреймворк](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/11).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Сгенерировал scaffold — не могу найти, где править логику.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Генератор кладёт код в <strong>предсказуемые слои</strong> (Controller/Service/Repository). Ищите partial class или hooks в документации; не правьте автоген без метки, её перезатрёт update. Подробнее здесь — [фреймворк](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/11), [модульность](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/2).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Автодополнение в IDE перестало предлагать методы — "как будто сломалось".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Перезапустите language server, выполните <strong>restore/build</strong>, проверьте, что открыт корень solution, а не один файл. Битый синтаксис в файле блокирует анализ всего проекта. Подробнее здесь — [IDE](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/10).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> У одногруппника проект собирается, у меня — "SDK not found" при той же версии в README.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Установлен другой <strong>minor SDK или workload</strong> (ASP.NET, Android). Поставьте версию из `global.json` / `engines` в package.json; на Windows проверьте несколько установленных SDK side-by-side. Подробнее здесь — [проект](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/1), [сборка](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/102).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> В solution три проекта — как понять, какой запускается по F5?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Задайте <strong>startup project</strong> в IDE (жирный шрифт в solution explorer). Для веб+API часто нужно поднять два процесса или один compose-профиль. Подробнее здесь — [проект](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/1), [IDE](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/10).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Hot reload не подхватывает изменения — всё равно перезапускаю вручную.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Hot reload ограничен — <strong>смена сигнатур, статики, native code</strong> требует полного restart. Для Razor/Blazor/React проверьте, включён ли dev-server и нет ли ошибки компиляции в overlay. Подробнее здесь — [IDE](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/10), [сборка](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/102).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Микрофреймворк (Flask, Express) или "полный" (Django, Nest) — перегруз на старте?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Микрофреймворк даёт <strong>минимум каркаса</strong>, структуру наращиваете сами; полный — батарейки сразу, но больше правил. Для первого REST API часто проще Express/Flask + один модуль. Подробнее здесь — [микрофреймворк](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/111), [фреймворк](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/11).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Скопировал проект на флешку — пути к ресурсам "C:\Users\..." больше не работают.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Абсолютные пути в коде и конфигах <strong>не переносимы</strong>. Используйте относительные пути от корня проекта, переменные окружения и content root API фреймворка. Подробнее здесь — [проект](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/1).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> CI на GitHub Actions падает, локально `npm test` зелёный.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Отличия <strong>версии Node, часового пояса, секретов и case-sensitive paths</strong> (Linux vs Windows). Воспроизведите workflow в Docker или WSL. Подробнее здесь — [сборка](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/102).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Тестовый проект не видит классы основного — "type or namespace not found".</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Добавьте <strong>ProjectReference</strong> или package reference; internal классы сделайте public/`InternalsVisibleTo`. Убедитесь, что test runner указывает на правильную target framework. Подробнее здесь — [проект](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/1), [модульность](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/2).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Документация фреймворка предполагает, что я уже знаю npm/pip/dotnet — куда идти за базой?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Сначала [проект и манифест](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/1), затем [IDE](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/10) и [запуск приложений](/encyclopedia/1-basics/1-035-bazovaya-informatika/208); параллельно — терминал из раздела 2.05.</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Решил "обойтись без фреймворка" — проект разросся в хаос из copy-paste.</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Без каркаса вы сами проектируете <strong>маршрутизацию, конфиг, DI</strong>. Вынесите повтор в модули или возьмите микрофреймворк; см. [модульность](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/2), [архитектура](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/112).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Сборка занимает минуты — это нормально для маленького учебного проекта?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Часто виноваты <strong>антивирус, сетевой restore и лишние target</strong>. Кэшируйте зависимости в CI, отключите анализ на каждый save, профилируйте slow MSBuild/npm script. Подробнее здесь — [оптимизация](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/3), [сборка](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/102).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Что такое проект в программировании (software project)?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Единица сборки — <strong>исходники, конфиг, зависимости и метаданные</strong> в `package.json`, `.csproj`, `pom.xml`. Подробнее здесь — [проект](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/1).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Что такое package.json в Node.js проекте?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Манифест npm-проекта — <strong>имя, версии, scripts, dependencies</strong>; по нему `npm install` и `npm run`. Подробнее здесь — [проект](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/1), [зависимости](/encyclopedia/4-code-dev/4-09-zavisimosti/intro).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Что такое файл .csproj?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Описание <strong>.NET-проекта</strong> — target framework, ссылки на пакеты NuGet, тип выхода (exe, library). Подробнее здесь — [проект](/encyclopedia/4-code-dev/4-04-proekt-i-freymvorki/1).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> VS Code или Visual Studio — что выбрать?</p>

## Что запомнить

Основные функции IDE:
	- Подсветка синтаксиса;
	- Автодополнение кода;
	- Отладка программы;
	- Контроль версий;
	- Интеграция с другими инструментами.
  
Три основных правила работы с IDE:
1. Настройте рабочее окружение под свои задачи.
2. Используйте все доступные инструменты отладки.
3. Регулярно проверяйте и обновляйте конфигурацию.

Три фундаментальных момента:
	- Правильная настройка IDE повышает эффективность работы;
	- Процесс подготовки программы включает несколько этапов;
	- Качественная отладка критична для стабильности программы.

Современная разработка программного обеспечения невозможна без чёткого понимания того, как организованы рабочие единицы кода и инструменты, в которых они создаются. **Проект** — это минимальная логическая и техническая единица, объединяющая исходный код, ресурсы, зависимости и метаданные, необходимые для сборки одного исполняемого артефакта. Он описывается специальным файлом (`.csproj`, `.pyproject.toml`, `package.json` и т.д.) и имеет чёткую структуру каталогов, заданную экосистемой языка.

Когда задача требует нескольких взаимосвязанных компонентов — например, бэкенд, фронтенд и мобильное приложение, — их объединяют в **решение**. Решение не содержит кода напрямую, но управляет проектами: определяет порядок сборки, общие настройки и зависимости между ними. Такой подход позволяет масштабировать систему, сохраняя контроль над её частями.

**Интегрированная среда разработки (IDE)** — это центральный инструмент, в котором разработчик пишет, проверяет, отлаживает и запускает код. От простых редакторов вроде VS Code до мощных платформ вроде IntelliJ IDEA или Visual Studio — каждая IDE предоставляет подсветку синтаксиса, автодополнение, встроенный отладчик и интеграцию с системами контроля версий. Выбор IDE зависит от языка, сложности проекта и предпочтений команды, но ключевая функция остаётся неизменной: ускорить переход от идеи к работающему коду.

**Фреймворк** — это готовая архитектурная основа, которая диктует правила организации кода и управляет его выполнением. В отличие от библиотек, которые вызываются разработчиком, фреймворк вызывает код разработчика (принцип инверсии управления). Он предоставляет каркас для маршрутизации, обработки запросов, работы с данными, авторизации и других повторяющихся задач. Использование фреймворка ускоряет разработку, повышает надёжность и обеспечивает единый стиль кода в команде.

Вместе эти четыре элемента — **проект, решение, IDE и фреймворк** — формируют основу современного процесса разработки. Они позволяют превратить набор текстовых файлов в сложное, масштабируемое и поддерживаемое программное обеспечение, не теряя контроля над его структурой и поведением.
