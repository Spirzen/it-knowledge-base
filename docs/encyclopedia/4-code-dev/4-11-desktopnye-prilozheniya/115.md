## Windows Forms (WinForms)

### Где применяют WinForms

**Windows Forms** — **API графического интерфейса** в составе [.NET](/encyclopedia/5-languages/5-04-platforma-dotnet/1): набор управляемых классов в пространстве имён `System.Windows.Forms`, которые упрощают доступ к элементам Windows за счёт **обёртки над Win32 API**. Классы WinForms **не зависят от языка** — один и тот же API доступен из C#, VB.NET, F# и других .NET-языков.

Это один из самых продуктивных способов собрать десктоп с **визуальным конструктором** в Visual Studio:

- контролы перетаскиваются на форму;
- свойства редактируются в окне Properties;
- а логика пишется в обработчиках событий.

Официальная документация: [Windows Forms для .NET](https://learn.microsoft.com/ru-ru/dotnet/desktop/winforms/). **Рецепты по каждому элементу UI** — [1152.md](./1152.md). **Галерея готовых окон с построчным разбором** — [C# WinForms и WPF — простые окна](/lab/Примеры/1138) (кнопка, TextBox, ListBox, конвертер температуры — для лабораторной и курсовой). Те же учебные задачи на **Java (Swing)** — [Lab — 1143](/lab/Примеры/1143). Платформа Windows в целом (WinUI, SDK, Store): [Разработка приложений для Windows](./116.md). Сравнение с WPF, MAUI и другими стеками: [Особенности разработки десктопных приложений](./112.md). ## История и место WinForms в экосистеме Windows

WinForms появился вместе с **.NET Framework 1.0** (февраль 2002) по аналогии с **AWT** в Java — как способ быстро собирать GUI-компоненты поверх нативных оконных примитивов ОС. По сути библиотека — **обёртка устаревающего Windows API**: многие методы вызывают Win32 напрямую, поэтому внешний вид и поведение контролов совпадают с «родными» окнами Windows, а перенос на другие платформы ограничен (проект **Mono** реализовал совместимый `System.Windows.Forms`, но для Microsoft целевой путь — Windows).

WinForms часто рассматривают как более простую альтернативу **MFC** (C++): меньше boilerplate, управляемая память, визуальный конструктор. Встроенной парадигмы уровня **MVC** у WinForms нет — UI-логика живёт в формах и обработчиках; для структурирования используют **MVP** или сторонние библиотеки (например, Microsoft **User Interface Process Application Block**).

| Этап | Что изменилось |
|------|----------------|
| **.NET 2.0** (2005) | ToolStrip в стиле Office 2003, улучшенная привязка данных, ClickOnce, расширенный конструктор |
| **.NET 3.0** (2006) | Появился **WPF** — UI на **DirectX** и **XAML**; WinForms остался параллельным стеком |
| **Build 2014** | Microsoft заявила: WinForms поддерживается, баги исправляются, **новые крупные функции не планируются** |
| **.NET 4.5+** | Улучшения **HiDPI** и масштабирования для элементов интерфейса |
| **.NET Core 3.0+ / .NET 5+** | WinForms перенесён в современный **.NET** с открытым исходником на [GitHub — dotnet/winforms](https://github.com/dotnet/winforms) |

Приложение WinForms — **событийно-ориентированное**: большую часть времени процесс ждёт действий пользователя (ввод в поле, клик по кнопке), а не выполняет линейный алгоритм от начала до конца, как пакетная программа. Эта модель совпадает с [архитектурой десктопа](./1.md) — цикл сообщений и обработчики событий.

## WinForms - формы, контролы и конструктор в Visual Studio

По [обзору Microsoft Learn](https://learn.microsoft.com/ru-ru/dotnet/desktop/winforms/overview/):

- WinForms — **технология UI для .NET**: набор управляемых библиотек для типовых задач (файлы, сеть, диалоги) и построения **интеллектуальных клиентских** приложений Windows.
- Платформа поддерживает **элементы управления**, **графику** (`System.Drawing`), **привязку данных** и **ввод пользователя** (клавиатура, мышь, перетаскивание).
- Приложения могут работать **автономно** и в сети, обращаться к **локальному оборудованию** и файловой системе в рамках прав ОС.
- Характерная черта — **конструктор форм** в Visual Studio с drag-and-drop, сеткой и линиями привязки для выравнивания контролов.

WinForms появился в **.NET Framework 1.0 (2002)**; с **.NET Core 3.0** и далее платформа перенесена в современный **.NET** (сейчас актуальны ветки вроде .NET 8/9/10). Подходит для **внутренних утилит**, **сопровождения legacy**, **быстрых CRUD-интерфейсов** и систем, где важны простота и интеграция с Windows, а не "богатый" кастомный UI.

## Модель приложения — форма, контролы, события

### Форма

В WinForms **форма** (`System.Windows.Forms.Form`) — визуальная поверхность окна или диалога: заголовок, границы, кнопки свернуть/развернуть, область для контролов. Класс `Form` позволяет создавать обычные, модальные, MDI-окна и настраивать `FormBorderStyle`, `StartPosition`, `Size`, `Text` и др. ([документация Form](https://learn.microsoft.com/ru-ru/dotnet/api/system.windows.forms.form)).

Типичное приложение:

1. Создаётся одна или несколько форм.
2. На форму добавляются **элементы управления** (`Control` и наследники).
3. На действия пользователя подписываются **обработчики событий** (клик, ввод текста, закрытие формы).

Подробнее: [События в Windows Forms](https://learn.microsoft.com/ru-ru/dotnet/desktop/winforms/forms/events).

---

### Контролы

Стандартные контролы: `Button`, `TextBox`, `Label`, `ComboBox`, `CheckBox`, `RadioButton`, `ListBox`, `TreeView`, `TabControl`, встроенный **WebBrowser** / современные варианты через WebView2 и др. Полный список: [элементы управления для Windows Forms](https://learn.microsoft.com/ru-ru/dotnet/desktop/winforms/controls/controls-to-use-on-windows-forms).

Для сложного UI без сторонних библиотек используют:

- `FlowLayoutPanel`, `TableLayoutPanel`, `SplitContainer` — быстрые макеты;
- `ToolStrip`, `MenuStrip`, `StatusStrip` — панели и меню в стиле Office;
- `UserControl` — [собственные составные контролы](https://learn.microsoft.com/ru-ru/dotnet/desktop/winforms/controls-design/how-to-create-usercontrol).

Отрисовка "вручную" — через `System.Drawing` (линии, фигуры, owner-draw).

---

### Событийная модель

Любое действие пользователя с формой или контролом порождает **событие**; приложение реагирует кодом в момент возникновения. Это та же идея, что перенесли в ASP.NET Web Forms (PostBack, ViewState) — см. [C# — Web Forms](/encyclopedia/5-languages/5-05-csharp/451.md).

## Разработка в Visual Studio

Рекомендуемый путь — [создание приложения WinForms в Visual Studio](https://learn.microsoft.com/ru-ru/dotnet/desktop/winforms/get-started/create-app-visual-studio):

1. Шаблон **"Приложение Windows Forms"** (.NET).
2. **Конструктор форм** — перетаскивание с Toolbox, свойства в **Properties**, автогенерация `*.Designer.cs` и `InitializeComponent()`.
3. Окно **"Источники данных"** — drag-and-drop привязки к БД, XML, JSON, веб-сервисам.

Минимальная структура точки входа (.NET 6+):

```csharp
namespace MyWinFormsApp;

static class Program
{
    [STAThread]
    static void Main()
    {
        ApplicationConfiguration.Initialize();
        Application.Run(new Form1());
    }
}
```

Файл проекта обычно использует SDK `Microsoft.NET.Sdk` с `UseWindowsForms`:

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>WinExe</OutputType>
    <TargetFramework>net8.0-windows</TargetFramework>
    <UseWindowsForms>true</UseWindowsForms>
    <Nullable>enable</Nullable>
  </PropertyGroup>
</Project>
```

Скачать среду: [Visual Studio 2022](https://visualstudio.microsoft.com/downloads/) с рабочей нагрузкой **"Разработка классических приложений .NET"**.

## Архитектура и ограничения

- Каждый стандартный контрол — обёртка над **HWND** (User32): нативный вид, высокая совместимость с Windows, но **внешний вид зависит от темы ОС**.
- Графика "из коробки" — **GDI+**, не DirectX: сложные эффекты (анимации, векторный UI) проще в [WPF](/encyclopedia/5-languages/5-04-platforma-dotnet/13.md) или [MAUI](/encyclopedia/5-languages/5-04-platforma-dotnet/13.md).
- Контролы **не маршалируются между доменами приложений** (`AppDomain`); multi-AppDomain-сценарии с передачей контролов через границы не поддерживаются.
- Официальная платформа — **Windows**; кроссплатформенность ограничена (Mono и аналоги — не целевой путь Microsoft).

Паттерны: код "в форме", **MVP** (удобно тестировать UI-логику), реже MVVM. См. [архитектурные паттерны](./112.md) в этом же разделе.

## Актуальное развитие (.NET 10+)

Платформа **не заморожена**: в [новых возможностях WinForms для .NET 10](https://learn.microsoft.com/ru-ru/dotnet/desktop/winforms/whats-new/net100) среди прочего:

- унификация API **буфера обмена** с WPF;
- улучшения **асинхронных форм** и отзывчивости UI при нескольких окнах.

Сообщество дополняет экосистему через [Windows Forms Community Toolkit](https://github.com/dotnet/winformscommunitytoolkit).

## Когда выбирать WinForms

| Выбирайте WinForms | Рассмотрите WPF / MAUI / Electron |
|--------------------|----------------------------------|
| Быстрый UI под Windows, знакомая событийная модель | Богатый кастомный дизайн, анимации, MVVM |
| Сопровождение существующего .NET Framework-приложения | Кроссплатформа macOS/Linux |
| Внутренние утилиты, админки, линейные формы | UI на HTML/CSS (команда веб-разработчиков) |

---

### Частые ошибки

| Симптом | Причина |
|---------|---------|
| "Зависание" формы | Долгая работа в обработчике `Click` |
| `Cross-thread operation not valid` | Обновление контрола не из UI-потока — `Invoke` |
| Дизайнер не открывается | Ошибка в `InitializeComponent` / partial class |
| DPI размытие | Нет `AutoScaleMode` / PerMonitorV2 в манифесте |

---

### Что попробовать

1. `async void` обработчик + `await Task.Run` для тяжёлой работы.
2. `BindingSource` + `DataGridView` — мини-CRUD без ручного refresh.
3. Встроить [WebView2](./113.md) на форму для гибридного UI.

## Практические шаблоны для рабочих форм

### Структура экрана "список + карточка"

- Левая зона: `DataGridView` с поиском и пагинацией.
- Правая зона: форма редактирования выбранной записи.
- Нижняя зона: `StatusStrip` со статусом операций и ошибками валидации.

Такой шаблон покрывает большинство внутренних CRUD-приложений и ускоряет разработку.

---

### Стандарты, которые окупаются

1. Единые базовые формы (`BaseForm`) с общей логикой логирования и обработки ошибок.
2. Централизованная валидация ввода до сохранения.
3. Фоновая загрузка справочников, чтобы UI открывался быстро.
4. Обязательный `CancellationToken` для долгих операций импорта/экспорта.

## Как масштабировать WinForms без хаоса

- Переносите бизнес-логику в сервисы и use-case классы.
- Оставляйте форму как слой отображения и маршрутизации действий.
- Вводите интерфейсы для репозиториев, чтобы писать unit-тесты без UI.
- Добавляйте feature-модули по доменам, а не один гигантский `Form1.cs`.

## План развития WinForms-приложения

### От "быстрой формы" к поддерживаемому продукту

1. Введите единый шаблон слоя UI и отдельный слой сервисов.
2. Добавьте обработку ошибок и технические логи в ключевых действиях пользователя.
3. Покройте бизнес-правила unit-тестами без запуска формы.
4. Подготовьте сценарии миграции данных и обновления версии приложения.

---

### Признаки зрелой WinForms-базы

- Формы остаются компактными и не содержат доменную логику.
- Долгие операции выполняются асинхронно и не блокируют UI.
- Новые экраны добавляются модульно без правок в "центральный" файл.
