#### Windows - отдельный стек десктоп-разработки

Раздел [Десктопные приложения](./intro) описывает общую архитектуру окон, событий и стеков (Qt, Electron, Java и др.). Для **Windows** Microsoft выделяет отдельную [платформу разработчика](https://learn.microsoft.com/ru-ru/windows/apps/get-started/?tabs=native): два уровня SDK, рекомендуемый UI (**WinUI 3**), классические [.NET-стеки](./115.md) и путь от настройки машины до [публикации в Microsoft Store](./117.md).

Официальный вход: [Обзор платформы разработчиков Windows](https://learn.microsoft.com/ru-ru/windows/apps/get-started/?tabs=native). Практический старт проекта: [Начните здесь](https://learn.microsoft.com/ru-ru/windows/apps/get-started/start-here?tabs=wingetconfig).

См. также: [Архитектура десктопных приложений](./1.md) (в том числе [что такое драйвер](./1.md#drayvery-i-dostup)), [Особенности разработки десктопных приложений](./112.md), [Платформа .NET — UI](/encyclopedia/5-languages/5-04-platforma-dotnet/13.md).

## Два SDK: Windows SDK и Windows App SDK

| | **Windows SDK** | **Windows App SDK** |
|---|-----------------|---------------------|
| Назначение | Заголовки, библиотеки и инструменты для **прямого доступа к API ОС** | Современный слой поверх Windows SDK: WinUI, жизненный цикл, окна, уведомления |
| Привязка к ОС | Привязан к **версиям Windows** | Поставляется через **NuGet**, обновляется чаще релизов ОС |
| Когда нужен | Низкоуровневые API, DirectX, последние функции ОС, Win32/C++ | Новые приложения с Fluent UI, интеграция в WPF/WinForms |

Документация: [Windows SDK](https://learn.microsoft.com/ru-ru/windows/apps/windows-sdk/), [Windows App SDK](https://learn.microsoft.com/ru-ru/windows/apps/windows-app-sdk/).

Любое Windows-приложение в итоге опирается на **Windows SDK**; **Windows App SDK** — рекомендуемый путь для современного UI и системных возможностей без ожидания обновления всей ОС. Поддерживается Windows 10 (1809) и новее.

## Выбор платформы приложения

Microsoft предлагает несколько «дорожек»; выбор зависит от того, новый ли проект, есть ли legacy и нужна ли кроссплатформенность.

### WinUI 3 — рекомендуемый UI для новых Windows-приложений

**WinUI 3** — нативный UI на базе [Windows App SDK](https://learn.microsoft.com/ru-ru/windows/apps/windows-app-sdk/) и **XAML** (C# или C++), с оформлением [Fluent Design](https://fluent2.microsoft.design/). Если вы впервые пишете под Windows или начинаете проект с нуля — [документация WinUI](https://learn.microsoft.com/ru-ru/windows/apps/winui/winui3/) и [старт WinUI](https://learn.microsoft.com/ru-ru/windows/apps/get-started/start-here?tabs=wingetconfig) — основная точка входа.

Особенности по сравнению с другими стеками (сводка Microsoft):

- современный интерфейс и **песочница AppContainer** (в отличие от классических Win32/WPF/WinForms без контейнера);
- нет визуального drag-and-drop дизайнера как у WinForms/WPF — UI чаще в XAML и коде;
- только Windows (не кроссплатформа; для macOS/Linux смотрите [.NET MAUI](/encyclopedia/4-code-dev/4-12-mobilnye-prilozheniya/1133)).

### WPF

[WPF](https://learn.microsoft.com/ru-ru/dotnet/desktop/wpf/overview/) — зрелая XAML-платформа для классических .NET-приложений: привязка данных, стили, векторная графика, MVVM. Подходит для существующих проектов и сложного desktop UI на Windows. Существующие WPF-приложения можно **модернизировать** возможностями Windows App SDK ([WPF + Windows App SDK](https://learn.microsoft.com/ru-ru/windows/apps/windows-app-sdk/wpf-plus-winappsdk)).

### Windows Forms

[Windows Forms](./115.md) — быстрые формы с визуальным конструктором; см. [обзор WinForms](https://learn.microsoft.com/ru-ru/dotnet/desktop/winforms/overview/). Модернизация через [WinForms + Windows App SDK](https://learn.microsoft.com/ru-ru/windows/apps/windows-app-sdk/winforms-plus-winappsdk).

### Win32 (C++)

Прямой доступ к Windows и оборудованию; максимальная производительность, DirectX, низкоуровневые сценарии. Старт: [Win32 desktop programming](https://learn.microsoft.com/ru-ru/windows/win32/desktop-programming/), современные обёртки — [C++/WinRT](https://learn.microsoft.com/ru-ru/windows/uwp/cpp-and-winrt-apis/).

### UWP (наследие)

[Universal Windows Platform](https://learn.microsoft.com/ru-ru/windows/uwp/) — общие API для семейства устройств Windows. Существующие UWP продолжают работать; для WinUI 3 и Windows App SDK Microsoft рекомендует [стратегию миграции](https://learn.microsoft.com/ru-ru/windows/apps/windows-app-sdk/migrate-to-windows-app-sdk/overall-migration-strategy).

### Кроссплатформа

**.NET MAUI** и **React Native** перечислены в [сравнении платформ](https://learn.microsoft.com/ru-ru/windows/apps/get-started/?tabs=native) как кроссплатформенные варианты с поддержкой Windows среди других ОС.

Полная таблица — на [странице обзора](https://learn.microsoft.com/ru-ru/windows/apps/get-started/?tabs=native). Упрощённо для выбора:

| Веб-команда, HTML UI | **Electron** → [114](./114.md) |

## Среда разработки

Перед первым проектом имеет смысл настроить рабочую станцию по [руководству Set up your development environment](https://learn.microsoft.com/ru-ru/windows/dev-environment/):

- **Visual Studio 2022** с workload «Разработка классических приложений .NET» и/или «Разработка приложений для Windows» (WinUI, C++);
- **Windows SDK** и при необходимости **Windows App SDK** (часто подтягиваются с проектом);
- **.NET SDK** для WinForms, WPF, MAUI;
- опционально **WinGet** и конфигурация окружения — см. вкладку winget в [Start here](https://learn.microsoft.com/ru-ru/windows/apps/get-started/start-here?tabs=wingetconfig).

Подробнее про IDE: [Visual Studio — установка и workloads](/encyclopedia/4-code-dev/4-14-razrabotka-i-otladka/1132).

## Драйверы (обзор для прикладного разработчика) \{#drayvery-obzor\}

Десктоп-приложение обращается к принтеру, камере, диску через **API ОС**, а не напрямую к регистрам устройства. Между приложением и железом работают **драйверы** — см. [Что такое драйвер?](https://learn.microsoft.com/ru-ru/windows-hardware/drivers/gettingstarted/what-is-a-driver-) и вводную в [Архитектуре десктопных приложений](./1.md#drayvery-i-dostup).

Если вы **не** пишете драйвер, достаточно знать:

- запросы идут через стек драйверов (фильтры, function driver, bus driver);
- сбой драйвера может вызвать нестабильность системы (в отличие от падения одного user-mode процесса);
- разработка драйверов — отдельная дисциплина: [Windows drivers](https://learn.microsoft.com/ru-ru/windows-hardware/drivers/), [Getting started with drivers](https://learn.microsoft.com/ru-ru/windows-hardware/drivers/gettingstarted/).

Прикладной код (WinUI, WPF, WinForms) остаётся в пользовательском режиме; к драйверам обычно не обращаются, кроме специализированных утилит и SDK производителя оборудования.

|---------|---------|

| Путаница SDK | Windows SDK ≠ Windows **App** SDK — см. таблицу выше |
