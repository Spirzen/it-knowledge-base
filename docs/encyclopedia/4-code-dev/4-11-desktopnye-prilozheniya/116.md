## Два SDK — Windows SDK и Windows App SDK

| | **Windows SDK** | **Windows App SDK** |
|---|-----------------|---------------------|
| Назначение | Заголовки, библиотеки и инструменты для **прямого доступа к API ОС** | Современный слой поверх Windows SDK: WinUI, жизненный цикл, окна, уведомления |
| Привязка к ОС | Привязан к **версиям Windows** | Поставляется через **NuGet**, обновляется чаще релизов ОС |
| Когда нужен | Низкоуровневые API, DirectX, последние функции ОС, Win32/C++ | Новые приложения с Fluent UI, интеграция в WPF/WinForms |

Документация: [Windows SDK](https://learn.microsoft.com/ru-ru/windows/apps/windows-sdk/), [Windows App SDK](https://learn.microsoft.com/ru-ru/windows/apps/windows-app-sdk/).

Любое Windows-приложение в итоге опирается на **Windows SDK**; **Windows App SDK** — рекомендуемый путь для современного UI и системных возможностей без ожидания обновления всей ОС. Поддерживается Windows 10 (1809) и новее.

## DirectX — графический стек под WPF и игры

**DirectX** — набор **API Microsoft Windows** для мультимедиа и графики: изначально создан, чтобы игры на Windows 95 получили прямой доступ к видеокарте, клавиатуре и звуку — тот же уровень контроля, что давала DOS, но в защищённой модели памяти. Сегодня DirectX используют и **игры**, и **инженерное ПО**, и **desktop UI** (WPF, WinUI).

Основные компоненты, полезные прикладному разработчику:

| Компонент | Назначение |
|-----------|------------|
| **Direct3D (D3D)** | 3D- и 2D-примитивы, шейдеры, аппаратное ускорение |
| **Direct2D** | двумерная векторная графика |
| **DirectWrite** | рендеринг текста (используется WPF) |
| **DirectShow** | аудио/видео потоки |
| **DXGI** | обмен буферами с монитором |

**Direct3D 11** (октябрь 2009, Windows 7) — ключевой слой между ОС, драйвером видеокарты и приложением. Он доступен и на Windows Vista через обновление платформы. WPF при отрисовке опирается на DirectX, а WinForms — на **GDI+**; поэтому сложная анимация и масштабирование на HiDPI в WPF обычно плавнее.

Для прикладного C#-разработчика Direct3D напрямую нужен редко (игры, CAD, кастомный рендер). Достаточно понимать цепочку: **XAML → WPF/WinUI → DirectX → драйвер GPU**. Низкоуровневый доступ — через **Win32 + Windows SDK** или обёртки вроде SharpDX / Vortice.Windows.

## Выбор платформы приложения

Microsoft предлагает несколько "дорожек"; выбор зависит от того, новый ли проект, есть ли legacy и нужна ли кроссплатформенность.

### WinUI 3 — рекомендуемый UI для новых Windows-приложений

**WinUI 3** — нативный UI на базе [Windows App SDK](https://learn.microsoft.com/ru-ru/windows/apps/windows-app-sdk/) и **XAML** (C# или C++), с оформлением [Fluent Design](https://fluent2.microsoft.design/). Если вы впервые пишете под Windows или начинаете проект с нуля — [документация WinUI](https://learn.microsoft.com/ru-ru/windows/apps/winui/winui3/) и [старт WinUI](https://learn.microsoft.com/ru-ru/windows/apps/get-started/start-here?tabs=wingetconfig) — основная точка входа.

Особенности по сравнению с другими стеками (сводка Microsoft):

- современный интерфейс и **песочница AppContainer** (в отличие от классических Win32/WPF/WinForms без контейнера);
- нет визуального drag-and-drop дизайнера как у WinForms/WPF — UI чаще в XAML и коде;
- только Windows (не кроссплатформа; для macOS/Linux смотрите [.NET MAUI](/encyclopedia/4-code-dev/4-12-mobilnye-prilozheniya/1133)).

### WPF

**Windows Presentation Foundation (WPF)** — презентационная подсистема .NET (с версии 3.0, 2006) для клиентских Windows-приложений с богатым визуальным взаимодействием. Разметка интерфейса пишется на **[XAML](/encyclopedia/3-data-markup/3-04-konfiguratsii-i-dannye/6)**; логика — на любом .NET-языке (чаще C#).

Ключевые отличия от WinForms:

| | **WinForms** | **WPF** |
|---|-------------|---------|
| Отрисовка | **GDI / GDI+** через HWND-контролы | **DirectX** (аппаратное ускорение) |
| Единица графики | пиксели экрана | **аппаратно-независимый пиксель** (1/96 дюйма) — масштаб без «лесенки» |
| Разметка | конструктор форм + код | **XAML** + разделение дизайна и кода |
| Кастомный UI | owner-draw, ограниченно | **Style**, **ControlTemplate**, **DataTemplate**, анимация |

WPF изначально поставлялся с Windows Vista (.NET 3.0) и далее входил в состав .NET Framework на Windows 7–10. Сейчас WPF — часть современного .NET (`net*-windows`); поддерживает автономные приложения и сценарии в браузере (XBAP — legacy).

**Возможности WPF**, которые редко нужны в WinForms:

- **Привязка данных** — `Binding`, `MultiBinding`, `TemplateBinding`, `PriorityBinding`; связь UI с ViewModel прямо в разметке.
- **Стили и шаблоны** — единое оформление контролов и карточек списков без дублирования кода.
- **2D/3D-графика** — векторные фигуры, эффекты, встроенная анимация; GPU снимает часть нагрузки с CPU.
- **Ресурсы** — иерархия `ResourceDictionary` от контрола до `Application`.

[WPF на Microsoft Learn](https://learn.microsoft.com/ru-ru/dotnet/desktop/wpf/overview/) — официальный обзор. Существующие WPF-приложения можно **модернизировать** через Windows App SDK ([WPF + Windows App SDK](https://learn.microsoft.com/ru-ru/windows/apps/windows-app-sdk/wpf-plus-winappsdk)). Пошаговый практикум — [Первая форма WPF — XAML, стили и шаблоны](./119.md). Клиент-серверный маршрут (MVVM, ASP.NET Core, Prism) — [Практикум WPF и клиент-сервер](./wpf-praktikum/intro).

### UWP

**Universal Windows Platform (UWP)** — платформа Microsoft, представленная в **Windows 10**, для **универсальных приложений**: один код запускается на ПК, планшете, смартфоне (Windows 10 Mobile), Xbox One и IoT-устройствах без переписывания под каждую форму-фактор. UWP — расширение **Windows Runtime (WinRT)**, появившегося в Windows 8; API реализован на C++ и доступен из C++, C#, VB.NET, F# и JavaScript.

Разработка велась в Visual Studio 2015–2019; приложения распространялись через Microsoft Store с **песочницей AppContainer** — ограниченный доступ к файловой системе и API в обмен на безопасность и единый магазин. UWP использует **XAML** для UI (как WPF, но другой набор типов и `xmlns`).

| UWP | WinUI 3 / Windows App SDK |
|-----|---------------------------|
| Привязан к версии Windows и Store | NuGet-пакет, обновляется чаще ОС |
| Metro/Fluent UI первого поколения | Fluent Design, современные контролы |
| Новые проекты — legacy | Рекомендуемый путь для новых Windows-приложений |

UWP-приложения **не запускаются** на Windows 7 и ниже. Существующие UWP продолжают работать; для новых проектов Microsoft рекомендует [WinUI 3](https://learn.microsoft.com/ru-ru/windows/apps/winui/winui3/) и [стратегию миграции](https://learn.microsoft.com/ru-ru/windows/apps/windows-app-sdk/migrate-to-windows-app-sdk/overall-migration-strategy) на Windows App SDK.

## Драйверы (обзор для прикладного разработчика)

Десктоп-приложение обращается к принтеру, камере, диску через **API ОС**, а не напрямую к регистрам устройства. Между приложением и железом работают **драйверы** — см. [Что такое драйвер?](https://learn.microsoft.com/ru-ru/windows-hardware/drivers/gettingstarted/what-is-a-driver-) и вводную в [Архитектуре десктопных приложений](./1.md#drayvery-i-dostup).

Если вы **не** пишете драйвер, достаточно знать:

- запросы идут через стек драйверов (фильтры, function driver, bus driver);
- сбой драйвера может вызвать нестабильность системы (в отличие от падения одного user-mode процесса);
- разработка драйверов — отдельная дисциплина: [Windows drivers](https://learn.microsoft.com/ru-ru/windows-hardware/drivers/), [Getting started with drivers](https://learn.microsoft.com/ru-ru/windows-hardware/drivers/gettingstarted/).

Прикладной код (WinUI, WPF, WinForms) остаётся в пользовательском режиме; к драйверам обычно не обращаются, кроме специализированных утилит и SDK производителя оборудования.

## Практический алгоритм выбора стека под Windows

1. Зафиксируйте срок жизни продукта: пилот на 6 месяцев или платформа на 5+ лет.
2. Определите требования UI: стандартные формы, сложные анимации, кастомный дизайн.
3. Проверьте ограничения среды: Store, корпоративные политики, офлайн-режим.
4. Сверьте экспертизу команды: C# и XAML, C++ и Win32, веб-стек.
5. Запустите по одному прототипу на 2 кандидатах и сравните время реализации одинакового сценария.

## Минимальный pilot checklist

- Окно приложения, навигация и базовая форма данных.
- Асинхронная загрузка данных без блокировки UI.
- Сборка и установка на чистой машине.
- Логирование и обработка ошибок при потере сети.
- Черновой сценарий обновления версии.

Этот набор дает объективное сравнение WinUI, WPF, WinForms или Electron до начала большого проекта.

## Как провести техническое сравнение стеков

### Минимальный формат архитектурного эксперимента

1. Выберите единый пользовательский сценарий для всех кандидатов.
2. Реализуйте одинаковый объем функциональности на WinUI, WPF или WinForms.
3. Замерьте время разработки, скорость UI, размер пакета и удобство поддержки.
4. Сведите результаты в таблицу с критериями бизнеса и эксплуатации.

---

### Решение после эксперимента

Финальный выбор делайте по совокупности факторов: срок жизни продукта, экспертиза команды, требования к UX, ограничения инфраструктуры и правила поставки в организации.
