## Резюме конвейера

1. **Модель** — числа в RAM (`x`, `y`, `hp`, флаги)
2. **Update** — логика + `dt` + ввод
3. **Render** — команды API (`fillRect`, `draw`, `drawArrays`)
4. **Прослойки** — Skia, SDL, ANGLE
5. **Графический API** — OpenGL, Vulkan, DirectX
6. **GPU + VRAM** — шейдеры, текстуры, framebuffer
7. **Swap + V-Sync** — целый кадр на монитор
8. **Растр по кабелю** — HDMI/DP, 60–144 Гц

Графический код читается проще, когда каждая строка отнесена к одному из этих этапов.

## FAQ

<div class="faq-list">

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Почему в одном файле и физика, и `ctx.arc`?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Исторически один проект — экономия файлов. Логически это <strong>три слоя</strong>: модель, update, render. При рефакторинге их разделяют. См. [1](./1), [2](./2).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Модель сама рисует себя на экране?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Нет. Модель — только данные. Пока <code>render()</code> не прочитает координаты, пиксели не меняются.</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Почему каждый кадр стирают весь canvas?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Canvas хранит только пиксели, без списка объектов. Без <code>clearRect</code> останутся следы старых позиций. См. [3](./3).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> DOM или Canvas для игры?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Игровое поле — <strong>Canvas/WebGL</strong>. Меню и текст — часто DOM/HTML поверх. См. [2](./2), [7](./7).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Чем Canvas 2D отличается от WebGL?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Canvas — команды "нарисуй фигуру", растеризация через Skia. WebGL — треугольники и шейдеры на GPU. См. [7](./7), [11](./11).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Что такое SDL и при чём Pygame?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> <strong>SDL</strong> — C-библиотека окна и ввода. <strong>Pygame</strong> — Python-обёртка над SDL2. См. [8](./8).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Почему круг в 3D — это треугольники?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> GPU растеризует <strong>только треугольники</strong>. Окружность — аппроксимация mesh. См. [11](./11).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Что делает ANGLE для WebGL?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> В Chrome на Windows WebGL идёт через ANGLE → DirectX. Объясняет различия между браузерами и платформами. См. [10](./10).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Почему игра тормозит при 30 FPS, хотя CPU не загружен?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Возможно узкое место на <strong>GPU</strong> или V-Sync cap. Смотрите frame time и профиль GPU. См. [12](./12), [13](./13).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Что такое tearing?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Разрыв кадра при swap во время сканирования монитора. Лечится <strong>V-Sync</strong> или G-Sync. См. [13](./13).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> 16.7 ms — откуда цифра?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> 1000 / 60 ≈ 16.7 ms — бюджет кадра при 60 FPS. Превышение → просадка FPS. См. [13](./13).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Y вверх или вниз?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Canvas и большинство 2D API — <strong>Y вниз</strong>, (0,0) сверху слева. В математических графиках и части движков — Y вверх. См. [2](./2), [5](./5).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Нужен ли Vulkan начинающему?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Для старта — Canvas, Pygame или Unity, затем OpenGL/WebGL. Vulkan — для движков и инженеров. См. [11](./11).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Frustum culling — это только 3D?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Идея общая: не рисовать невидимое. В 2D — отсечение по границам экрана. См. [4](./4).</p>
</div>

<div class="faq-item">
  <p class="faq-q"><span class="faq-label">Вопрос.</span> Unity Update и render — где граница?</p>
  <p class="faq-a"><span class="faq-label">Ответ.</span> Логика в <code>Update</code>; движок рендерит сцену после всех Updates. Кастомная графика — <code>OnRenderObject</code> / URP passes. См. [9](./9), [3](./3).</p>
</div>

</div>

## Терминология раздела

| Термин | Смысл |
|--------|--------|
| **Модель** | Числа в RAM — координаты, HP, флаги; без команд рисования |
| **Update / render** | Логика меняет модель; render читает модель и вызывает API |
| **Draw call** | Команда GPU «нарисуй этот примитив»; дорогие при тысячах в кадре |
| **Retained mode** | Платформа хранит дерево сцены (DOM, Unity) |
| **Immediate mode** | Программист каждый кадр заново отдаёт команды (Canvas, классический GL) |
| **Растризация** | Перевод геометрии в сетку пикселей |
| **Шейдер** | Программа на GPU (vertex / fragment) |
| **VRAM** | Видеопамять — текстуры, буферы кадра |
| **Double buffering** | Рисование в back buffer, показ front buffer |
| **V-Sync** | Синхронизация swap с частотой монитора |
| **Frame time** | Миллисекунды на полный кадр; 60 FPS ≈ 16,7 ms |
| **FPS** | Кадров в секунду |
| **Culling** | Пропуск невидимых объектов до draw call |
| **HiDPI** | `devicePixelRatio` — физические vs CSS-пиксели canvas |
| **Skia / ANGLE** | 2D-движок Canvas в Chrome; транслятор WebGL → DirectX/Vulkan |

Подробнее по этапам — главы [6](./6)–[14](./14).

## Типичные ошибки

| Ошибка | Следствие | Что делать |
|--------|-----------|------------|
| Нет `clear` перед draw | шлейф объектов | clearRect / fill фон |
| Без `dt` в движении | разная скорость на разных FPS | умножать на delta time |
| Рисование в `update` | смешение слоёв | только в render |
| Игнор `devicePixelRatio` | размытый canvas на Retina | масштабировать размер canvas |
| Upload текстуры каждый кадр | CPU/GPU stall | загрузить один раз |
| Тысячи draw calls | узкое место CPU | batching, atlas |
| Глобальный GL state | случайный blend/depth | VAO, PSO, discipline |
